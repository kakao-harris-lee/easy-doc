# 검사 도구 계획

> 이 문서는 **로드맵**이다. 확정된 계약은 `DESIGN.md`에 있고, 여기 적힌 것이 구현되면 그 결과도 DESIGN.md로 옮긴다.
>
> 작성 근거: 2026-08-29 세션. 다듬은말 18,340건 적재를 시도하다 **한 건도 적재하지 않고** 배포 중이던 사전에서 결함 다수를 발견한 과정에서 도출했다.

## 1. 왜 지금인가

지금 사전은 2,142건이고 갭 리스트는 2,831건이다. **사전보다 구멍이 크다.** 그런데 이번 세션이 보여준 것은 이렇다.

| 결함 | 규모 | 어떻게 발견됐나 |
|---|---|---|
| 승자 결정이 CSV 행 순서로 정해짐 | 37건 | 적재 전 병합을 재보라고 지시해서 |
| 알파벳순이 틀린 답 선택 (`가주소 → 거짓 주소`) | 211건 | 목록을 눈으로 훑다가 |
| 어종 오판 (`提供--`를 외래어로) | 1,815건 | 태그 출력을 눈으로 보다가 |
| 동음이의어 (`한 번 → 까지 번`) | 8건 처분 | 예문 뽑다 우연히 |
| 죽은 엔트리 (조회 불가) | 3건 | 다른 수정 검증 중에 |
| 로마자 경계 (`CCTV → C전류 변성기V`) | 404개 표면형 노출 | 예문 표본을 보다가 |
| 활용형 비문 (`받음하실`) | — | 예문 표본을 보다가 |
| 예문 원천이 엔트리 귀속을 가져감 | 318건 | 예문 재추출 결과가 이상해서 |

**전부 사람 눈에 우연히 걸렸다.** 그 동안 테스트 127개는 전부 통과하고 있었다.

마지막 항목은 이 문서를 쓴 **직후에** 나왔다. 예문만 얹으려던 원천이 엔트리 318개의 `source_id`를 가져갔고, 그 원천이 신뢰도 표에 없어 tier 0이라 §6.8 키②가 승자를 뒤집었다. **재현성 검사는 `source_id`를 대조 항목에 안 넣어서 못 잡았다** — 아래 §2의 "겨냥이 틀린 검사"가 계획을 쓰자마자 실물로 나온 셈이다.

§8의 반성이 그대로 재현됐다.

> 계약에서 파생된 테스트는 계약의 구멍을 그대로 물려받는다.

사전을 키우면 이 문제도 같이 커진다. **검사 도구를 먼저 갖추는 것이 커버리지를 메우는 것보다 앞선다.**

## 2. 진단: 검사가 없는 게 아니라 진입점이 없다

```
tests/           7개 파일, 173개 테스트      있음
tools/           5개 도구                    있음
Makefile         없음
scripts/         없음
```

이번 세션에 실제로 결함을 잡은 검사들은 **대화 안에서 손으로 친 명령**이었다. 세션이 끝나면 사라진다. 다음 사람은 같은 명령을 다시 발명해야 한다.

그리고 §5.5에 새로 추가된 결함 유형이 이 문제의 핵심을 짚는다.

> **검사 도구의 겨냥이 틀린 경우** — 순서를 바꿔 비교하는 검사는 그 순서가 파일 내부에 있으면 무력하다.

**검사가 무엇을 못 보는지 모르면, 통과가 안전을 뜻하지 않는다.**

## 3. 네 개의 층위

검사를 "무엇에 답하는가"로 나눈다. 층위마다 비용도 판정 권한도 다르다.

| 층위 | 질문 | 비용 | 판정 | 현재 |
|---|---|---|---|---|
| 1 | 산출물이 스스로 모순되지 않는가 | 0 | 기계 · **차단** | 부분 |
| 2 | 실제 문서를 통과시키면 무슨 일이 나는가 | 초 | 기계 · **차단** | **없음** |
| 3 | 대치어가 그 뜻이 맞는가 | API·분 | 기계 후보 → **사람 판정** | 초안 |
| 4 | 무엇이 빠졌는가 | 초 | 사람 | 있음 |

### 층위 1 — 구조 불변식

이미 있는 것: `substitute`+`review` 공존 금지, `readability` 범위, `deprecated` 유출, `simple.jsonl` 계약.

**빠진 것 두 가지가 이번에 결함으로 드러났다.**

- **도달 가능성** — 모든 엔트리가 자기 표면형에서 조회되는가. `가설`·`거치`·`내방`이 사전에 있는데 영영 안 나왔다
- **보호 엔트리 승리** — `gloss`/`keep`/`high`/`review`가 `substitute`에 지지 않는가. 37건이 지고 있었다

### 층위 2 — 코퍼스 통과 (없다)

**이번 세션에서 가장 많은 결함이 나온 자리인데 자동화가 하나도 없다.** `CT`, `한 번`, `받음하실` 전부 여기서 나왔어야 했다.

### 층위 3 — 의미 검증

`tools/detect_homonym_risk.py`가 초안 상태다. krdict `sup_no`로 동형어를 잡는다. **오탐 2종을 고쳐야 쓸 수 있다.**

### 층위 4 — 커버리지

`tools/extract_gaps.py`가 이미 한다. 갭 2,831건.

## 4. 단계

### Phase 1 — 진입점 (최우선, 가장 싸다)

**완료(2026-08-29)**: `scripts/check.sh` + `tools/check_invariants.py`. 층위 1에 도달 가능성·보호 엔트리 승리·엔트리 귀속 불변까지 포함됐다.

`scripts/check.sh` (또는 `Makefile`) 하나. 층위 1+2를 돌리고 실패하면 비영 종료.

```
scripts/check.sh
  ├─ 기존 테스트 173개
  ├─ 불변식 검사        (층위 1)
  └─ 코퍼스 스모크       (층위 2)
```

**완료 조건**: 명령 하나로 전부 돌고, 이번 세션의 결함 7종을 그 시점 코드에 되돌려 넣으면 **각각 정확히 실패한다.**

이 마지막 조건이 핵심이다. 이번 세션에서 반복해 확인한 습관 — **규칙을 일부러 빼서 테스트가 실패하는지 본다** — 을 검사 자체에 적용한다. 안 하면 통과가 무의미하다.

### Phase 2 — 층위 2를 만든다 (없던 것)

**완료(2026-08-29)**: `tools/audit_corpus.py` + `tools/audit_corpus.baseline.json`(커밋 대상) + `tools/tests/test_audit_corpus.py` + `check.sh` 4/4 단계 + README "빌드 검증" 절.

`tools/audit_corpus.py`. 골든 57건에 현행 `dist/`를 통과시켜 센다.

| 검사 | 이번 세션 근거 |
|---|---|
| 경계 위반 (한글 4방향 + 로마자·숫자) | `CT`-in-`CCTV` |
| 원문 파괴 — annotate 출력이 원문 토큰을 깨뜨림 | `C전류 변성기V` |
| 활용형 substitute 비문 후보 | `받음하실` |
| 한 표면형에 상충 지침이 나가는가 | `build_prompt_context` |

**기준선을 파일로 고정하고 늘어나면 실패시킨다.** 지금 남아 있는 알려진 사례(`조제`, `시스템`)를 0으로 만들 수 없으니, 0을 요구하는 대신 **증가를 막는다.**

**완료 조건**: 현행 `dist/`에서 경계 위반 0건이 재현되고, `CT` 수정을 되돌리면 1건으로 늘어난다.

### Phase 3 — 층위 1의 구멍

**완료(2026-08-29)**: 아래 표 6항목 전부. 도달 가능성·보호 엔트리 승리·엔트리 귀속 불변은 Phase 1의 `tools/check_invariants.py`에, 나머지 셋은 `src/easydict/build.py`(CLI 인자 정렬)·`tests/test_reproducibility.py`(파일 내부 행 순서 독립성)·`tests/test_rebuild_determinism.py`(재빌드 diff, 신규)에 들어갔다.

| 검사 | 막는 결함 |
|---|---|
| 도달 가능성 | 죽은 엔트리 (`가설`·`거치`·`내방`) |
| 보호 엔트리 승리 | 승자 결정 오류 37건 |
| **파일 내부** 행 순서 독립성 | 기존 재현성 검사가 원리상 못 잡는 구간 |
| **엔트리 귀속 불변** | 예문 원천의 `source_id` 탈취 318건 |
| **CLI 인자 정렬** | `--source-role`이 엉뚱한 원천에 붙음 (아래) |
| 재빌드 diff | §5.5(6) 상태 이중화 (예문 CSV 스냅샷) |

다섯 번째는 재빌드를 직접 하다 걸린 것이다. `--source-role`을 **마지막 원천에만** 주었더니 인덱스 0(`nikl:admin2018`)에 배정돼 1,717건짜리 원천이 예문 전용으로 처리됐다.

```
nikl:admin2018 (role=examples): 입력 1075행 -> 엔트리 0개
엔트리 2,142 -> 449
```

원천별 인자(`--input`/`--source-code`/`--default-tag`)는 개수가 맞아야 짝이 맞는데, `--source-role`만 한 번 줘도 통과한다. **폐기 1,075건을 사유와 함께 소리 내어 보고한 덕에(§5.5(4)) 잡혔지만**, 검사로 막는 편이 낫다.

> 원천별 인자의 개수가 `--input` 개수와 다르면 빌드를 중단한다. §5.1이 컬럼 별칭 해석 실패에 대해 정한 것과 같은 원칙 — **조용히 그럴듯한 결과를 내느니 크게 실패한다.**

세 번째가 중요하다. 기존 `test_reproducibility.py`는 `--input` **파일 간** 순서만 바꾸고 후보를 `frozenset`으로 비교한다. 이번 결함 50건은 전부 **한 파일 내부** 문제였고, 그래서 이 검사로는 원리상 안 잡힌다.

네 번째는 **대조 항목 자체가 빠져 있던 경우**다. fwd/rev 비교가 `(term_norm, easy_term, strategy, risk, status, readability)`만 봤고 `source_id`가 목록에 없었다. §6.8 키②가 원천 신뢰도를 읽으므로 `source_id`는 **승자를 바꾸는 값**인데 검사 대상이 아니었다.

> 검사는 자기가 무엇을 대조하는지 목록으로 드러내야 한다. 목록에 없는 필드는 검사되지 않는 것이고, 그 사실이 보이지 않으면 통과가 안전으로 읽힌다.

### Phase 4 — 층위 3 정리

**완료(2026-08-29), 보류 31건 남음**: 도구·처분 모두 끝났다. 아래 1·2는 `tools/detect_homonym_risk.py`에 반영됐고, 처분은 `src/easydict/build.py`의 `HOMOGRAPH_COLLISION_TERMS`/`DEPRECATED_HOMOGRAPH_TERMS`에 들어갔다.

1. **오탐 2종 수정 — 완료.** `~하다`/`~되다` 접미(krdict는 `捺印하다`, 우리는 `捺印`), 빈도 경계(`자`가 875 → 실측 53). 빈도는 `text.count()`가 아니라 `find_all()` 기준으로 바뀌었다 — **빈도가 우선순위를 정하는 지표라 이걸 안 고쳤으면 순위가 통째로 틀렸다.**
2. **검사 불가 573건(62%) 분리 보고 — 완료.** 실행 요약이 `플래그 / 정상 / 검사불가-표제어없음 / 검사불가-부분일치 / 조회실패` 다섯으로 쪼개져 나오고, 검사 불가가 있으면 경고 줄이 따로 찍힌다.
3. **검수 큐 운영 규칙 — 부분.** 처분은 코드 상수에 근거 주석과 함께 기록한다(원천 오류는 `data/raw/*.known-errors.md`로 분리). **누가 언제 보는가는 아직 안 정했다.**

#### 처분 결과 (40건 플래그 기준)

| 권고 | 건수 | 내용 |
|---|---|---|
| 구조 수정 | 3+ | `~하다` 어간 변형형 억제로 한꺼번에 해소 (§5.5.1) |
| 비활용 | 1 | `개시(開示)` — 코퍼스 4/4가 `開始`, krdict에 `開示` 자체가 없음 |
| 유지 | 5 | `자` · `수령` · `소요` · `도래하다` · `가산` |
| 보류 | 31 | 빈도 0이라 근거 부족 — 코퍼스를 넓힌 뒤 다시 본다 |

**`가하다` 진단이 처분을 바꾼 것이 이 라운드의 핵심이다.** 빈도 40으로 잡혔는데 40건 전부 `加`도 `可`도 아니라 **열거 기호 `가.`**였다. 동형어 문제가 아니라 어간 변형형 문제였고, 엔트리를 비활용했으면 멀쩡한 `부담을 가하다`까지 잃었다. `배치하다`·`부상하다`도 같은 구조였다 — **40건 중 실제 처분 대상은 1건뿐이었다.**

보류 31건 중 **"우리 한자가 krdict 뜻 목록에 아예 없는" 강신호 5건**(`감수`·`강매`·`공기`·`수수`·`투기`)은 따로 표시해 두었다. 빈도 0은 "안전하다"가 아니라 "코퍼스 57건에 안 나온다"이다.

별건으로 **원천 자체의 한자 오류**가 하나 나왔다 — `소화하다`가 한자는 `消化`인데 대치어가 `불끄다`(`消火`)다. 2018년 국립국어원 원문 PDF 507행을 대조해 **우리 파싱이 아니라 원천의 오류**임을 확인했고, 고치지 않고 `data/raw/nikl_admin_terms_2018.known-errors.md`에 근거와 함께 기록했다. 원천을 임의로 고치면 다음에 원천을 다시 받을 때 그 수정이 사라진다.

## 5. 원칙

이번 세션에서 값을 치르고 얻은 것들이다.

**하나. 기계가 확실히 아는 것만 차단한다.** 오탐 있는 휴리스틱으로 빌드를 막으면 사람이 게이트를 우회하는 법을 배운다. 층위 1·2는 차단, 층위 3·4는 리포트.

**둘. 검사가 무엇을 못 보는지 함께 보고한다.** 927건 중 573건은 krdict에 없어 검사 자체가 불가능했다. 이걸 "통과"로 세면 사전이 안전하다는 착각이 생긴다.

**셋. 신호는 판정이 아니다.** `자(者)`는 동형어 5개로 플래그되지만 코퍼스 92% 정확이다. 자동 처분했으면 `졸업한 자는 → 졸업한 사람은`이라는 **이 제품의 핵심 변환**을 잃었다.

**넷. 탐지 도구에도 정규화를 적용한다.** 실패한 방법의 신호 37건이 NFKC 정규화 후 2건이 됐다 — 35건이 CJK 호환 한자 이체자와 오탈자였다. 검수자에게 잡음을 읽히면 검사를 안 믿게 된다.

**다섯. 검사를 일부러 깨서 실패를 확인한다.** 규칙을 빼도 테스트가 통과하면 그건 테스트가 아니라 장식이다. 이번 세션에서 세 번 이 확인이 실제로 겨냥 실패를 잡아냈다.
