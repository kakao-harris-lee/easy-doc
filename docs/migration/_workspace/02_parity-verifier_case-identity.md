# 케이스 정체성 장치 — 케이스 축의 하한과 보류 마커 (J-1 + J-3)

작성: `parity-verifier` (2026-08-14) · 근거: `reviews/10_detector-redesign_cross.md` R-4·C-4 · 리더 판정(J-1+J-3 통합)
산출물: `.github/parity-case-floor.txt` · `compare_parity.py`(`case_floor_problems`·`verdict_pending_problems`)

> **한 줄 요약.** 케이스가 조용히 사라지는 것과, 마커만 붙여 두고 아무도 읽지 않던 보류를 함께 닫는다. **하한은 개수가 아니라 케이스 id**이고, 보류 마커는 **소유자·기한·회부처를 필수**로 만들어 은폐형에서 탐지형으로 바꿨다.

## 1. 왜 개수가 아니라 id 인가

리더 판정이 지목한 대로 이 저장소는 같은 판정을 이미 한 번 내렸다(`86c6a99` — *"개수를 정체성으로 바꾼다"*). 총개수 하한은 **순소실만** 막는다.

| 편집 | 개수 하한 | 케이스 id 하한 |
|---|---|---|
| 케이스 1건 삭제 | 잡는다 | 잡는다 |
| **1건 지우고 아무거나 1건 추가** | **통과** | **잡는다** |
| **이름만 바꾸기** | **통과** | **잡는다** |

가운데 줄이 위험한 이유는 지워지는 것이 하필 **유일한 과잉 가드**일 수 있기 때문이다. 개수는 정체성의 대리 지표이고, 대리 지표로 실물을 판정하는 것이 이 하네스가 금지하는 바로 그것이다.

**실증이 이 판단을 그대로 되받았다.** 보류 케이스 2건의 id를 `known-gap-*` → `deferred-*` 로 바꾸자 게이트가 잡았고, 메시지가 이렇게 찍혔다:

> `masking` **케이스가 사라졌다**: masking-known-gap-five-…, masking-known-gap-four-…
> 하한은 이 도메인에서 83건을 요구하는데 fixture 에는 **83건이 있다**

**개수가 같은데 정체성이 갈린 상태** — 개수 하한이었다면 조용히 통과했을 자리다.

## 2. 비대칭 — 추가는 자유, 삭제·개명은 차단

`.github/parity-*-floor.txt` 두 파일의 전례를 그대로 따른다.

- **추가** → 통과. 검증이 늘어난 것이라 무해하다. 비교기가 「케이스 하한 미등재」 구획에 이름만 찍는다.
- **삭제·개명** → 실패. 그 케이스가 지키던 성질이 조용히 사라진다.

**개명이 삭제로 잡히는 것은 의도다.** id는 리포트·참고 갈림 원장·명세 문서가 함께 쓰는 키라, 바꾸면 그 셋이 전부 어긋난다(실제로 위 개명에서 원장 항목 2건이 낡은 항목으로 함께 지목됐다).

`--only` 로 케이스 하나를 골라 돌린 실행에서는 이 검사를 건너뛴다. 켜 두면 정상적인 단일 케이스 재현이 매번 빨개진다.

## 3. `known_gap` → `verdict_pending` — 은폐형에서 탐지형으로

**R-4의 요지**: 옛 `known_gap` 은 자유 문자열이었고 **어느 게이트도 읽지 않았다.** 마커를 붙이는 것이 곧 "판정을 미뤘다"의 기록이었는데, 미룬 것을 **누가 언제까지** 닫는지가 어디에도 없어 미룸이 영구가 됐다.

```json
"verdict_pending": {
  "reason": "무엇이 열려 있나",
  "owner": "누가 닫나",
  "deadline": "언제까지",
  "referred_by": "누가 회부했나"
}
```

넷은 각각 다른 질문에 답하고 **하나라도 비면 게이트가 막는다**. 옛 `known_gap` 키가 남아 있어도 막는다(마이그레이션 가드).

**CLAUDE.md 규칙 4의 어휘로 쓰면**: 면제 조항은 **은폐형**이라 넓히지 않고 **탐지형으로 갈아탄다**. 같은 마커가 필드를 갖는 순간 리포트에 소유자와 기한이 찍히고, 그 줄이 비면 막힌다.

## 4. 판정 수에서 분리한다

보류 케이스는 구조 불변식(`restores_input` 등)은 그대로 실행하되 **`성질 판정 N건` 에 넣지 않는다.** 넣으면 *아무도 방향을 정하지 않은 자리*가 커버리지 지표를 채운다.

```
성질 판정 106건(단언 370개) / 판정 보류 2건 / 참고 갈림 32건 / …
```

리포트에 별도 구획이 붙는다 — 도메인·케이스·소유자·기한·회부·실행 단언 수·무엇이 열려 있나. **이 표가 비어 보이면 마커가 지워진 것이지 보류가 닫힌 것이 아니다.**

## 5. 마커 제거까지 막는다 — 음성 대조가 찾은 구멍

처음 구현에서 **마커를 떼면 아무것도 막지 않았다.** 케이스는 남아 있으니 id 하한은 조용하고, 그 케이스는 조용히 `성질 판정` 수로 넘어간다(106 → 108, 보류 2 → 0). **판정된 적 없는 자리가 판정 수를 채우는데 게이트는 초록**이었다.

하한 줄에 ` !deferred` 꼬리표를 붙여 **보류 상태까지** 기억하게 해서 닫았다. 보류를 실제로 닫으려면 방향을 단언으로 걸고 하한에서 꼬리표를 지워야 하고, 그 diff가 리뷰에 올라간다.

```
masking/masking-deferred-four-groups-single-space !deferred
```

## 7. §2.4 정의 어긋남 — 이것으로 해소되는가

**해소된다.** 직전 회차에서 내가 신고한 어긋남은 이랬다 — 마스킹 명세 §2.4가 `known_gap` 을 *"아직 어느 게이트에도 판정을 요청하지 않은 자리"*로 정의했는데, 연도 배열 2건은 *"판정을 요청받고 명시적으로 판정하지 않기로 한"* 상태였다. 대기 표기가 없어 `known_gap` 을 쓸 수밖에 없었다.

새 마커는 그 구분을 **필드로 표현한다.**

| 상태 | 새 체계에서 |
|---|---|
| 아무도 안 봤다 | 그런 자리는 마커를 붙일 근거가 없다 — `owner`·`referred_by` 를 채울 수 없다 |
| 회부됐고 판정 대기 | `referred_by` 에 회부 문서, `owner` 에 판정할 레인, `deadline` 에 기한 |
| 회부됐고 "판정하지 않기로" 판정됨 | 같은 필드 + `reason` 이 왜 지금 단언할 수 없는지 적는다 (연도 배열 2건이 이것) |

즉 마커가 **"아무도 안 봤다"가 아니라 "열린 결정의 소유권"**을 뜻하게 바뀌었고, 그래서 §2.4의 옛 정의는 더 이상 필요하지 않다. 마스킹 명세 §2.4·§10.3을 그렇게 고쳤다.

**남는 것 하나**: 새 체계는 "마커를 붙일 자격"을 검사하지 않는다 — `owner` 에 아무 이름이나 적고 `deadline` 에 먼 날짜를 적으면 통과한다. 그것은 리뷰가 받는 자리다. 이 장치가 하는 일은 **보류를 조용할 수 없게** 만드는 것이지 부당한 보류를 불가능하게 만드는 것이 아니다.

## 8. 막지 못하는 것

- **케이스 내용이 무르게 바뀌는 것** — 단언을 약한 것으로 바꾸는 편집은 id가 그대로라 이 하한이 못 잡는다. 그 자리는 fixture 정본 대조(생성기 재실행 후 전량 비교)가 받는다.
- **하한 파일 자체를 같은 커밋에서 함께 고치는 것** — 저장소 안의 어떤 파일도 저장소 자신에 대한 절대 기준이 될 수 없다. 하는 일은 축소를 불가능하게 만드는 것이 아니라 **조용할 수 없게** 만드는 것이고, 최종 방어선은 리뷰다.

## 9. 후속 (2026-08-14) — 게이트 11 비교기 몫 (X-2·X-3·X-4·C-4)

### 9.1 X-2·X-3 — 하한이 비교 범위만큼만 닿았다

**사실.** `case_floor_problems` 가 `pairs`(= `--only-domain` 으로 좁혀진 비교 대상)를 순회했다. 부분 게이트에서 선언하지 않은 도메인은 `pairs` 에 없으므로 그 케이스는 **하한 밖**이었다 — 선언 151건 중 **139건만 도달**. `export` 12건이 하한·형태·값 어느 것도 받지 않는 상태였고, 실제로 12 → 3으로 줄여도 지적 0건이었다(재현 확인).

**고친 것.** 하한이 대조하는 대상을 **fixture 실물 전체**로 바꿨다(`floor_scope`). 하한은 "무엇을 비교했는가"가 아니라 **"무엇이 남아 있는가"**의 검사라 비교 범위와 다른 축으로 읽어야 한다. `pending` 도메인도 여기 들어온다 — 생산자가 없어 값 비교는 못 해도 **케이스가 사라지는 것**은 지금 막을 수 있다.

**형태 검증도 열었다.** `spec_shape_problems` 가 `pending_spec` 에서 통째로 빠져나갔다. 지금은 pending 도메인도 **중복 입력·보류 마커 형태** 검사를 받는다. 다만 단언을 전제로 하는 둘(**단언 없는 케이스**·**방향 가드**)은 뺐다 — pending 은 정의상 단언이 없으므로 그것을 걸면 pending 이라는 상태 자체가 결함이 된다.

### 9.2 codex 가 연 사각 — "비어 있지 않은 무의미 선언"

하한 파일에 `bogus/placeholder` 한 줄을 넣어도 **지적 0건**이었다. `floor.get(도메인)` 이 없는 도메인을 조용히 건너뛰었기 때문이다.

**빈 선언을 막는 검사는 있는데(`floor_count == 0`) 무의미한 선언을 막는 검사가 없었다.** "하한이 비어 있지 않다"가 "하한이 무언가를 지킨다"를 뜻하려면 선언이 **실물과 대응**해야 한다. 실물에 없는 도메인을 선언하면 이제 차단한다.

### 9.3 X-4 — 유도의 **입력**까지 독립으로 (리더 판정)

충돌의 양쪽이 다 참이었다. 유도 **로직**은 독립이었지만(Claude) 유도의 **입력**이 산출물 자기 보고였다(codex). 그래서 생산자가 문장을 통째로 버리면(`sentences: []`) 유도값도 비어 **양쪽이 사이좋게 0**이 되어 통과했다.

**닫은 방법**: 비교기가 **fixture 입력 텍스트를 직접** 종결부호(`.`·`!`·`?`·개행)로 갈라 **더 쪼갤 수 없는 구간**을 얻고, 그중 상한을 넘는 것을 **하한**으로 요구한다(`contains_derived` + `style_length_floor`·`style_comma_floor`).

**왜 이것이 문장 분리를 판정하지 않으면서도 성립하는가**: 구간 안에 종결부호가 없으므로 **어떤 분리기도 이보다 잘게 쪼갤 수 없다.** 따라서 그 구간이 상한을 넘으면 어떤 구현이든 반드시 위반으로 보고해야 한다. 하한이지 정답이 아니고, 문장 분리 경계는 여전히 판정하지 않는다.

기존 `equals_derived` 두 건은 그대로 둔다 — 그쪽은 **정확 일치**(건전성 포함)를 보고, 새 둘은 **누락 불가**를 본다. 둘이 다른 것을 본다.

> **남는 한계**: 종결부호를 **끼워 넣어** 긴 문장을 잘게 만드는 입력에서는 하한이 낮아진다. 이 하한이 막는 것은 *보고를 버리는 것*이지 *분리를 조작하는 것*이 아니다. 후자를 막으려면 문장 분리를 판정 대상으로 삼아야 하고, 그것은 요구사항이 명시적으로 하지 않기로 한 자리다.

### 9.4 C-4 — 사전은 표제어만이 아니라 **값**이 자산이다

`contains_all` 은 표제어만 봤다. 뜻풀이를 통째로 바꿔도 통과했고, 그 값은 **프롬프트에 그대로 실려 모델에게 간다**. 246개는 실측 큐레이션 산출물이라 값이 곧 자산이다.

`contains_entries` 를 더했다 — `[표제어, 값]` 쌍으로 대조하고 **추가는 허용**(포함 관계), **값 변경만 차단**.

## 10. 후속 (2026-08-15) — 게이트 12 비교기 몫 (#4 · #3)

### 10.1 #4 — 파일명 축에 over 방향이 **하나도 없었다** (Phase 2 저지)

**재현이 먼저다.** export 파일명 21개를 전부 대체 이름(`쉬운 글.txt`)으로 바꿔 넣었다.

```
성질 불충족 0건 · 불충족 6건(전부 원장 갈림)
```

**사용자가 올린 제목이 통째로 사라져도 성질 판정은 초록**이었다. `present` 니들이 확장자뿐이라 "무엇이 없어야 하는가"만 재고 있었고, `export-filename-all-forbidden` 은 참고값 자체가 대체 이름이라 갈림 신호조차 없다.

**처방은 X-4에서 만든 입력 유도 하한을 그대로 옮긴 것이다.** `equals_field` 로 정제 결과를 못박는 방식은 쓰지 않았다 — 공백 접기·앞뒤 점 깎기 규칙까지 값으로 고정돼 **규칙 개선이 회귀로 잡힌다**(§7.1 정합). 대신 비교기가 **fixture 입력 제목에서** 표지를 뽑는다.

**"사라질 수 없다"의 근거 둘** — 이것이 이 하한이 성립하는 이유다.

1. 금지 문자·공백·점으로 **가른 뒤**의 조각이라, 어떤 정제도 그 조각 **안**을 건드리지 않는다(정제 대상이 경계에만 있다).
2. 제목 앞 40자에서만 뽑고 조각도 8자로 자른다. 정제는 길이를 **줄이기만** 하므로 그 앞부분은 줄기 상한 80자 안에 반드시 들어온다.

| 표본 | 유도된 표지 |
|---|---|
| `기초연금 신청 안내` | 기초연금 · 신청 · 안내 |
| `../etc/passwd` | etc · passwd |
| `제\x00목\x1f입니다` | 입니다 (1자 조각은 뺀다) |
| `가`×120 | 앞 8자 |
| `///` | **없음** → 대체 이름 단언이 따로 받는다 |

마지막 줄이 남은 구멍이었다. 제목이 전부 금지 문자면 표지가 없어 하한이 아무것도 요구하지 않는다. 그 자리는 "사용자에게 보일 이름을 대신 쓴다"를 따로 못박았다.

> **별도 케이스로 만들려다 M-08 중복 검사에 막혔다.** 입력이 `{"title": "///"}` 로 같아 같은 산출물을 두 번 재는 구조였다. 지적이 옳아 기존 케이스에 단언을 합쳤다 — **직전 회차에 내가 넣은 장치가 이번에도 나를 먼저 물었다.**
>
> 한계 하나: 대체 이름 문자열은 계약에 없고 **구현 상수**(`_FALLBACK_NAME`)가 기준이다. Kotlin 이 다른 이름을 쓰면 걸리므로 제약은 실재하나, "그 이름이 옳은가"는 이 게이트가 판정하지 않는다.

**검출 실증** (대조군 exit 3 · 12건 · 141단언 · 불충족 0)

| 주입 | 결과 |
|---|---|
| 파일명 전부 대체 이름 | **exit 1 · 6건** — `'기초연금', '신청', '안내' 를 담지 않았다` |
| 확장자만 남긴 이름(`.txt`) | **exit 1 · 7건** (대체 이름 케이스가 하나 더 걸린다) |

### 10.2 #3 — 8/8은 강제된 성질이 아니라 **오늘 참인 상태**였다

전체/부분 게이트 판정이 `declared == canonical` 로 계산되고 `canonical` 은 **BUILDERS 키**다. 그래서 생성기에 builder 를 하나 더하면 등식이 깨져 **부분 게이트로 내려가고, 종료 코드 3 사면이 되살아난다.**

**전체 게이트 도달 상태를 하한으로 고정했다** — `.github/parity-full-gate.txt`. 있으면 "선언이 정본 전부를 덮은 적이 있다"는 뜻이고, 그 뒤 부분 게이트로 내려가는 것은 강등이라 차단한다.

**자기 무장(self-arming)으로 만들었다.** 이 장치가 빠지기 쉬운 함정은 "아직 도달 안 했으니 나중에 만들자"가 되어 **도달 0인 채 잠드는 것**이다. 그래서 두 방향을 모두 막는다.

| 상태 | 판정 |
|---|---|
| 선언 < 정본, 표시 없음 (오늘) | 통과 — 아직 도달 전이라 막을 것이 없다 |
| 선언 ⊇ 정본, **표시 없음** | **exit 1** — "도달했다. 하한을 고정하라" |
| 표시 있음, 선언 < 정본 | **exit 1** — "전체 게이트에서 내려왔다" |

도달하는 **순간** 비교기가 고정을 요구하므로 만들어 두는 것을 잊을 수 없다.

**음성 대조 4종**

| 변형 | 결과 |
|---|---|
| 7선언 · 정본 8 · 표시 없음 (현재) | **exit 3** — 막지 않는다 |
| 8선언 · 표시 없음 | **exit 1** — `전체 게이트에 도달했다 — 하한을 고정하라` |
| 표시 있음 · 7선언으로 되돌림 | **exit 1** — `전체 게이트에서 내려왔다: export` |
| **표시 있음 · 가짜 builder 추가(정본 9)** | **exit 1** — `전체 게이트에서 내려왔다: fake-new-domain` |

마지막 줄이 리뷰가 지목한 바로 그 시나리오다.

**자기 무장이 실제 상황에서 발화했다 (2026-08-15).** 이 절을 쓰는 동안 `kotlin-implementer` 가 `export` 를 선언해(`adb4197`) 선언이 8이 됐고, 다음 실행이 정확히 그 문구로 막았다.

```
- **전체 게이트에 도달했다 — 하한을 고정하라**: 선언 8개가 정본 8개를 전부 덮었다
종료 코드 1
```

**설계가 의도한 그대로다** — 도달을 사람이 기억해 표시 파일을 만드는 것이 아니라, 도달하는 순간 게이트가 요구했다. 그 뒤 `.github/parity-full-gate.txt` 를 만들었고 강등 음성 대조(선언 7로 되돌림)가 `전체 게이트에서 내려왔다: export` 로 막는 것을 확인했다.

**그리고 전체 게이트가 닫혔다.**

```
[전체 게이트] 기대 도메인 8/8개 전부를 판정 범위에 넣었다
요구 성질 충족: 도메인 8/8 / 성질 판정 152건(단언 608개) / 판정 보류 0건
             / 미검증 0건 / 불충족 0건 / 도메인 누락 0개    종료 코드 0
```

CI 는 `선언 == 정본` 일 때 `--only-domain` 을 주지 않고 돌리므로(그래야 비교기가 기대 집합 전부를 요구한다) 이 경로가 실제 CI 경로다. **이 시점부터 종료 코드 3은 통과가 아니다.**

### 10.3 부기 — 복원 사고 2건째 (규칙 5)

가짜 builder 음성 대조를 정리하며 `git checkout -- dump_parity_fixtures.py` 를 돌렸는데, 그 파일에 **#4의 미커밋 변경이 함께 있었다.** 프로브만 되돌리려던 명령이 그날 작업을 함께 지웠다.

즉시 발견해 복구했다(`grep -c export_title_markers` = 0 확인 → 재적용 → 대조군 exit 3 재확인). 지난 회차의 `cp` 별칭 사고와 **기제는 다르고 형태는 같다** — *복원 대상이 프로브보다 넓었다.*

**규칙으로 옮긴다**: 프로브를 위해 제품 파일을 고쳤으면, 되돌리기 전에 **그 파일에 미커밋 작업이 있는지 먼저 본다.** 있으면 `git checkout` 을 쓰지 않고 주입한 조각만 역으로 지운다. 가장 싼 예방은 **프로브 전에 커밋하는 것**이다.
