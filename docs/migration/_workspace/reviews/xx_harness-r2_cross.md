## 2. 리더 질의 ①: codex ⑴ 과 Claude C-2 / X-3a 는 같은 자리인가

**다른 구멍이다. 어느 쪽도 다른 쪽을 포함하지 않으며, 처방도 다르다.** 같은 파일·인접 코드라는 것만 공통이다.

| | Claude C-2 | codex ⑴ |
|---|---|---|
| 기제 | 상태 칸이 `_LEDGER_STATES` 밖 → `_ledger_rows` 가 **조용히 `continue`** (파싱 층) | 상태 칸이 **정상 어휘 `이연`** → 행은 분모에 들어오지만 **닫힘 검사에서 제외** (의미 층) |
| 사라지는 것 | 행 자체가 분모에서 증발 | 행은 남고 **의무만** 증발 |
| 재현 방식 | 사람 손 오타(`대기` / `**대기**` / `대기(미리뷰)`) | 규약을 **정확히 지킨** 정상 기재 |
| 처방 | 「표처럼 보이는 행 수 = 파싱된 행 수」 대조(R-1) + `닫힘` 헤더 단언(R-2) | 출하 모드에서 `이연` 행도 `닫힘`(또는 리뷰 범위 포함)을 요구 |
| 상대 처방으로 닫히는가 | codex ⑴ 처방을 넣어도 **안 닫힌다** — 오타 행은 그 검사 앞에서 이미 버려진다 | C-2 처방(R-1·R-2)을 넣어도 **안 닫힌다** — `이연` 행은 정상 파싱된다 |

**둘 다 반드시 따로 닫아야 한다.** 합치면 「출하 판정이 거짓 초록이 되는 경로」가 최소 셋이다(C-1 무하중 행 · C-2 오타 행 · codex ⑴ `이연` 행).

## 3. 리더 질의 ②·③: 실행 검증 결과 (제3의 근거)

두 codex 지적 모두 **정적 읽기가 아니라 실행으로 재현했다.** codex 자신은 테스트 실행에 2회 실패해 정적 분석만 했다고 기록했으므로(codex 산출물 「미실행·실패 항목」), 이 절이 그 공백을 메운다. 어느 지적도 삭제하지 않았고 근거만 더했다.

### 3.1 codex ⑵ — **재현됨. Claude 1차가 놓친 진짜 결함이다** (근거 약하지 않음)

`wt-cross`(HEAD `76b5cc1`)에서 두 스킬 파일 양쪽의 축⑤(`작업 큐·LLM 호출 규약`) 한 줄을 삭제:

| 변이 | 결과 |
|---|---|
| 기준선 (무변조) | `1 passed` |
| **MUT-1 — 축⑤ 삭제, 번호 유지**(`1.2.3.4.` `6.` `7.`) | **`45 passed`, exit 0** — `test_리뷰_4축_사본이_갈리지_않는다` 통과. 파일 전체 45건 중 **아무것도** 발화하지 않음(장치 밖 탐지 0) |
| MUT-2 — 축⑤ 삭제 + 번호 재부여(`…4.` `5.` `6.`) | `1 failed` — `AssertionError: 4축 열거 블록을 찾지 못했다: [kotlin-migration/SKILL.md, codex-review/SKILL.md]` |

**codex 가 지목한 정확한 조건에서만 통과한다** — 번호를 재부여하면 7번 anchor 가 사라져 잡힌다. 그리고 이 조건이 결함을 **더 무겁게** 만든다:

> 마크다운 순서 목록은 첫 번호만 쓰고 이후 숫자를 무시한다. `1.2.3.4.6.7.` 은 렌더링에서 **1~6 으로 정상 표시된다.** 즉 번호를 안 고치는 편집이 자연스러운 인간 편집이면서 **읽는 사람 눈에도 결손이 보이지 않는다.**

`_AXIS_NAMES` 는 `CLAUDE.md` 리뷰 게이트 절에만 대조되므로(`:1460`), `CLAUDE.md` 를 그대로 둔 채 두 스킬에서 축 하나를 지우면 **라우팅 정본이 6축으로 줄어든 채 게이트가 초록**이다. 사라진 축에 닿는 변경은 「일곱에 닿지 않는 변경」으로 분류돼 묶여 이연된다 — `CLAUDE.md:25` 가 「면제 없다」고 선언한 자리에 면제가 생긴다.

**Claude 1차가 왜 놓쳤나(사실만):** 1차는 축 목록 자체가 아니라 커버리지·장부 표의 위조 내성에 실행 예산을 썼다. `test_리뷰_4축_사본이_갈리지_않는다` 는 재실행 22건 목록에 없었다.

### 3.2 codex ⑴ — **재현됨.** 게이트의 경고문이 스스로 지목한 우회가 강제되지 않는다

구성: 합성 비면제 커밋 `453e82b`(`tests/conftest.py` 변경 — docs 전용 아님), 커버리지 범위 밖, 장부에 `상태=**이연**` · `리뷰할 회차=xx_harness-r3` · **`닫힘`=`-`(공란)** 한 줄. 24개 `대기` 행은 전부 `닫힘` 을 채워 이 회차가 정직하게 상환된 상태를 모사. 커버리지 행 `xx_harness-r2 | cbf6e8d..76b5cc1` 추가(산출물 3역할 커밋 완료 — X-2a·X-2b·X-2c 유효 판정 통과).

| 실행 | 결과 |
|---|---|
| 평시 | `4 passed` |
| **출하 모드 `REVIEW_COVERAGE_REQUIRE_SETTLED=1`** | **`4 passed`, exit 0** ← 미리뷰 비면제 커밋을 안고 출하 판정 통과 |
| **음성 대조 — 같은 행의 `상태` 만 `이연` → `대기`** | `2 failed` · `assert not (LedgerRow(sha='453e82b', state='대기', round_='xx_harness-r3', closed='-'),)` |

**한 낱말 차이가 exit 0 과 exit 1 을 가른다.** 커밋도, 미리뷰 사실도, 빈 `닫힘` 칸도 동일하다.

그리고 실패한 쪽이 출력하는 메시지가 이것이다:

```
상태를 `이연` 으로 내려 적어 통과시키지 마라 — 그것은 거짓 기록이다.
```

**게이트가 자기 문면으로 금지한 바로 그 행동에 탐지자가 0이다.** 규칙 3 의 「산문은 강제자가 아니다」가 게이트 자신의 경고문에서 성립한 형태이고, Claude 1차 M-2 가 같은 종류를 다른 파일에서 지적했다(산문 언급 ≠ 강제자).

정적 확인으로도 뒷받침된다 — `_DEFERRED_STATE` 의 전 저장소 출현은 4곳뿐(`:316` 정의 · `:319` 어휘 튜플 · `:431` 출하 모드 필터 · `:627` 경고 문자열)이고, **`이연` 행의 `닫힘` 칸을 읽는 코드는 어디에도 없다.** X-3b(`:542`)와 `_unsettled`(`:416`)는 둘 다 `row.state == _WAITING_STATE` 로 잠겨 있다.

**오늘의 하중:** 현재 장부 25행 중 `이연` 은 **0건**(전부 `대기`). 즉 사건은 아직 없고 장치만 비어 있다. 그래서 마감을 「이 회차」가 아니라 **Phase 4 종료 판정 전 / 첫 `이연` 행이 적히는 순간 중 빠른 쪽**으로 적는다 — 심각도는 낮추지 않는다(규칙: 「아직 안 쓰이는 게이트니 차단이 아니다」로 스스로 낮추지 않는다).

**codex 원문의 심각도는 `[P2]` 다.** 「Critical ②(장치)」로 올린 것은 codex 원문이 아니라 래퍼의 정리 구획이다(§6-①). 위 실행 근거를 기준으로 이 표에서는 **차단 ②장치**로 적되, codex 자신의 값은 P2 였다는 사실을 남긴다 — 판정은 리더 몫이다.

### 7.2 종합 중 발견 — 미교차 (다음 회차 범위로 제안)

**①  `codex-reviewer` 래퍼가 자기 계약이 금지한 「심각도 부여」를 했다.**
