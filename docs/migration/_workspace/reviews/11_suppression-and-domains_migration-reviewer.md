### 2.1 보안 불변식

#### N-01 — **[Critical · 차단 ②장치]** 표기의 도달이 사유의 범위를 넘는다. 이 축에서는 구판보다 약해졌다

**마감: 지금** (`ci.yml:104` 이 이 스캐너를 BLOCK 으로 상시 실행 중).

**기제.** 억제 표기는 `(파일, 물리 줄, 규칙 id)` 에 묶인다 —
`scan_privacy_invariants.py:888-898` `_marker_for`. 그런데 적중은 **논리 줄당 규칙 하나**만 기록된다 —
`:982-994` `_is_candidate` 가 첫 후보에서 `return True` 하고, 호출부(`:1053`)가 `logical.number` 를 줄
번호로 쓴다. 따라서 표기 하나가 누르는 것은 "그 줄의 그 적중"이 아니라 **그 논리 줄 전체의 그 규칙**
이고, 논리 줄은 `MAX_LOGICAL_LINE_SPAN = 40`(`:590`) 까지 물리 줄을 삼킨다.

§4-octies.3 방어 (e) 는 *"줄 단위만 … 단일 물리 줄에만 붙는다"* 라고 선언한다. 그것은 **표기를 붙이는
위치**의 규칙이고, **눌리는 범위**는 선언과 다르다.

**실물 실측 (E-3).** 저장소의 실제 표기 줄
`backend-kotlin/infrastructure/src/main/kotlin/kr/easydoc/infrastructure/db/FlywayBaselineGuard.kt:54-59`
을 그대로 두고 인자 목록에 본문 값 하나를 더했다(`result.migrationsExecuted,` → `result.migrationsExecuted, draft.value,`).

| 입력 | 구판(`refine` 훅, `56a70c1`) | 신판(표기, `cd23aec`) |
|---|---|---|
| 원본 | 적중 0 / 억제 1 | 적중 0 / 표기억제 1 |
| **`draft.value` 추가** | **적중 1 — 잡는다** | **적중 0 — 놓친다** |

음성 대조로 적중이 실재함을 확인했다: 신판에서 표기 줄만 지우면 `LOG-BODY` 가 `:55` 에서 적중한다.

**왜 구판이 잡았고 신판이 놓치는가.** 구판 훅은 매 스캔마다 **값을 다시 판정**했으므로 `draft.value` 가
안전 멤버 목록에 없어 억제가 풀렸다. 신판 표기는 **사람이 한 번 적은 사유**에 묶여 있고, 그 사유가 더는
그 줄을 서술하지 않아도 계속 누른다. 방어 (f) 고아 검출도 듣지 않는다 — 적중은 여전히 존재하므로 표기는
고아가 아니다.

**설계문의 중심 주장이 거짓이다.** §4-octies.2 는 이렇게 적었다:

> *"파싱 결함은 앞으로도 **미검출**을 낼 수 있지만 **조용한 억제는 더 이상 낼 수 없다.** 결함의 종류
> 하나가 통째로 사라진다."*

사라진 것은 **파서 결함이 억제를 만들어 내는 경로** 하나뿐이다. **코드 편집이 기존 표기 아래에서
억제를 만들어 내는 경로**가 새로 생겼고, 그 경로는 구판에 없었다. 종류가 사라진 것이 아니라 바뀌었다.

**리포트도 이 자리에서 비대칭이다.** 적중은 매치 텍스트를 함께 싣는데(`:1148` `found[:40]` 이 `text[:160]`
출력), **억제는 위치와 사유만 싣는다**(`:1087`). 즉 방어 (b) 가 "전량 노출"을 달성한 항목이
하필 **내용이 빠진 항목**이다. 리뷰어가 리포트에서 보는 것은 옛 사유
(`적용 개수와 스키마 버전만 보간한다`)뿐이고, 그 줄이 무엇이 되었는지는 파일을 열어야만 안다.

**같은 형태가 한 물리 줄 안에서도 재현된다** (탐침 P1·R):

```kotlin
if (ok) log.info("건수 {}", stats.count) else log.info("본문 {}", draft.value) // privacy-allow: LOG-BODY — 앞의 집계 호출
```
→ 적중 0 · 표기억제 1. 표기 제거 시 적중 1. 게이트 10 R-1 이 *"안전한 접근이 위험한 접근의 방패"* 라고
이름 붙인 구조가 **억제 층으로 자리를 옮겨 그대로 남아 있다.** R-1 은 양 레인 합의로 차단 ②장치였다.

**해제 조건 대비.** §4-octies.8 의 여섯 조건은 전부 충족돼 있고(§3.1 참조), **이 결함은 여섯 중
어느 것도 묻지 않는다.** §4-octies.4 의 음성 대조 8종에도 "표기가 누르는 범위가 사유의 범위와 같은가"를
묻는 항목이 없다. `tests/test_privacy_scanner.py:817` 의 하중 검사는 *개수 동치*
(`len(without.hits) == len(with_markers.suppressions)`)만 보므로 이 결함에서 통과한다.

**처분 방향 (구현자 판단 몫 — 코드를 쓰지 않았다).** 셋 중 어느 것이든 이 축을 닫는다.
1. `Suppression` 에 매치 텍스트를 실어 리포트에 남긴다 — **가장 싸고, 적중과 리포트 대칭을 회복한다.**
2. 표기가 논리 줄 전체가 아니라 **그 물리 줄에서 시작한 적중**만 누르게 한다.
3. 표기에 내용 지문(줄 해시)을 붙여 **줄이 바뀌면 고아가 되게** 한다 — 방어 (f) 를 편집 축으로 확장.

**음성 대조를 반드시 붙일 것**: 위 표의 `draft.value` 추가 케이스가 고친 뒤 BLOCK 이 되고, 고치기
전에는 통과함을 같이 보인다.

### 2.2 parity 위험

#### N-02 — **[Major]** `export` 12 케이스 하한이 CI 도달 0 — 선언 151, 도달 139

`case_floor_problems` 는 `for pair in pairs` 로 돈다(`compare_parity.py:1010`). `pairs` 는
`collect_pairs(..., selected)` 가 **선택된 도메인으로 좁힌** 결과다(`:1723`). CI 는 선언 7 < 정본 8
이므로 부분 분기를 타고 `--only-domain` 7개를 준다(`ci.yml:449-458`).

결과: `export/` 로 시작하는 하한 12줄은 **아무 실행에서도 읽히지 않는다.** 오늘 `export` 케이스를
지우거나 개명해도 CI 는 초록이다.

`.github/parity-case-floor.txt` 는 151 id 를 선언하고, **실제로 강제되는 것은 139** 다.
케이스 정체성 장치는 "선언한 범위와 실제 도달이 갈리는 것"을 막으려고 만든 장치인데, 그 장치 자신이
같은 형태로 갈렸다. `case_floor_problems` 의 KDoc 은 `scoped`(`--only`) 만 건너뛴다고 적고
**`--only-domain` 으로 pairs 가 좁아지는 경로는 적지 않는다.**

`export` 는 아직 미포팅이고 fixture 는 `spec_status=pending` 이라 ①사건 위험은 없다. **②장치의
도달 결손**이다. 마감은 `export` 선언 시점이 아니라 **지금** — 하한 파일이 지키려던 것이 "선언 전에
조용히 사라지는 것"이기 때문이다.

#### N-03 — **[Major]** `pending_spec` 도메인은 형태 검증을 통째로 건너뛴다

`spec_shape_problems` 가 `:1080` 에서 즉시 반환한다:

`export` 의 12 케이스는 현재 **하한도, 형태 검증도, 값 비교도 받지 않는다.**

| 생성기 `dump_parity_fixtures.py:1359` | `id="[0-9a-f]{6,}"` |
| 비교기 `compare_parity.py:217` | `id="[0-9a-f]{4,}"` |

같은 규약(문서 구분자 id 를 정규화한다)의 정본이 둘이고 이미 갈렸다. 양쪽 산출물이 모두 비교기의
`{4,}` 를 지나므로 오늘 오판은 없다. 남는 것은 **탐지 하한**이다 — Kotlin 이 4자리 hex(16비트)
id 를 내도 정규화되어 통과한다. 그 id 는 프롬프트 주입 경계를 짓는 값이고
(`Prompts.kt` `DOCUMENT_ID_BYTES`), 엔트로피 성질은 parity 가 아니라 Kotlin 단위 테스트가 진다.
**parity 가 이 성질을 보지 못한다는 사실 자체를 fixture 나 원장에 적어야 한다** — 지금은 정규화 규칙
표에 `mask_document_id — prompts` 로만 적혀 있어, 무엇이 정규화로 사라졌는지는 드러나지 않는다.

#### N-13 — **[Minor]** style-tables 갈림 원장이 6필드를 1필드로 보이게 한다

**정렬로 덮지 않은 판단은 적정하다.** `sort_lists` 는 FORBIDDEN 이고 사유가 적혀 있다
(`compare_parity.py:213` — *"목록 순서는 프롬프트 렌더링 순서이자 위반 보고 순서다"*).
한 건의 갈림을 이유로 전역 정규화를 켜는 것은 CLAUDE.md 규칙 4 가 **은폐형에 대해 금지**한
바로 그 동작이다. 켜지 않은 것이 옳다.

기록 쪽에 둘이 빠졌다. `parity/reference-ledger/style-tables.json:6-12` 는
`first_diff_path: "$.PROMPT_ONLY_WORDS[0]"` 하나만 남긴다.

1. **실제로 갈린 것은 6필드**다 — `PROMPT_ONLY_WORDS` · `LEXICALIZED_GLOSSES` ·
   `COMPOUND_TAIL_KEYS` · `COMPOUND_HEAD_NOUNS` · `NOMINAL_GLOSSES` ·
   `MODIFIER_CHECKED_GLOSSES`. 전부 집합이 동일하고 순서만 다르다. `first_difference` 가
   첫 자리만 남기는 구조(`:1573`)라 원장을 읽는 사람은 폭을 알 수 없다.
2. **근원이 `frozenset` 이라 순서가 성질이 아니다.** Python 은 `frozenset` 을 `sorted()` 로
   직렬화하고(`dump_parity_fixtures.py:1275-1280`), Kotlin 은 `setOf(...)` 의 선언 순서
   (`DifficultWords.kt:331-338`, `LinkedHashSet`)를 낸다. **양쪽 모두 순서 없는 그릇이고,
   Python 쪽 순서는 직렬화가 만들어 낸 것이다.** 이것을 적어 두지 않으면 다음 사람이
   ⑴ Kotlin 선언 순서를 Python 의 `sorted()` 에 맞추는 무근거 작업을 하거나,
   ⑵ 순서가 성질이라고 오해해 임의 순서를 단언으로 박는다. 둘 다 요구사항에 근거가 없다.

단언이 `contains_all` 7종 + `equals_field` 2종이라 게이트가 열리지 않는 것도 적정하다 — 순서가
성질이 아닌 필드에 집합 단언을 쓴 것이 맞다.

### 4.2 리더 질의 — 종료 조건 행을 어떻게 적을 것인가

`00_progress.md:352` 현재:

```
| **종료 조건**: 외부 API·DB 없이 도는 parity suite … | 아니오 | `안 돎` | 전 도메인 | - | 8개 도메인 전부 … |
```

**권고 — 세 칸을 고친다.**

**⑴ `실행 경로` 를 `안 돎` → `ci:kotlin` 으로.** 이것이 가장 중요하다. parity 비교는
`ci.yml:262` 스텝에서 **매 실행 돌고 있다.** `안 돎` 은 도달 **과소** 신고이고, 과소 신고는 과대
신고와 같은 정도로 나쁘다 — 다음 사람이 "아무도 안 보고 있다"고 읽고 ⑴ 같은 것을 다시 배선하거나
⑵ exit 3 초록을 근거 없는 초록으로 할인한다. 이 저장소는 도달 0 을 의심하라고 규칙에 적었지,
도달을 0으로 **적으라고** 하지 않았다.

**⑵ `충족` 은 `아니오` 유지.** 다만 사유를 "안 돎"에서 **"범위 7/8"** 로 바꾼다. 지금 미충족의
내용은 "게이트가 없다"가 아니라 "게이트가 도는데 한 도메인이 그 안에 없다"이다.

**⑶ `근거` 칸에 실측을 적는다 — 지금 비어 있다(`-`).** 제안 문면:

> 부분 게이트(선언 7) `exit 3` · 성질 판정 137건(단언 437개) · 판정 보류 2건 · 참고 갈림 33건 ·
> 미검증 0 · 도메인 누락 0 (2026-08-14 실측). 전체 게이트(정본 8) `exit 1` — 원인은 **값 갈림이
> 아니라** `parity/actual/export/export.json` 부재(Kotlin `export` 미구현). 두 게이트 모두 외부
> API·DB 없이 완주 — **"외부 API·DB 없이"는 이미 충족이고 남은 것은 범위다.**

**⑷ `미해결` 칸에 두 줄을 더한다.**

> - `export` 미포팅 1개 — 이것만 닫히면 CI 가 전체 게이트 분기로 자동 전환된다(`ci.yml:433`,
>   `declared_count == canonical_count`). 사면 장치가 스스로 사라지는 지점이다.
> - **`export` 는 지금 어느 검사도 받지 않는다** — 케이스 하한 12건이 부분 게이트에서 도달 0(N-02),
>   `spec_shape` 형태 검증이 `pending_spec` 에서 꺼짐(N-03), 값 비교 미실행. 선언 전에 조용히
>   삭제·개명·무단언화될 수 있다.

**⑸ `exit 3 은 전체 통과가 아니다` 는 그대로 둔다.** 이 문장은 정확하고, `ci.yml:467-470` 이
부분 범위에서 exit 0 이 나오면 오히려 실패시키는 자기 정합 가드까지 갖췄다.

### 4.4 CLAUDE.md 골든셋 트리거 — 해당 여부 판정

리더가 판단을 요청한 항목이다. 규약: *"프롬프트·스타일 규칙·LLM 설정을 변경하면 반드시
`uv run pytest tests/golden` 실행."*

**해당하지 않는다. 실행하지 않은 것이 옳다.** 근거 셋 — 앞의 둘만으로는 부족하고 셋째가 결정적이다.

1. `tests/golden` 은 **Python 구현**(`app/`)을 잰다. 이 배치는 `app/**` 와 `tests/golden/**` 를

2. 규약이 지명한 정본(`app/easyread/style_rules.py`·`prompts.py`)이 무변경이다.
3. **규약이 막으려는 실질 — "스타일 규칙 변경이 프롬프트를 움직이는 것" — 이 일어나지 않았음을
   따로 쟀다.** 스냅샷 리소스 `python-prompt-snapshot.json` 이 범위 내 무변경이고,
   `renderViolations` 가 `kind` 를 읽지 않으며, prompts 도메인 4케이스가 Python 참고값과
   전건 `agree` 다(E-5).

**다만 앞으로의 구멍을 지금 적어 둔다(지적 아님, 마감 표기).** 이번이 **Kotlin 쪽 스타일 타입
변경만으로 프롬프트가 움직일 수 있었던 첫 배치**다. 오늘은 골든셋이 Python 을 재므로 그런 움직임을
잡지 못한다 — 잡은 것은 prompts parity 도메인과 스냅샷이었다. **Kotlin 이 프롬프트 생성의 정본이
되는 시점(Phase 5)에는 골든셋 트리거가 Kotlin 쪽 대체물을 가리켜야 하고, 그때까지 규약 문면은
도달이 비어 간다.** Phase 5 범위로 제안한다.

| 백틱 식별자 · raw string · 문자 리터럴 | **검토함 — 지적 없음(방향 확인).** 탐침 E·F·G. `F`(백틱 안 따옴표)는 어휘 상태가 열린 채 상한에 걸려 **`unscanned` BLOCK** 으로 끝난다 — 미탐지가 아니라 fail-closed. 다만 정상 코드에서 가짜 BLOCK 이 날 수 있는 자리다 |
| Argon2 · JWT · AEAD (I-7~I-9) | **범위 밖.** 이 배치가 건드리지 않았다. 판정 정본은 `privacy-gate` |
| 범용 품질 축(성능·유지보수성) | **범위 밖.** `multi-review` 를 별도로 돌릴 것을 리더에게 권고한다(역할 중복 방지) |
| codex 리뷰와의 대조 | **해당 없음 — 1차 회차.** codex 산출물을 찾지 않았고, 이 회차에서 부재는 정상이다. 실패로 기록하지 않는다 |

## 6. 리더에게 (1차 요약)

1. **차단 1건 신규: N-01.** §4-octies 이관은 해제 조건 6을 **전부** 충족했는데, **여섯이 묻지 않는
   자리에서 구판보다 약해졌다.** 실물 파일 실측으로 확인했다 — 표기가 달린 호출의 인자 목록에 본문
   값을 더하면 구판(`refine` 훅)은 **잡고** 신판(표기)은 **놓친다.** 설계문의 중심 주장
   *"조용한 억제는 더 이상 낼 수 없다"* 가 거짓이다. 트리거가 파서 결함에서 코드 편집으로 바뀌었을
   뿐 종류가 사라지지 않았다. 마감은 **지금**(CI BLOCK 라이브).
2. **게이트 10 차단 4건은 R-4 를 빼고 전부 해소.** R-1·R-2·R-3 은 실측과 음성 대조로 확인했고
   회귀도 붙어 있다. R-4 는 4요소 중 3 충족 + 개수 축을 id 축(`!deferred`)으로 대체 — **그 대체는
   개수 하한보다 강해서 적정**하나 신규 보류 증가는 무제한(N-15)이고 `pending_spec` 도메인에는
   아예 적용되지 않는다(N-03).
3. **J-4 무효 조건 4개는 하나도 저촉되지 않았다.** 커밋 순서·전수 유지·R-3 선행·R-4 마감 전부 이행.
   다만 N-01 은 J-4 의 근거 1(소급 검사로 회복 가능)이 **표기 아래에서는 성립하지 않는다**는 것을
   보인다 — 소급 스캔을 몇 번 돌려도 눌린 자리는 계속 눌린다.
4. **이탈 3건 처리는 전부 옳다.** ① 예산 3→7 은 **구판 실측이 정확히 7**임을 확인했다(E-3) —
   설계문의 `3` 이 낡았고 "실측 + 0" 원칙을 따른 결과가 7이다. ② 위치 인자 자기검사는 실재하고
   `XML-DTD` 를 키워드로 전환했다(잔여는 N-14). ③ `SECRET-LITERAL` 재표적은 `finditer` 전환의
   당연한 귀결이고 회귀(`:557`)가 붙어 있다.
5. **5도메인 배선의 세 쟁점 판정.** ⑴ prompts 왕복은 프로덕션 순서와 **등가**다 — `preimageOf` 는
   마스킹의 역이지 이중 마스킹이 아니고, 왕복 단언이 실패를 시끄럽게 만든다. 보정 경로가
   `ModelDraft` 로 감싸는 것도 프로덕션(`conversion.py:152`)과 같은 출처다. ⑵ `StyleRuleKind` 는
   **계약·프롬프트 불변이 참**이고(세 갈래로 확인), 도입 자체도 적정하다. ⑶ style-tables 를
   **정렬로 덮지 않은 판단이 옳다** — 다만 갈린 것이 6필드이고 근원이 `frozenset` 이라 순서가
   성질이 아니라는 사실을 원장에 적어야 한다(N-13).
6. **골든셋 트리거는 해당 없음이 옳다.** 다만 Kotlin 이 프롬프트 정본이 되는 Phase 5 에 규약 문면의
   도달이 비어 간다 — 그때 대체물이 필요하다.
7. **원장이 이 배치가 한 일을 부정한다(N-04).** fixture 생성 행만 `7/8` 로 고쳐지고 **바로 아래
   선언 행은 `2/8`** 로 남아 한 표 안에서 모순이다. 도메인 4행의 「미해결」은 전부 "fixture
   미생성·미선언"인데 넷 다 생성·선언·충족됐다. 종료 조건 행 권고는 §4.2.
8. **2차(교차 종합) 재호출이 필요하다.** 이 문서는 Claude 단독 판단이고, 게이트 10 에서 두 레인이
   서로 못 본 차단을 하나씩 냈다는 사실이 그 필요를 그대로 재확인한다.
