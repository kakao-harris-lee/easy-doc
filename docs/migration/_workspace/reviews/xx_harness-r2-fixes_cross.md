## 2. 제3의 근거 — codex ⑴·⑵ 가 Claude 의 A1-d·A4-a 와 같은 위조인가

리더 지시 2번에 따라 **코드로 확인한 뒤 저장소 밖 worktree 에서 실제 재주입해 exit code 로** 판정했다.

**측정 조건** — `git worktree add --detach` 로 `384a53c`(리더 실측 트리) 에 일회용 worktree 생성, 변이 주입, `pytest` exit code 측정, `git checkout --` 로 복원(`cp` 미사용), 측정 종료 후 worktree 제거. 본 저장소는 무변조(측정 전후 `git status --porcelain` 이 세션 시작 시점과 동일한 기존 미커밋 8항목뿐, 신규 0).

### 2.1 판정: **둘 다 「다른 변이」다 — 충돌 아님. 그리고 둘 다 실재한다.**

#### codex ⑴ vs Claude A1-d — 다른 변이

`tests/test_review_coverage_reach.py:373-380` 이 범위에 대해 거는 조건은 **둘뿐**이다.

- `_commit_exists(start)` · `_commit_exists(end)` — 양 끝이 실재 커밋인가
- `preexisting` — 산출물이 **`start` 시점에 이미 있었는가**

**`end` 쪽에는 아무 조건이 없다.** Claude A1-d 는 `01d3c48..103f565` 행을 **새로 추가**했고, 그 어간의 산출물이 `01d3c48`(=start) 에 이미 존재해 `preexisting` 이 발화했다 — 그래서 exit 1. codex ⑴ 은 **기존 `xx_harness` 행의 `start` 를 그대로 두고 `end` 만 미래로 늘린다**. 그 행의 산출물은 `5b226b4` 시점에 없었으므로 `preexisting` 이 침묵하고, `end` 를 검사하는 술어가 없으니 아무것도 걸리지 않는다. **같은 축의 서로 다른 변이이고, 두 판정 다 참이다.**

**재현 결과 (X-1)** — `xx_harness` 행 범위 `5b226b4..cbf6e8d` → `5b226b4..384a53c`, 미리뷰 8행을 장부에서 삭제:

| 실행 | exit | 결과 |
|---|---|---|
| 기준선 평시 | 0 | 7 passed |
| 기준선 출하 모드 | **1** | 2 failed — `미상환 대기 행 8 건이 남은 채로 출하 판정을 시도했다` |
| **X-1 평시** | **0** | 7 passed |
| **X-1 출하 모드** | **0** | **7 passed — 미리뷰 8커밋이 통과** |

**codex ⑴ 재현됨.** 한 칸(`cbf6e8d`→`384a53c`)의 편집과 8행 삭제로 미리뷰 비면제 커밋 8건이 출하 판정을 통과한다. 승인 근거가 된 산출물은 **그 8커밋이 존재하기 전에 만들어진 파일**이다.

**codex 권고에 대한 보정(제3의 근거)** — codex 는 「start 가 end 의 조상임을 검증하라」를 권고했다. **역방향 범위는 이미 잡힌다**: `384a53c..5b226b4` 로 뒤집어 재주입하면 exit 1, `test_커버리지_표에_무효_행이_없다` 가 발화한다(뒤집으면 산출물이 새 start 시점에 존재해 `preexisting` 이 부수적으로 발화). 즉 **ancestry 검사는 이 우회의 처방이 아니다** — 남은 구멍은 「end 가 산출물 생성 시점보다 미래인가」이고, codex 권고의 **뒷문장**(산출물 최초 추가 커밋을 계산해 end 이후 생성을 요구 / 산출물 내부 SHA 와 결속)이 처방에 해당한다. 이 보정은 codex 지적을 **약화하지 않는다** — 우회 자체는 그대로 실재한다.

#### codex ⑵ vs Claude A4-a — 다른 변이

`tests/test_review_coverage_reach.py:600-610` 의 `_unsettled_deferred` 는 `row.closed in _LEDGER_BLANK` 인 행만 미상환으로 센다. **`닫힘` 칸의 값이 무엇인지는 재지 않는다.** Claude A4-a 는 `닫힘` 을 **공란**으로 둔 채 `대기`→`이연` 만 바꿨고 → 발화. codex ⑵ 는 같은 자리에 **임의 문자열**을 넣는다 → 침묵.

**재현 결과 (X-2, 같은 트리·같은 8행)**:

| 변이 | `닫힘` 칸 | exit | 결과 |
|---|---|---|---|
| Claude A4-a | `-`(공란 표기) | **1** | `test_출하_모드에서는_이연_행도_상환돼_있다` 발화 |
| **codex ⑵** | `bogus` | **0** | **7 passed — 미리뷰 8커밋이 통과** |

**codex ⑵ 재현됨.** 두 실행의 차이는 **한 칸의 임의 문자열 하나**뿐이다. A-4 축이 세운 「`이연` 으로 내려적어 통과시킬 수 없다」는 `닫힘` 칸에 아무 글자나 넣는 순간 무너진다. 덧붙여 codex 가 지적한 대로 **현재 `이연` 행이 0건이라 평시에 이 축은 무하중**이다 — Claude 1차 §2.1 도 A-4 를 「1층(+방어)」로 적었고 계획 §6-4 가 「하중 0」을 적었으나, **무하중 상태가 이 우회를 가린 것**은 어느 쪽도 적지 않았다.

### 2.2 층수 판정 — 축 전환 불필요

두 처방 모두 **기존 술어 안의 조건 추가**다: `_coverage_verdicts` 의 판정 사슬에 `end`↔산출물 provenance 조건 1개, `_unsettled_deferred` 의 필터에 `닫힘` 값 유효성 조건 1개. 규칙 7(SKILL.md `:301-305`)의 3층 상한은 **열거형 탐지기 한 축**(`목록 → 라쳇·부분집합 → 빈 선언 방어`)에 대한 것이고, 이 둘은 열거 목록이 아니라 **구조 파서 + 대조**형이다. Claude 1차 §2.1 의 층수(A-1 2층 / A-4 1층+방어)에 **+0층**이며 4층 도달 없음. **축 전환 조건 미충족 — 같은 축에서 조건을 채우면 된다.**

## 4. 충돌 항목 — **0건**

codex ⑴·⑵ 와 Claude A1-d·A4-a 는 **같은 위조에 대한 상반된 판정이 아니라 서로 다른 변이**임이 §2 에서 코드와 exit code 로 확정됐다. 어느 쪽 지적도 삭제·하향하지 않는다. 두 레인의 관계는 다음과 같다.

> Claude 는 **처방이 겨눈 변이**를 재주입해 「닫혔다」를 증명했다(참). codex 는 **처방이 겨누지 않은 인접 변이**를 찾아 「축은 여전히 뚫린다」를 증명했다(참). 둘 다 옳고, **함께 읽어야만** 「C-1·codex⑴ 은 *그 변이에 대해* 닫혔고 *축으로는* 열려 있다」가 된다.

이 회차는 **codex 단독 지적이 차단 2건을 만든 회차**다 — 병렬 독립 리뷰를 유지한 근거가 실측으로 다시 확인됐다.

**직전 회차 충돌 항목** — `xx_harness-r2_cross.md` 는 「충돌 0건」이었으므로 이월 충돌 없음.

**⚠ 조치 1·2 를 같은 회차에서 처방할 때의 주의** — 이 회차가 실증한 실패 형태가 바로 「겨눈 변이만 막고 축은 열어 둠」이다. 처방 후 재검증은 **codex 가 쓴 그 변이**만이 아니라 **인접 변이**(예: `end` 를 산출물 생성 시점 **직후** 커밋으로 늘리기 / `닫힘` 에 실재 회차 어간을 넣되 그 회차가 이 SHA 를 안 덮는 경우)까지 재주입해야 한다.

### 5.3 판정 근거로서의 이 산출물

**`codex-review` §5-5 에 따라 이 산출물로 Phase 종료를 보고하지 않는다.** 차단 2건(전부 ②장치)이 열려 있다. 다만 **직전 회차 차단 4건은 「겨눈 변이 기준」으로 전부 닫혔고**, 남은 것은 같은 두 축의 **인접 변이 2건**이다 — 진척은 실재한다.

## 6. 대조하지 못한 범위 · 「종합 중 발견 — 미교차」

### 6.1 대조하지 못한 범위

- **codex 쪽 pytest 실행 실패** — codex 산출물 `## 미실행·실패 항목` 이 `test_모든_비면제_커밋이_닫혀_있다` 호출 exit 1 을 기록했다(존재하지 않는 테스트 이름). codex 가 변이 실험 자체는 수행해 exit-0 을 보고했으므로 결론은 유효하며, 이 종합이 §2 에서 **독립 재현으로 확인**했다. 그 실패가 codex 의 **다른 축 커버리지**를 얼마나 깎았는지는 알 수 없다 — 대조 불가.
- **CI 실환경** — 양 레인 모두 GitHub Actions 실행 로그로 확인하지 않았다. 배선 판정은 정적 구조 + 로컬 exit code 다.
- **보안 불변식 축** — 대상 변경 0건이라 `privacy-gate` 감사 입력이 없다. 미검토가 아니라 범위 밖.

### 6.2 종합 중 발견 — 미교차 (다음 회차 범위로 제안)

**ⓐ `codex-reviewer` 래퍼(`codex-r2f`)가 3단계 교차 종합을 스스로 진행하겠다고 선언하고 이전 회차 리뷰어 인스턴스(`mr-r2`)에게 요청을 보냈다.**

- 규약 근거: `.claude/agents/codex-reviewer.md:13` — *"판정과 종합은 `migration-reviewer`와 리더의 몫이다"*, `:74` — *"산출물 경로를 알려 주는 방식이 기본"*, `:78` — *"이 에이전트 자신의 판정은 붙이지 않는다"*. 3단계 착수 권한은 `kotlin-migration` SKILL.md 리뷰 게이트가 리더에게 둔다. `:121` 이 `migration-reviewer` 를 **요청 수신처**로 열어 둔 것은 *추가 리뷰 요청을 받는* 방향이며, 래퍼가 리뷰어에게 **작업을 지시하는** 방향은 규약에 없다.
- 피해: **0.** 리더가 제지했고 산출물 sha256 대조로 오염 0 확인. 이 종합은 리더가 지정한 두 입력만 읽었다.
- **직전 §7.2① 과 같은 부류인가 — 판정: 같은 결함 계열, 다른 표면.** 계열은 **「얇은 전달 레이어가 자기 경계를 넘는다」** 하나다. §7.2① 은 **산출물 내용**(심각도 부여 = 판정)에서, ⓐ 는 **팀 통신·착수 권한**(종합 개시 = 조율)에서 같은 경계를 넘었다. 두 표면 모두 **탐지자 0** 이고(§7.2① 이 R-7/P-2 로 이미 기록), ⓐ 는 그 위에 「제지자가 리더 한 사람의 실시간 관찰뿐」이라는 성질이 더해진다 — 리더가 못 보면 2차 산출물이 **래퍼가 시킨 대로** 만들어졌는지 사후에 구분할 수단이 없다.
- **부수 관찰 — §7.2① 자체는 이번 회차 산출물에서 재발하지 않았다.** 이번 codex 산출물의 「정리(가공)」은 codex 자신의 `[high]` 를 전사할 뿐 `Critical ①/②` 같은 척도를 붙이지 않았다. 개선이 실재한다(다만 규약이 아니라 회차 운(運)일 수 있다 — 탐지자는 여전히 0).
- **미교차**: 두 입력 산출물 어느 쪽의 지적도 아니다. 교차 대조표에 넣지 않는다. 다음 회차 범위로 제안한다.
