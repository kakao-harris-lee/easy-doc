### 2.2 parity 위험 — 검토함, 지적 3건 (문법 본체는 해소 확인)

#### 해소 확인 — SEP 문법·성별코드·VT/FF (§4-ter 전건)

**회신을 근거로 쓰지 않고 소스에서 상수를 프로그램으로 추출해 재구성했다.**

```
소스 추출: HYPHEN = 002D 2010 2013 2014 2212 FF0D   SPACE = 0020 0009 00A0 2007 202F 3000
Masking.kt:296  SEP = (?:[SPACE]?[HYPHEN][SPACE]?|[SPACE]?)
```

`§4-ter.2`가 지정한 `SEP := (?: SPACE? HYPHEN SPACE? | SPACE? )`와 **문자 단위로 같다.** RRN(`:355`)·CARD(`:360`)가 **같은 상수 하나**를 참조한다(해제조건 2 충족). 12탐침을 내 손으로 다시 돌려 **12/12 일치**했다 — 정당 5 유지 · 과잉 4 탈락 · 누락 2 신규 검출.

`acceptsRrnGenderCode`(`:325-340`)는 `codePointCount(0, length) != 1`로 거른 뒤 `Character.digit(codePointAt(0), 10)`을 쓴다 — `Character.digit(Char, Int)` 오버로드를 피하라는 §4-ter.1 지침 그대로다(해제조건 1 충족). `INVISIBLE_RANGES`(`:458-478`)에서 `0x000B..0x000C`가 사라졌고 「의도된 구멍」 주석이 붙어 있다(해제조건 3 충족).

회귀(해제조건 4)도 실재한다 — `MaskingTest.kt:121-210`이 12탐침을 세 `@ParameterizedTest`(5+4+3)와 대칭 단언 1건으로, `:212-250`이 보충 평면 양성·음성 2건으로, `:418-470`이 LF·CR·**VT·FF·ZWSP·SHY 여섯 개 독립 `@Test`**로 둔다. §4-ter.3이 「묶어서 한 케이스로 만들지 말라」고 한 형태를 지켰다.

**판정: §4-ter 해제조건 1·2·3·4는 내 독립 검증으로도 충족이다.**

#### Z-11 (판정 필요) — TAB 한 글자가 곧 열 구분인 자리

`SEP`의 근거는 **개수**다 — §4-ter.2: *"같은 자리에 공백이 둘 이상 오는 표기는 '구분'이 아니라 정렬이다."* 그런데 `SPACE_CHARS`에는 **U+0009 TAB**이 들어 있고(`Masking.kt:257`), TAB은 **한 글자가 이미 열 경계**인 문자다. 실측:

```
900101<TAB>1234567              -> 가림
1234<TAB>5678<TAB>9012<TAB>3456 -> 가림 (카드번호로 판정)
```

즉 §4-ter.2가 막으려던 바로 그 시나리오(*"표 열 맞춤으로 떨어져 있는 접수번호 6자리와 관리번호 7자리"*)가 **TAB으로 적힌 표에서는 그대로 결합된다.** 개수 기준은 문자 종류를 묻지 않기로 한 설계인데, TAB에서는 그 전제(1개 = 조판 여백)가 성립하지 않는다.

노출 범위는 제한적이다 — 우리 추출기는 블록을 `"\n"`으로 잇는다(`app/ingest/extractors.py:130-139`, 셀 사이 TAB을 만들지 않는다). 남는 경로는 PDF 추출과 사용자 붙여넣기다. **과잉 방향**(STY-03 팩트 소실)이라 C-10과 같은 축이고, C-10이 「판정 필요」였으므로 같은 무게로 올린다. 결정 권한은 `privacy-gate`.

fixture 상태: `masking-rrn-tab`은 TAB-하이픈-TAB만 본다. **단일 TAB은 fixture·테스트 어디에도 없어 어느 쪽으로도 동결돼 있지 않다.**

#### Z-4 (수정 필요) — C-08과 같은 종류가 필드 하나 옆에 남아 있다

`AnthropicProvider.kt:252-264`의 `parse()`는 `LlmCompletion(...)` **인자 목록 안에서** `requireModel(node)`(`:327-328`)를 부른다. 모델 이름이 없으면 거기서 던지므로 **completion 객체가 만들어지지 않고, 같은 응답 본문에 실려 온 `usage`가 통째로 사라진다.** HTTP 200에 usage가 실제로 있는 경로다.

#### 해소 확인 — toString 5종 (판정 5 / §4-quinquies)

`MaskedText`·`MaskingResult`·`ModelDraft`·`ReviewedBody`·`PlaceholderRestoration` 다섯 다 재정의돼 있고, 단언이 **「길이 표기가 있다」가 아니라 「본문이 없다」**를 본다(`MaskingTest.kt:801-802` 주석이 그 이유를 적었다 — 전자는 `MaskedText(48자) value=...` 도 통과시킨다). 마스킹 범위 밖 값(전화·이메일)을 일부러 섞어(`:805-806`) *"가려졌으니 안전"* 을 배제한 것도 옳다. **§4-sexies.1의 5종 해제와 내 독립 판정이 일치한다.**

#### Z-1 (**차단 ②장치**) — 종단 고정이 `.` 연속 하나만 막는다

`scan_privacy_invariants.py`:

```python
_SAFE_ACCESS = re.compile(rf"\.(?:(?:{_SAFE_QUALIFIERS})\.)*(?:{_SAFE_MEMBERS})\b(?!\.)")
```

§4-sexies.3이 요구한 것은 *"접근 사슬 전체가 한정자 + 종단 안전 멤버로만 이뤄질 것"*이다. 구현은 그것을 **「뒤에 점이 오지 않을 것」**으로 적었다. 점이 아닌 이어짐은 전부 통과한다. 내 실측(모듈 직접 적재, LOG-BODY 규칙):

| 입력 | 판정 |
|---|---|
| `logger.info("x {}", draft.document.id.value)` | 잡음 ✓ (§4-sexies.3 재회부 3식) |
| `logger.info("x {}", draft.stats.count.original)` | 잡음 ✓ |
| `logger.info("x {}", draft.document.category.body)` | 잡음 ✓ |
| **`logger.info("x {}", draft.stats.count[0].value)`** | **SUPPRESSED** |
| **`logger.info("x {}", draft.id[0])`** | **SUPPRESSED** |
| **`logger.info("x {}", draft.stats.count().value)`** | **SUPPRESSED** |
| **`logger.info("x {}", draft.id . value)`** | **SUPPRESSED** |

`draft.id[0]`은 §4-quater.1이 표 아래에 **명시로 "그대로 후보로 남긴다"**고 적은 「첨자·슬라이스」다. 명세를 직접 어겼다.

**그리고 마지막 줄이 이 지적을 차단으로 올리는 이유다.** 공백 낀 점은 손으로 적을 일이 없어 보이지만, **`5c6cb33`이 도입한 논리 줄 결합이 바로 그 형태를 만든다.** 결합은 `" ".join(부분)`이라 ktlint가 강제하는 다중 줄 체인이 전부 ` .` 이 된다. 합성 `.kt` 파일 실측:

```kotlin
logger.info(
    "변환 완료 {}",
    draft.id
        .value,          // ← 논리 줄: logger.info( "변환 완료 {}", draft.id .value, )
)
logger.info("변환 완료 {}", draft.id.value)   // 같은 유출, 한 줄
```
```
적중(BLOCK 후보):  줄 11 | logger.info("변환 완료 {}", draft.id.value)
눈감음: {'LOG-BODY': {'값의 모양이 불변식 대상이 아님': 2}}
```

**같은 유출이 한 줄로 쓰면 잡히고, 이 저장소의 린터가 강제하는 형태로 쓰면 「불변식 대상이 아님」으로 분류된다.** 이것이 단순 미탐보다 나쁜 이유는 리포트가 *"보고 넘겼다"*고 적기 때문이다 — C-03 이전에는 안 보였을 뿐인데, 지금은 **적극적으로 안전 판정을 받는다.**

`refine`은 정의상 **은폐형 장치**다. `CLAUDE.md`는 은폐형에 대해 *"⑴이 참이어도 넓히지 않는다"*고 못박았는데, 여기서는 근거(오탐 3줄)보다 넓은 범위(안전 멤버 뒤 임의의 사슬)를 눈감고 있다.

관련 종료 조건: §6 Security · INV-01 · §5 Phase 7 즉시 중단(마스킹 전 전송 계열의 로그 유출). **마감 즉시** — §4-sexies.3 재회부와 같은 레인이다.

#### Z-2 (**차단 ②장치**) — 「클래스 삭제 시 실패」가 둘 다 지워져야 실패한다

`.github/workflows/ci.yml:204-208`:

```yaml
      - name: 보안 불변식 탐지기 존재 확인 (클래스 삭제 시 실패)
```

Gradle의 `--tests` 실패 판정은 **패턴별이 아니라 전체 집합 기준**이다. 내가 직접 돌렸다:

```
--tests <없는 이름> --tests <있는 이름>   →  RC=0   (BUILD SUCCESSFUL)
```

따라서 `ProvenanceCreationSitesTest.kt`를 **혼자 지우면** 이 스텝도 `gradlew build`도 초록이다. 그 파일이 provenance 탐지기 전부인데도 그렇다. 스텝 이름이 선언한 것(「클래스 삭제 시 실패」)과 실제 도달(「**둘 다** 삭제 시 실패」)이 다르고, 현실적인 삭제는 언제나 하나씩이다.

codex B-2 ④(「테스트 삭제 시 `gradlew build` 통과」)를 닫으려고 넣은 장치가 그 ④를 닫지 못했다. 메서드 하나를 지우는 경우·클래스 이름을 바꾸는 경우도 같다(클래스 필터가 남은 메서드에 걸린다).

#### Z-3 (수정 필요) — 인자 목록 판정이 첫 `)` 에서 끊긴다

`LOG_CALL` 패턴은 `...\([^)]*\b(?:BODY_NAMES)\b` 다. `[^)]*`는 **중첩 호출의 닫는 괄호를 넘지 못한다.** 합성 파일 실측:

```kotlin
logger.info("완료 {} {}", trim(id), draft.value)     // ← 무적중
logger.info("완료 {}", draft.value)                  // ← 잡음
```

기존 결함이고 이 배치가 만든 것은 아니다. 다만 **C-03 해제의 근거 범위를 좁힌다** — 논리 줄 결합의 목적이 「인자 목록을 본다」인데, 다중 줄 호출은 인자에 중첩 호출을 끼우는 형태가 특히 흔하다(`keyOf(draft)`·`trim(id)`·`maskedCount(items)`). §4-sexies.4의 「C-03 해제」는 유효하되, **탐지 범위 주장은 "논리 줄의 첫 `)` 이전 인자"로 정정돼야 한다.** `refine` 훅이 줄 전체를 훑는 보수성(`log_body_is_real_candidate`)은 패턴이 애초에 발화하지 않으면 무의미하다.

#### Z-18 (권고) — `#`를 줄 주석으로 보는 것이 `.ts`에서 과소 결합을 만든다

`_depth_after`가 `#`를 만나면 그 줄의 나머지를 코드가 아니라고 보고 즉시 깊이를 확정한다. `.ts`의 private 필드(`this.#cache`)·`.kt`의 문자열 밖 `#`에서 어긋난다. 실측:

```
_depth_after("const n = this.#cache.get(", 0) = 0     (정상값 1)
```

`logical_lines`의 KDoc이 *"깊이를 못 세면 **이어 붙이는 쪽**으로 틀리게 두었다"*고 선언했는데, 이 경로는 **끊는 쪽**으로 틀린다. 선언과 실제가 반대다. 좁은 자리이므로 권고로 둔다.

### 2.5 테스트 적정성 — 검토함, 지적 6건

#### Z-12 (권고) — 하이픈 가지의 경계 짝이 없다

`SEP`은 두 가지다: `SPACE? HYPHEN SPACE?` 와 `SPACE?`. **공백 가지의 경계 짝은 정확히 있다** — `masking-rrn-space-one`(1칸, 가림) vs `masking-keeps-rrn-space-two`(2칸, 안 가림). 12탐침이 그 자리를 노렸다.

**하이픈 가지의 경계 짝은 없다.** `900101 - 1234567`(양옆 1칸, 가림)은 있는데 `900101  -  1234567`(양옆 2칸, 안 가림이어야 함)이 fixture·Kotlin 테스트 어디에도 없다. 구현은 정상 동작한다(내가 돌렸다 — 좌2우2·좌1우2·좌2우1·하이픈 2개 모두 안 가림). **동작이 옳은데 고정돼 있지 않은 상태**라, 다음에 `SPACE_CLASS?`를 `SPACE_CLASS*`로 되돌리는 편집이 12탐침을 전부 통과한다.

U+3000 쪽도 1개(가림)와 3개(안 가림)만 있어 경계(2개)를 건너뛴다. 우선순위는 하이픈 가지가 높다.

### 4.2 SEP 문법의 요구 정합 (리더 특별 점검 2)

- **구현·테스트가 §4-ter.2 12탐침 표와 문자 단위로 같은가**: **그렇다.** 소스 추출 재구성으로 12/12 독립 재현. `SEP` 문자열이 판정문과 동일. RRN·CARD가 상수 하나 공유.
- **경계 짝이 fixture에 실재하는가**: **공백 가지는 실재**(1칸/2칸 정확히 인접). **하이픈 가지는 부재**(Z-12). U+3000은 1↔3으로 경계를 건너뜀.
- **fixture 방향이 12탐침 표와 일치하는가 (용어 확인 1건, 독립 검증 요청)**: **일치한다. 리더가 확인한 독해가 옳다.**

  하네스 어휘에서 `present[masked_text]=[원문숫자열]`은 *"가려지지 않아 원문이 그대로 남아 있다"*, `absent`는 *"가려져서 사라졌다"*다. 69케이스 전수 파싱 결과:

2. **문법 본체(§4-ter)는 내 독립 검증으로도 해제다.** 회신을 믿지 않고 소스 추출로 재구성해 12/12를 재현했다. fixture 방향도 12탐침 표와 정합하며, 리더가 확인한 독해가 옳다.
3. **판정문 §4-ter.4 조건 5의 문언 한 줄이 아직 반대로 적혀 있다.** fixture는 정본을 따랐지만 문언은 그대로다 — `privacy-gate`가 정정하지 않으면 다음 사람이 fixture를 뒤집는다.
4. **원장은 값이 아니라 사유를 고쳐야 한다**(§4.3). 과대 신고 0건이므로 급하지 않으나, 닫힌 차단 사유를 남겨 두면 다음 사람이 그 사유만 보고 `예`로 뒤집는다.
5. 이 문서는 **1차 산출물이다.** Phase 2 종료 판정의 근거로 쓰려면 `codex-reviewer` 산출물과 교차 종합한 `09_masking-grammar_cross.md`가 필요하다. 2차 재호출 시 두 산출물 경로를 함께 주면 된다.
