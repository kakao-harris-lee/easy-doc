사용하고, 교차 순서·워밍업·충분한 표본을 갖춘 **시간 분포 회귀와 지연 변이 음성 대조**를 추가하라."*

**Claude S-3 (원문 요지).** *"시간이 아니라 구조로 건 판단은 옳다 — 같은 배치가 시간 축 게이트의 한계를
실측했고(X-3ⓒ 변이가 비 1.013~1.090), **흔들리는 게이트는 곧 꺼진다**는 근거가 이 저장소 안에 있다."*
*"회귀의 결속이 둘이다 — 문장 수 균일 + 「더미 조회가 실패를 성공으로 만들지 않는다」. 둘째가 없으면 nil
UUID 행이 우연히 생기는 날 통과가 뒤집힌다. **옳은 짝이다.**"*
음성 대조 재현: 균일화 제거 → `{성공=1, 삭제=1, 위조=0, 만료=0, 형식오류=0}` · 2중 1 red · 과잉 결합 0.
**다만 스스로 한계를 적었다** — *"시간 축 수치 자체는 1관점(구현자)뿐이다 … 101 표본 실측을 재현하지 않았다."*

**privacy-gate (원문 요지).** 독립 재실측 — 3갈래 **1.003**(문턱 1.5), 4갈래 2.185, DB 왕복 1/1/1/1/0,
본문·헤더 이름 집합 전건 동일. nil UUID 오라클은 **열리지 않는다**(기록 ③ 4축 표) — *"`ABSENT_USER_PROBE_ID`
가 컴파일 상수라 공격자가 고를 수 없다 · 질의 문면이 삭제 계정 갈래와 **동일**하고 둘 다 0행 · 실측 편차
0.3% · 반환값을 쓰지 않는다."* 잔여는 *"nil UUID 행이 존재하면 그 갈래만 행을 읽어 시간이 갈린다"* 이며
발생 경로 없음(v4 만 생성).

**충돌의 정체.** codex 는 *"미래 회귀를 잡는 장치가 있는가"*(→ 없다), Claude 는 *"오늘 어떤 장치를 고를
것인가"*(→ 구조가 옳다), privacy-gate 는 *"오늘 값이 균일한가"*(→ 균일하다). **세 답이 모두 참일 수 있다.**
**제3 근거(대조 산출):** privacy-gate 의 「캐시 온도」 반박은 **오늘 실측**(편차 0.3%)이지 **상시 회귀**가
아니다 — codex 가 든 변이(catch 에 지연·CPU 추가)는 privacy-gate 실측으로 검사되지 않는다. 반대로
codex 가 든 「`UUID(0,0)` 전역 과열」 우려는 privacy-gate 실측에서 **관측되지 않았다**(1.058 vs 1.061).

**리더 판단 요청 (3).** ⑴ 상시 시간 회귀를 **추가할 것인가**(codex 처방) — 이 저장소는 시간 축 게이트가
흔들려 꺼진 선례를 가지고 있고(Claude 근거) 문턱 1.5 의 선례도 있다. ⑵ 아니면 **구조 회귀 + 주기적
독립 실측**(privacy-gate 방식)의 현 조합을 유지할 것인가. ⑶ codex 처방의 「요청별 존재 불가능 UUID」는
Claude·privacy-gate 가 **고정 상수를 안전 근거로 든 것과 정면으로 갈린다**(공격자가 고를 수 없다 ↔ 전역
과열) — 이 갈림은 어느 관점도 상대의 근거를 읽지 않은 상태에서 나왔다.

### Ⅱ. 행 1 — 403 두 상수 xfail 의 **처분** (게이트 23 충돌 Ⅱ 의 재상신)

**성격 판정은 더 이상 충돌이 아니다**(§3-ⓐ — 두 실측이 같은 답). 남은 충돌은 **처분**이다.

- **리더 판정(원장 `:1302`, 게이트 23)**: *"**xfail 을 유지한다.** … `\b` 경계를 풀면 … 새 오탐 무리를
  들인다. 조용한 0 대신 `xfail(strict=True)` 로 선언하는 것이 이 하네스의 규약이고 … **정밀화 이전부터
  있던 기존 결함**이라 이 배치의 회귀가 아니다. **넓힐지는 별건**."*
- **codex X24-1**: *"strict xfail 은 향후 수정 시 XPASS 를 실패시킬 뿐, **현재 소유권 코드가 이 표준 상수로
  403 을 반환하는 것을 막지 않는다**. 따라서 quality 잡이 초록이어도 타인 자원 존재가 노출될 수 있다."*
- **Claude S-2**: *"그 형태가 이 저장소의 사각지대가 아니다 — `sendError` 는 이미 다루는 관용구이고
  (`PrivateResponseHeadersReachTest:151`), 서블릿 API 를 직접 쓰는 층이 이미 셋 있다
  (`AuthenticationInterceptor`·`PrivateResponseHeadersFilter`·Tomcat 밸브). **소유권 판정이 그 층으로
  올라가면 `sendError(SC_FORBIDDEN)` 이 자연스러운 표현**이다. Phase 4 가 소유 자원을 대량 추가한다."*

**리더 판단 요청 (1)(2)는 §3-ⓐ 에 적었다.** 여기서는 **판정이 갱신되지 않을 경우의 상태**만 명시한다 —
「별건」으로 남은 항목이 **마감 없이** 두 게이트를 지났고, 이번 게이트에서 **실측 2건이 추가로 붙었다.**

### Ⅲ. 행 7 — 인라인 헤더 파서의 마감이 집행 가능한가 (§3-ⓔ 참조)

**리더 판단 요청 (4).** 마감을 유지하되 codex 처방 후단(**`$ref` 없는 헤더 선언에서 명시적 실패**)을

헤더 커밋」이 **자동으로 실패**해 마감이 집행된다.

### Ⅳ. 행 16 — `CountingDataSource` 전제의 처분
