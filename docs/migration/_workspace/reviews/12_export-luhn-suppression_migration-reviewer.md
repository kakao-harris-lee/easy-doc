### 2.1 parity 위험 — **N-01 (Major, 수정 필요)** · export의 「필수 정보 유지」 축에 차단 단언이 0개다

**근거**: `parity/fixtures/export/export.json` 파일명 7케이스(`export-filename-hangul` 외 6건) · P-1 실측.

`export` 12케이스 117단언은 네 축을 건다 — `absent`(금지 문자) · `present`(확장자) · `max_length`(상한) · `ascii_only`(헤더). **`present` 니들이 `.docx`/`.txt`/`.hwpx` 확장자뿐이다.** 그래서 제목을 통째로 버리고 대체 이름만 내는 구현이 **7케이스 105단언을 전부 통과한다.**

P-1 실측:

```
[불충족] 도메인 8/8 / 성질 판정 152건(단언 584개) / 판정 보류 0건
         / 참고 갈림 42건 / 미검증 0건 / 불충족 6건
```

**성질 불충족은 0건이다.** 6건은 전부 `기록되지 않은 참고 갈림`이고, 리포트가 스스로 적는 해소 절차는 *"`--record-reference` 로 원장을 갱신하고 그 diff를 리뷰에 올린다 **(구현을 되돌리라는 뜻이 아니다)**"* 이다. 즉 **원장을 갱신하면 초록이다.**

두 가지가 이 지적을 무겁게 만든다.

1. `export-filename-all-forbidden`(입력 `///`)은 참고값 자체가 `쉬운 글.docx`라 **갈림 신호조차 나지 않는다** — 7케이스 중 1건은 원장 방어선 밖이다.
2. 이 축은 §5 Phase 7 즉시 중단 기준의 *"문서 추출·**내보내기의 필수 정보 누락**"* 에 직접 대응한다. 그 축의 차단 장치가 **참고 갈림 원장 하나**인데, 원장은 설계상 *"차단 사유가 아니다"*.

`02_parity-verifier_domain-fixtures.md` §7.1이 값을 못박지 않은 이유(*"정제 결과를 못박으면 … 규칙 개선이 회귀로 잡힌다"*)는 **옳다.** 그러나 §7.3의 검출 실증 6종은 전부 *under* 방향(정제 안 함·상한 없음·인코딩 없음·자리표시자 삭제·반복 치환·BOM 부착)이고 *over* 방향(**제목을 버린다 · 과하게 자른다**)은 하나도 없다.

> **이 배치가 style에서 이미 정답을 만들었다.** X-4 처방(`f73b8bd`)은 값을 못박지 않고 **입력에서 하한을 유도**했다(`_indivisible_segments` + `contains_derived`). 같은 형태를 파일명 축에 적용하면 §7.1의 우려에 걸리지 않는다 — 예: 입력 제목에서 금지 문자·공백을 걷어낸 뒤 남는 **식별 가능한 조각**이 파일명에 남아 있을 것(부분 문자열 하한). 그러면 `기초연금 신청 안내` → `쉬운 글`은 red가 되고, 공백 접기·앞뒤 점 깎기 규칙을 고쳐도 green이 유지된다.

**마감**: Phase 2 종료 판정 전. 이 도메인이 이미 종료 조건 집계(성질 152건)에 들어와 있다.

### 2.3 parity 위험 — **N-05 (Minor, 권고)** · X-4 하한의 정당화 문언이 증명보다 넓고, 한 방향이 열려 있다

**근거**: `.claude/skills/python-kotlin-parity/scripts/compare_parity.py:840-869`(`SENTENCE_TERMINATORS` · `_indivisible_segments`).

⑴ **문언이 넓다.** KDoc — *"구간 안에 종결부호가 없으므로 **어떤 분리기도** 이보다 잘게 쪼갤 수 없고"*. 이는 분리기가 `.!?\n`의 **부분집합**에서만 자를 때만 참이다. 한국어 종결어미·`;`·`·`·불릿으로 추가 분할하는 구현이 오면 하한이 **거짓 양성**을 낸다. 방향은 안전하지만(시끄러운 실패) 정당한 개선을 회귀로 잡는다 — §7.1이 export에서 피하려던 바로 그 형태다. 커밋 메시지는 한계를 하나(*"종결부호를 끼워 넣어 분리를 조작하는 입력"*)만 적었고 이 방향은 적지 않았다.

⑵ **"합치는" 방향이 열려 있다.** X-4가 닫은 것은 생산자가 문장을 **버리는** 경로다. 생산자가 `sentences = [전체 텍스트]` · `length_violations = [전체 텍스트]`를 보고하면 `equals_derived`(자기 보고 기반, `_reported_sentences:827-837`)와 `contains_derived`(부분 문자열 포함, `:673-676`)를 **둘 다 통과한다.** 피해는 과잉 보고(불필요한 보정 유발)라 데이터 유실은 아니지만, 이 축을 "닫혔다"로 적으면 안 된다.

⑶ 유도의 **입력**이 실제로 독립인 것은 확인했다 — `_indivisible_segments`가 `call.payload`를 읽고, `CheckCall`은 `:1011`에서 `CheckCall(actual, case.get("input"), …)`으로 만들어진다. **X-4의 핵심 처방은 실물로 이행됐다.**

### 2.4 테스트 적정성 — **N-04 (Minor, 권고)** · `export-txt-bytes`가 `content_sha256_hex`를 단언하지 않는다

**근거**: `parity/fixtures/export/export.json` `export-txt-bytes` · 인계 요청 `02_kotlin-implementer_export-domain.md:71` · 승격 문서 `02_parity-verifier_domain-fixtures.md:135`.

두 문서가 같은 것을 요구한다 — *"TXT 1건 … `content_sha256_hex` 일치(컨테이너 없는 형식이라 성질이 된다)"* / *"zip 컨테이너가 없어 **본문 UTF-8 바이트 = 파일**이라 값이 성질이 된다"*. 실제 단언 6개는 `absent`(BOM·NUL·제목) + `present`(본문 조각 2) + `equals_field`(media_type)이고 **해시는 `reference`에만 있다.**

통과하는 구멍: 줄바꿈 변환(CRLF), 후미 개행 추가, 본문 중복, 꼬리 문자열 부착. **요청과 산출이 갈렸는데 어느 문서도 그 갈림을 적지 않았다** — 갈림 자체보다 이쪽이 문제다(다음 사람은 두 문서를 읽고 해시가 걸려 있다고 믿는다).

### 2.5 보안 불변식 — **N-06 (Minor, 권고)** · 해제 조건 1의 「넷 모두」가 구현에서는 셋이다

**근거**: `scan_privacy_invariants.py:152-167`(`Marker`) · `:1062-1072`(`_marker_touches`) ↔ §4-novies.3·§4-novies.4 방어 e′ · §4-decies.2 조건 1.

설계 문언 — *"표기는 `(path, call_ref, rule_id, content_digest)` **넷 모두**가 일치하는 적중 하나를 억제한다"*. 구현 — `Marker`에 **`call_ref` 필드가 없고**, `_marker_touches`는 `rule_id`·`digest`·**줄 인접**만 본다. §4-decies.2가 조건 1을 "충족"으로 적은 근거는 `Hit` 쪽 계약(`Hit(path, line, call_ref, digest, text)`)만 확인한 것이다.

**실효 차이는 좁다** — 같은 줄에 지문이 같은 적중이 둘이면 불변량 4가 fail-closed로 받는다(**P-2 실측: 적중 2 유지·억제 0·`marker_problems` 1건**). 남는 차이는 *같은 줄에서 인자 구간이 같고 수신자만 다른 호출*(`logger.info(X)` ↔ `log.error(X)`)로 표기가 옮겨 붙을 수 있다는 것뿐이고, 그때도 사람이 승인한 **내용**은 동일하다.

그래도 지적으로 남긴다 — **문언과 구현 중 하나를 맞춰야 한다.** 지금은 조건 목록이 검증한 것보다 강한 문장을 적고 있고, 그 상태가 §4-octies에서 이미 한 번 사고를 냈다.

### 2.6 보안 불변식 — **N-07 (Minor, 권고)** · `MARKER_BUDGET` 값에 기계 고정이 없다 (같은 파일 안의 비대칭)

**근거**: `scan_privacy_invariants.py:149`(`MARKER_BUDGET = 7`) · `tests/test_privacy_scanner.py:830-838` ↔ `:915-926`.

같은 파일 안에서 두 방어가 다른 대접을 받는다.

| 방어 | 값 고정 | 근거 |
|---|---|---|
| `markable` 배정 6종 | **있다** — 집합 등식 | `test_markable_배정이_설계대로다:917-925` |
| 표기 예산 `7` | **없다** — 기제만 | `test_예산_상한을_넘으면_실패한다`가 `monkeypatch.setattr(scanner, "MARKER_BUDGET", 1)`로 잰다 |

방어 a가 기대는 것은 *"상한을 올리려면 `MARKER_BUDGET`을 고치는 커밋이 필요하고, 그 diff가 리뷰에 올라간다"* 인데, §4-novies.2는 **바로 그 논거(diff 가시성이 상쇄한다)를 X-1에서 철회했다.** 두 자리가 완전히 같지는 않다 — 예산 편집은 그 줄 자체가 바뀌므로 철회 논거가 그대로 적용되지 않는다. 그래서 차단이 아니라 권고이고, 지적하는 것은 **비대칭 자체**다.

### 2.7 테스트 적정성 — **N-08 (Minor, 권고)** · 실물 체인 미도달 가드가 결코 빨개질 수 없는 형태다

**근거**: `tests/test_privacy_scanner.py:1190-1206` · `:1153-1160`(`LOGGER_SHAPES`) · §4-novies.6-bis.

`test_실물_체인_호출이_탐지에_잡힌다`는 **명령형** `pytest.xfail(...)`을 쓴다(`:1204`). 명령형 xfail은 `strict` 개념이 없어 **미도달이 해소돼도 조용히 통과로 끝난다.** 강제자는 파라미터 표의 `체인 팩터리` 항목(`:1156`, `xfail(strict=True)`)인데 그 입력은 **한 줄짜리 합성 문자열**이다.

§4-novies.6-bis가 못박은 *"줄 모델 수정과 수신자 가정 수정은 **독립이며 둘 다 필요하다**"*를 대입하면 다음이 성립한다:

> 수신자 가정만 고치면 → 합성 케이스가 `xpass` → strict 실패 → 표를 `reached=True`로 옮긴다.

### 2.9 계약 준수 — **N-10 (Minor, 권고)** · `contentDisposition`이 확장자 조각을 검증 없이 헤더에 싣는다

**근거**: `backend-kotlin/core/src/main/kotlin/kr/easydoc/core/easyread/Export.kt:121-125`.

```kotlin
val suffix = filename.substringAfterLast('.', "").let { if (it.isEmpty()) "" else ".$it" }
return "attachment; filename=\"$ASCII_FALLBACK_STEM$suffix\"; " + "filename*=UTF-8''${percentEncode(filename)}"
```

`filename*` 쪽은 퍼센트 인코딩이 CR/LF·따옴표를 전부 덮지만, **ASCII 대체 이름의 `suffix`는 입력에서 그대로 온다.** `exportFilename`이 만든 이름만 들어오면 안전한데 이 함수는 임의 `String`을 받는다 — `contentDisposition("x.\"; evil=\"")` → `attachment; filename="easy-read."; evil=""; filename*=…`.

Python 원본(`app/easyread/export.py:127-138`, `PurePosixPath(filename).suffix`)도 같은 모양이라 **회귀가 아니다.** 다만 재개발의 판정 기준은 요구사항이지 Python 동일성이 아니므로 기록한다.

**오늘 도달 0** — 호출부는 `ExportParityTest.kt:99` · `ExportTest.kt:90,104,105,111,119,127`뿐이다(실측). **마감: Phase 4 착수 전** — api 계층이 이 함수를 부르는 첫 지점이다.

**계약 정합 자체는 확인했다.** `contracts/easy-doc-v1.yaml:1068-1081`과 `api-contract-freeze/SKILL.md:195-196`이 요구하는 `attachment; filename="easy-read.<ext>"; filename*=UTF-8''<percent-encoded>`를 Kotlin이 그대로 낸다. `URLEncoder`를 쓰지 않고 안전 문자를 직접 정한 것(`Export.kt:133-144`)도 RFC 5987 `ext-value` 요구(공백 `%20`, `unreserved` = 영숫자 + `_.-~`)에 맞고 Python `quote(..., safe='')`과 같은 집합이다. `ExportTest.kt:104-111`이 `+` 부재와 `~` 보존을 단언한다.

### 3.1 【도달 0】 전체 게이트 분기는 CI 러너에서 한 번도 실행된 적이 없다

**근거**: `.github/workflows/ci.yml:437-447` · `git status -sb` 실측.

```
if [ "$declared_count" -eq "$canonical_count" ]; then
  echo "전체 게이트로 실행한다 (--only-domain 없이). 통과 조건: 종료 코드 0."

```

이 분기는 **선언이 정본을 전부 덮은 순간에만 참**이 되고, 그 순간이 **이 배치(`2839ec8`)에서 처음 왔다.** 그리고:


**로컬이 origin보다 71 커밋 앞서 있다.** 즉 `cd23aec..516c0e9` 전체가 아직 푸시되지 않았고, 전체 게이트 분기가 실제 러너에서 돈 적이 없다.

코드 자체를 읽어서는 결함을 찾지 못했다(`set -euo pipefail` 아래에서 `|| status=$?` · `-ne 0` 분기 · `exit 0` 모두 정상). **그러나 "읽어서 맞다"와 "돌아서 맞다"는 다르고, 이 저장소가 그 차이로 일곱 번 물렸다.** 부분 게이트(exit 3 사면) 경로만 러너에서 검증됐고, 지금부터 판정을 내리는 경로는 검증되지 않은 쪽이다.

**이것이 `:352`(Phase 2 종료 조건)를 뒤집으면 안 되는 첫째 사유다.** 심각도는 **권고**로 둔다 — 코드 결함이 아니라 **증거의 한계**이고, 처방은 수정이 아니라 **푸시해서 한 번 돌리는 것**이다.

### 3.2 Luhn 도입은 은폐형인가 — **아니다. 선언형이다** (규칙 4 적용)

탐지 **범위를 좁히는** 변경이라 은폐형(무시 패턴·억제·면제 조항) 의심 대상이다. 셋으로 갈랐다.

| 축 | 판정 |
|---|---|
| 좁힘의 근거가 실측인가 | **그렇다.** 실문서 카드형 16자리 적중 30건 중 Luhn 통과 **1건**(유일한 IIN 대역 후보), 단일 공백 4×4 25건 **전부** Luhn 실패, 그중 14건이 연속·인접 연도 (§4-decies.4) |
| 좁힘 **자체**를 재는 장치가 생겼는가 | **그렇다.** `masking-keeps-card-luhn-invalid`를 **같은 커밋에서 신설**했다. 커밋 메시지가 그 필요를 정확히 적는다 — *"양성을 전부 유효값으로 옮긴 지금 도입 전후를 가르는 것은 이 케이스 하나뿐이다. 없으면 Luhn이 아무것도 바꾸지 않은 것처럼 보인다"* |
