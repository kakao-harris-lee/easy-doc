**S-1 — 값이 빈 **읽기 세대**는 KCV 대조에서 조용히 빠진다 — 수정 필요**

- 근거: `infrastructure/crypto/CryptoConfiguration.kt:196-202` (`checkValueProblems` 의 `.filterNot { it.value.isBlank() }`)
- `CryptoConfiguration` KDoc 은 기동에서 **세 가지**를 확인한다고 선언한다(`:83-92`). 그중 3번(세대별 KCV 대조)은 **값이 비지 않은 세대에만** 돈다. 쓰기 세대는 2번이 별도로 지키므로 안전하지만, **읽기 전용 옛 세대의 환경변수가 빠지면 기동이 그대로 통과한다.**
- 그 결과는 F-3 이 겨눈 것과 **정확히 같은 형태**다 — 오설정이 쓰기 시점에는 조용하고, **옛 행을 읽는 순간** 드러난다. `KeyCheckValue` KDoc 이 「그 사이에 쓴 문서는 되돌릴 수 없다」로 적은 그 자리다(읽기 방향이라 손실이 아니라 **접근 불가**가 될 뿐 성질은 같다).

**S-2 — 면제 스위치가 「테스트 프로파일」이 아니라 **모든 테스트 태스크의 전역 시스템 속성**이다 — 수정 필요**

**S-3 — 제품 설정 훑기가 「열거하지 않는다」고 선언하고 **셋을 열거한다** — 수정 필요**

- 실제: `backend-kotlin/**/src/main/resources/**.yml` 만 `walkTopDown` 이고, `docker-compose.yml`·`.env.example`·`backend-kotlin/Dockerfile` 은 **정확한 경로 3개를 `resolve` + `takeIf { it.isFile }`** 로 붙였다. 파일이 옮겨지거나 이름이 바뀌면 `takeIf` 가 **조용히 떨어뜨린다.** 새 배포 매니페스트(k8s·helm·`docker/`·워크플로 `env`)는 애초에 범위 밖이다.

**S-5 — `migrate` 프로필까지 막는 문제: 리더의 「면제하지 않음」이 놓치는 것 — 판정 필요**

리더 판정에 **동의하는 부분부터**: 「프로필마다 다른 안전 수준이 곧 다음 사고의 자리」는 옳고, 면제를 두면 그 면제가 다음 사고의 통로가 된다. 그 위에 세 가지를 덧붙인다.

1. **판정 ④의 근거가 그 범위를 지지하지 않는다.** 근거는 *"쓰기 키는 **문서 API 의 필수 전제**"* 였다. `kotlin-migrate` 에는 문서 API 가 없다. 근거는 `api`·`worker` 를 겨누는데 강제는 `infrastructure` 를 조립하는 **모든 컨텍스트**에 걸린다 — `CLAUDE.md` 가 금지하는 「범위가 근거를 넘는다」의 형태다. 뒤집으라는 뜻이 아니라, **유지한다면 근거를 프로필 축까지 넓혀 다시 적어야** 다음 사람이 읽는다.
2. **복구 레인을 암호 설정에 결속시켰다.** `V4__key_version_domain.sql` 의 DO 블록은 위반 행을 만나면 *"재암호화 마이그레이션을 따로 써라"* 라고 끊는다. 그 마이그레이션을 돌리려면 `kotlin-migrate` 가 떠야 하고, 이제 그것은 **키 + 맞는 KCV** 를 요구한다. 즉 **키 사고(오설정·유실·KCV 불일치)가 난 상황에서 스키마 복구 경로가 함께 막힌다.** 이 결합의 방향이 복구를 어렵게 하는 쪽이다.
3. **어느 쪽으로 판정하든 강제자가 0이다.** 「`migrate` 도 막힌다」는 오늘 **자기 보고의 산문**일 뿐이다. 어떤 테스트도 프로필별 기동 동작을 단언하지 않고, compose 스모크는 자기 보고 §5.2 가 **미실행**으로 신고했다. 게다가 `.env.example` 은 `EASYDOC_ENCRYPTION_KEY_V1=` **빈 값**을 배포하므로, 예제를 그대로 복사한 사람의 `docker compose --profile kotlin up` 은 **세 서비스 전부 실패**한다 — 자기 보고의 「실무 경로에서는 문제가 없다」는 그 전제(운영자가 이미 키를 채웠다)가 성립할 때만 참이고, **검증되지 않았다.**

- **리더 판단 요청.** ⑴ 면제하지 않는다면 근거를 프로필 축으로 다시 적을 것 ⑵ 어느 쪽이든 **프로필별 기동 동작을 단언하는 테스트 1건**을 붙일 것 ⑶ compose 스모크 1회를 documents 착수 전에 넣을지.
- 마감: **documents 단위 착수 전**. 관련: I-7 검증 5 · §5 Phase 4.

**W-1 — 오탐의 절반만 닫혔고, 남은 절반이 **선언되지 않았다** — 수정 필요**

- 근거: `scan_privacy_invariants.py:726` — 숫자 갈래 `\b403\b` 는 **자리를 묻지 않는다**. 줄 전체 주석만 건너뛰므로 **문자열 안**과 **후행 주석**의 `403` 은 그대로 BLOCK 이다.
- codex H6 의 두 예시가 마침 둘 다 식별자였을 뿐, **결함의 뿌리(어휘 분석 없음)는 숫자 갈래에 그대로 남아 있다.** 규칙은 `markable=False` 라 **억제할 수 없다** — `documents` 단위가 한국어 오류 문구나 「403 이 아니라 404」 같은 후행 주석을 쓰는 순간 출구 없는 BLOCK 이 되고, 그때의 압력은 **규칙을 약화시키는 쪽**이다.
- 그리고 이 잔여는 `xfail(strict)` 로도 **선언되지 않았다.** 선언된 D1·D2 는 **둘 다 미탐**이다. 자기 보고 §2.5 가 이 장치의 근거로 든 문장 — *"게이트 23 이 잔여를 선언 없이 남겼다가 게이트 25 에서 같은 자리가 다시 발견된 것이 이 장치의 근거다"* — 이 오탐 잔여에 그대로 적용되는데 적용되지 않았다.
- 마감: 문서 소유권 경로 진입 전.

**W-2 — 이름 열거를 버리고 **자리 열거**를 얻었다 — 수정 필요**

- 근거: `scan_privacy_invariants.py:509-533` — ⓐ 는 함수 이름 16개의 **열거**다.
- 실측 미탐 3형태가 전부 여기서 나온다. 특히 두 가지가 무겁다.
  - `setStatusCode(` — **Spring WebFlux `ServerHttpResponse` 자신의 API 이름**이고, 열거된 `setStatus` 와 **단어 경계 하나 차이**다.
  - `ProblemDetail.forStatus(` — Spring 6 의 표준 오류 응답 조립 지점. 이 저장소의 오류 계약이 겨누는 바로 그 자리다.
- 자기 보고의 논리(「종류로 넓히는 대가를 자리로 치른다」)는 옳다. 문제는 **자리 자체가 종류가 아니라 인스턴스 목록**이라는 것 — 규칙 4 로 보면 **같은 기제의 재발**이고, 이번엔 축만 옮겼다.
- 마감: 문서 소유권 경로 진입 전.

**W-3 — `xfail(strict)` 2종은 「선언으로 끝나고 마는 자리」인가 — 판정: **장치로는 살아 있고, 예시가 위험을 낮춰 읽게 한다****

- **살아 있다는 근거.** `strict=True` 는 해소 순간 `xpass` 로 뒤집혀 스위트를 빨갛게 만든다. 실제 스캐너 패턴으로 재고, 대리 경로가 아니다. 「조용한 0 → 선언된 0」이라는 이 장치의 목적은 달성된다.
- **다만 세 가지가 걸린다.**
  1. **D2 의 예시가 위험을 축소해 읽힌다.** `statuses.add(HttpStatus.FORBIDDEN)` 은 드문 형태로 읽히지만, **같은 종류의 현실적 인스턴스는 예외→상태 매핑표**(`mapOf(… to HttpStatus.FORBIDDEN)`)이고 실측으로 미탐이다. 그것은 Phase 4 소유권 처리가 놓일 **가장 그럴듯한 자리**다.
  2. **마감도 수신자도 없다.** 「근거가 생길 때」는 근거가 예측 가능한 이 경우에 맞지 않는다 — 근거는 `documents` 단위 커밋 자체다.
  3. **결속 단언이 없다.** 같은 파일의 `X-5` 장치는 「xfail 이 가리키는 실물이 사라지면 여기서 실패한다」는 **바깥 단언**을 붙여 두었다(`tests/test_privacy_scanner.py:1228-1243`). D1·D2 에는 그 짝이 없다 — 규칙이 크게 재작성되면 이 두 xfail 이 무엇을 재는지 모르는 채 남는다.
- 판정: **권고**(선언 자체는 유효). D2 에 **현실적 예시 1건(매핑표)** 을 더하고 마감을 「documents 단위 소유권 경로 커밋」으로 못박을 것.

### 4.4 R-10 이 찾은 유출은 참인가 (리더 질문 ④)

**참이다.** 두 갈래로 확인했다.

- 종전 `ExportFile.toString()` 은 `"ExportFile(filename=$filename, …)"` 로 **파일명을 그대로** 찍었다(`git diff` 확인).
- `filename` 은 **문서 제목에서 만들어진다** — `Export.kt:220` `filename = exportFilename(stripControlChars(title), ExportFormat.TXT)`. 제목은 계약이 사용자 콘텐츠로 분류하는 값이다.
- 즉 이 게이트는 「오늘 0건」이 아니라 **실제 유출 재정의 1건**을 찾았다. 대조군으로서 값이 있는 결과다.
- 남은 두 후보(`Converted`·`StoredUser`)는 검사에 들어와 `leaks()` 를 통과했다.

**그 게이트가 이제도 빼는 종류** (T-5 상세):

| 빠지는 종류 | 기제 | 위험 |
|---|---|---|
| 민감 자리를 이름 토큰으로 못 알아본 일반 class | `planted.isEmpty() → null`, **`undecidable` 에도 안 남는다** | H3 구멍의 상속. 가장 큼 |
| **sealed 상위가 `toString` 을 선언하고 하위가 물려받는 형태** | 상위는 `!isAbstract` 로 제외, 하위는 `declaresToString` 거짓 | 실질 위험 있음 |
| 커스텀 `toString` 을 든 **enum** | `!it.java.isEnum` | 낮음(오늘 `EncryptedField` 는 기본 `toString`) |
| **주 생성자 밖 프로퍼티**를 찍는 `toString` | 표본을 심을 자리가 없다 | 중간 |
| `worker` 모듈의 모든 형태 | api 테스트 런타임 클래스패스에 `project(":worker")` 없음 | cross §7 U-3 — **여전히 열려 있다** |
