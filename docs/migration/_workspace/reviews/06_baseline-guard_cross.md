> 새 분기는 잡 이름이 `jobs`에 있고 조건 문자열이 아무 추적 파일이면 통과시킨다. 따라서 실제 조건과 무관한 정확한 문자열 `ci:llm-lane(조건:README.md)`로 현재 두 셀을 바꿔도 `judge_tables` 위반 0건, census 위반 0건이다. 또한 `_normalize_cell`이 인라인 코드 안의 `**`까지 삭제하므로 원문상 미추적 경로 `ci:llm-lane(조건:.github/llm-lane-**paths.txt)`와 존재하지 않는 잡 `ci:llm-**lane(조건:.github/llm-lane-paths.txt)`도 각각 실재 값으로 **변조되어** 통과한다. … 이 형식은 선언상 '조건 정본'을 검사하는 것처럼 보이지만 실제로는 **새 자기서명 통과 카드**다.

**Claude (m-2, Minor) 원문:**
> 저자가 한계를 정확히 적었다 — "`ci:llm-lane` 단순형은 그 잡이 실제로 조건부여도 그대로 통과한다 … 형식은 그 과장을 **표현 가능하게** 할 뿐 강제하지 못한다". 이 자기 진단에 동의한다. … **있는 값**: 괄호 안 경로가 `1회성:`과 동일한 git 추적 기준을 받아 `조건:나중에` 같은 산문으로 행을 닫을 수 없다. … **없는 값**: 검사기는 이미 `ci.yml`을 파싱해 `jobs:`를 읽고 있다. 같은 자리에서 단순형을 거부할 여지가 있는데 하지 않았다.

**두 리뷰가 본 것이 다르다.** Claude는 *단순형으로 과장하는 방향*(형식을 안 쓰는 자유)을 봤고 저자의 자기 진단에 동의해 권고로 뒀다. codex는 *형식을 쓰면서 우회하는 방향*(조건 정본이 아무 추적 파일이어도 통과, `**` 정규화가 원문에 없는 값을 만들어 통과)을 봤다. **Claude는 codex가 본 두 경로를 보지 못했다.**

**제3 근거(종합 중 실행)**: codex 재현 명령을 그대로 돌려 세 문자열 모두 **위반 0**을 확인했다. codex의 사실 주장은 참이다.

**판정이 필요한 이유**: 이 저장소 척도로 "게이트가 검사하는 것처럼 보이면서 아무것도 재지 않는다"는 **차단②** 후보다. 특히 `_normalize_cell`의 `**` 삭제는 검사기가 **자기가 만들어 낸 값**을 검사하게 만드는 것으로, 「검사의 기준이 검사 대상 자신에게서 나오지 않는가」에 정면으로 걸린다. 반면 이 어휘가 지금 쓰이는 행은 2개뿐이고 아직 실사용 게이트가 아니다. **심각도를 이 문서에서 정하지 않고 판정 필요로 올린다.**

### 3.2 X-9 — `.gitignore` 범위: **같은 결론인가, 다른 결함인가**

리더 질문에 대한 답: **범위 논거는 같은 결론이고, 심각도는 충돌하며, 양쪽이 서로 없는 논거를 하나씩 더 갖고 있다.**

**공통(합의) — 근거보다 넓다**
- codex: "근거는 현재 13개 PDF/HWPX인데 규칙은 `docs/golden/` 아래 모든 이름·형식을 숨긴다. 앞으로 생기는 인벤토리, 체크섬, 복구 코드, 다른 형식 원본, 잘못 저장된 파일도 `git status`와 working-tree 리뷰에서 보이지 않는다."
- Claude: "`*.pdf`·`*.hwpx` **전역**을 거부하는 데는 규칙을 적용했는데(옳다), **디렉터리 전체 무시**에는 적용하지 않았다. 근거는 파일 13개이고 범위는 디렉터리다."

**Claude 단독 논거 — 두 번째 근거가 무시 대상에 닿지 않는다**
> 주석은 "**24KB 미만 파일은 본문을 그대로 외부 호출에 싣는다**(실측 — 미추적 74건)"를 무시의 실질적 이유로 든다. 그런데 무시 대상 13건은 **전부 24KB 이상**이다(`find docs/golden -type f -size -24k` → 0건, 최소 파일 73,724 B). 즉 이 13건에 실제로 적용되는 효과는 "리뷰 대상 목록이 파일명으로 희석된다"뿐이고, "보낼 의도가 없던 **자료**가 나간다"는 성립하지 않는다. **근거와 범위가 서로 다른 파일 집합을 가리킨다.**

→ **codex는 이 논거를 다루지 않았다.** 이것은 "범위가 넓다"와 **다른 결함**이다 — 범위 문제는 *규칙이 근거보다 넓다*이고, 이것은 *제시된 근거 중 하나가 대상에 애초에 적용되지 않는다*이다. 두 결함이 겹쳐 있으므로 X-9를 닫을 때 둘 다 처리해야 한다.

**codex 단독 논거 — 추적 이력 0건의 의미**
> 이 경로는 전체 git 이력에서 추적 0건이고 현재 review clone에도 없으므로, '한 번도 추적되지 않았다'는 사실은 범위를 정당화하지 않는다. **오히려 fresh clone에 원본이 없고 삭제·유실을 저장소가 감지하지 못한다는 위험을 확정한다.**

→ Claude는 같은 사실(추적 0건)을 M-6의 근거로 썼지만 "범위 정당화 여부"라는 각도로는 다루지 않았다.

**심각도 충돌**: codex **high** ↔ Claude **Minor(권고, 마감 없음)**. Claude가 Minor로 둔 이유는 명시돼 있지 않고, 같은 대상의 데이터 손실 측면은 M-6(Major)로 분리해 올렸다. **두 리뷰의 심각도 합이 아니라 분해가 다르다** — codex는 한 항목에 high로 묶었고 Claude는 m-1(권고) + M-6(Major)로 쪼갰다. 판정 시 X-9와 X-10을 함께 봐야 한다.

### 3.3 X-11 — "이 기계 작업 사본에서 생존" 서술 (정면 충돌)

**codex (B-2):**
> `03_rebuild-extraction-list.md`의 fresh-clone 부재 설명은 맞지만 '이 기계 작업 사본에서 생존'은 **이 checkout에서 거짓이며 저장소 근거로 확인할 수 없다.**

**Claude (M-6):**

**제3 근거(종합 중 실행)**: 두 진술은 **서로 다른 checkout**을 가리키며 그 범위 안에서 각각 참이다.

**어느 쪽도 삭제하지 않는다.** 다만 문서 서술이 "이 기계"라고만 적고 **어느 기계인지 저장소가 검증할 수 없다**는 codex 지적은 X-10과 함께 처리하면 자연히 닫힌다.

### 3.4 X-14 — 게이트 표 `ci:` 표기 (정면 충돌 · 리더 판정 요청 항목)

**Claude (M-5, Major):**
> 어휘 정의는 `ci:<잡>(조건:…)` = "그 잡에 **배선돼 있으나** 조건이 맞을 때만 돈다"이고, `local:` = "CI 도달 0이며, **그 사실이 표에 드러나는 것이 이 표기의 목적이다**". … 이 행의 실제 도달은 **0**이다. 표기를 바꾸기 전에는 "CI 도달 0"이 표에 드러났고 명령은 실제로 돌 수 있었다. 바꾼 뒤에는 도달이 여전히 0인데 표에는 CI 배선으로 읽힌다 — **도달 정보가 늘어난 것이 아니라 줄었다.** 커밋 메시지("실행 경로를 사실에 맞춘다")가 뜻한 방향과 반대다.

**codex (회차 B 요약, 반대 견해):**
> 두 표 치환은 **사실 표기의 정확성만 높였고** 게이트 실행·강도는 바꾸지 않았다.

**제3 근거(종합 중 실행)**: Claude의 사실 주장이 실측으로 확인된다 — `llm-lane` 잡은 `64f1757`(2026-08-13)에서 신설됐고 워크플로 트리거는 `push:[main]` + `pull_request` + `workflow_dispatch`인데, 원격 브랜치 `feat/kotlin-migration-harness`는 **`64f1757`에 머물러 있고**(대상 4커밋 미푸시) PR도 없으며, 최근 CI 실행 3건은 전부 main·2026-08-09다. → **실행 0회.**

**두 진술이 양립하는 해석도 있다.** codex는 *"표기가 ci.yml의 배선 사실과 맞는가"*를 물어 참으로 판정했고(배선은 실재한다 — Claude도 §4-10에서 인정), Claude는 *"표기가 도달 정보를 전달하는가"*를 물어 후퇴로 판정했다. codex 원문에는 `gh run list`류의 **실행 이력 확인 흔적이 없다** — codex가 실행 0회를 알고도 개선으로 판정한 것인지, 확인하지 않은 것인지는 원문으로 판별되지 않는다. **사실만 남기고 짐작하지 않는다.**

## 6. 대조하지 못한 범위 · 종합 중 발견(미교차)

### 6.1 codex 리뷰 부재·실패로 대조하지 못한 범위

**없다.** codex 회차 A는 1차 유실 후 재실행으로 회수됐고 두 회차 모두 원문이 실려 있다. 다만:

- **회차 A의 1차 실행이 무엇을 지적하려 했는지는 영영 알 수 없다.** 잘린 하트비트 2건이 남았으나 codex 문서 스스로 "추정이며 근거로 쓰지 마라"고 적었고, 이 종합도 그것을 근거로 쓰지 않았다.
- **codex 재현 명령 부재** — 회차 A 5건 중 4건(X-1·X-5·X-7·X-4)에 실행 가능한 재현 명령이 없다. 그중 **X-1은 리더가 직접 재현해 확정**했고, 나머지 3건은 미검증이다.
- **codex가 표기한 라인 번호 대조 불가** — `tests/golden/` 3파일이 현재 수정 중이라 지금 시점의 라인 대조는 무의미하다.
- **양쪽 공통 미실행**: `uv run pytest -m llm`(금지 — 크레딧 소진). 따라서 이 게이트 전체가 **정적 분석 + 비-llm 테스트 실행**에 근거하며, 실제 변환 실행으로 확인한 것이 아니다.
- **codex 축 밖**: 계약 준수 · 보안 불변식(로그·키·마스킹). Claude만 검토했다(§2.2).
