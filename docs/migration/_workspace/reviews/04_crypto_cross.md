## 5. 충돌·견해차 — 양쪽 근거 병기 (리더 판단 요청)

> 어느 쪽도 삭제하지 않았다. 각 항목의 마지막 줄이 **리더가 답해야 할 질문**이다.

### ⓐ X1 — round-trip 비가역 손실: **결함인가, 입력 정의 문제인가** ★리더 판단 필요

**codex(high, 실행 근거).**
> 암호 계층이 임의 바이트가 아니라 String만 받고 UTF-8로 암호화한 뒤 다시 String으로 만든다.
> 실제로 `x\uD800y`를 왕복시키면 `x?y`로 바뀌었다. 따라서 표준 AEAD 바이트 round-trip을 제공하지 못하며,
> **파서가 비정상 UTF-16 코드 단위를 만든 경우 인증에는 성공하면서 사용자 문서가 영구 손상된다.**
> 현재 표본에는 1바이트·본문 NUL·이 반례가 없다. → 처방: 포트를 `ByteArray` 로, 또는 `CharsetEncoder` REPORT 모드로 **쓰기 전에 거부**.

**privacy-gate(결함 아님 + 기록 R-2).**
> 이것은 AEAD 결함이 **아니라** `String.toByteArray(UTF_8)` 의 JVM 표준 동작이다 — 짝 없는 UTF-16
> 서로게이트는 UTF-8 로 인코딩될 수 없어 (치환)된다. **Kotlin `String` 을 UTF-8 로 저장하는 어떤 구현도 같다.
> 판정: 결함 아님.** 다만 문서 추출기가 손상된 파일에서 고아 서로게이트를 만들어 낼 수 있으므로,
> "저장하면 문자가 바뀔 수 있다"는 사실은 `I-13`(초안 원본 보존) 축에서 다음 단위가 알고 있어야 한다.

**Claude(1차, 미지적).** round-trip 축을 검토했으나 **입력 집합에 비쌍 서로게이트가 없었다**(6종 충족으로 판정).
privacy-gate 는 16종, codex 는 그 6종·16종 **밖의 1종**을 들었다.

**교차 종합이 확정한 사실(§4-②).** ⑴ 치환은 실재하고 **비가역**이다(`equals=false`).
⑵ 치환 문자는 `?`(U+003F)이며 privacy-gate 표의 「U+FFFD」는 **틀린 값**이다(원인 진단은 옳다).
⑶ 손실은 **암호화 이전**에 일어나므로 AEAD 자신의 round-trip 은 무결하다 — 즉 세 관점이 **같은 현상을
서로 다른 경계로 이름 붙였다**: codex 는 「제품이 제공하는 round-trip」, privacy-gate 는 「AEAD 의 round-trip」.
⑷ 도달: `documents.source_text_encrypted` 에 쓰는 경로가 아직 0. **문서 추출기(`ingest`)가 붙는 순간
입력이 사용자 파일이 되고, 손상된 docx/hwpx 가 고아 서로게이트를 만들 수 있다** — privacy-gate 스스로 그렇게 적었다.

**리더 판단 요청.**
① §5 Phase 7 즉시 중단 기준 「AEAD round-trip 실패」에 **이 형태가 포함되는가** — 포함되면 **차단①**, 아니면 수정 필요.
② 포함되지 않더라도, **documents 단위에서 「쓰기 전 거부(REPORT 모드)」를 강제할 것인가**
(codex 처방) 아니면 「치환을 수용하고 I-13 에 기록」할 것인가(privacy-gate 처방). **두 처방은 양립하지 않는다.**
③ privacy-gate §1 표의 값 정정(U+FFFD → U+003F) — 감사 산출물의 사실 오류이므로 별도 처리 필요.

### ⓑ X2 — `PlainBody` Jackson 직렬화: 사실은 합의, **심각도가 갈린다**

**codex(high, 실행).** 「저장소의 Jackson Kotlin 모듈로 직접 확인한 결과 `PlainBody("PII-…")` 가 JSON 문자열
`"PII-…"` 로 출력됐다. **향후 복호화 결과가 응답 DTO나 구조화 로그에 들어가면 래퍼가 보호 장치가 되지 못한다.**」

**privacy-gate(항목 7 — 도달 0).** 「Jackson 직렬화 경로 — **도달 0**. `PlainBody` 는 `crypto` 패키지
**밖에서 참조 0건**. DTO·응답 스키마에 실린 자리가 없다.」 + `@JvmInline value class` 인라인 함정을 별도 확인.

**Claude(검토함, 오늘 기준).** 「`toString` 재정의가 있고 게이트가 실제로 닿는다(MUT-G 1 red).
**Jackson 경로는 오늘 0** — DTO 어디에도 쓰이지 않는다.」

**교차 확정(§4-④).** 세 관점이 **같은 사실**에 서 있다 — 기제는 열려 있고 도달은 0.
