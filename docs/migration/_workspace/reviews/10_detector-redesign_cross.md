## 3. R-1 병합 상세 — **두 레인이 독립적으로 같은 자리에 도달했다** (이 회차의 핵심 사실)

**병합 근거.** 두 지적은 같은 코드 지점의 같은 기제를 가리킨다. 종합 단계에서 소스로 확인했다 —
물리 줄 순회(`:828`)와 논리 줄 순회(`:865`) **양쪽 모두** `match = rule.pattern.search(line)` 로
**첫 적중 하나만** 꺼내 `rule.refine(match)` 에 넘기고, 안전 판정이 나면 `drop()` 후 `continue` 한다.
호출 단위 순회가 없다. 따라서 C-1 과 N-01 은 표현이 다를 뿐 한 행이다.

**그러나 병합해서 무게를 잃으면 안 되는 것이 있다.** 두 레인은 **서로의 결과를 보지 못한 채**
다른 방법으로 같은 자리에 닿았다.

| | codex C-1 | Claude N-01 |
|---|---|---|
| 도달 경로 | 적대적 입력 설계 | refine 훅 docstring 의 선언 범위 대조 → 반례 구성 |
| 제시한 반례 | 세미콜론 다중 문장 · `.also { }` | `if/else` 두 호출 · `.also { }` (e2e `scanner.scan()` 정식 경로) |
| 고유 기여 | 세미콜론 갈래 | **순서 의존 실증**(순서만 바꾸면 HIT) · **리포트 무흔적**(숫자만 증가) · 인용 범위가 두 순회 모두 |

**가중치.** 이 저장소에서 두 레인의 관심 표면은 거의 겹치지 않았다 — 게이트 08은 24행 중 21행이,
게이트 09는 24행 중 20행이 한쪽만 본 지적이었고, **게이트 09의 차단 3건(M-01·M-02·M-03)은 전부
한 레인에서만 나왔다.** 그 구성에서 **이번에 처음으로 차단 등급의 합의가 나왔다.**

독립 도달은 심각도를 낮출 근거가 아니라 **높일 근거**다. 서로 다른 방법을 쓰는 두 관측자가
같은 결함에 닿았다는 것은 그 결함의 **도달 반경이 넓다**는 뜻이다 — 즉 우연히 눈에 띈 것이 아니라
평범한 코드 모양에서 재현된다. 게이트 05 의 R-1 판정 전례(*"양쪽 독립 발견이므로 낮추지 않는다"*)를
그대로 적용한다. **R-1 의 차단 등급은 종합에서 유지된다.**

## 4. 상충 후보의 해소 — R-2(codex C-2) vs Claude 의 주석 파서 해소 확인

리더가 지목한 상충 후보다. **기제로 갈랐고, 결론은 충돌이 아니라 상보(相補)다.** 어느 쪽도 삭제하지 않았다.

### 4.1 두 진술

- **Claude 1차 §3.1**: stop-gate 주석 지적은 **해소**. `CommentProbe.kt` 3건 · `comment_probe.py` 2건 CAUGHT,
  상시 음성 대조 `test_privacy_scanner.py:497`·`:515` 존재.
- **codex C-2**: 중첩 블록 주석에서 **주석 유무가 검출을 바꾼다** — 불변량 위반. 참조 주석 제거기도
  같은 Boolean 모델이라 이 위반을 못 잡는다.

### 4.2 갈랐다 — c2255dc 가 닫은 자리와 C-2 가 여는 자리는 **같은 함수·같은 결함 형태·다른 입력 종류**다

`c2255dc` 커밋 메시지가 자기가 닫은 조건을 셋으로 명시한다:
① 주석 안에 짝 없는 `)` → 인자 구간 조기 폐쇄 ② 그 앞에 **안전한** 접근 ③ 진짜 위험한 접근이 그 뒤.
처방은 "주석 제거를 별도 패스로 두지 않고 `_advance` 가 어휘 상태와 코드 부분을 **함께** 돌려준다".
실측 범위는 "Kotlin 줄·블록 주석과 Python `#` 셋" — **전부 비중첩**이다.

C-2 가 여는 것은 그 처방 **안쪽**이다. `_advance` 는 `depth, quote, block = state.depth, state.quote,
state.in_block_comment` 로 블록 주석 상태를 **Boolean 하나**로 들고, `rest.startswith("*/")` 에서
무조건 `block = False` 로 닫는다. Kotlin 블록 주석은 **중첩 가능**하므로, 중첩 주석의 첫 `*/` 이후
꼬리가 **코드 텍스트로 재유입**되고 거기 든 `)` 가 다시 ①을 성립시킨다. 즉 **c2255dc 가 세운
"주석은 코드가 아니다"라는 처방 자체가 중첩 입력에서 무너진다.**

### 4.3 제3의 근거 — 종합 단계에서 직접 실행했다

> 양쪽 근거를 지우지 않기 위한 확인이다. **어느 쪽 지적도 이 실행으로 삭제하지 않는다.**

컴파일된 스캐너를 적재해 `LOG-BODY` 규칙의 패턴 + `refine` 을 직접 호출했다(재구현 없음).

| 입력 | 결과 |
|---|---|
| `logger.info("n={}", draft.stats.count, /* outer /* inner */ ) outer */ draft.value)` | pattern=HIT **refine=SUPPRESSED** |
| 같은 코드에서 **주석만 제거** | pattern=HIT **refine=CAUGHT** |
| **비중첩** 주석 `/* outer */` 로 교체 | pattern=HIT **refine=CAUGHT** |

**codex 의 관측이 재현된다.** 그리고 비중첩이 CAUGHT 라는 세 번째 줄이 **Claude 의 해소 판정도
동시에 재현한다** — 두 진술이 모두 참이다.

### 4.4 처분

**충돌 아님. 두 지적을 모두 유지한다.**

- Claude 의 「해소」는 **그 회차가 검사한 입력 종류(비중첩 3종)에 대해 정확하다.** 판정을 정정하지 않는다.
- codex 의 C-2 는 **그 해소가 닿지 않은 잔여 입력 종류**를 연다. 새 결함이 아니라 **같은 결함의 미폐쇄 종류**다.
- 이 구도 자체가 Claude 가 N-06 에서 지적한 형태와 같다 — *"결함은 한 건이 아니라 **종류**였는데
  처방이 인스턴스 단위"*. **N-06 의 진단이 스캐너 자신에게 적용된 사례**이며, 이 대조는 두 레인의
  산출물만으로 성립한다.

## 5. 축 (3) 합의의 가중치 — codex 무지적 × Claude 4/4 정합 (`codex-review` §7 방식)

### 5.1 §7 이 정한 기록 방식

`codex-review` 스킬 §7 은 **"지적 0건"과 "리뷰 근거 없음"을 엄격히 가른다**:

> 지적 0건 | exit 0 + "No material findings" | **"지적 없음"을 그대로 기록한다. Claude 가 대신 지적을
> 만들어 채우지 않는다** — 그건 독립 리뷰가 아니다. **단 exit 0일 때만 그렇게 기록한다**
> (5·7은 지적 0건이 아니라 리뷰 근거 없음이다).

**이 회차는 전자다.** 스크립트 종료 코드 `0`, 대상 판정 `non-empty`(26파일), 출력 비절단
(`Findings:` 5건·`Next steps:` 3항 모두 닫힘). 따라서 축 (3) 무지적은 **admissible 한 관측**이며,
"리뷰가 돌지 않았다"로 격하되지 않는다. codex 산출물 §4.5 가 판정을 보류하고 넘긴 것을 여기서 닫는다.

### 5.2 그러나 대칭이 아니다 — 무엇이 합의되고 무엇이 안 됐는가

| | Claude | codex |
|---|---|---|
| 성격 | **적극적 검증** — 해제조건 4건을 항목별 대조, `git diff` 로 동작 무변경 확인, 게이트 실행으로 갈림 32 재현 | **반증의 부재** — 축 (3)이 focus 에 명시 배정됐으나 지적을 내지 않음 |
| 증명하는 것 | "판정문이 요구한 것이 실물에 있다" | "적대적으로 읽어 무너뜨릴 자리를 찾지 못했다" |
| 증명하지 않는 것 | 판정문 자체의 옳음(권한 밖) | **얼마나 깊이 봤는지** — 축 (3)에는 "실제로 돌려 봤다"류 서술이 **없다**(§4.3에 C-1·C-2·C-4만 있음) |

**따라서 이것은 R-1 식의 "독립 도달 합의"가 아니다.** 두 레인이 같은 결론에 각자 닿은 것이 아니라,
**한 레인이 실측으로 확인하고 다른 레인이 반증을 내지 못한** 비대칭 수렴이다. 표기를 `합의(비대칭)` 로
구분한 이유가 이것이다.

### 5.3 그럼에도 이 자리의 신뢰도는 이 배치에서 가장 높다 — 세 가지 이유

1. **codex 가 그 축에서 전역적으로 침묵한 것이 아니다.** 같은 실행이 축 (1)에 2건, (2)·(4)·(5)에
   각 1건씩 냈다. 축 (3)만 비었다 — 레인이 얕게 돌았다는 설명은 나머지 4축이 반증한다.
2. **축 (3)은 검증의 성질이 다르다.** (1)·(2)는 *"뚫을 수 있는가"*(적대적 탐색 — 못 찾은 것이
   없음을 뜻하지 않는다)인데, (3)은 *"판정문이 요구한 문자가 실물에 있는가"*(대조 — 유한하고 열거 가능)다.
   후자는 한 레인의 성실한 대조로 닫히는 종류이고, Claude 가 `git diff`·게이트 실행으로 그것을 했다.
3. **Claude 의 검증이 요구를 초과했다.** 회귀 2건 요구에 4건, 등가성 단언을 `isEqualTo` 가 아니라
   **양쪽 모두 `isEmpty()`** 로(등가성보다 엄격 — "둘 다 가려짐"으로는 만족 불가), 경계축 짝을
   **생성기 comprehension 으로 구조 결합**. 초과분은 반증 부재를 보완하는 독립 신호다.

### 5.4 판정

**§4-septies 해제조건 1~4는 종합 기준으로 충족이다.** 이 배치에서 **유일하게 "닫혔다"고 보고할 수
있는 자리**이며, 이 판정은 Claude 의 실측을 근거로 하고 codex 의 무반증을 보조 근거로 둔다.

**남기는 유보 한 줄**: TAB 제거는 **누락 방향**(커버리지 축소)이고, 그 대가가 코드 KDoc·테스트 이름·
fixture 설명·원장 **네 곳**에 표기돼 있다. 원장 342행 마스킹 행이 `아니오` 로 유지돼 게이트는 열려 있다
— **집행 정합과 방향 정당성은 다른 문제**이며, 후자는 `privacy-gate` 판정 §4-septies.9 소관으로 남는다.

### 6.2 Claude ④ 의 `known_gap` 처방 — 대조 결과 codex 반증 없음, 그리고 **C-4 와 같은 장치를 요구한다**

Claude 1차 §6.4 의 판단은 셋이었다.

1. **정의를 넓히지 않는다.** `known_gap` 은 은폐형(면제 조항)이고 `CLAUDE.md` 규칙 4가

2. **표기만 신설하는 것으로는 아무것도 바뀌지 않는다.** `known_gap` 은 지금 **어느 게이트도 읽지 않는다**
   (`compare_parity.py` 등장 0회). `SKILL.md:322` 의 *"선언이 붙은 케이스는 별도 목록으로 올린다"* 가
   구현 0이고, 무단언 2건이 `성질 판정 108건` 에 그대로 들어간다.
3. **탐지형 전환** — 필수 필드 `owner`/`deadline`/`referred_by`(없으면 exit 1) · 별도 구획 리포트 ·
   커버리지 분리 집계 · 선언 하한 방식 개수 상한.

**codex 는 이 셋 중 어느 것에도 반대 견해를 내지 않았다(무지적).** 축 (4)에서 codex 가 유일하게
낸 C-4 는 대상이 다르다(집합 크기). 따라서 §5의 비대칭 수렴조차 성립하지 않는다 — **R-4는 순수 단독**이다.

**그러나 종합에서 드러나는 것이 하나 있다.** Claude 처방 ④(**선언 하한 방식으로 개수를 못박는다**)와
codex C-4 권고(**필수 case ID·방향을 생성기와 독립된 manifest 에 고정**)는 **같은 장치의 두 요청**이다.
두 레인 어느 쪽도 상대의 요청을 보지 못했다. 종합 단계에서 확인한 사실 — 현재 저장소의 하한 파일
2종(`parity-canonical-floor.txt`·`parity-declared-floor.txt`)은 **도메인 이름만** 고정하고
**케이스 축 하한은 존재하지 않는다.** 즉 두 요청은 같은 빈자리를 서로 다른 쪽에서 가리키고 있고,
**하나의 장치로 함께 닫힌다.** 이 병합은 두 산출물의 대조에서만 나온다.

## 7. R-5(C-4) 와 기판정 C-09·X-3 의 관계 — **재도출 + 미판정 잔여 1**

리더가 갈라 달라고 한 항목이다.

### 7.1 기제는 동일하다 — 이미 판정된 한계의 **네 번째** 재도출

| 게이트 | 표기 | 대상 표면 | 처분 |
|---|---|---|---|
| 01 | **X-3** (codex 단독) | `BUILDERS`/`VERIFIERS` 동시 약화 | 리더 판정(2026-08-12): *"정본도 같은 커밋에서 함께 바뀔 수 있다 — 한 칸 더 옮기는 것은 방어가 아니라 이동"* |
| 08 | **C-09** (충돌) | `ParityFixtures.root()`·시스템 프로퍼티 | 리더 판정(2026-08-14): *"규약이다 — 구조 봉쇄 기각. … **닫은 것이 아니라 관리하는 한계**"* |
| 09 | **M-07** | fixture 백스톱 | **C-09 재적용 — 변경 없음.** (M-08 만 분리) |
| **10** | **C-4** | `canonical_fixture` = `BUILDERS[domain]()` 재실행 | **← 이 문서** |

`compare_parity.py:924-940` 의 docstring 이 스스로 그 한계를 적어 두었다 —
*"파일이 정본 생성기의 산출물인지는 **생성기를 돌려 대조하는 것 말고 확인할 방법이 없다**."*
**C-4 의 기제는 X-3 = C-09 = M-07 과 같다: 정본과 검사 대상이 같은 커밋에서 함께 바뀐다.**
이 부분은 **새 결함이 아니라 재도출**이다. 그리고 codex 가 **네 번째 게이트에서, 다른 대상 표면으로,
기판정을 모른 채 같은 구조를 다시 꺼냈다**는 사실 자체가 이 한계의 실재성에 대한 독립 증거다.

### 7.2 그러나 C-09 판정 근거의 **절반이 이 표면에서는 비어 있다**

C-09 를 "관리하는 한계"로 닫은 리더의 근거는 두 개였다. 각각을 C-4 의 표면(**케이스 삭제**)에 대입한다.

| C-09 의 방어 근거 | 케이스 축에 대입하면 |
|---|---|
| ⑴ **회귀 주입 검출 실증**(`3934f06` — 진짜 Kotlin 산출물에 5종 주입, 전부 exit 1) | **대입 불가.** 주입은 **남아 있는 케이스**에 대한 방어다. 케이스가 삭제되면 주입할 대상 자체가 없다 |
| ⑵ 하네스 수정 커밋은 리뷰 게이트를 지난다 | **유효.** `build_masking` 편집은 diff 에 뜨고 리뷰에 올라간다 |

그리고 **축의 단위가 다르다.** 지금까지의 재도출은 전부 **도메인 단위**였고, 저장소는 그 축에
비대칭 하한 2종을 실제로 세워 두었다(0개 금지 + 비감소). **케이스 단위에는 어떤 하한도 없다** —
종합 단계에서 두 하한 파일을 읽어 확인했다. codex 의 *"CI 하한은 도메인 이름만 고정한다"* 는 **사실이다.**

**선례가 이미 존재한다.** 게이트 09 에서 리더는 M-07(구조 한계)은 C-09 로 닫고, **M-08(케이스 내용
무의미화)은 "저장소 기준의 한계가 아니라 비교기의 별개 결손"이라며 분리**했다. **C-4 는 M-08 의
삭제 방향 쌍둥이다** — M-08 이 "케이스를 무의미하게 만들기", C-4 가 "케이스를 없애기"이며 둘 다
결과가 `전건 일치 + 도메인 유지`다. M-08 이 분리됐다면 C-4 도 같은 이유로 분리 후보다.

### 7.3 판정 제안 (결정은 리더)

**C-4 = 「기판정 C-09 의 재도출(도메인 축)」 + 「미판정 잔여(케이스 축)」로 가른다.**

> **리더 판단 요청 — 두 레인의 근거를 지우지 않고 병기한다.**

## 8. `refine` 훅 — 사전 등록된 선이 이 종합에서 닿았다 (합산의 산술)

> **새 지적이 아니다.** Claude 1차가 자기 결론에 **미리 등록한 조건**에, 두 산출물을 합친 목록이
> 닿았는지를 세는 일이다. 세는 것 자체가 대조다.

Claude 1차 §12.3:
> *"`refine` 훅은 **네 번 연속 새는 방향으로 틀렸다**(M-01·M-09·stop-gate·N-01). … 나는 점 수정
> (`finditer`)을 권고하되, **다섯 번째가 나오면 훅을 걷어내는 선**을 지금 정해 둘 것을 제안한다."*

그 시점 Claude 가 센 것은 **4**였다. codex 의 C-2 를 더하면 목록은 이렇게 된다.

| # | 갈래 | 출처 | 레인 |
|---|---|---|---|
| 1 | `_SAFE_ACCESS` 가 종단을 열거 (ktlint 표준 표기가 안전 판정) | M-01 | 게이트 09 |
| 2 | 메시지 안 괄호가 인자 구간 절단 | M-09 | 게이트 09 |
| 3 | 비중첩 주석 안 `)` 가 인자 구간 조기 폐쇄 | stop-gate → `c2255dc` | 게이트 09 |
| 4 | 논리 줄 내 다중 호출 — 첫 적중만 판정 | **R-1 (양 레인)** | 게이트 10 |
| 5 | **중첩 블록 주석 꼬리가 코드로 재유입** | **R-2 (codex)** | 게이트 10 |

**다섯 번째가 나왔다.** 다섯 번 모두 한 문장으로 서술된다 —
*"판정이 하나만 보고, 거기서 '안전'을 찾으면 나머지를 검사하지 않는다."*

**세는 방법을 두 가지로 제시하고 판단은 리더에게 넘긴다.**

- **인스턴스로 세면 5** — Claude 가 등록한 조건이 문자 그대로 충족됐다.
- **결함 구조로 세면 1** — `CLAUDE.md` 규칙 4의 판정 기준은 *"겪은 **횟수가 아니라 결함의 구조**"*다.
  다섯 갈래는 **같은 구조 하나**이고, 그 구조가 **열거할 수 없는 자리를 종류로 댈 수 있는 상태**
  (문법 요소가 늘 때마다 새 갈래가 난다: 종단·괄호·주석·호출 경계·주석 중첩)다.

**두 방법이 같은 결론을 가리킨다.** 규칙 4의 후속 조항이 이 자리를 직접 규정한다 —
*"**은폐형**(무시 패턴·억제·면제 조항)은 ⑴이 참이어도 **넓히지 않는다 — 탐지형으로 갈아탄다.**"*
`refine` 은 억제 장치이므로 은폐형이다. 즉 규칙은 **"갈래를 하나 더 막는 점 수정"이 아니라
"훅을 탐지형으로 갈아타기"**를 지시한다.

**이 문서가 결정하지 않는다.** 점 수정 3건(`finditer` · 중첩 depth · 정규식 한 글자)으로 갈지,
훅을 걷어낼지는 비용이 크게 다르고 **리더 판정 사항**이다. 다만 **점 수정을 택할 경우 여섯 번째가
날 자리를 종류로 예고하는 것**이 §11 조치 목록에 담긴 이유가 이것이다.

### 11.2 **판정 — 잔여 5개 도메인(text·style·prompts·postprocess·export) 착수를 차단하는가**

리더가 요청한 판정이다. 원칙은 **②장치의 마감 = 그 게이트가 처음 실제로 쓰이는 시점**이고,
R-1·R-2·R-3 의 게이트는 **이미 CI 에서 BLOCK 으로 돌고 있으므로 마감이 "지금"**이다.
그럼에도 **착수 차단 여부는 별개 축**이다.

#### 판정: **차단하지 않는다 — 조건부.** 단 R-3 은 착수 전에 닫을 것을 권고한다(차단이 아니라 순서).

**근거 1 — 스캐너가 전수로 돈다. 이것이 결정적 비대칭이다.**
`ci.yml:104` 는 `uv run python .../scan_privacy_invariants.py` 를 **인자 없이** 부른다.
`--changed` 증분이 아니다. 바로 위 주석이 그 선택을 명시한다 — *"계속 넓어지거나 fork point 이동으로
흔들리고, **전수가 이미 1초 미만이다**."* 따라서 **구멍을 나중에 막고 전수를 다시 돌리면 그 사이 쓰인
코드까지 소급 검사된다.** 늦게 고치는 비용이 코드량에 비례해 누적되지 않는다.
**늦은 수정이 회복 가능한 구조**라는 점이 착수 차단을 요구하지 않는 핵심 근거다.

**근거 2 — ①사건 0건이 두 레인 합의다.** §10 참조. 프로덕션 트래픽 없음, 절체 전, 즉시 중단 기준 해당 0건.

**근거 3 — 파일 충돌이 없다.** R-1·R-2·R-3 은 전부 `.claude/skills/migration-safety-gate/scripts/`
한 파일이고, 잔여 5개 도메인은 `backend-kotlin/core/` 다. 병렬 진행이 가능하다.

**무효 조건 — 아래가 깨지면 이 판정은 무효다. 원장에 함께 적어야 한다.**

| 조건 | 내용 |
|---|---|
| **(a)** | R-1·R-2·R-3 의 마감은 "Phase 2 종료 전"이 아니라 **"잔여 5개 도메인 병합 전"**이다. 소급 검사가 성립하려면 **마지막 전수 스캔이 고쳐진 스캐너로** 돌아야 한다 |
| **(b)** | 스캔이 `--changed` 류 **증분으로 바뀌면 근거 1이 소멸**한다. 증분 전환은 이 판정의 무효 조건이다 |
| **(c)** | **R-3 만은 착수 전에 닫기를 권고한다.** 잔여 5개 도메인이 새 로거 호출을 추가할수록 `log.` 미탐지의 노출 표면이 늘고, 수정 비용은 **정규식 한 글자**다. 가장 싼 것을 가장 늦게 고칠 이유가 없다 |
| **(d)** | **R-4(`known_gap`)가 닫히기 전에는 `성질 판정 N건` 을 Phase 2 종료 판정의 근거 수치로 쓰지 않는다.** 잔여 5개 도메인이 각각 무단언 케이스를 낳을 수 있고, 그 수는 지금 커버리지 대리 지표로 읽힌다. 수치를 쓸 경우 `known_gap` 수를 **손으로 빼고** 읽는다 |

**요약**: 잔여 5개 도메인은 **착수해도 된다.** 스캐너 3건은 **병렬 배치**로 진행하고, **R-3 은 먼저**,
나머지 둘은 **5개 도메인 병합 전**에 닫는다. `known_gap`(R-4)은 착수를 막지 않되 **Phase 2 종료
판정 수치의 전제**이므로 종료 판정 전에 반드시 닫힌다.

## 13. 리더에게 (종합 결론)

1. **차단은 3 → 4로 늘었다.** R-1(합의) · R-2(codex 단독) · R-3(Claude 단독) · R-4(Claude 단독).
   **전부 ②장치이고 ①사건은 두 레인 합의로 0건이다.**
2. **이 회차에서 처음으로 차단 등급의 합의가 나왔다**(R-1). 게이트 09는 차단 3건이 전부 단독이었다.
   동시에 **두 레인이 서로 못 본 차단을 하나씩 더 냈다** — codex 는 R-3·R-4를, Claude 는 R-2를 놓쳤다.
   **어느 한 레인만으로도 게이트는 잘못 닫혔을 것이다.**
3. **충돌 0건.** 상충 후보였던 R-2는 기제로 갈랐다 — `c2255dc` 가 닫은 것은 **비중첩** 주석,
   C-2 가 여는 것은 **중첩** 주석이며, 종합 단계 실행이 **양쪽 진술을 모두 재현**했다(§4.3).
   Claude 의 해소 판정을 정정하지 않았고 codex 의 지적도 지우지 않았다.
4. **§4-septies 집행은 종합 기준으로 충족이다** — 이 배치에서 유일하게 닫힌 자리다. 다만 근거의
   성질을 정확히 적는다: **Claude 실측 4/4 + codex 무반증**이지, 두 레인 독립 확인이 아니다(§5).
5. **`refine` 훅에 다섯 번째 갈래가 났다**(§8). Claude 1차가 미리 등록한 조건이 충족됐고,
   `CLAUDE.md` 규칙 4는 은폐형에 대해 *"넓히지 않는다 — 탐지형으로 갈아탄다"* 를 지시한다.
   **점 수정인가 전환인가는 J-2 로 올린다.**
6. **C-4 는 기판정 C-09 의 네 번째 재도출이되, 케이스 축은 덮이지 않는다**(§7). C-09 방어 근거 ⑴
   (회귀 주입 검출)이 **삭제된 케이스에는 대입되지 않고**, 하한 파일 2종은 **도메인 이름만** 고정한다.
   M-08 분리 선례가 적용되는지가 J-1이다.
7. **Claude R-4 와 codex R-5 는 같은 장치를 서로 다른 쪽에서 요청하고 있다**(§6.2). 한쪽만 채택하면
   나머지 절반이 다음 게이트에서 다시 올라온다 — J-3.
8. **잔여 5개 도메인 착수는 차단하지 않는다 — 조건부**(§11.2). 스캐너가 **전수**로 돌아 늦은 수정이
   소급 회복되기 때문이다. 단 **R-3(정규식 한 글자)은 먼저**, 나머지 둘은 **병합 전**, 그리고
   **증분 스캔 전환은 이 판정의 무효 조건**이다.

10. **미판정 이월은 C-07 하나다**(J-5). 답이 오지 않았다는 이유로 조용히 닫지 않고 그대로 다시 올린다.
