**음성 대조 (N2).** `lockForDeletion` 의 집합 잠금

load-bearing 이고, 그 사실이 실행으로 확인됐다.

**FK 409 방벽.** 문서가 든 작업 공간 삭제 → `409` ·

`/workspaces` 2건을 제거하고 돌렸다.

```
AuthenticationCoverageContractTest → FAIL
  "계약이 보호로 선언했는데 인증이 걸리지 않은 경로: [/workspaces, /workspaces/{workspace_id}]"
WorkspaceContractTest → 16건 중 13건 FAIL, 전부 500
```

두 가지가 확인된다. ⑴ 계약 대조 게이트가 **실제로 탐지한다**(빈 선언에서 통과하지 않는다).
⑵ 목록 등재를 빠뜨렸을 때의 실패 모드가 **조용한 인증 우회가 아니라 시끄러운 500** 이다 —
`AuthenticatedUserArgumentResolver` 가 속성 부재를 `error()` 로 끊기 때문이고, 이 이중 방벽이 실측됐다.

### 기록 R-3 — 계정이 지워진 유효 토큰의 처리가 `/auth/me` 와 `/workspaces` 에서 갈린다

토큰은 유효한데 `users` 행이 없는 상태를 만들고 5개 경로를 잰 결과다.

| 경로 | 응답 |
|---|---|
| GET `/auth/me` | **401** `이메일 또는 비밀번호가 올바르지 않습니다` |
| GET `/workspaces` | **200** `{"items":[]}` |
| POST `/workspaces` | **500** `{"detail":"요청을 처리하지 못했습니다"}` (사용자 FK 위반) |
| PATCH `/workspaces/{id}` | **404** |
| DELETE `/workspaces/{id}` | **404** |

**양쪽 해석을 병기한다.**

- *위반 쪽*: 계약 `x-auth.failure_uniformity`(L299–302)가 *"이메일 부재·비밀번호 불일치·토큰 만료·
  위조·**계정 삭제**를 모두 같은 401과 같은 메시지로 처리한다"* 고 조건 단위로 적었다. `/workspaces` 는
  같은 조건에 401 이 아닌 세 가지 다른 코드를 낸다.
- *위반 아님 쪽*: 그 조항은 `x-auth` 아래에 있어 인증 API 를 서술하는 절로 읽을 수 있고, 계약이
  `/workspaces` 응답 목록에 그 갈래를 두지 않았다. 인터셉터를 401 로 만들려면 **매 요청 사용자 조회**
  가 붙는데 계약이 그것을 요구한 적이 없다.

**판정: 기록(차단 아님).** 근거 셋. ⑴ 교차 사용자 노출이 아니다 — 소유 조건이 지워진 사용자 id 로
걸려 GET 은 빈 목록, PATCH·DELETE 는 404 다(I-5 무손상). ⑵ 500 본문이 고정 문구라 정보 유출이 0 이다.
⑶ **계약에 계정 삭제 엔드포인트가 없다**(`/auth` 는 signup·login·me 셋뿐) — 현재 이 상태는 DB 직접
조작으로만 만들어지므로 도달 경로가 제품에 없다.

**다만 조건부다**: 계정 삭제 기능이 들어오는 순간 이것은 「탈퇴한 계정이 토큰 수명(60분)까지 API 를
일부 쓴다」는 실제 인가 결함이 된다. **계정 삭제 기능 커밋과 같은 단위에서 해소**할 것을 조건으로 건다.

구현자가 산출물 `03_kotlin-implementer_workspaces.md` 미결 ⑥ 으로 이미 등재했다(POST→500 한 갈래만).
나머지 네 갈래는 이 감사가 처음 잰 것이고, **GET → 200** 이 그중 가장 눈에 띄는 자리다.

후자가 더 강한 성질이다. 다만 이 측정만으로는 **로깅이 생기는 순간**을 잡지 못하므로, 작업 공간
이름을 로그 후보 문자열로 넣은 회귀가 Phase 4 에 필요하다(개선 권고).

`GlobalExceptionHandler` 의 두 로그(`log.error("...: {}", simpleName)`)는 예외 **타입 이름만** 남긴다.
P7 에서 500 이 224건 났고 그 경로가 그 로거인데, 위 캡처에서 유출 0 이 유지됐다.

## 8. 감사 자체의 격리 (규칙 5 / X-9)

- 탐침·변조는 전부 일회용 worktree(`pgaudit`, `pgaudit2`)에서 돌았다.
- 복원은 `cp` 가 아니라 **`git checkout --`** 로 했고, 세 파일의 sha256 을 본 저장소와 대조해
  **전건 일치**를 확인했다(`JdbcWorkspaceRepository.kt`·`Argon2PasswordHasher.kt`·`AuthenticatedEndpoints.kt`).
- `git worktree remove --force` 로 두 worktree 를 제거했고, 본 저장소 `git status --porcelain` 은
  세션 시작 스냅샷과 동일하다(기존 미추적 3건뿐). **Kotlin 코드 수정 0 · 커밋 0 · `00_progress.md` 무접촉.**
- 이 문서에 실제 사용자 데이터·평문 본문·키·암호문을 옮겨 적지 않았다. 등장하는 UUID·이메일·
  이름은 전부 탐침이 그 자리에서 만든 합성 값이다.
