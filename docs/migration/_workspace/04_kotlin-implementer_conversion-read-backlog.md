# C6 개선 백로그 — **적용하지 않은** 후보

계획 §4.6 의 원칙(포팅과 개선을 섞지 않는다)과 리더 승인 규약에 따라, C6 작업 중 발견했지만
**코드에 넣지 않은** 것들이다. 리더가 명시적으로 승인하기 전까지 손대지 않는다.

## 포팅 동등성과 무관하게 **관측했지만 건드리지 않은** 사실

- `ConversionResponse.toString()` 이 `model`·`providerName` 을 가린다. 벤더 식별자라 개인정보는
  아니고, `SensitiveToStringReachTest` 의 이름 토큰 판정이 `providerName` 의 `name` 을 민감으로
  읽은 결과다. **판정을 좁히지 않고 값을 가리는 쪽**을 골랐다(면제 추가는 규칙 4 ⑵ 금지).
  판정기를 정교하게 만드는 것은 별건이고, 오늘 그 정교화가 얻는 것은 로그 한 줄의 벤더 이름뿐이다.
- `JdbcConversionRepository` 에 `JsonMapper` 인스턴스가 하나 더 생겼다(`MaskedItemCodec` 과 별개).
  합치면 봉인 대상 코덱과 평문 컬럼 파서가 한 클래스에 섞인다 — 그 경계가 더 값지다고 판단했다.
