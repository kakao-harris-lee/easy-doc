## 0. 읽는 법 — 태그 규약

각 수치에 다음 중 하나를 붙인다. **이 구분이 무너지면 현재 성능이 그대로 합격선이 되어 개선 여지가 사라진다.**

| 태그 | 뜻 |
|---|---|
| `[실측·현재]` | 오늘 이 저장소에서 재실행해 얻은 값. "지금 이렇다" |
| `[실측·과거]` | 저장소에 남아 있는 과거 실행 결과. 시점·조건을 함께 적는다. **현재 값이 아니다** |
| `[기준·기존]` | 이미 코드나 SSOT에 박혀 있어 지금도 강제되는 합격 수치. "이래야 한다" |
| `[미정]` | 정해진 바 없음. 이 문서가 선택지만 제시한다 |

**모든 `[실측]`은 "이래야 한다"가 아니다.** 아래 §4의 원문 분포는 *코퍼스가 얼마나 어려운가*이고, §5의 출력 분포는 *2026-08-08의 한 실행이 얼마나 잘했는가*다. 어느 쪽도 합격선이 아니다.

## 1. SSOT에 이미 있는 수치 — 이것이 우선한다

`docs/master-plan.md`가 SSOT이므로 여기 적힌 수치가 새로 정할 수치보다 앞선다.

| 출처 | 수치 | 태그 |
|---|---|---|
| master-plan §7 KPI 표 | 골든셋 자동 평가 **통과율 90%+** | `[기준·기존]` |
| master-plan §7 주석 | 90% 기준은 n=20 단일 실행에서 통계 변동이 큼(90% 품질 provider도 18/20 미달 확률 ≈32%). **경계값 재실행·표본 확대 판단은 사람이 한다** | `[기준·기존]` |
| master-plan §3.3 | 골든셋 = 스타일 규칙 검사 + LLM-as-judge, 프롬프트·모델 변경 시 CI 강제 | `[기준·기존]`(수치 아님) |
| master-plan §3.3 | 장문 한계 실측 인용: "**2,000자 초과 통과율 0.11**" | `[실측·과거]`(2026-08-08 이전, gpt-4o 계열) |

**master-plan에 없는 것:** judge 절대 점수, 규칙별 위반 허용치, 코퍼스 크기 고정값. 이 셋이 §9-A가 말한 진짜 공백이다.

## 2. §9-A 인벤토리 기술 정정 — 합격 수치는 **일부 이미 존재한다**

§9-A는 "합격 수치가 저장소 어디에도 없다"고 적었다. **이 진술은 부정확하다.** 아래 넷은 코드에 상수로 박혀 있고 `-m llm` 실행에서 실제로 assert된다.

| 상수 | 값 | 위치 | 의미 | 태그 |
|---|---|---|---|---|
| `PASS_RATE_THRESHOLD` | **0.90** | `tests/golden/test_golden_eval.py:41` | 스타일·팩트·플레이스홀더 **AND** 전부 만족한 문서 비율 | `[기준·기존]` |
| `JUDGE_COVERAGE_THRESHOLD` | **0.90** | 같은 파일 :44 | 채점이 이루어진 문서 비율 하한 | `[기준·기존]` |
| `JUDGE_SCORE_THRESHOLD` | **4.0** | 같은 파일 :45 | 충실성 평균·이해 용이성 평균 각각의 하한 | `[기준·기존]` |
| `DEFAULT_FIDELITY_FLOOR` | **2** | `app/easyread/judge.py:24` | 충실성 ≤2 문서가 **0건**이어야 함(날조 방어선) | `[기준·기존]` |

`PASS_RATE_THRESHOLD`의 주석은 이 값이 master-plan §7 KPI에서 차용됐다고 명시한다. 따라서 **STY-03의 "절대 합격선"은 문서 단위 AND 통과율 90%로 이미 정의돼 있다.**

### 그럼 진짜로 없는 것은 무엇인가

| 공백 | 왜 문제인가 | 태그 |
|---|---|---|
| **규칙별 위반 허용치** | `check_style`은 전부-아니면-전무다. 위반 1건이면 그 문서는 실패(`StyleCheckResult.passed = not issues`). 문장 길이 1건 초과와 어려운 표현 111건이 같은 판정을 받는다. 규칙별·건수별 허용치는 정의된 적이 없다 | `[미정]` |
| **judge 절대 점수의 "절대"성** | 4.0은 평균 기준인데 **채점 모델을 고정할 수단이 없다**. `GOLDEN_JUDGE_PROVIDER`는 벤더만 고르고 모델은 `settings.llm_model`을 따라간다(`app/llm/factory.py`). 채점자가 바뀌면 같은 출력에 다른 점수가 나온다 — `docs/quality/2026-08-08-golden-reeval-gpt41.md` §6-2가 "judge 점수의 이전 대비 절대 비교는 성립하지 않는다"고 이미 기록했다 | `[미정]` |
| **코퍼스 크기·구성 고정** | `MIN_DOCUMENTS = 20`(`tests/golden/test_schema.py:26`). 현재 56건이지만 20건까지 줄어도 스키마 게이트는 통과한다. 통과율은 코퍼스 구성에 따라 움직인다(`2026-08-08-golden-baseline-56.md` §해석 2가 실측으로 확인: 25→36건 편입만으로 0.51→0.446) | `[미정]` |
| **통과 시 수치 미기록** | `format_report`·`format_judge_report`는 assert 메시지라 **게이트가 통과하면 아무 수치도 남지 않는다**. 기준선을 쌓을 수 없다(reeval 문서 §6-3이 같은 지적) | `[미정]` |

## 3. 지금 코드가 이미 강제하는 것

이미 게이트인 항목에 새 수치를 얹으면 중복이거나 모순이다. 아래가 현재 강제 목록이다.

### 3.1 기본 스위트 (`uv run pytest tests/golden`) — LLM 호출 없음

```
$ uv run pytest tests/golden -q
.......................                                                  [100%]
23 passed, 2 deselected in 1.47s
```

`pyproject.toml`의 `addopts = "-m 'not llm'"`이 `test_golden_eval.py`의 2건을 deselect한다. 남는 23건 중 20건은 `test_schema.py`(코퍼스 자체 검증), 3건은 `test_floor_gate_wiring.py`(바닥 게이트 배선).

`test_schema.py`가 강제하는 코퍼스 조건 `[기준·기존]`:

| 상수/검사 | 값 |
|---|---|
| `MIN_DOCUMENTS` | 20 |
| `MIN_DIFFICULT_WORDS` (문서당 고유 어려운 표현) | 2 |
| `MIN_FACTS` / `MAX_FACTS` | 3 / 6 |
| `MIN_SOURCE_CHARS` | 500 |
| `MAX_SYNTHETIC_SOURCE_CHARS` | 1,500 |
| `MAX_COLLECTED_SOURCE_CHARS` | 4,000 (`MAX_CONVERTIBLE_CHARS`와 수동 동기) |
| `test_원문은_모두_변환이_필요한_상태다` | **모든 원문이 `check_style` 실패여야 함** — 원문 위반 하한 1건이 이미 게이트다 |
| `PII_BEARING_SYNTHETIC_DOCUMENTS` | `{003: RRN, 011: CARD}` — 정확히 이 분포여야 함 |
| 카테고리 통제 어휘 | 10종 고정 |
| 팩트 제약 | canonical 원문 존재 / 마스킹 대상 패턴 불가 / 마스킹 후 잔존 / 치환 키 불포함 / accept≠canonical |

`test_floor_gate_wiring.py`는 FakeProvider로 하네스가 `find_low_fidelity`를 **실제로 호출하는지** 고정한다(호출을 지워도 기본 스위트가 초록으로 남는 것을 막는 장치).

### 3.2 `-m llm` 스위트 — 외부 API 필요, 기본 실행 제외

`test_골든셋_규칙_기반_통과율`: 문서별 3조건 AND(스타일 0위반 ∧ 팩트 유실 0 ∧ 플레이스홀더 유실 0) → 통과 비율 ≥ 0.90.
`test_골든셋_judge_점수`: 커버리지 ≥0.90 → **바닥 게이트(충실성 ≤2 문서 0건) 먼저** → 충실성 평균 ≥4.0 → 이해 용이성 평균 ≥4.0.

> 바닥 게이트가 평균보다 먼저 오는 것은 설계 의도다(`judge.py:41-45` 주석): 루브릭 5~2점은 누락의 정도(연속)이고 1점만 날조·의미 반전이라는 다른 축이라, 평균만 보면 소수의 1점이 희석된다.

### 3.3 새 수치를 얹을 때 중복·모순이 되는 자리

- 문서 단위 통과율 하한 → **이미 0.90.** 새로 정하면 master-plan §7과 충돌한다.
- "원문에 위반이 최소 N건" → **이미 1건 이상 강제.** 상향은 코퍼스 편입 기준 변경이지 품질 합격선이 아니다.
- 충실성 바닥 → **이미 ≤2 0건.** "평균 몇 점"을 새로 얹으면 4.0과 이중 기준이 된다.

## 6. judge 점수의 현재 분포

### 6.1 judge가 무엇을 몇 점 척도로 채점하는가 `[기준·기존]`

`app/easyread/judge.py` — **두 축, 각각 1~5 정수** + 코멘트 1문장. `JudgeScore` Pydantic 모델이 `ge=1, le=5`로 범위를 강제해 집계 오염을 막는다.

**충실성(fidelity)**
| 점수 | 기준 |
|---|---|
| 5 | 원문 정보가 빠짐없이 남고 왜곡 없음 |
| 4 | 사소한 정보 하나 누락, 뜻은 유지 |
| 3 | 부가 정보 여러 개 누락 |
| 2 | 날짜·금액·대상·신청 방법 등 중요 정보 누락 |
| 1 | 원문에 없는 내용 날조 또는 의미 반전 |

**이해 용이성(readability)**
| 점수 | 기준 |
|---|---|
| 5 | 발달장애인이 한 번 읽고 이해 가능 |
| 4 | 대체로 쉽지만 어려운 낱말 한두 개 잔존 |
| 3 | 문장이 길거나 어려운 한자어 여러 개 잔존 |
| 2 | 행정 문투 잔존 |
| 1 | 원문과 다를 바 없이 어려움 |

**척도 설계상의 주의(코드 주석에 명시됨):** 5~2점은 누락의 정도를 재는 연속 축이고 **1점만 날조라는 다른 축**이다. 두 축이 한 척도에 섞여 있어 평균이 날조를 희석한다(15건 5점 + 5건 1점 = 평균 4.0). 그래서 평균 기준과 별도로 `find_low_fidelity`(≤2 개별 차단)가 실제 방어선이다.

기타: judge 호출도 마스킹 선행 불변식 적용(`judge_conversion`이 `mask_text` 통과 후 전달), `JUDGE_MAX_TOKENS=512`, 난수 id 구분자로 인젝션 방어, 자리표시자는 감점 대상 아님을 프롬프트에 고지.

| 관측된 충실성 평균 범위 | 4.35 ~ 4.89 (부분집합 포함) | 2026-08-07 ~ 08-08 |
| 관측된 이해 용이성 평균 범위 | 4.77 ~ 5.00 | 2026-08-08 |
| 이해 용이성 최저 개별 점수 | 4 (56건 중 3점 이하 0건) | 2026-08-08 anthropic |
| 충실성 바닥(≤2) 발생 | gpt-4o 3건 → gpt-4.1 0건 → claude-sonnet-5(low) 1건 | 2026-08-07 ~ 08-08 |

**이해 용이성은 관측 전 구간에서 4.77 이상**이다. 현행 기준 4.0은 이 축에서 사실상 구속력이 없다 — 어떤 모델도 걸린 적이 없다. 충실성 4.0은 4.35~4.89 대비 여유가 0.35~0.89로 좁다.

### 6.5 judge를 돌리려면 무엇이 필요한가

| 필요 | 상세 |
|---|---|
| API 키 | `ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY` (`.env` 또는 환경변수, `app/config.py:Settings`). 키 없으면 `create_provider`가 `None` → 테스트 skip |

| 호출 수 | 변환 56~112회(문서당 1~2, 보정 조건부) + judge 56회 = **112~168회** |
| 소요 시간 | openai gpt-4.1 56건 **629초** 실측(2026-08-08). anthropic은 변환 지연 중앙값 24.24초·최대 92.39초 → 변환만 20분 이상 |
| 비용 | 벤치마크 §건당 원가 추정 참조(변환+보정, judge 제외) |

| 재현성 | n=1 단일 실행. 진단 §3.4가 judge 재현성 문제를 정량화(6건 중 5건이 1~2점 이동) |

## 7. 합격선을 정할 때 걸리는 선택지와 대가

수치는 정하지 않는다. **선택지와 그 대가만 적는다.**

### 선택 1 — 판정 단위: 문서 vs 코퍼스

| 안 | 내용 | 대가 |
|---|---|---|
| A (현행) | 문서 단위 AND → 통과 문서 비율 ≥0.90 | 위반 1건과 111건이 같은 판정. 긴 문서가 구조적으로 불리(§5.4: 2,000자 초과 통과율 7%). master-plan §7과 일치 |
| B | 코퍼스 단위 총 위반 밀도(100문장당 N건 이하) | 짧고 깨끗한 문서가 긴 문서의 위반을 상쇄해 **개별 문서의 심각한 실패가 숨는다**. §4.8에서 확인: 정규화 축을 문장으로 바꾸면 합성/실수집의 우열이 뒤집힌다 |
| C | 문서 단위 + 축별 상한 병기 | 규칙마다 수치가 늘어 유지 비용 증가. 축 간 가중치를 정해야 함 |

### 선택 2 — 문장 길이 상한을 어디로 잡는가

현행 50자. §4.6 스윕이 대가를 보여 준다(원문 기준).

| 절단선 | 걸리는 문장 | 위반 0 문서 | 대가 |
|---|---|---|---|
| 40자 | 26.4% | 3.6% | 국립국어원 권고에 가깝지만 실수집에서 사실상 전건 실패 |
| **50자 (현행)** | 15.2% | 5.4% | 현행. 변환문 기준으로는 2026-08-08 실행에서 80.4%가 위반 0 |
| 60자 | 9.0% | 17.9% | 문장 기준은 6%p 완화인데 문서 기준은 3배 완화 — **문서 단위 판정에서 가장 효과가 큰 구간** |
| 80자 | 4.2% | 50.0% | 합성 95%가 깨끗해지지만 실수집은 25%. "쉬운 글"의 취지가 흔들림 |
| 상한 없음 | — | — | STY-03의 핵심 축이 사라짐 |

**대안 축:** 상한을 바꾸는 대신 **초과 문장 비율**로 판정(예: 문서 내 50자 초과 문장이 X% 이하). 원문 기준 문서별 초과 비율 중앙값은 전체 17.9% / 합성 15.3% / 실수집 22.5%이고, 문서별 편차가 0%(039·041·051)에서 81.5%(062)까지 벌어진다.

### 선택 3 — 축별 허용치를 둘 것인가

현행은 전 축 0건이다. §5.3의 완화 효과(2026-08-08 실행 기준):

| 허용치 | 스타일 축 통과 문서 |
|---|---|
| 0건 (현행) | 45/56 |
| 1건 | 49/56 (+4) |
| 2건 | 52/56 (+7) |
| 3건 | 54/56 (+9) |
| 10건 | 56/56 |

대가: 허용치 3건이면 스타일 축은 96%가 통과해 **사실상 팩트 축만 남는 게이트**가 된다(AND 통과율은 팩트 유실 14건이 지배). 반대로 0건 유지는 §4.5의 추출 아티팩트 문서(060·063·064)를 영구 실패로 고정한다.

### 선택 4 — 코퍼스 구성을 고정할 것인가

| 안 | 대가 |
|---|---|
| 현행 유지 (`MIN_DOCUMENTS=20`, 상한·구성 무제약) | 통과율이 코퍼스 구성으로 움직인다. 실측: 25→36건 편입만으로 0.51→0.446 (`2026-08-08-golden-baseline-56.md`). **합격선이 있어도 분모를 바꾸면 무력화된다** |
| 56건·합성20/실수집36 고정 | 코퍼스 개선(아티팩트 문서 교체)이 게이트 변경 절차를 요구하게 됨 |
| 합성·실수집 **분리 합격선** | §4.3·§5.3이 두 집단의 분포가 다름을 보인다(2026-08-08 실행에서 합성 스타일 위반 0/20, 실수집 11/36). 기준이 둘로 늘고, "실수집이라 느슨하다"는 `test_schema.py` 서문의 경계와 충돌 |
| 아티팩트 문서(063·064·060) 제외 | 세 차례 권고됐음. 제외 시 통과율 상승분은 실력이 아니라 노이즈 제거 — **제외를 합격선 확정 전에 하면 합격선이 그만큼 높아지고, 후에 하면 게이트가 갑자기 느슨해진다.** 순서가 결과를 바꾼다 |

### 선택 5 — 길이 조건부 합격선

§5.4가 2,000자 경계의 절벽을 보인다(91% → 7%). master-plan §3.3은 이미 "파일럿 안내의 2,000자 내외 권장"을 이 사유로 유지하고 있다.

| 안 | 대가 |
|---|---|
| 단일 합격선 | 실수집 장문 15건이 게이트를 지배. 코퍼스 길이 분포가 합격 여부를 결정 |
| 길이 구간별 합격선 | 제품이 4,000자까지 받는데 게이트는 구간별로 봐준다 — **사용자가 겪는 품질과 게이트가 어긋난다** |
| 게이트 대상 길이를 2,000자로 제한 | 2,000~4,000자 구간이 무검증 상태가 됨. 현재 코퍼스의 27%(15/56) |

### 선택 6 — judge 절대 점수

| 안 | 대가 |
|---|---|
| 현행 유지 (평균 ≥4.0, 바닥 ≤2 0건) | 이해 용이성 축은 관측 전 구간 4.77↑라 구속력 없음. 충실성 여유는 0.35~0.89 |
| 평균 상향(예: 4.5) | 2026-08-08 anthropic 4.66은 통과, openai 4.70도 통과, 부분집합 4.35·4.60은 실패. **채점 모델을 고정하지 않으면 상향분이 잡음에 먹힌다**(§6.5) |
| 평균 폐기, 분포 기준으로 전환(예: 4점 이상 문서 ≥95%) | 2026-08-08 anthropic 기준 55/56 = 98.2%. 평균의 희석 문제(§6.1)를 구조적으로 피함. 기준을 새로 만들어야 함 |
| 바닥 기준 강화(≤3 0건) | 관측상 3점 문서가 0건이라 지금은 무변화. 향후 회귀에 민감해짐 |

**어느 안을 고르든 선행 조건:** judge 모델 고정 수단(§6.5)과 통과 시 수치 기록(§2)이 없으면 **합격선을 정해도 그 수치가 지켜졌는지 축적할 수 없다.**

## 9. 이 문서를 근거로 판단할 사람에게

1. **§9-A의 "합격 수치가 없다"는 기술을 먼저 정정해야 한다.** 통과율 0.90·judge 평균 4.0·바닥 2·커버리지 0.90은 존재하고 강제된다. 진짜 공백은 **축별 허용치·채점자 고정·코퍼스 고정·통과 시 기록** 넷이다.
2. **현재 성능을 합격선으로 옮기지 말 것.** §4는 코퍼스 난도이고 §5·§6은 2026-08-08의 한 실행이다. 특히 2026-08-08 두 실행은 **현행 통과율 기준(0.90)을 둘 다 통과하지 못한다**(anthropic 0.643, openai 0.446). 이 값들을 기준선으로 삼으면 게이트가 현재 실패 상태를 합격으로 승인한다.
3. **수치를 정하기 전에 계측기부터 고쳐야 하는 항목이 있다.** judge 모델 고정과 통과 시 집계 기록이 없으면, 정한 수치가 지켜지는지 확인할 방법이 없다.
4. **Kotlin 전환 맥락에서의 함의:** STY-03·STY-04는 `[기능]` 항목이라 Python 동일성이 요구사항이 아니다. 다만 위 수치들이 확정되기 전에는 Kotlin 쪽 판정도 동일하게 불가능하며, `tests/golden`은 Python 전용 하네스라 **Kotlin이 같은 판정을 받으려면 하네스를 어느 런타임에 붙일지도 함께 정해야 한다**(이 문서 범위 밖).
