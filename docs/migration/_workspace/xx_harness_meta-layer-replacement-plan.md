# 메타 층 교체 계획 — 열거를 네이티브 도구로 갈아탄다

**작성:** 2026-08-22 (리더) · **사용자 결정:** 메타 층 **동결** + 교체 계획만 작성, 구현은 별건
**`{scope}`:** `harness` (`{phase}` = `xx`) · **선행 회차:** `xx_harness` · `xx_harness-fixes`

> **이 문서는 계획이다. 여기에 적힌 것을 이번 세션에서 구현하지 않는다.**
> 구현 자체가 또 한 회차가 되는 것이 이 계획이 피하려는 것이다.

---

## 1. 왜 — 사용자 지적 두 개가 진단을 뒤집었다

> "토큰 절약을 위해 불필요한 작업과 문서, 코드 등을 정리하려고 했는데 계속 이 작업으로 하루를 써야 해?"
> "**Kotlin 작업인데 pytest 문제로 계속 반복적인 실패를 한다면 python 을 재검토해.**"

둘째가 정확했다. 실측하면 구조가 뒤집혀 있다.

| | 규모 |
|---|---|
| **Python 메타 가드 층** (Kotlin 을 텍스트로 훑어 판정) | **6,036줄** / 5파일 |
| 그중 Kotlin 소스·리포트를 파싱하는 자리 | 26곳 (`rglob('*.kt')` · `testcase@classname` · Gradle XML) |
| 제품 Kotlin 코드 | 15,375줄 |

**폐기 대상 언어로 쓴 6천 줄이 목표 언어를 문자열로 훑어 판정한다.**

### 이번 두 회차의 반복 실패는 전부 그 층에서 났다

| 실패 | 실제 기제 | 제품 결함인가 |
|---|---|---|
| CI `quality` 잡 전체 도달 0 | Python 가드 파일의 **E501** 2건 | 아니다 |
| 「pytest 돌렸다 ⇒ ruff 돌았다」가 거짓 | **pytest 수집 의미론**(표적 실행·`-k`·`-x`) | 아니다 |
| 커밋 전 측정을 트리 건강으로 보고 (3회) | Markdown 에 **git SHA 를 손으로 적는** 부기 | 아니다 |
| 라쳇·바닥·개수·스냅샷의 우회 연쇄 (5회) | **열거를 열거로 지키는** 구조 | 아니다 |

**제품 결함 0건.** 유일하게 제품에 닿은 위험(CI 꺼짐)조차 **가드 층의 lint 위반이 원인**이었다.

### 그리고 각 관심사에 네이티브 답이 이미 있다

| 지금 (Python 열거) | 네이티브 답 | 상태 |
|---|---|---|
| 테스트 클래스가 조용히 사라지지 않게 — `TEST_CLASSES` + `TEST_CLASS_COUNT` + `MIN_TEST_CLASSES` + `FLOOR_TEST_CLASSES` + `MIN_TESTS_IN_FLOOR_CLASS` + `MIN_FLOOR_CLASSES` + 정체성 스냅샷 (**7개 선언 · 4층**) | **pitest 변이 테스트** — 「이 가드를 변이시켰을 때 죽이는 테스트가 어딘가에 있는가」를 직접 묻는다. 어느 클래스가 그것을 담는지 **열거할 필요가 없다** | 백로그 **B-19 에 이미 설계돼 있다.** `SKILL.md` 규칙 7 이 스스로 *"진짜 답은 변이 테스트"* 라고 **3번** 적었다 |
| lint 사슬이 실제로 도는가 | **Gradle `check` 태스크 그래프** | `ktlint`·`detekt` 가 `build.gradle.kts` 에 **이미 배선돼 있다** |
| 커밋이 리뷰를 받았는가 (`test_review_coverage_reach.py` + 원장 표 2개) | **GitHub branch protection + required PR review** | 플랫폼 기본 기능 |

마지막 줄이 가장 아프다 — **「커밋이 리뷰를 받았는지 검사하는 Python 테스트」를 만들었다.** GitHub 가 기본 제공하는 것을 Markdown 표 파싱으로 재구현한 것이고, 그것이 우회 연쇄의 진원지였다(F-1·F-2·F-11). `CLAUDE.md` 의 **「바퀴를 매번 새로 만들지 않는다」** 를 정면으로 위반했다.

## 2. 층을 갈라 판정한다 — 전면 리셋이 아니다

| 층 | 판정 | 사유 |
|---|---|---|
| **제품 불변식 가드** — 마스킹 선행 · 소유권 은닉 404 · AEAD round-trip/변조 거부 · `no-store` · 평문 미저장. Kotlin 테스트 + `migration-safety-gate` | **유지** | 깨지면 **사용자 데이터가 나간다.** 값이 실증됐고, 열거 병리가 없다 |
| **메타 층** — 가드를 지키는 가드 6,036줄 | **동결 → 교체** | 5회 연속 「고치면 옆이 열림」. 각 관심사에 네이티브 답이 있다 |
| **문서·원장** | 유지 + 아카이브 | 이미 59% 줄였다(3,123 → 1,276) |

**재작성이 아니라 교체다.** 같은 언어·같은 열거 기제로 다시 지으면 같은 나선이다. **기제**를 바꿔야 한다.

## 3. 동결 — 지금 하지 않는 것

- **F-3**(계획 §5 마지막 불릿의 두 키 중 어느 것이든 삭제 가능) — 장부에 남기고 닫지 않는다.
- **pytest 사슬의 표적 실행 우회** — `conftest.py` 의 `pytest_sessionfinish` 이관을 착수했다가 **되돌렸다**(위임 중단 + `git checkout`). 아이디어는 §4 후보 R-4 로 남는다.
- 그 밖 메타 층 지적 전건.

**동결의 근거:** 메타 층의 구멍은 **사용자 데이터가 아니라 리더의 부기를 위협한다.** 제품 불변식은 다른 층(Kotlin 테스트)이 지고 있다.

## 4. 교체 후보 (별건 · 짧게)

| # | 무엇 | 없어지는 것 | 규모 |
|---|---|---|---|
| **R-1** | `pitest` 도입 (B-19 설계 그대로) | `TEST_CLASSES` 계열 **7개 선언 · 4층 전부**, `tests/test_kotlin_class_snapshot_reach.py` 통째 | Gradle 플러그인 + 임계값 설정 |

**예상 결과:** Python 메타 가드 **6,036줄 → 수백 줄**(설정 + CI 배선). 이번 두 회차가 만든 우회 연쇄가 **구조적으로 소멸**한다.

## 5. 착수 조건과 순서

1. **제품 Phase 4 C6 완료 후**에 착수한다. 이 계획의 구현이 또 한 회차가 되는 것이 최대 위험이므로 제품 뒤에 둔다.
2. 순서는 **R-2 → R-1 → R-3 → R-4**. R-2 가 가장 많이 지우고 위험이 가장 낮다(코드 삭제 + 플랫폼 설정).
3. 각 R 은 **삭제가 본체**다. 새 장치를 세우는 것이 아니라 **네이티브가 이미 하는 일을 중복으로 하던 코드를 지우는 것**이다. 그래서 음성 대조의 형태도 다르다 — 「지운 뒤에도 그 위험이 여전히 잡히는가」를 확인한다(네이티브 쪽에서).
4. **R-1 착수 전 확인:** `pitest` 가 Kotlin + JUnit 5 + 이 저장소의 Gradle 버전에서 실제로 도는지. 안 되면 R-1 을 보류하고 열거 층을 **그대로 동결 유지**한다(되살려 고치지 않는다).

## 6. 이 계획이 스스로 지키는 규율

- **범위 대조:** 위 표의 「없어지는 것」은 전부 **실측된 파일·줄 수**다. 「전부」·「모든」을 쓴 자리는 §2 의 층 구분 하나뿐이고 그것은 판정이 아니라 분류다.
- **강제자:** 이 계획에는 **강제자가 없다.** 동결을 기계로 재는 장치는 0개이고, 지키는 것은 리더의 규율이다. 이 사실을 지우지 마라.
- **미해결 그대로 남는 것:** F-3 · pytest 사슬 표적 실행 우회 · 반복 실패 (a) 커밋 전 측정 보고 · (c) 리더의 독립성 누출. 넷 다 재는 장치가 0이고, (a) 는 R-2 가 소멸시키고 (c) 는 어느 R 도 고치지 않는다.
