### 2.2 무엇을 바꿨나

`OWNERSHIP-403` 을 `multiline=True` 로 옮기고 `opener` 를 줬다. 호출 이름 목록은
`_403_CALL` 로 뽑아 **자리 패턴과 opener 가 같은 조각을 쓰게** 했다 — 목록을 두 벌 적으면
사본이 갈리고, 갈린 사본은 늘 조용한 쪽이었다(게이트 23 ⓐ 가 겪은 형태).

**대가가 없다는 근거:** 논리 줄은 `_advance` 가 **주석을 뺀 코드만** 잇고, 한 줄로 끝나는

즉 이 전환은 저장소의 실제 트리에서 후보를 하나도 새로 만들지 않았고 하나도 잃지 않았다.

### 2.4 `xfail(strict)` 2종 — **은폐형 판정을 받아들여 전환했다**

D1(계산값)·D2(응답 자리 밖 인자)를 `xfail(strict=True)` 에서 **형태 목록의
`blocks=False` 항목**으로 옮겼다.

| 축 | `xfail(strict)` 판 | **전환 후** |
|---|---|---|
| 알려진 실패를 성공 종료로 바꾸는가 | **그렇다** (codex B-3 의 규정) | **아니다** — 통과하는 단언일 뿐이다 |
| 해소되면 시끄러운가 | 그렇다(XPASS) | **그렇다** — S2 로 실측 |
| 선언을 떼면 무엇이 깨지는가 | **아무것도** | **아무것도** — 바뀌지 않았다(S3 로 실측) |

- **S2**(자리 목록에 `add` 를 더해 D2 가 잡히게 만듦) → **red**. 「해소되면 시끄럽다」가
  전환 후에도 성립한다.
- **S3**(D1·D2 항목을 표에서 삭제) → **exit 0, 아무것도 안 깨진다.** 이 잔여는 xfail 판과
  같으며 이번 변경이 없앤 것은 「실패를 성공으로 바꾸는」 성질 하나다. **더 낫다고 적지
  않는다 — 정확히 그만큼만 나아졌다.**
- **D1 에는 보상 통제가 실재하고 그것은 결속돼 있다.** 계산의 출처가 `= 403` 리터럴이면
  그 선언 줄이 BLOCK 으로 남고 N14~N16 이 `blocks=True` 로 고정한다. D1 은 「전면 미탐」이
  아니라 「선언 줄 경유 탐지」다.
- **S1**(`multiline=True` 되돌리기) → **5 failed** — 형태 4건 + 기제 테스트 1건.

### 2.5 판단이 갈릴 수 있는 자리 — `return` 뒤 줄바꿈을 닫지 않았다

privacy-gate S-1 표의 두 형태 중 **하나는 닫고 하나는 닫지 않았다.** 근거를 적는다.

- `.status(` 계열은 **괄호가 열려 있어** 논리 줄 결합기가 올바로 잇는다 → 닫혔다.
- `return` 뒤 줄바꿈은 괄호가 열려 있지 않아 **두 개의 논리 줄**이 된다. 이것을 닫으려면
  결합기가 값 산출 키워드 뒤에서도 이어 붙여야 하는데, 그 변경은 `LOG-BODY`·
  `LLM-RAW-INPUT`·`PLAINTEXT-PERSIST` 를 포함한 **모든 multiline 규칙의 판정 범위**를
  바꾼다. 이번 게이트에서 그 위험을 지지 않았다.
- **그리고 그 형태는 이 저장소가 쓰는 어느 언어에서도 403 자리가 아니다.** Kotlin·Python 은
  `return` 에서 문장이 끝나 Unit/None 을 돌려주고 다음 줄은 죽은 식이며, TypeScript 는
  ASI 로 같다. 실제 자리가 되는 언어는 **Java 하나**이고 저장소의 `.java` 는 **0개**다
  (`git ls-files '*.java'` — 실측).
- **그 전제를 산문이 아니라 트리거로 지킨다.** `test_java_소스가_들어오면_return_
  줄바꿈_판정을_다시_한다` 가 `.java` 유입 시 빨개진다 — **S4 로 실측**(더미 `.java` 를
  `git add` → red, 제거 후 green).

**리더가 다르게 판단할 수 있는 자리다.** 옛 판이 이 형태를 BLOCK 한 것은 사실이고,
「옛 판 대비 손실 0」을 엄격히 요구하면 결합기를 고쳐야 한다. 이 레인은 **언어 의미론상
자리가 아니라는 근거 + 유입 트리거**로 대신했다.

### 2.6 그대로 남긴 것

게이트 25 가 남긴 리더 확인 요청(`@ApiResponse(responseCode = "403")` 을 통과로 바꿀
것인가)은 **이 배치에서 손대지 않았다.** 판정이 오지 않았고, 지금은 탐지를 잃지 않는
쪽(BLOCK 유지)이다.

## 3. 조치 3 — 원시 제어문자 전수 탐지 (`a1d6005`)

### 3.1 설계 (지시 그대로 + 교차 §10-① 폐쇄)

| 요구 | 구현 |
|---|---|
| 자리 = `quality` 잡의 「경로 명시」 계열 | `tests/test_raw_control_chars.py` + `ci.yml` quality 잡 스텝. 개인정보 스캐너에 넣지 않았다 — 축이 다르다 |
| 루트 목록이 아니라 전수 | `git ls-files -z` (실측 727 추적) |
| 바이너리 제외를 git 에 위임 | `git ls-files --eol -z` 의 `i/-text` |
| 면제 목록·억제 표기 없음 | **0개** |
| 훑은 수 0 이면 실패 | `test_훑은_텍스트_파일이_0건이_아니다` |
| 판정 기준 = 원시 제어문자 보유 | C0 전부(TAB·LF·CR 제외) + DEL(0x7F) |
| git 바이너리 상태 별도 표시 | 실패 메시지에 「git 이 이미 바이너리로 잡아 diff 가 보이지 않는다」 + 첫 8000바이트 안 NUL 여부 |
| `.gitattributes` 강제 | **채택하지 않음**(표현형 — 바이트가 남아 다른 도구는 계속 속는다) |

**교차 §10-① 이 지적한 함정을 성질로 닫았다.** 「git 이 바이너리라 부름」을 **제외 사유로**
쓰면 `AesGcmContentCipherTest.kt` 처럼 **NUL 이 앞 8000바이트에 있는 텍스트 파일**이 통째로
빠진다 — 정확히 이번 사고의 본체다. 그래서 두 단으로 판정한다.

```
진짜 바이너리 = (git 이 -text 라 부름) AND (바이트 전체가 UTF-8 로 디코드되지 않음)
```

**실측이 저장소를 정확히 가른다** — 진짜 바이너리 8건(jar·zip 2·docx 4·hwpx)은 UTF-8 디코드에
**전건 실패**하고, 제어문자를 실수로 품은 텍스트는 **전건 성공**한다. 즉 git 이 바이너리라
부르는 것은 **제외 사유가 아니라 가중 사유**이고, 그 상태를 실패 메시지가 따로 표시한다.

### 3.5 자기 정정 — **이 문서가 같은 결함을 다시 저질렀다 (네 번째 사례)**

숨기지 않고 적는다. 이 문서 초판(24,550바이트)에 **원시 `0x7f` 두 개**가 있었다.
자리는 §3.3 표와 §6 표의 *"JSON 은 (이스케이프 표기) 가 규격이라 무손실"* 문장이다 —
**「이스케이프를 쓰라」고 적으면서 그 자리에 이스케이프 대신 그 글자를 넣었다.**

| 항목 | 값 |
|---|---|
| 발견 방법 | **이 회차가 만든 장치로 자기 검사** — 문서 작성 직후 전 바이트를 훑었다 |
| 초판 상태 | 24,550바이트 · `0x7f` 2개(오프셋 18304 · 23933, 280행 · 373행) |
| git 이 바이너리로 잡았는가 | **아니다** — `0x7f` 로는 git 이 바이너리 판정을 하지 않는다. 교차 §10-① 이 「git 의 분류를 판정 기준으로 삼으면 안 된다」고 적은 바로 그 자리다 |
| 정정 | 원시 바이트 → 유니코드 이스케이프 표기. 24,560바이트. sha256 `1e6a3da7…` → `66092506…` |
| 정정 방식 | 같은 파일 안 바이트 치환 + 재검사. `cp` 미사용(규칙 5) |

**이것이 §3 의 논거를 다시 확인한다.** 교차 §12.1 이 센 아홉 번째에 이어 **열 번째**이고,
**네 번 모두 「제어문자에 관해 쓰는 도중」** 일어났다. 앞의 세 번은 사람의 사후 검사로만
발견됐으나 **이번에는 이 회차가 세운 장치가 잡았다** — 장치의 첫 실전 적중이 자기 자신의
산출물이었다.

### 3.6 이 커밋 이후의 상태 — **`uv run pytest` 는 빨갛다**

숨기지 않고 적는다. `a1d6005` 이후 전체 스위트는 위 4건이 고쳐질 때까지 **1 failed** 다.

- 이것은 **면제 목록을 두지 말라**는 지시의 직접 귀결이다. baseline·억제 표기를 넣으면
  초록이 되지만 그 순간 이 장치는 은폐형이 되고 규칙 4 ⑵ 에 걸린다.
- 4건 전부 **한 파일당 한 번의 바이트 치환**으로 닫힌다. 닫히면 `quality` 잡이 초록이 된다.
