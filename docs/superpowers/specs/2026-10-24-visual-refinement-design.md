# 색상 역할과 시각적 위계 개선 설계

## 목표

현재 파란색과 노란색으로 형성된 브랜드 정체성을 유지하면서 색상의 의미와 화면의 시각적 위계를 일관되게 정리한다. 구조, 문구, 기능은 바꾸지 않고 공통 색상 토큰과 공통 컴포넌트를 먼저 개선한 뒤 랜딩, 가이드, 예시, 검수 화면에 적용한다. 사용자가 주요 행동, 선택 상태, 경고, 완료 상태를 색과 강조 수준만으로도 일관되게 예상할 수 있어야 한다.

## 범위

### 포함

- 라이트·다크 모드의 공통 색상 역할과 표면, 테두리, 상태 토큰 정비
- 버튼, 링크, 입력, 카드, 배지, 안내 블록, 아코디언, 메뉴의 공통 스타일
- 랜딩, 가이드, 예시, 검수 화면 및 공통 헤더에 공통 규칙 적용
- hover, active, disabled, focus-visible 상태와 키보드 사용성
- 두 테마의 텍스트·컨트롤 대비와 지정 화면 폭에서의 회귀 검증

### 제외

- 화면 구조, 정보 순서, 문구, 기능, 라우팅, 입력 및 저장 동작 변경
- 로고와 브랜드 색 계열의 교체, 새로운 일러스트 제작
- 백엔드와 API 계약 변경
- 관리자 화면의 별도 재설계
- 새로운 검증 하네스 또는 Python 구현

## 현재 문제

- 노란색이 브랜드 배지뿐 아니라 활성 메뉴와 예시 카드 호버에도 사용되어 브랜드 강조와 조작 상태의 의미가 섞인다.
- 여러 일반 섹션 카드에 같은 그림자가 적용되어 핵심 예시와 요금처럼 실제로 주목해야 할 영역의 상대적 강조가 약하다.
- 가이드의 보조 설명과 순서 목록이 테두리와 카드 배경을 함께 사용해 내용의 계층보다 컨테이너가 먼저 눈에 들어온다.
- 경고 블록이 배경뿐 아니라 본문까지 경고색으로 표시한다. 특히 다크 모드의 어두운 황토색 배경과 노란 계열 전경이 만나면 경고 상자가 무겁고 눈에 부담스럽게 보인다.
- 검수 도구 모음처럼 여러 행동이 나란히 놓인 영역은 주행동과 보조 행동의 스타일 차이를 공통 규칙으로 설명하기 어렵다.
- 랜딩 일러스트 주변의 노란색 번짐과 곳곳의 노란색 전경은 다크 모드에서 브랜드 포인트보다 넓은 면적을 차지한다.
- 일반 카드, 강조 카드, 입력, 팝오버가 비슷한 명도와 테두리를 공유하면 다크 모드에서 표면과 조작 영역의 구분이 약해질 수 있다.

## 선택한 접근법

색상 의미를 먼저 고정하고 표면과 컴포넌트가 그 의미를 소비하도록 한다. 개별 화면에서 임의의 색이나 강조를 추가하지 않으며, 공통 토큰과 공통 컴포넌트로 해결할 수 있는 변경을 페이지별 예외보다 우선한다. 페이지별 작업은 공통 규칙의 적용과 불가피한 조합 관계 조정에 한정한다.

브랜드 노란색을 제거하지 않되 사용 목적을 좁히고, 조작과 선택은 파란색으로 통일한다. 모든 콘텐츠를 카드와 그림자로 강조하는 대신 배경→표면→강조 표면의 3단계를 사용해 주목 순서를 만든다.

## 색상 역할과 토큰 설계

### 색상 역할

| 색 계열 | 허용하는 의미와 대표 사용처 | 사용하지 않을 곳 |
|---|---|---|
| 파란색 | 주요 버튼, 링크, 키보드 포커스, 선택·활성 상태 | 일반 본문의 장식, 브랜드 일러스트의 무차별적 채색 |
| 노란색 | 브랜드 배지, 물료 체험 혜택, 일러스트의 제한적인 포인트 | 활성 메뉴, 일반 카드 호버, 경고, 긴 본문 |
| 주황색 | 주의와 경고의 아이콘·제목·보조 강조 | 브랜드 혜택, 일반 선택 상태, 경고 본문 전체 |
| 초록색 | 저장 완료처럼 긍정적으로 완료된 상태 | 일반 정보, 진행 중 상태, 주요 행동 유도 |

기존 오류의 빨간색과 일반 정보의 파란색 의미는 유지한다. 초록색 완료와 파란색 정보를 서로 대체하지 않으며, 경고와 브랜드 노란색은 별도 토큰과 별도 명도 체계를 유지한다. 색상만으로 의미를 전달하지 않고 현재의 아이콘, 제목, 굵기, 밑줄 등 비색상 단서를 유지한다.

### 공통 토큰 구조

- 중립 토큰은 페이지 배경, 일반 표면, 강조 표면, 기본 전경, 보조 전경, 구분선, 입력 경계로 역할을 나눈다.
- 파란색 토큰은 기본·hover·active 주행동과 옅은 선택 표면, 링크, 포커스 링을 구분한다. 두 테마에서 같은 의미의 토큰을 사용하되 실제 명도는 배경 대비에 맞춰 조정한다.
- 노란색 토큰은 브랜드 전경, 브랜드 배경, 브랜드 포인트로 한정한다. 메뉴 활성화와 일반 상호작용 토큰이 브랜드 토큰을 참조하지 않게 한다.
- 경고 토큰은 경고 전경과 저채도 경고 표면을 분리한다. 경고 블록의 일반 본문은 기본 전경 토큰을 사용한다.
- 완료 토큰은 완료 전경과 완료 표면을 분리하고 긍정적 완료 메시지에만 적용한다.
- 대화상자와 팝오버는 별도의 상위 표면과 그림자를 사용한다. 일반 카드는 이 그림자를 공유하지 않는다.
- 토큰 이름은 색상값이 아니라 용도를 기준으로 유지해 테마 전환 시 컴포넌트가 달라지지 않게 한다.

## 표면과 강조 기준

### 배경→표면→강조 표면

1. **배경:** 페이지 전체와 카드 사이의 기본 바탕이다. 콘텐츠 묶음 자체를 강조하지 않는다.
2. **표면:** 일반 카드, 헤더, 입력, 팝오버의 기본 바탕이다. 배경과 구분되되 과도한 채도나 그림자를 쓰지 않는다.
3. **강조 표면:** 선택된 항목, 펼친 가이드 항목, 핵심 결과처럼 현재 주목할 상태에만 사용한다. 상호작용 강조는 옅은 파란색, 브랜드 혜택 강조는 옅은 노란색으로 의미를 구분한다.

핵심 재작성 예시와 요금 영역만 테두리와 표면 대비로 뚜렷하게 강조한다. 설명성 섹션, 반복되는 목록, 부가 안내는 구분선과 여백을 우선하고 모두 같은 강도의 카드로 만들지 않는다. 카드 안에 또 다른 강조 카드를 중첩하지 않는다.

그림자는 대화상자와 팝오버처럼 다른 콘텐츠 위에 떠 있는 레이어에 우선 사용한다. 일반 콘텐츠 카드는 얇은 테두리와 표면 차이로 구분하고, 핵심 카드도 깊은 그림자보다 명확한 테두리와 여백으로 위계를 만든다.

## 공통 컴포넌트 변경

### 버튼과 링크

- 시각적으로 독립된 섹션이나 행동 묶음에는 파란색 채움 스타일의 주행동을 하나만 둔다. 나머지 행동은 중립적인 외곽선, 배경 없는 보조 버튼 또는 링크로 표현한다.
- 보조 버튼은 브랜드 노란색이나 경고 주황색을 사용하지 않는다. 기본 상태는 표면과 입력 경계를 사용하고 hover에서는 중립 강조 표면을 사용한다.
- 링크는 파란색과 기존 밑줄 규칙을 유지한다. 주요 버튼과 동등한 링크를 같은 묶음에 중복해 두지 않는다.
- 검수 도구 모음의 첫 번째 주행동만 파란색 채움으로 유지하고 나머지 행동은 동작과 순서를 바꾸지 않은 채 중립 스타일로 통일한다.

### 메뉴와 선택 상태

- 데스크톱과 모바일의 활성 메뉴는 노란색 대신 옅은 파란색 배경과 파란색 계열 전경을 사용한다.
- 활성 상태는 배경색 외에 현재의 글자 굵기 차이를 유지한다. 비활성 메뉴는 보조 전경색과 중립 hover를 사용한다.
- 선택 상태와 단순 hover를 구분한다. 선택 상태는 사용자가 항목을 떠나도 유지되고, hover는 포인터가 벗어나면 사라진다.

### 카드와 예시 링크

- `DocumentExampleCards`의 기본 상태는 일반 표면과 기본 테두리를 사용한다.
- hover에서는 노란색 배경을 제거하고 파란색 테두리와 옅은 파란색 배경을 적용한다. active에서는 hover보다 진한 파란색 테두리를 사용하고 옅은 파란색 배경은 유지한다.
- hover 때 테두리 두께를 바꿔 카드 크기나 주변 레이아웃이 움직이지 않게 한다. 제목, 요약, 화살표의 내용과 배치는 유지한다.
- focus-visible은 공통 파란색 포커스 링으로 표시하고 hover와 독립적으로 식별 가능하게 한다.

### 입력과 안내 블록

- 입력은 일반 표면을 유지하되 입력 경계를 카드 구분선보다 진하고 명확하게 한다. 오류 상태의 빨간 경계와 파란 포커스 링을 함께 식별할 수 있어야 한다.
- 경고 블록은 낮은 채도의 배경과 절제된 경고 테두리를 사용한다. 본문은 기본 전경색으로 읽고, 경고 아이콘과 제목에만 주황색을 사용한다. 제목이 없는 경고 블록에서는 아이콘에만 주황색을 적용한다.
- 완료 메시지는 초록색 아이콘·제목과 옅은 완료 표면을 사용하고 본문은 기본 전경색으로 유지한다.
- 경고와 완료 모두 현재의 메시지, 아이콘, 접근성 역할 및 노출 조건을 바꾸지 않는다.

### 가이드 아코디언

- 아코디언 묶음은 개별 카드의 반복보다 항목 사이 구분선을 중심으로 구성한다.
- 접힌 항목은 기본 표면을 유지하고, 펼친 항목만 옅은 파란색 강조 배경으로 현재 범위를 드러낸다.
- 요약 영역과 본문의 제목 계층, 기존 펼침 동작과 키보드 조작은 유지한다. 펼침 표시와 포커스 링은 배경 대비가 충분해야 한다.

## 페이지별 적용

### 랜딩

- 첫 화면의 주요 체험 링크를 해당 행동 묶음의 유일한 주행동으로 유지하고 이용 가이드 링크는 중립적인 보조 스타일로 둔다.
- 브랜드 배지와 물료 체험 혜택에는 노란색을 제한적으로 유지하되 설명 본문과 이용 조건은 기본·보조 전경색을 사용한다.
- 초안 검수 경고는 공통 경고 블록 규칙을 적용해 본문을 기본 전경색으로 바꾸고 주황색은 경고 아이콘에만 사용한다.
- 핵심 재작성 예시와 Start 요금 영역만 뚜렷한 핵심 카드로 유지한다. 서비스 적합 문서와 작업 흐름처럼 설명 중심인 영역은 그림자를 줄이고 표면·구분선·여백으로 정리한다.
- 재작성 후 결과는 브랜드 홍보가 아니라 핵심 결과이므로 넓은 노란색 배경 대신 파란색 계열 강조 표면을 우선한다. 바꾸기 전과 후의 구분은 현재 제목과 아이콘으로도 유지한다.
- 문서 예시 카드는 공통 파란색 hover 규칙을 적용하고, 예시 전체 보기 링크는 별도의 주요 버튼으로 승격하지 않는다.
- 일러스트의 노란색 포인트는 유지하되 주변 번짐의 면적과 불투명도를 줄여 텍스트와 카드보다 배경 장식이 앞서지 않게 한다.

### 가이드

- 페이지 본문과 목차는 기본 표면과 구분선 위주로 정리하고 연속된 안내를 모두 카드로 감싸지 않는다.
- 아코디언은 공통 구분선·펼침 배경 규칙을 적용하고, 펼치지 않은 항목에는 강조 배경을 쓰지 않는다.
- 본문 링크는 파란색과 밑줄을 유지한다. 경고 인용은 공통 경고 블록 규칙을 따라 본문을 기본 전경색으로 표시한다.
- 순서 목록은 읽기 흐름이 우선이도록 불필요한 중첩 테두리와 그림자를 제거하되 목록 구조와 번호는 유지한다.

### 예시

- 랜딩과 예시 화면이 같은 `DocumentExampleCards` 규칙을 사용하도록 한다.
- 카드 분류와 화살표의 파란색은 유지하고, 제목·요약은 각각 기본·보조 전경색을 사용한다.
- 핵심 예시 본문만 강조 표면을 사용하고 반복 카드와 부가 설명은 일반 표면으로 낮춰 예시 간 비교가 쉽게 한다.

### 검수

- 원문과 결과의 편집 구조, 도구 순서, 저장 및 재변환 동작은 그대로 유지한다.
- 원문 영역은 중립적인 구분을 유지하고 결과 편집 영역은 옅은 파란색 강조 표면으로 현재 작업 대상을 드러낸다. 노란색으로 검수 완료를 암시하지 않는다.
- 도구 모음에는 하나의 주행동만 파란색 채움을 적용하고 보조 행동은 중립 스타일로 통일한다.
- 저장 완료는 초록색 완료 규칙, 주의가 필요한 검수 안내는 주황색 경고 규칙을 적용한다. 편집 중이나 처리 중 상태를 완료색으로 표시하지 않는다.
- 입력과 편집 영역의 경계, 포커스, 비활성 상태는 공통 입력·버튼 규칙을 그대로 따른다.

## 라이트·다크 모드

- 두 테마 모두 배경, 일반 카드, 강조 표면의 명도 순서와 용도가 일관되어야 한다. 다크 모드에서는 배경보다 카드가 밝고, 상위 레이어는 일반 카드와 추가로 구분되어야 한다.
- 다크 모드 카드 테두리는 표면을 부드럽게 구분하는 수준으로 낮추되 사라지지 않게 한다. 입력 경계는 별도 토큰으로 더 진하게 유지한다.
- 다크 모드 파란색은 주요 버튼, 링크, 선택, 포커스에서 같은 상호작용 의미를 유지한다. 일부 화면에만 다른 파란색 계열을 쓰지 않는다.
- 노란색은 작은 브랜드 요소와 짧은 혜택 강조에 집중하고 긴 본문의 노란 전경과 넓은 노란 배경을 줄인다. 노란 전경이 필요한 곳은 대비를 확보하되 면적을 늘리는 방식으로 보정하지 않는다.
- 경고 표면은 기존의 짙은 황토색 상자보다 중립 표면에 가까운 저채도 배경으로 완화한다. 주황색 아이콘과 제목, 기본 전경 본문의 조합으로 경고성과 가독성을 함께 확보한다.
- 일러스트의 노란색 번짐은 다크 모드에서 더 좁고 약하게 조정한다. 라이트·다크 이미지 전환과 대체 텍스트 동작은 유지한다.
- 테마 전환 시 컴포넌트의 상태 의미가 바뀌거나 색이 사라져 선택·경고·완료를 구분할 수 없는 상태가 없어야 한다.

## 상호작용과 접근성

- hover, active, disabled, focus-visible은 각각 독립적인 상태로 정의하고 한 상태의 스타일을 다른 상태의 유일한 단서로 재사용하지 않는다.
- disabled는 중립적인 색과 낮아진 강조로 표시하되 현재의 비활성 동작과 커서 규칙을 유지한다. disabled를 hover나 active처럼 보이게 하지 않는다.
- focus-visible은 모든 링크, 버튼, 입력, 카드 링크, 아코디언에서 파란색 포커스 링으로 일관되게 보이게 한다. 배경이나 테두리 변경으로 링이 가려지지 않아야 한다.
- 일반 본문은 배경에 대해 4.5:1 이상, 큰 텍스트는 3:1 이상의 대비를 확보한다. 입력 경계, 버튼 외곽, 포커스 표시, 상태 아이콘 등 의미 있는 비텍스트 요소는 인접 색과 3:1 이상 구분한다.
- 보조 전경과 옅은 상태 배경도 실제 조합으로 대비를 측정한다. 대비 확보를 위해 브랜드색을 상태색으로 바꾸거나 모든 본문을 상태색으로 칠하지 않는다.
- 선택, 경고, 완료, 비활성 상태는 색과 함께 텍스트, 아이콘, 굵기, 테두리 또는 기존 접근성 의미 체계로 전달한다.
- 기존 키보드 초점 이동, Esc 동작, 본문 바로가기 링크, 최소 터치 대상, 모바일 메뉴 동작을 변경하지 않는다.
- 색과 테두리 전환은 부드럽게 하되 움직임을 새로 추가하지 않는다. `prefers-reduced-motion`에서 현재의 전환·애니메이션 축소 규칙을 유지한다.

## 검증

- `320px`, `375px`, `768px`, `1024px`, `1440px` 폭에서 랜딩, 가이드, 예시, 검수 화면과 공통 데스크톱·모바일 메뉴를 확인한다.
- 각 화면을 라이트·다크 모드로 확인하고 배경·표면·강조 표면, 카드와 입력 경계, 경고·완료 블록의 구분을 점검한다.
- 주요 버튼, 보조 버튼, 링크, 예시 카드, 활성 메뉴, 입력, 아코디언의 기본·hover·active·disabled·focus-visible 상태를 점검한다. 해당 상태가 없는 요소는 있는 상태만 확인한다.
- 키보드만으로 주요 메뉴, 계정 메뉴, 예시 카드, 가이드 아코디언, 검수 도구를 이동하고 포커스가 보이며 기존 초점 복귀와 Esc 동작이 유지되는지 확인한다.
- 두 테마에서 실제 텍스트·배경 조합과 컨트롤 경계의 대비가 위 기준을 충족하는지 측정한다. 특히 경고 본문, 노란 브랜드 전경, 다크 모드 보조 텍스트와 입력 경계를 확인한다.
- 320px와 375px에서 hover 스타일 변경으로 인한 크기 변화, 카드 흔들림, 텍스트 잘림, 가로 넘침이 없어야 한다. 768px 이상에서도 주행동과 보조 행동의 위계가 유지되어야 한다.
- reduced motion을 켜고 테마 전환과 상호작용 상태 변경 시 불필요한 움직임이 없는지 확인한다.
- 기존 Vitest 및 Playwright 구조 안에서 필요한 시각·상호작용 회귀 검증을 갱신한다. 완료 전 `npm run check`, `npm run test -- --run`, `npm run build`를 실행한다.

## 범위 밖 사항

- 페이지별 레이아웃 재구성, 컴포넌트 추가·삭제, 콘텐츠 재작성은 하지 않는다.
- 새 브랜드 색 도입, 로고 변경, 마케팅 일러스트 교체는 하지 않는다.
- 버튼의 기능이나 우선순위를 제품 논의 없이 바꾸지 않는다. 시각적 주행동 지정은 현재 행동 구조 안에서 이루어진다.
- 관리자 전용 색 체계와 화면은 이번 개선의 검증 범위에 포함하지 않는다. 공통 토큰 변경으로 영향을 받는 스타일이 있는지는 회귀 검토에서 확인하되 별도 재설계는 후속 작업으로 분리한다.
- 디자인 작업을 이유로 새로운 런타임, 검증 하네스, API 또는 데이터 형식을 추가하지 않는다.
