# 반응형 텍스트와 핵심 화면 UI 개선 설계

## 목표

모바일과 PC의 다양한 화면 폭에서 사용자 핵심 화면의 텍스트가 잘리거나 넘치지 않고 자연스럽게 읽히도록 한다. 공통 타이포그래피 규칙을 정비해 화면 간 일관성을 유지하면서, 각 화면에는 필요한 레이아웃 보정만 적용한다.

## 범위

### 포함

- 공통 제목·본문·보조 문구·버튼의 반응형 표시 규칙
- 랜딩, 문서 변환, 검수, 기록, 사용량, 가이드, 예시 화면
- 공통 헤더와 푸터, 페이지 제목 및 관련 공통 컴포넌트
- 긴 문서 제목, 파일명, 이메일과 브라우저 확대 상황
- 기존 단위 테스트와 E2E 테스트 체계 안에서의 회귀 검증

### 제외

- 관리자 화면
- 백엔드와 API 계약 변경
- 색상, 브랜딩, 기능, 문서 내용 변경
- 새로운 검증 하네스 또는 Python 구현

## 선택한 접근법

공통 반응형 규칙과 각 핵심 화면의 보정을 함께 적용한다. 전역 CSS만으로 모든 화면을 통제하면 기존 컴포넌트에 의도하지 않은 영향을 줄 수 있고, 화면 단위로만 수정하면 타이포그래피 규칙이 다시 분산된다. 공통 규칙은 재사용 가능한 스타일로 두고 레이아웃 특수성은 해당 컴포넌트에서 처리한다.

## 공통 타이포그래피

- 페이지 제목, 섹션 제목, 본문, 보조 문구에 재사용 가능한 반응형 스타일을 정의한다.
- 좁은 화면에서 가독성을 해치는 과도한 축소를 피하고, 넓은 화면에서는 제목과 본문 크기가 자연스럽게 조정되도록 한다.
- 제목에는 균형 잡힌 줄바꿈을 적용한다.
- 한글 본문은 어절 중간의 불필요한 분리를 줄인다. 긴 URL, 식별자, 파일명처럼 일반 줄바꿈만으로 넘칠 수 있는 문자열에는 제한적인 예외 규칙을 적용한다.
- 본문과 보조 문구에는 현재 색상 토큰과 충분한 줄 간격을 유지한다.

## 화면과 컴포넌트 동작

- 공통 페이지 제목 컴포넌트와 개별 핵심 화면의 제목에 공통 규칙을 적용한다.
- 버튼과 링크는 최소 터치 높이를 유지하되, 문구가 길어지면 고정 높이나 무조건적인 한 줄 표시 때문에 잘리지 않도록 한다.
- 카드, 안내 배너, 폼 도구 모음은 좁은 폭에서 내용에 따라 세로로 쌓이거나 여러 줄로 배치한다.
- 표처럼 가로 공간이 필요한 콘텐츠는 기존의 국소적인 가로 스크롤 방식을 유지한다. 페이지 전체의 가로 스크롤은 허용하지 않는다.
- 헤더와 푸터의 긴 문구는 현재 메뉴 구조를 유지하면서 사용 가능한 폭 안에 표시한다.
- 검수와 변환의 편집 영역은 입력 동작과 저장 상태를 바꾸지 않고 텍스트 표시와 컨트롤 배치만 조정한다.

## 오류와 특수 입력 처리

긴 제목, 파일명, 이메일, 연속된 영숫자 문자열이 레이아웃을 밀어 내지 않아야 한다. 서버 오류와 개인정보 경고 같은 기존 메시지는 문구와 노출 조건을 그대로 유지하면서 여러 줄로 자연스럽게 표시한다. 반응형 표시 문제를 해결하기 위해 오류를 숨기거나 임의로 생략하지 않는다.

## 검증

- `320px`, `375px`, `768px`, `1024px`, `1440px` 폭에서 핵심 화면을 확인한다.
- 페이지 전체의 의도하지 않은 가로 스크롤, 텍스트 잘림, 컨트롤 겹침이 없어야 한다.
- 브라우저 확대와 긴 제목·파일명·이메일에서도 내용과 조작 수단이 유지되어야 한다.
- 기존 Vitest 및 Playwright 구조 안에 필요한 회귀 검증을 추가하거나 갱신한다.
- 완료 전 `npm run check`, `npm run test -- --run`, `npm run build`를 실행한다.
