# 유료 출시 준비

## 범위와 완료 기준

2026-10-11 사용자 승인 계획에 따라 거래 증빙 분리 보존과 회원 탈퇴, 카드 등록 콜백 재로그인 복구, 환불 심사 기록, Supabase 외부 백업을 구현한다. Kotlin/Spring Boot와 React/TypeScript만 제품 런타임으로 사용한다. 실제 유료 모델 호출, 신규 유료 서비스 구매, 고객 청구를 구현 검증에 포함하지 않는다.

기준 커밋은 `34622c1a`다. 변경 전 backend build(3,690개), frontend check/test(1,016개)/build, Compose 검증을 통과했다. 변경 후에는 이 결과를 재사용하지 않고 최종 코드에서 다시 검증한다. 구현·검증·독립 리뷰·수정은 최대 3회 순환한다.

## 출시 절차

1. 최종 코드의 backend build, frontend check/test/build, Compose 모델, 관리자 및 격리 Toss 테스트 E2E를 통과하고 릴리즈 커밋·이미지를 고정한다.
2. 운영 이미지·Flyway 버전·API/worker 설정을 기록한다. 운영 DB를 변경하기 전에 백업을 격리 DB에 복원해 신규 마이그레이션을 리허설한다.
3. 아래 차단 설정을 유지한 상태로 API와 worker, 프런트를 교체한다. CD 이미지 게시와 서버 배포 완료를 구분한다.
4. 공개 로그인·휴대폰 인증·카드 등록 콜백·관리자 권한·원격 백업 복원을 검증한다.
5. 빌링 계약·MID·라이브 키 쌍·공급자 웹훅, 최종 유료 고지가 확인된 후 승인된 작업공간·금액·환불 범위만 제한 실결제한다.
6. 실제 승인·50크레딧 지급, 부분/전체 환불과 회수, 카드 교체·갱신 중단, 거래 알림 전달, 탈퇴 후 보존 자료를 대조한다. 정상 이용 주기를 가속하지 않고 첫 갱신까지 감시한다.
7. 필수 항목 통과 후 일반 구매와 자동 갱신을 단계적으로 개방한다. 장애 시 구매·자동 청구를 끄고 라이브 데이터에 호환되는 수정 이미지를 배포한다.

```dotenv
EASYDOC_PAYMENT_PURCHASE_ENABLED=false
EASYDOC_PAYMENT_AUTO_CHARGE_ENABLED=false
EASYDOC_PAYMENT_ALLOWED_WORKSPACES=
EASYDOC_READING_LEVEL_MIDDLE_SCHOOL_ENABLED=false
EASYDOC_READING_LEVEL_EXTRA_EASY_ENABLED=false
EASYDOC_ACTION_GUIDE_ENABLED=false
EASYDOC_ACTION_GUIDE_WORKER_ENABLED=false
EASYDOC_ACTION_GUIDE_ANALYSIS_ENABLED=false
EASYDOC_ILLUSTRATION_SUGGESTIONS_ENABLED=false
EASYDOC_ILLUSTRATION_SUGGESTIONS_WORKER_ENABLED=false
```

중등 수준을 포함한 미검증 선택 기능은 실제 모델 품질 검증 전 개방하지 않는다. 읽기 수준 설정은 서버 접수와 프런트 빌드에 함께 적용한다. 기존 저장 결과 조회는 유지한다.

## 외부 선행 조건

- 유료 적용일, 실제 통신판매업 신고번호와 고객지원 연락 수단. 공개 법적 문안·결제 동의 버전·불리한 변경의 고지 기간을 함께 확인한다. 준비 문안은 초안으로 관리하며 임의 시행일이나 사업자 정보를 게시하지 않는다.
- Supabase 프로젝트 URL, 리전, 요금제·용량과 비공개 백업 버킷. S3 자격증명은 서버 비밀 설정으로만 넣는다. 백업 복호화 개인키와 본문 암호화 키는 서버/버킷과 분리해 보관한다. 해외 보관이면 개인정보처리방침을 운영 설정과 일치시킨다.
- 빌링 MID와 해당 라이브 키 쌍, 공급자에서 설정한 웹훅의 실제 전달. 비용 지불 자체를 계약 활성화나 실거래 검증으로 기록하지 않는다.
- 제한 실결제의 작업공간·금액·환불 범위. 별도 대상 승인이 없는 동안 허용 목록은 비워 둔다.

## 구현과 운영 적용

- 카드 등록 시작 응답의 `callback_url`을 Toss 반환 주소로 사용한다. 공개 반환 API는 인증 값을 암호화해 잠시 보관하고, 브라우저에는 불투명한 `resume` 값만 전달한다. 일반·소셜 로그인 후 인증된 복구 API로 완료한다. 인증 값은 10분 후 제거하고 복구 메타데이터는 24시간 후 정리한다.
- V48~V50은 거래 원장·심사 이력, 콜백 복구 자료, 계정·문서 삭제 표시를 추가한다. 신규 원장은 사용자 삭제 CASCADE와 분리하고 암호화 키 회전 대상으로 포함한다. 거래와 환불·공급·동의 증빙은 5년, 민원 심사 이력은 3년 보존한다. 과거 증빙을 확인할 수 없는 경우 탈퇴를 차단한다.
- 관리자 보존 원장의 환불 판단은 심사 기록이다. 실제 환불 실행과 갱신 중단은 기존 결제 처리로 별도 확인해야 한다. 기록 화면의 성공만으로 환불 완료를 판정하지 않는다.
- `ops/nginx/easydoc.kr.conf`도 운영 호스트에 적용하고 `nginx -t`를 통과한 후 다시 읽어야 한다. 콜백 요청은 외부 nginx에서 IP별, API에서 상태 값별로 제한한다. 두 nginx의 콜백 경로 오류 로그를 차단하고 접근 로그에서 쿼리를 제외하여 인증 값이 남지 않도록 했다.
- 원격 백업은 기본 비활성이다. 프로젝트·버킷·키·용량 확인 후 설정하고 [파일럿 운영 절차](../pilot-runbook.md)의 원격 검증과 복원을 수행한다. 복원한 DB를 서비스에 연결하기 전에 최신 삭제 표시를 적용하여 삭제된 계정과 문서를 다시 제거한다.

## 최종 검증 기록

구현 후 실제 실행한 명령, 성공/실패/미실행, 테스트 건수와 독립 리뷰 지적을 아래에 기록한다. 운영 자격증명·원문·백업을 이 문서나 Git에 넣지 않는다.

- Backend: `cd backend-kotlin && ./gradlew build` 통과. 5개 모듈의 JUnit 결과 총 3,716개 테스트, 실패·오류·건너뜀 0건. 정적 검사와 포맷 검사 포함. 마이그레이션 전용 프로필의 암호화 키 없는 실행, 거래 보존의 실패 시 롤백, 콜백 UUID 계약 검증도 통과했다.
- Frontend: `npm run check`, `npm run test -- --run`, `npm run build` 통과. 83개 파일, 1,036개 테스트.
- Compose: 기본 모델과 pilot overlay의 `config --quiet` 통과. 필수 외부 설정의 모델 검사에는 합성 값을 사용했다.
- 관리자/Toss E2E: 관리자 화면의 기존 Playwright 테스트 1건 통과(모의 API). 관리자 원장 실제 HTTP/PostgreSQL 테스트와 로컬 가짜 gateway 기반 콜백 테스트 통과. Toss 공급자 페이지를 이용하는 E2E는 미실행이다.
- 백업: 기존 shell 경계 테스트, `shellcheck`, shell 구문 검사 통과. PostgreSQL 16.4 격리 fixture에서 실제 계정·문서 제거와 반복 적용, 잘못된 DB·오래된 export 거절을 확인했다. CSV 입력 누락을 주입하면 건수 대조에서 롤백하고, 정상 입력에서는 삭제 대상만 제거했다. 실제 암호화 원격 dump 전체 복원과 신규 백업 이미지 빌드는 미실행이다.
- nginx: 캐시된 nginx 이미지에서 두 설정의 구문 검사 통과. 합성 인증 값으로 콜백 429·502를 발생시켰으며 두 프록시의 접근/오류 로그에 인증 값이 남지 않았다. 운영 설정은 별도 적용해야 한다.
- 독립 리뷰: 동의/결제 ID 충돌, 작업공간 삭제의 증빙 우회, 콜백 제한·오류 로그 노출, Linux 날짜 파싱과 복원 삭제 처리를 수정했다. 수정 범위의 최종 리뷰에서 남은 중대 지적은 없다.
- Supabase 원격 업로드/복원: 프로젝트 정보·자격증명 미확인.
- 운영 배포/라이브 거래: 미실행.
