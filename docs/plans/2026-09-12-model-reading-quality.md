# 모델·추론 강도와 독해 품질 개선

## 승인과 비용

사용자는 모델/effort 비교, OpenAI 키 이용, 다른 해결 방법 조사·구현과 최대 US$20의 유료 호출을 승인했다. 이전 실측 US$1.464392를 포함해도 US$20을 넘지 않도록 이번 실행의 예약 합계는 US$18.535608 이하로 제한한다. 모든 재시도도 호출 전에 예약하며 예약을 돌려주지 않는다. 새 Python 구현이나 검증 하네스는 만들지 않고 기존 Kotlin 레인을 사용한다.

## 연구에서 적용할 원칙

- 쉬운 정도와 의미 보존을 별도로 판단한다. 단일 종합 점수가 서로 반대인 변화를 감출 수 있다. [Cripwell 외, READI 2024](https://aclanthology.org/2024.readi-1.1/)
- 결과만 읽고 원문에 관한 독해 질문에 답할 수 있는지 확인한다. 기존 자동 지표만으로 정보 누락을 보장할 수 없다. 실제 초등학생 실험을 했다고 주장하지 않는다. [Agrawal·Carpuat, TACL 2024](https://aclanthology.org/2024.tacl-1.24/)
- 명확한 판정 기준·경계 사례를 사용하고 judge를 직접 대조로 보완한다. [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)
- Sonnet 5 low는 짧고 좁은 작업 중심이며 복잡한 문서에서 충분히 검토하지 않을 수 있다. 강도를 바꾼 실제 결과로 결정한다. [Anthropic Sonnet 5 지침](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)

## 실행 순서

1. OpenAI effort 누락을 고친다. Responses API 요청과 설정 조립을 테스트하고 기존 미설정 요청은 보존한다.
2. 지난 실측에서 확인한 숫자·공백 날짜·퍼센트 오탐과 yes 접두 판정 오류를 고친다. 원문 오류 보존을 실패시키지 않도록 judge를 명확히 한다. 모든 비교 조건에 같은 평가 기준을 적용한다.
3. 공통 소스를 고정하고 이전 공개 문서 3건을 Sonnet 5 low, high, GPT-5.6 Sol medium에서 각 1회 변환한다. 출력 상한은 8,192토큰으로 같게 둔다. 추론 토큰이 상한에 포함되므로 절단이 있으면 품질과 별도로 기록한다. 모델별 judge 결과는 진단용이며 같은 Codex 대조 기준으로 결과를 비교한다.
4. 문맥 설명·공식 이름·조건 관계 보존을 개선한다. 기존 변환+최대 1회 보정의 호출 수를 유지한다. 필요하면 더 강한 모델도 남은 예산에서 제한적으로 시험한다.
5. 후보를 정한 뒤 기존 3건과 별도로 고른 088 의료급여 임신출산, 090 에너지바우처를 반복 검증한다. 보류 표본은 프롬프트 예문을 만드는 데 쓰지 않는다.
6. 전체 백엔드 빌드, 산출물 보존, 비용·오류·한계 보고를 마친다. 유료 품질 레인 실패와 일반 코드 테스트 통과를 분리한다.

## 판정 기준

- 의미: 날짜의 연도, 기관·서류 이름, 금액, 대상·제외·가능성·의무·조건 결합이 유지되어야 한다. 원문 모순을 추측으로 고치면 실패다.
- 이해: 대상/조건/절차를 결과만 읽고 설명할 수 있어야 한다. 중위소득·자산·친족 범위 등 핵심 개념을 어려운 말로 반복하는 것은 미달이다.
- 문맥: 관련 문장이 같은 문단에서 이어져야 하고 비문·기계적 뜻풀이 삽입이 없어야 한다.
- 결정: 의미 보존과 이해를 필수 조건으로 두고, 이를 충족하는 구성 가운데 실패·보정·재시도까지 포함한 문서당 처리 비용이 가장 낮은 구성을 선택한다. 품질 비교에서 우세한 모델을 곧바로 운영 기본값으로 확정하지 않는다. 소규모 표본 통과를 전체 문서 또는 실제 고학년 독자의 검증으로 확대하지 않는다.

## 실행 중 결정과 표본 배정

공통 기준 비교에서 Sonnet high는 8,192토큰 한도에 두 호출이 걸렸다. 이 결과를 출력 한도를 늘린 high의 품질로 일반화하지 않는다. Sol medium은 문단·이름 보존이 나아졌으나 신혼부부와 예비 신혼부부에 함께 적용되는 자녀 조건을 분리했다.

같은 개선 소스에서 Astra medium은 해당 조건을 유지하고 핵심 개념 설명을 더 구체적으로 제공했다. 개발 문서 judge는 2/3 통과했다. 남은 부모상담 문서의 서류 설명과 친족 범위 설명을 보강하기 위해, 특정 문서 예문 대신 필요한 서류의 역할과 숫자가 들어간 용어의 범위를 설명하는 일반 지침을 추가했다.

마지막 검증은 부모상담 087 재실행과 보류 표본 088·090 각 1회로 정했다. 새 유료 호출의 남은 보수적 예약 한도는 US$6.187972이고, 이 회차 상한은 US$6.10이다. 현재 문서 반복 대신 확인된 미달 문서를 반복하며, 변경된 프롬프트이므로 동일 조건 반복 실험으로 합산하지 않는다. 두 보류 표본은 프롬프트 예문에 사용하지 않았다. 최종 결과·사용액·적용 상태는 [보고서](../reports/2026-09-12-model-reading-quality.md)에 남긴다.

## 완료 상태

52회 유료 호출과 5개 원문·17개 최종 결과를 보존했다. 새 측정 US$4.100860, 이전 포함 US$5.565252이며 승인 상한을 지켰다. 최종 추가 검증은 judge 2/3 통과, 원문 오타 `비금여`의 설명 미달 1건이다. 전체 백엔드 빌드 2,772개 테스트와 Compose 설정 검사를 통과했다. 로컬 API·워커에 Astra medium과 최종 지침을 적용하고 직접/프런트 프록시 health를 확인했다. 원문 오타와 누락된 법적 자격 근거까지 해결한 것으로 포장하지 않는다.

## 비용 요구를 반영한 후속 결정

동일 phase2에서 평가 호출을 뺀 문서당 평균은 Sol $0.174220, Astra $0.365513으로 2.10배 차이가 났다. Astra 비용의 51.2%는 보정이다. 따라서 Astra의 운영 기본 모델 선정은 보류한다. 로컬 비교 설정은 현재 Astra이며 이번 비용 검토에서 바꾸지 않았다.

후속 순서는 보정 전후 품질·사유 확인, 불필요한 보정 축소, 공통 최종 프롬프트에서 저비용 모델/effort 재비교, 필요할 때만 상위 모델을 쓰는 경로 검증이다. 현재 자료로 보정 생략의 안전성이나 저비용 후보의 최종 품질을 주장하지 않는다. [비용 분해·선택 기준·검증 순서](../reports/2026-09-12-model-cost-review.md)를 따르며 추가 유료 실행은 아직 하지 않았다.
