# 스프린트 2 구현 계획 — 이메일 계정 + 파일 텍스트 추출 + 변환 API·비동기 처리

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 스프린트 1의 변환 파이프라인 위에 DB·인증·파일 인제스트·비동기 변환 API를 얹어, 사용자가 가입 → 문서 업로드/붙여넣기 → 비동기 변환 → 결과 조회까지 API로 수행할 수 있게 한다 (master-plan 로드맵 스프린트 2).

**Architecture:** `api/`(라우터+스키마) → `services/`(비즈니스 로직) → `repositories/`(SQLAlchemy async) 레이어 규칙 준수. PostgreSQL(+pgvector 이미지, 벡터 컬럼은 아직 없음) + Redis(arq). 업로드 원문·변환 결과는 **Fernet 암호화 저장**, 30일 보존 필드 포함 (master-plan 3.2). 변환은 arq 워커에서 스프린트 1의 `ConversionService`를 그대로 사용 — 마스킹 선행 불변식 유지.

**Tech Stack 추가:** SQLAlchemy 2.0(async)+asyncpg / alembic / arq+redis / argon2-cffi(비밀번호) / PyJWT / cryptography(Fernet) / python-multipart / python-docx / pypdf / (dev) fpdf2

**전제·차단 요소:**
- 벤더 확정(벤치마크 실행)은 API 키·실제 수집 문서 확보 대기 — 이 계획 범위 밖(사용자 결정 사항).
- **DB·Redis 통합 테스트는 `@pytest.mark.db` 마커**로 분리: `DATABASE_URL`/`REDIS_URL` 환경변수가 없으면 skip. 기본 스위트는 인프라 없이 통과해야 한다(서비스 로직은 fake repository로 단위 테스트). CI에는 Postgres·Redis 서비스 컨테이너를 추가해 db 마커까지 실행.
- 로컬 Docker 가용 여부 미확인 — 미션 K에서 확인, 없으면 docker-compose 검증은 CI로 위임하고 보고.
- 이메일 알림(P0-3)·크레딧 차감(P0-7)·문단 단위 재변환은 이번 스프린트 범위 밖 (Lean MVP 단계 구분).

class Document(Base):

    id: Mapped[uuid.UUID]  # PK, default uuid4
    user_id: Mapped[uuid.UUID]  # FK users.id, index

    status: Mapped[str]  # "pending" | "processing" | "done" | "failed" (CHECK 제약)
    easy_text_encrypted: Mapped[bytes | None]
    masked_items_encrypted: Mapped[bytes | None]  # JSON 직렬화 후 암호화 (원문 개인정보 포함이므로)

    output_tokens: Mapped[int | None]
