# 개인정보 처리 인벤토리 — 항목·보유기간·처리위탁·국외이전·안전성 확보조치

- 작성 2026-09-10. 사용자 지시: 「인벤토리부터 진행.」
- **용도 둘.** ⑴ 법률 자문 의뢰서에 첨부한다 — 변호사는 「무엇을 어디로 보내는지」를 모르면 국외이전 구조도 약관 책임 조항도 쓸 수 없다. ⑵ 개인정보처리방침 문안의 원자료가 된다.
- 관련: 자문 질문은 `docs/plans/2026-09-10-legal-counsel-questions.md`, 고지 위치·푸터는 `docs/plans/2026-09-09-legal-footer-and-support.md`, 정책 정본은 `docs/plans/2026-09-10-legal-tax-policy-final.md`.

## 0. 이 문서의 성격

**전부 코드에서 뽑았다.** 마이그레이션(V1~V21), `application.yml`, 파기 배치, 암호화 어댑터, LLM 어댑터를 직접 읽었다. 기억이나 추정으로 적은 칸은 없고, 확인하지 못한 것은 **「확인 필요」로 표시했지 채워 넣지 않았다.**

**스키마가 바뀌면 이 문서도 같은 변경 단위에서 바뀐다.** 개인정보가 실리는 열을 더하면서 여기를 갱신하지 않으면 처리방침이 곧바로 사실과 어긋난다.

## 1. 처리 항목 인벤토리

### 1.1 계정과 인증

| 표 | 항목 | 성격 | 수집 목적 | 법적 근거(안) |
|---|---|---|---|---|
| `users` | `email` | 식별자 | 로그인 ID, 알림 수신, 본인 확인 | 계약 이행 |
| | `password_hash` | 인증 정보(해시) | 인증 | 계약 이행 |
| | `email_verified_at` | 상태 | 이메일 소유 확인 | 계약 이행 |
| | `is_admin` | 권한 | 운영자 구분 | 정당한 이익 |
| `user_identities` | `provider`, `provider_user_id` | 외부 계정 식별자 | 소셜 로그인 연결 | 계약 이행 |
| | `email` | 식별자(제공자 스냅샷) | 연결 시점 이메일 기록 | 계약 이행 |
| `email_verification_codes` | `code_hash`, `salt` | 인증 정보(해시) | 이메일 소유 확인 | 계약 이행 |
| `password_reset_codes` | `code_hash`, `salt` | 인증 정보(해시) | 비밀번호 재설정 | 계약 이행 |
| `oauth_states` | `state`, `nonce`, `redirect_uri`, `user_id`(null 가능) | 세션 상태 | CSRF·재생 공격 방지 | 계약 이행 |
| `signup_grant_records` | `email_hash` | **가명 식별자** | 무료 이용량 중복 수령 방지 | 정당한 이익 |

`signup_grant_records.email_hash`는 평문 이메일이 아니라 **비밀 pepper를 섞은 HMAC-SHA256(64자 16진)** 이다. 단순 SHA-256이면 사전 공격으로 곧바로 되돌려지므로 그렇게 하지 않았다. 이 표는 `users`에 FK가 **없다** — 탈퇴해도 남아야 목적을 이루기 때문이고, 그래서 별도 파기 배치가 유일한 소거 경로다(§2.1).

### 1.2 이용자가 올린 문서 — **가장 중요한 자리**

| 표 | 항목 | 성격 | 비고 |
|---|---|---|---|
| `documents` | `source_text_encrypted` | **본문(암호화)** | 변환 대상 원문 |
| | `title` | 이용자 입력 문자열 | 평문 저장 |

| `document_originals` | `file_bytes_encrypted` | **업로드 원본 파일(암호화)** | 텍스트 붙여넣기에는 없다 |
| `conversions` | `easy_text_encrypted` | **변환 결과(암호화)** | |

**전제와 실제.** 제품 전제는 「변환 대상은 공개 배포용 안내문이라 개인정보를 담지 않는다」이고, 담겨 들어오면 **입력한 이용자의 책임**이라고 고지한다(정책 §3.5). 2026-09-10부터 등록 전에 주민등록번호·카드번호를 **경고**하지만 막지는 않는다(계약 2.31.0).

그러므로 **본문에 제3자의 개인정보가 섞여 들어올 가능성은 구조적으로 남아 있다.** 이 사실이 국외이전 구조와 약관 책임 조항을 결정하는 핵심이며, §5의 첫 자문 항목이다.

## 2. 보유기간과 파기

### 2.1 구현된 파기

| 대상 | 기간 | 구현 |
|---|---|---|
| 문서·변환·업로드 원본 | **30일** (`retention_expires_at`) | `RetentionPurgeScheduler` 1단계, 매일 03:00 |
| 피드백 자유 의견 3열 | **30일** → NULL | 2단계 (지표 숫자는 남는다) |
| 미검증 계정 | **24시간** | 3단계 (문서를 가진 계정은 건너뛰고 개수만 센다) |
| 가입 이용량 이메일 해시 | **부여 후 2년** | 4단계 (2026-09-10 구현, PR #106) |
| 계정 전체 | **탈퇴 즉시** | `POST /auth/me/deletion` — 유예 없이 즉시 파기 |

탈퇴하면 `users` 행 삭제로 `workspaces`·`documents`·`user_identities`·`oauth_states`·인증 코드가 FK CASCADE로 함께 사라진다. `conversion_feedback`은 **FK가 없어**(V2, 의도된 설계) 사용자 행보다 **먼저** 지운다.

### 2.2 보유기간이 정의되지 않은 것 — **공백 셋**

이 인벤토리를 만들면서 드러난 것이다. **세 표에 `DELETE` 구문이 코드 어디에도 없다**(테스트 제외, 2026-09-10 확인).

| 표 | 지금 어떻게 되는가 | 왜 문제인가 |
|---|---|---|
| `email_verification_codes` | 계정 삭제 시에만 사라진다 | 코드는 **10분**이면 만료되는데 행은 무기한 남는다 |
| `password_reset_codes` | 같음 | 같음 |
| `oauth_states` | `user_id`가 **NULL인 행은 영영 남는다** | 가입·로그인 전 흐름에서 만들어진 상태가 대부분이다 |

세 표 모두 **목적을 다한 뒤에도 남는다.** 개인정보 보호법 §21의 「목적 달성 시 지체 없이 파기」와 어긋나는 방향이고, `oauth_states`는 무한 증가하는 표이기도 하다.

**권고: 만료·소비된 행을 지우는 5번째 파기 단계를 더한다.** 세 표 모두 `expires_at`·`consumed_at`을 이미 갖고 있어 판정 기준이 따로 필요 없다. 규모가 작아 한 조각(S)이다. **파일럿 전에 닫는 것을 권한다** — 처리방침에 「보유기간」을 적어야 하는데 지금은 적을 값이 없다.

### 2.3 영구 보존하는 것과 그 근거

`llm_calls`·`credit_transactions`는 청구·원가 근거라 남긴다. 개인과의 연결은 탈퇴 시 끊는다(`user_id` NULL). `conversion_feedback`의 지표 숫자는 품질 개선 목적으로 남기되 자유 의견은 30일에 지운다 — **본문성 정보와 통계치를 나눈 것이 이 설계의 핵심**이다.

법정 보존의무(전자상거래법의 거래기록 등)가 어느 항목에 걸리는지는 자문 대상이다.

## 3. 처리위탁·국외이전

### 3.1 해외 LLM — **개인정보 국외이전에 해당하지 않는다**

**정본은 `docs/plans/2026-09-10-legal-tax-policy-final.md` §3.5다.** 그 문서의 결론은 「해외 LLM API에 개인정보를 보내지 않으므로 §28조의8의 국외이전 대상이 없다」이고, 이 인벤토리는 그 결론을 **코드로 검증한 결과**를 싣는다.

| 항목 | 내용 |
|---|---|
| 보내는 곳 | Anthropic (기본), OpenAI (설정으로 전환) |
| 처리 국가 | 미국 (확인 필요 — 실제 처리 리전) |
| 보내는 것 | **변환 대상 문서 본문**과 시스템 프롬프트, 출력 한도 |
| **보내지 않는 것** | **이용자 식별자·계정정보·이메일·결제정보·접속기록** |
| 목적 | 쉬운 말 변환 (서비스의 본질적 기능) |
| 시점·방법 | 변환 요청 시점, HTTPS API 호출 |
| 저장 여부 | OpenAI 요청은 **`store=false`를 명시**한다. Anthropic 측 보유·학습 정책은 **확인 필요** |

**정책 §3.5-2의 사실 주장을 코드에서 확인했다(2026-09-10).** OpenAI 요청 본문은 `model`·`instructions`·`input`·`max_output_tokens`·`store=false` 다섯뿐이고, 두 어댑터 어디에도 사용자 식별자를 싣는 코드가 없다. **즉 「누가 보냈는지」는 나가지 않는다** — 이것이 국외이전 해당성을 부정하는 논거의 사실적 토대다.

**그래서 처리방침에는 국외이전 절을 두지 않는다.** 대신 정책 §3.5-4에 따라 **서비스 안내와 이용약관**에 해외 LLM 사용 사실·사업자·처리 국가·입력과 결과의 저장 여부와 기간·모델 학습 사용 여부를 공개한다. 처리방침에는 **실제로 처리하는 개인정보만** 적는다.

**남는 위험은 전제가 깨지는 경우다.** 본문에 개인정보가 섞여 들어오면 그것이 함께 나간다. 정책이 둔 완화 장치는 ⑴ 업로드 화면 안내 ⑵ 약관의 입력 금지 의무 ⑶ 등록 시점 경고용 검출(§3.5-7, 구현됨) ⑷ 발견·신고 시 변환 중단과 삭제다. ⑷의 이용자 경로는 `DELETE /documents/{document_id}`(즉시 파기)로 있으나, **신고를 받아 운영자가 처리하는 절차는 문서로 정해져 있지 않다**(확인 필요).

### 3.2 국내 처리위탁

| 수탁자 | 업무 | 이전 항목 | 상태 |
|---|---|---|---|
| 메일 발송(현재 Daum SMTP relay) | 인증 코드·변환 완료 알림 | 수신 이메일, 인증 코드 | **임시** — SES 전환 예정(2026-09-04 결정) |
| 호스팅·인프라 | 서비스 운영 | 전부 | **확인 필요 — 사업자 확정 후 기재** |

### 3.3 제공받는 경로 (위탁이 아니다)

Google·Kakao·Naver 소셜 로그인 — 제공자로부터 계정 식별자와 이메일을 **받는다.** 우리가 주는 것이 아니므로 처리위탁·제3자 제공이 아니라 **수집 경로**로 적는다. 다만 각 제공자의 동의 항목이 무엇인지는 콘솔 설정과 일치해야 한다.

## 4. 안전성 확보조치

| 조치 | 구현 |
|---|---|
| 저장 암호화 | 문서 본문·원본 파일·변환 결과·수정본·피드백 의견을 **AES-256-GCM**으로 암호화(`aes256gcm-v1`). 열마다 `key_version`을 두어 **키 회전**을 지원한다 |
| 비밀번호 | 해시로만 저장 |
| 인증 코드 | 해시 + 개별 salt. 시도 횟수(`attempts`)와 만료(`expires_at`) 제한 |
| 이메일 해시 | HMAC-SHA256 + 비밀 pepper (환경변수) |
| 비밀값 관리 | API 키·pepper·SMTP 비밀번호는 **환경변수로만** 주입. 구성 파일에 값이 아니라 참조만 둔다 |
| 로그 | **본문·개인정보·토큰·키·프롬프트를 로그에 남기지 않는다.** 강제 TRACE로 실제 누출 여부를 재는 테스트가 여러 경로에 있다 |
| 접근 통제 | 다른 사용자의 자원은 **존재를 숨기려 404**로 응답. 소유권 검사를 강제하는 가드 테스트가 있다 |
| 운영자 권한 | `users.is_admin` 분리, 관리자 전용 엔드포인트 표시(`x-admin-only`) |
| 전송 구간 | HTTPS |

접속기록 보관·정기 점검 등 관리적 조치는 **아직 정리되지 않았다** — 처리방침에 적으려면 운영 절차를 함께 정해야 한다(확인 필요).

## 5. 자문·확인이 필요한 것

**A. 변호사에게 (가장 먼저 답이 필요한 순서)**

1. **「개인정보를 보내지 않으므로 국외이전이 아니다」(정책 §3.5)가 유지되는가.** §3.1의 코드 확인 결과(식별자 미전송, `store=false`)를 근거로 제시한다. 확인받을 것은 둘 — ⑴ 본문에 개인정보가 **섞여 들어올 수 있다는 잔여 위험**이 있어도 이 결론이 유지되는가 ⑵ 유지된다면 §3.5-4의 공개(약관·서비스 안내)만으로 충분한가.
2. **본문에 섞여 들어온 제3자 개인정보에 대해 우리는 무엇인가.** 이용자가 개인정보처리자이고 우리가 수탁자인가. **이 답이 약관 책임 조항을 결정한다.** §1.2의 전제·경고 구조가 그대로 유효한지도 함께.
3. **세금계산서 요청의 제3자 정보**(§1.4, 특히 대표자 성명) — 보유기간과 법정 보존의무. 이용자가 타인 정보를 입력하는 구조에 별도 고지·동의가 필요한가.
4. **법정 보존의무 대조** — §2.3의 영구 보존 항목 중 법이 요구하는 것과 우리가 정하는 것의 구분.
5. **만 14세 이상 확인 한 줄**로 충분한가(`2026-09-09-legal-footer-and-support.md` 11번).

**B. 우리가 채워야 하는 빈칸**

1. **호스팅·인프라 사업자 확정** — §3.2가 비어 있다.
2. **Anthropic·OpenAI의 실제 처리 리전과 보유 정책** — 공식 문서로 확인해 §3.1을 채운다.
3. **접속기록 보관·점검 주기** 등 관리적 조치(§4 마지막 줄).

**C. 구현으로 닫아야 하는 것**

1. **§2.2의 공백 셋** — 만료·소비된 인증 코드와 OAuth 상태를 지우는 파기 단계. 처리방침에 보유기간을 적으려면 값이 있어야 한다.

## 6. 한 줄 요약

계정·문서·과금 세 갈래 모두 항목과 근거가 정리됐고, 파기는 다섯 갈래가 구현돼 있다. 해외 LLM에 **이용자 식별자가 나가지 않는다**는 정책의 사실 주장은 코드로 확인됐다(§3.1).

**막고 있는 것은 두 가지다** — 본문에 개인정보가 섞여 들어올 잔여 위험을 안고도 「국외이전 아님」 결론이 유지되는가(자문 A-1·A-2)와, **보유기간이 정의되지 않은 표 셋**(C-1). 앞의 것은 자문 없이 못 풀고, 뒤의 것은 작은 조각 하나로 닫을 수 있다.
