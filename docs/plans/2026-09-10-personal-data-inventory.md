## 0. 이 문서의 성격

**증거 수준을 구분한다.** 아래 표의 구현 설명은 최초 작성자가 2026-09-10에 마이그레이션(V1~V21), 설정, 파기 배치, 암호화·LLM 어댑터를 읽었다고 기록한 조사 결과다. 이번 문서 정리에서 제품 코드·배포 환경을 재검증한 것은 아니다.

| 구분 | 의미 |
|---|---|
| 기존 코드 조사 기록 | 최초 조사 내용을 유지한다. 현재 동작을 확정하려면 파일·행 또는 심볼, 커밋, 검증 결과를 연결해야 한다 |
| 공식 자료 확인 | §7의 법령·공급자 문서에서 확인한 일반 기준. 실제 계정·계약에 적용되는 조건은 별도 확인한다 |
| 운영 정책 | 사업자가 정한 지원 범위·목적·기간. 구현 완료 또는 법적 요건 충족을 뜻하지 않는다 |
| 확인 필요 / 제안 | 근거·설정·운영 증거가 부족하거나 아직 결정·구현하지 않은 사항 |

법적 근거의 후보, 보관 의도, 코드 동작을 서로 대신하는 증거로 쓰지 않는다. 미확인 사항은 §5에서 확인 방법과 완료 기준을 관리한다. 개인정보 분야는 관련 정책 정본 §3.5와 함께 이 구분을 적용한다.

**스키마가 바뀌면 이 문서도 같은 변경 단위에서 바뀐다.** 개인정보가 실리는 열을 더하면서 여기를 갱신하지 않으면 처리방침이 곧바로 사실과 어긋난다.

## 1. 처리 항목 인벤토리

### 1.1 계정과 인증

| 표 | 항목 | 성격 | 수집 목적 | 법적 근거(안) |
|---|---|---|---|---|
| `users` | `email` | 식별자 | 로그인 ID, 알림 수신, 본인 확인 | 계약 이행 |
| | `password_hash` | 인증 정보(해시) | 인증 | 계약 이행 |
| | `email_verified_at` | 상태 | 이메일 소유 확인 | 계약 이행 |
| | `is_admin` | 권한 | 운영자 구분 | 정당한 이익 |
| `user_identities` | `provider`, `provider_user_id` | 외부 계정 식별자 | 소셜 로그인 연결 | 계약 이행 |
| | `email` | 식별자(제공자 스냅샷) | 연결 시점 이메일 기록 | 계약 이행 |
| `email_verification_codes` | `code_hash`, `salt` | 인증 정보(해시) | 이메일 소유 확인 | 계약 이행 |
| `password_reset_codes` | `code_hash`, `salt` | 인증 정보(해시) | 비밀번호 재설정 | 계약 이행 |
| `oauth_states` | `state`, `nonce`, `redirect_uri`, `user_id`(null 가능) | 세션 상태 | CSRF·재생 공격 방지 | 계약 이행 |
| `signup_grant_records` | `email_hash` | **가명 식별자** | 무료 이용량 중복 수령 방지 | 정당한 이익 |

위 법적 근거는 **후보**다. 계약 이행의 필요성, 정당한 이익의 목적·필요성·정보주체 권리와의 비교 및 최소 보유기간을 항목별로 기록해야 한다.

기존 조사상 `signup_grant_records.email_hash`는 비밀 pepper를 사용한 HMAC-SHA256(64자 16진)이고 `users`에 FK가 없다. 탈퇴 후에도 중복 수령 방지 목적으로 보유하는 정책이며 별도 파기 배치가 기록돼 있다(§2.1). 여기서 「가명 식별자」는 기술적 설명으로, 법상 가명정보 해당성이나 익명화를 확정한 표현이 아니다. HMAC 적용만으로 개인정보 규율에서 제외되지는 않는다.

### 1.2 이용자가 올린 문서 — **가장 중요한 자리**

| 표 | 항목 | 성격 | 비고 |
|---|---|---|---|

| `document_originals` | `file_bytes_encrypted` | **업로드 원본 파일(암호화)** | 텍스트 붙여넣기에는 없다 |

**정책과 동작을 구분한다.** 지원 범위는 개인정보 없는 공개 배포용 안내문이다. 공개 문서라는 사실만으로 개인정보가 없다고 판단하지 않는다. 기존 조사상 주민등록번호·카드번호는 등록 전에 경고하지만 차단하지 않는다(계약 2.31.0). 입력 금지 의무는 운영 정책이며, 이를 고지했다고 사업자의 책임이 모두 이용자에게 이전되는 것으로 결론 내리지 않는다.

따라서 본문에 이용자 또는 제3자의 개인정보가 섞여 들어올 가능성이 남는다. 현재 경고 기능은 개인정보 부재를 보장하지 않는다. 혼입 시 처리 근거·역할·대응 절차는 §5에서 직접 확인할 항목이다.

## 2. 보유기간과 파기

### 2.1 기존 조사에 기록된 파기

| 대상 | 기간 | 구현 |
|---|---|---|
| 문서·변환·업로드 원본 | **30일** (`retention_expires_at`) | `RetentionPurgeScheduler` 1단계, 매일 03:00 |
| 피드백 자유 의견 3열 | **30일** → NULL | 2단계 (지표 숫자는 남는다) |
| 미검증 계정 | **24시간** | 3단계 (문서를 가진 계정은 건너뛰고 개수만 센다) |
| 가입 이용량 이메일 해시 | **부여 후 2년** | 4단계 (2026-09-10 구현, PR #106) |
| 계정 삭제 경로의 운영 DB 대상 행 | **탈퇴 요청 처리 시** | `POST /auth/me/deletion`. 탈퇴 후 잔존 기록·백업·외부 공급자 보관분까지 즉시 삭제된다는 뜻은 아님 |

탈퇴하면 `users` 행 삭제로 `workspaces`·`documents`·`user_identities`·`oauth_states`·인증 코드가 FK CASCADE로 함께 사라진다. `conversion_feedback`은 **FK가 없어**(V2, 의도된 설계) 사용자 행보다 **먼저** 지운다.

위 설명은 기존 코드 조사 범위다. 이메일 HMAC과 과금 잔존 기록은 별도 보유 대상이다. 30일·24시간은 파기 대상이 되는 기준이며 일일 배치의 실제 삭제 시각과 다를 수 있다. 배치 활성화·시간대·실패 재처리, 백업 만료·복원 시 재삭제 및 공급자 삭제 범위는 확인되지 않았다.

### 2.2 보유기간이 정의되지 않은 것 — **공백 셋**

**재확인 완료(2026-09-10).** 표 이름 검색만으로는 알 수 없어 **저장소 구현 파일을 직접 열어** 확인했다. 세 표를 다루는 구현은 `JdbcVerificationCodeStore.kt`·`JdbcPasswordResetCodeStore.kt`·`JdbcOneTimeCodeStore.kt`·`JdbcOAuthStateStore.kt` 넷이고, **그 어느 파일에도 `DELETE`가 없다.** 저장소 안에서 삭제를 수행하는 것은 `JdbcUnverifiedAccountPurge`(미검증 `users` 행)와 `JdbcAccountDeletionRepository`(탈퇴)뿐이며, 세 표는 그 둘의 `users` FK CASCADE로만 사라진다.

| 표 | 지금 어떻게 되는가 | 왜 문제인가 |
|---|---|---|
| `email_verification_codes` | `users` CASCADE로만 사라진다 | 코드 유효기간은 10분인데 **행은 계정이 사는 동안 계속 쌓인다.** 유효기간과 저장기간이 분리돼 있다 |
| `password_reset_codes` | 같음 | 같음 |
| `oauth_states` | **`user_id`가 NULL인 행은 삭제 경로가 없다** | 삽입 시 `userId: UUID?`로 받고 가입·로그인 전 흐름은 NULL을 넣는다(`JdbcOAuthStateStore`) — CASCADE가 닿지 않아 **영구 잔존하며 단조 증가한다** |

이 세 줄은 「검색 범위 내 결과」가 아니라 구현 파일을 다 읽은 결과다. 다만 **DB 차원의 작업(운영자 수동 정리, 외부 스케줄러, `pg_cron` 등)까지 없다는 증거는 아니다** — 배포 환경 확인은 남는다.

목적 달성 후 불필요한 개인정보는 파기해야 한다는 기준에 맞춰 저장 목적과 삭제 지연을 확인한다(§7, 개인정보 보호법 제21조). 삭제 경로가 없다고 확인되면 정리 기능이 필요하다. 이 문서만으로 운영 데이터 잔존량이나 법 위반을 확정하지 않는다.

**구현 제안:** 삭제 경로 재확인 후 만료·소비된 행의 정리 단계를 추가한다. 기존 조사에 기록된 `expires_at`·`consumed_at`을 기준 후보로 삼되 재시도·재사용 방지·동시 요청에 필요한 기간과 배치 주기를 정한다. 이번 정리는 구현 완료나 작업 규모를 확정하지 않는다.

### 2.3 기한 없는 보관과 보유 정책의 미확정 사항

청구·원가·품질 개선은 보유 목적의 설명이며 영구 보존의 근거를 확정하지 않는다. 숫자 지표도 식별자나 다른 기록과 연결되면 익명 통계로 단정할 수 없다.

직접 정할 것은 ⑴ 법령 적용 대상·필드·보존기간·기산점 ⑵ 운영 목적의 최소 보유기간 ⑶ 장기 통계에 필요한 집계·연결 제거 방법 ⑷ 기간 종료 시 삭제와 증거다. 현재 각 기록에 대한 대조와 익명성 검증은 완료되지 않았다.

## 3. 처리위탁·국외이전

### 3.1 해외 LLM — 전송 사실과 적용 판단

**기존 코드 조사 기록:** LLM 요청에는 변환 대상 본문이 들어가고 서비스 계정 식별자를 별도 첨부하지 않는다. **운영 정책:** 개인정보 없는 공개 안내문만 지원한다. 이 둘을 합쳐 실제 전송 내용에 개인정보가 없다고 확정하지 않는다.

| 항목 | 내용과 확인 수준 |
|---|---|
| 공급자 | 기존 조사상 Anthropic 기본, OpenAI 설정 전환. 실제 배포의 공급자·모델·계약 주체 확인 필요 |
| 처리 국가 | 미확정. 저장·추론·지원 접근·재수탁 경로를 실제 계약과 리전 설정으로 확인해야 함 |
| 전송 내용 | 기존 조사상 문서 본문, 시스템 프롬프트, 모델·출력 한도 등 호출 설정 |
| 별도 첨부하지 않는 정보 | 기존 조사상 서비스 이용자의 계정정보·사용자 식별자·이메일·결제정보·접속기록. 본문에 포함된 정보까지 제외된다는 뜻은 아님 |
| 목적·시점·방법 | 쉬운 말 변환 요청 시 HTTPS API 호출 |
| OpenAI 요청 설정 | 기존 조사상 `store=false`. 공급자의 모든 보관을 끄는 설정으로 해석하지 않음 |
| 실제 보관·학습 조건 | 일반 정책은 아래 참조. 실제 조직·프로젝트·모델의 계약·설정 적용 여부는 미확인 |

기존 조사에는 OpenAI 요청 필드가 `model`, `instructions`, `input`, `max_output_tokens`, `store`로 기록돼 있다. 이는 요청 본문의 구성에 관한 기록이며, 본문 속 개인정보 부재나 공급자가 API 인증·네트워크 정보를 받지 않는다는 증거가 아니다.

**공식 자료로 확인한 일반 정책(2026-09-10 문서 검토):** OpenAI는 명시적으로 공유에 동의하지 않으면 API 데이터를 모델 학습에 사용하지 않는다고 안내한다. 별도의 부정사용 감시 로그에는 입력·출력이 포함될 수 있고 기본 최대 30일 보관 및 예외가 있다. `store=false`와 ZDR 승인·설정은 구분한다. Anthropic은 API 입력·출력의 기본 30일 이내 삭제와 계약·법령·정책 위반 및 일부 모델 등의 예외를 안내한다. 이 일반 안내를 실제 서비스의 무보관·학습 미사용·미국 한정 처리 보장으로 옮겨 적지 않는다. [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data), [Anthropic 보관 정책](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)

**적용 판단:** 실제 전송 내용에 개인정보가 없다면 해당 전송에는 개인정보 국외이전 규정의 대상이 없다. 그러나 본문으로 개인을 식별할 수 있다면 계정 필드를 붙이지 않았다는 사실만으로 이를 부정할 수 없다. 법의 국외이전에는 제공·처리위탁·보관이 포함된다. 현재 경고 구조에서 서비스 전체의 국외이전 비해당이나 처리방침의 국외이전 항목 생략을 확정하지 않는다. [개인정보 보호법 제2조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028631167), [제28조의8](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334953)

해외 LLM 사용 사실과 확인된 공급자 조건은 공개할 운영 정책이다. 개인정보 혼입 시에는 정보주체·처리 목적·계약 관계별 적용 근거와 공개·통지 범위를 직접 대조한다. 가입자의 확인이나 동의가 문서 속 제3자의 동의를 대신한다고 전제하지 않는다.

**혼입 대응의 상태:** 입력 금지 안내와 경고 기능은 기존 기록에 있으나 차단은 하지 않는다. 이용자 삭제 API가 있다는 사실은 진행 중인 호출 취소, 운영자 신고 처리, 공급자 보관분 삭제가 구현됐다는 뜻이 아니다. 신고 접수·처리 중단·삭제 범위·처리 기록 절차는 확인·작성 대상이다. 검출 시 차단으로 바꾸는 방안은 검토 후보이며 이번 문서 수정으로 채택하거나 구현하지 않는다.

### 3.2 메일·호스팅 처리 경로 — 국내 여부 미확정

| 수탁자 | 업무 | 이전 항목 | 상태 |
|---|---|---|---|
| 메일 발송(현재 Daum SMTP relay) | 인증 코드·변환 완료 알림 | 수신 이메일, 인증 코드 | **임시** — SES 전환 예정(2026-09-04 결정) |
| 호스팅·인프라 — **가비아** | 서비스 운영 | 서비스 데이터. 구성 요소별 범위 미확인 | 사업자 확정(2026-09-10, 사용자). **국내 사업자이므로 이 경로는 국외이전이 아니다.** 남은 확인: 상품·리전, 백업 보관 위치와 기간, 기술지원의 데이터 접근 범위, 재수탁 여부 |

메일 설정은 기존 조사 기록이며 실제 운영 확인이 필요하다. SES 전환 예정이라는 사실만으로 현재 사용 또는 국내 처리를 확정하지 않는다. 수탁 계약 주체와 데이터 처리 위치를 확인한 후 위탁·국외이전 분류를 정한다.

### 3.3 소셜 로그인 수집 경로

기존 조사상 Google·Kakao·Naver로부터 계정 식별자와 이메일을 받는다. 이 수신 항목은 수집 경로로 기록한다. OAuth 요청·브라우저 리디렉션의 발신 정보와 공급자 자체 수집 정보는 별도로 확인해야 하며, 수신 경로라는 이유만으로 전체 흐름에 외부 전송이 없다고 단정하지 않는다. 실제 제공자 활성화·동의 항목은 콘솔 설정과 대조한다.

## 4. 안전성 확보조치

| 조치 | 기존 코드 조사 기록 |
|---|---|
| 저장 암호화 | 문서 본문·원본 파일·변환 결과·수정본·피드백 의견을 **AES-256-GCM**으로 암호화(`aes256gcm-v1`). 열마다 `key_version`을 두어 **키 회전**을 지원한다 |
| 비밀번호 | **Argon2id**로만 저장(`Argon2PasswordHasher`). 메모리·반복 파라미터는 `easydoc.auth.argon2.*` 구성값이고, 저장된 해시의 파라미터가 현재 정책과 다르면 재해시 대상으로 판정한다 |
| 인증 코드 | 해시 + 개별 salt. 시도 횟수(`attempts`)와 만료(`expires_at`) 제한 |
| 이메일 해시 | HMAC-SHA256 + 비밀 pepper (환경변수) |
| 비밀값 관리 | API 키·pepper·SMTP 비밀번호는 **환경변수로만** 주입. 구성 파일에 값이 아니라 참조만 둔다 |
| 로그 | 민감 내용 비기록 정책과 일부 경로의 TRACE 누출 테스트가 기록돼 있음. 전체 로그 경로의 무누출을 입증한 것은 아님 |
| 접근 통제 | 다른 사용자의 자원은 **존재를 숨기려 404**로 응답. 소유권 검사를 강제하는 가드 테스트가 있다 |
| 운영자 권한 | `users.is_admin` 분리, 관리자 전용 엔드포인트 표시(`x-admin-only`) |
| 전송 구간 | HTTPS 사용 기록. 실제 TLS 종단·내부 구간·배포 설정은 재확인 필요 |

키 버전 필드는 실제 키 회전 수행의 증거가 아니며, 환경변수 참조는 배포 비밀값의 접근통제까지 입증하지 않는다. 로그 검증 범위에는 프록시·APM·오류 수집·메일·인프라 로그를 추가 확인한다.

접속기록 보관·정기 점검 등 관리적 조치는 **아직 정리되지 않았다** — 처리방침에 적으려면 운영 절차를 함께 정해야 한다(확인 필요).

## 5. 직접 확인·결정할 항목

외부 변호사의 답변을 완료 조건으로 두지 않는다. 공개 법령·기관 지침과 실제 계약·설정·구현 증거를 대조하고, 근거가 부족한 항목은 미확정으로 유지한다. 아래 완료 기준은 내부 확인 절차이며 현재 충족됐다는 뜻이 아니다.

| 우선 | 항목·현재 상태 | 확인 방법과 완료 기준 |
|---|---|---|
| 1 | 본문 혼입·국외이전 근거 미확정 | 개인정보 없는 입력과 혼입 상황을 나누고, 정보주체·목적·처리자/수탁자 관계·적용 조문·요건 충족 증거·고지 위치를 기록한다. 근거 미확정인 처리를 지원 가능으로 표시하지 않는다 |
| 1 | LLM 공급자 조건 미확인 | 실제 공급자·모델·계약 주체·처리/보관 국가·재수탁자·기간과 예외·학습 여부·ZDR 등 적용 설정을 공식 문서 및 계정 증거와 대조한다. 비밀값은 증거에 넣지 않는다 |
| 1 | 혼입 신고·중단·삭제 절차 미정 | 접수 창구·담당자·진행 중 요청 처리·운영 DB/백업/공급자별 삭제 범위·정보주체 대응·처리 기록을 정하고 실제 가능한 조치와 한계를 확인한다 |
| 1 | 보유기간·탈퇴 잔존 범위 미확정 | 각 표/필드의 목적·근거·기간·기산점·탈퇴 처리·삭제 방법을 정한다. 과금 기록의 법정 보존분과 운영 보존분, 피드백의 연결 가능성을 구분한다 |
| 1 | 인증 코드·OAuth 정리 경로 미확인 | 코드·운영 삭제 경로 확인 후 누락 시 구현 과제로 등록한다. 유효기간과 저장기간, 재시도·재사용 방지 영향 및 삭제 주기를 확정한다 |
| 2 | 메일·호스팅·로그·백업 흐름 미확인 | 실제 사업자·계약·리전·전송 항목·보관기간·접근자를 기록한다. 프록시/APM/오류 수집 사용 여부와 임시 파일·복제본·백업 만료 및 복원 시 재삭제도 확인한다 |
| 2 | 이메일 HMAC 2년 정책의 근거 미완료 | 중복 방지 필요성·더 짧은 기간/대안·정보주체 권리 영향을 기록한다. 2년은 사업자 정책이며 법정 의무기간이나 적법성 확정으로 표시하지 않는다 |
| 2 | 세금계산서 요청 정보 미정 | 자연인/법인/개인사업자와 요청·취소·발급 상태를 구분해 수집 근거·최소 항목·보존기간·기산점을 현행 법령에 대조한다 |
| 2 | 연령·가입 고지 방식 미확정 | 실제 가입 대상과 필수 수집 항목별 법적 근거를 정하고, 동의가 필요한 처리와 다른 근거의 처리를 구분한다. 연령 확인·14세 미만 처리 방침을 관련 법령에 대조한다 |
| 2 | 안전조치 운영 증거 미확인 | 배치 실행·실패 대응, 키 관리·회전, 접근권한·접속기록·점검 주기와 수행 기록을 확인한다. 코드 테스트를 운영 증거로 대신하지 않는다 |

각 항목은 `담당자 / 확인일 / 근거 URL 또는 파일·커밋 / 적용 조건 / 결정 / 남은 작업`을 기록한 뒤 완료로 바꾼다. 처리방침 공개 전에 실제 처리 흐름과 문안의 일치 여부를 확인한다.

## 6. 현재 정리된 범위

계정·문서·과금 관련 기존 코드 조사 기록과 공식 자료의 일반 기준을 분리했다. 서비스 정책은 개인정보 없는 공개 안내문 지원이며, 현재 경고 기능은 본문에 개인정보가 없음을 보장하지 않는다.

서비스 전체의 국외이전 비해당, 공급자 무보관, 탈퇴 즉시 모든 사본 파기, 잔존 기록의 익명화 및 영구 보존의 적법성은 확정하지 않는다. §5의 확인·결정·구현 과제를 직접 진행한다. 이번 수정은 문서 정리이며 제품 동작 변경·운영 검증·출시 적합성 확인 완료가 아니다.

## 7. 공식 근거와 적용 한계

2026-09-10 문서 검토에서 열람한 자료다. 법령의 시행일과 공급자 정책 변경 여부는 실제 정책 확정 시 다시 대조한다.

- [개인정보 보호법 제2조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028631167): 개인 식별·다른 정보와의 결합 및 가명정보 정의. 실제 데이터의 익명성은 별도 검증 대상이다.
- [개인정보 보호법 제21조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0021&lsiSeq=270351&urlMode=lsScJoRltInfoR): 불필요해진 개인정보의 파기 및 법령에 따른 보존 시 분리 관리. 각 과금 기록의 법정 보존기간까지 이 조문으로 확정하지 않는다.
- [개인정보 보호법 제28조의8](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334953): 국외 제공·처리위탁·보관과 허용 근거. 개별 처리의 요건 충족은 별도 확인 대상이다.
- [OpenAI API 데이터 정책](https://developers.openai.com/api/docs/guides/your-data): 학습 사용 기본값, 보관 종류와 보관 통제. 실제 조직·프로젝트의 적용 상태는 미확인이다.
- [Anthropic API 보관 정책](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data): 일반 보관기간과 예외. 실제 모델·계약의 보관 및 학습 조건은 미확인이다.
