# P0-4 S8 — 표·목록 구조 힌트: 구조는 두고 그 안의 문장만 바꾼다

- 작성일: 2026-09-06 (세션 모델 단독 저작, CLAUDE.md 「기획 문서 단독 저작」)
- 결정 근거: backlog §1.3 「표·목록 구조 보존」 **결정(2026-09-06, 사용자)** — 구조 유지가 가능한
  형식(DOCX·HWPX·TXT)에서만 진행하고, 표·목록 구조는 원본 것을 그대로 두고 **그 안의 문장만
  교체**한다. PDF는 렌더러 미도입 결정(§1.3)대로 범위 밖.
- 선행: P0-4 S1–S7(`docs/plans/2026-09-04-p0-4-paragraph-mapping-reconversion.md`), 특히 S6
  (내보내기의 지도 소비, PR #45)과 S7(`compliant_source_units`, PR #51).

## 0. 이미 참인 것 (코드로 확인, 2026-09-06)

읽어서 확인한 사실이다. 이 절이 틀리면 아래 결정도 다시 본다.

1. **추출은 표 셀을 이미 줄로 뽑는다.** `DocxExtractor.elementBlocks`·`HwpxExtractor.SectionBlocks`
   는 문단 요소 `p`를 만날 때마다 블록을 끊는다. 표 셀(`w:tc`·`hp:tc`) 안의 문단도 `p`라 셀 하나가
   줄 하나(또는 여럿)가 된다. 3×4 표는 원문 12줄이다. **셀인지 본문인지는 기록되지 않는다.**
2. **출력은 이미 「구조는 두고 문장만 교체」다.** S6의 `TextUnitWalk`가 추출과 같은 차례로 `p`를
   걸어 `TextUnit`을 만들고 `rewrite`가 그 자리의 `t`를 갈아 끼운다. 셀 합침(N:1)·셀 안 나눔(1:N)
   에도 표 구조가 남는 것을 `PackagedOriginalReflectorTest`(「표 셀 둘이 한 줄로 합쳐져도 표 구조는
   그대로다」·「표 셀 안 1:N 나눔」)가 고정한다.
3. **프롬프트는 구조를 모른다.** `buildUserPrompt`는 마스킹 원문 전체를 `<문서>` 구간 하나에
   그대로 싣고, 스타일 규칙은 「나열할 것이 있으면 줄을 바꿔 한 줄에 하나씩」이라고 **줄을 늘리는
   방향**만 말한다. 셀 안에서 줄을 늘리면 1:N 나눔이 되고, 짧은 표제 칸(「구분」·「금액」)은 문장으로
   불어난다.
4. **정렬 앵커는 자리표시자와 사실뿐이다**(`SegmentAlignment.chooseAnchors`). 표제 칸·짧은 항목은
   앵커가 없어 `low`로 떨어지고, 화면은 「대응을 확인하지 못했습니다」, 내보내기는 차례 폴백이 된다.
5. **골든 63건 중 30건이 표·목록형이다** — 줄의 30% 이상이 8자 이하이거나 탭·세로선 셀이 있는
   문서(2026-09-06 계수). 장문 공고(`022`·`023`)는 절반이 그런 줄이다. 이 결함은 변두리가 아니다.
6. **저장 원문 형식은 바꿀 수 없다.** S1–S7의 모든 색인(`source_unit_indexes`·
   `compliant_source_units`·재변환 경로 변수)이 `splitUnits(source_text)` 좌표다. 계약도 저장 원문을
   「줄바꿈 통일 외에는 올린 그대로」로 못박았다(PR #53).
7. **자동 변환 1건 = LLM 호출 최대 2회**(master-plan §3.2). 셀마다 호출을 쪼갤 수 없다.

## 1. 결정

### 1.1 구조는 「원본 단위의 종류」 하나로 표현한다

원본 단위(=`splitUnits(source_text)`의 줄)마다 종류 하나를 붙인다. 새 데이터 모델은 이것뿐이다.

```text
enum UnitKind { BODY, TABLE_CELL, LIST_ITEM }     // core/segment
SourceStructure(kinds: List<UnitKind>)            // kinds.size == source_unit_count 가 불변식
```

- 표의 행·열 좌표, 목록의 깊이, 제목 수준은 **싣지 않는다.** 이번 결정은 「셀·항목을 합치거나
  나누지 말고 그 안만 바꿔라」를 말할 수 있으면 충분하고, 좌표를 실으면 S1–S7의 단위 모델(「추출
  원문의 한 줄」, 계획 §5)이 바뀐다. 좌표는 출력이 이미 원본 XML에서 직접 얻는다(S6).
- 종류가 **연속된 구간**(run)이 프롬프트와 화면의 단위다 — 「12~23째 줄은 표의 칸」.

### 1.2 종류는 추출 시점에 한 번 정하고 문서에 저장한다

`segment_map`은 매 조회마다 유도하지만(계획 §2) 종류는 **저장**한다. 이유 둘:

- 유도의 원천이 **원본 바이트**(DOCX·HWPX XML)다. 조회마다 최대 10MB 원본을 복호화해 DOM을
  세우는 비용은 `alignSegments`(≈수 ms)와 자릿수가 다르다. 반면 추출 시점에는 그 DOM이 이미
  손에 있다.
- 종류는 원문과 함께 **불변**이다. 원문이 바뀌지 않으니 낡을 일이 없다 — 검수본이 바뀌면 낡는
  `segment_map`과 다르다.

저장 위치: `documents.source_unit_kinds`(Flyway **V11**, `text`, nullable). 값은 줄 수만큼의
한 글자 코드 문자열(`B`·`T`·`L`)이다 — 20,000자 상한 문서도 수백 바이트이고 JSON 배열보다
읽고 비교하기 쉽다. `null`은 「이 조각 이전에 만든 문서」이고 전부 `BODY`로 읽는다. **백필하지
않는다** — 옛 문서는 다시 올리면 된다.

**형식별 원천**

| 형식 | `TABLE_CELL` | `LIST_ITEM` |
|---|---|---|
| DOCX | `p`의 조상에 `tc`가 있음 | `pPr/numPr`이 있음 |
| HWPX | `p`의 조상에 `tc`가 있음 | 문단 머리 텍스트 휴리스틱(아래 TXT와 같음) — HWPX 번호 매김은 스타일 참조라 1차에서 풀지 않는다 |
| TXT·붙여넣기 | 없음(전부 `BODY`) — 평문에는 셀이 없다 | 줄 머리가 `LIST_MARKER`(`StyleRules`, 「1.」「가)」「①」)이거나 글머리 기호(`•`·`·`·`-`·`○`·`□`·`※`)인 줄 |
| PDF | 범위 밖 — 전부 `BODY` | 범위 밖 — 전부 `BODY` |

휴리스틱은 core의 순수 함수 `inferUnitKinds(lines): List<UnitKind>` 하나이고, DOCX·HWPX 추출기는
XML에서 `TABLE_CELL`을 정한 뒤 나머지에 같은 휴리스틱을 적용한다(추출기의 `BlockSink.add`가
종류를 함께 받는다). **불변식 「종류 수 = 줄 수」가 깨지면 예외가 아니라 전부 `BODY`로 접고
카운터 하나만 올린다** — 구조 힌트는 파생 정보이지 변환을 막을 이유가 아니다.

### 1.3 프롬프트에는 구간으로 말한다

`buildUserPrompt`가 `SourceStructure`를 선택 인자로 받아, `<문서>` 구간 **뒤**에 `[구조]` 절을
붙인다. 구간이 하나도 없으면(전부 `BODY`) 절 자체가 없어 **오늘의 프롬프트와 바이트 단위로
같다** — 골든 기준선이 움직이지 않는다.

```text
[구조]
표: 12~23째 줄(「구분」부터 「비고」까지)은 표의 칸입니다. 한 줄이 한 칸입니다.
  - 칸을 합치거나 나누지 마세요. 줄 수와 순서를 그대로 두세요.
  - 칸 안에서는 줄을 바꾸지 말고, 길면 마침표로 문장을 나누세요.
  - 낱말 하나뿐인 칸(「구분」·「금액」 같은 표제)은 바꾸지 말고 그대로 쓰세요.
목록: 30~35째 줄은 목록 항목입니다. 항목 수·순서·앞의 기호(「①」·「-」)를 그대로 두고 항목 안의
  문장만 쉽게 바꾸세요.
```

- 줄 번호와 **첫·끝 칸의 문구**를 함께 준다 — 줄 번호만으로는 모델이 세지 못하고, 문구만으로는
  같은 문구가 여러 번 나올 때 어긋난다. 문구는 원문 조각이므로 `<문서>`와 같은 난수 id 구분자
  안에 둔다(리뷰 HIGH-4의 이유 그대로 — 원문 조각이 지시로 읽히면 안 된다).
- 「한 줄에 하나씩」 규칙과의 충돌은 이 절이 이긴다고 명시한다: 「위 규칙 중 줄을 바꾸라는 것은
  표·목록 밖에서만 적용합니다.」
- 보정 패스(`buildRepairPrompt`)에도 같은 절을 실어 2차 호출이 구조를 되돌리지 않게 한다.
- 재변환(`ReconvertUnitService`)은 대상 단위가 `TABLE_CELL`·`LIST_ITEM`이면 같은 문장을 단위
  단위로 붙인다(「이 문단은 표의 칸입니다 …」).

### 1.4 정렬에는 구조 사전확률을 준다 (게이트 뒤)

`alignSegments`는 그대로 두고, 그 결과에 **후처리** 하나를 더한다: 앵커로 경계가 잡힌 두 앵커
사이에서 원본 구간이 `TABLE_CELL`/`LIST_ITEM` run이고 쉬운 글 줄 수가 그 run의 줄 수와 **같으면**
차례 1:1 대응을 `high`로 올린다. 모델이 구조 지시를 지켰을 때 화면이 「확인 못 함」이라고 말하지
않게 하는 장치다. **이 항목은 §3 측정으로 지시 준수율을 본 뒤 켠다** — 준수율이 낮으면 같은 줄 수가
우연일 수 있어 `high`가 거짓이 된다.

### 1.5 화면

원본 패널 단위 목록에서 run을 시각적으로 묶고(연속 셀은 한 테두리, 항목은 들여쓰기) 첫 줄에
「표 칸」·「목록」 배지를 단다 — S7의 배지·`aria-describedby` 패턴 그대로. 표제 칸(낱말 하나)은
S7의 `compliant_source_units`와 겹치는 일이 많다 — 두 배지가 같이 붙어도 된다. 재변환 버튼은
막지 않는다.

계약: `segment_map.source_unit_kinds: string[]`(enum `body`·`table_cell`·`list_item`, 길이
`source_unit_count`, **required**) — S7과 같은 자리·같은 좌표. 옛 문서(컬럼 `null`)는 전부
`body`로 낸다. 계약 **2.19.0**.

### 1.6 하지 않는 것

- 표·목록을 **새로 만드는** 것(TXT 원본을 DOCX로 낼 때 실제 표 객체 생성). TXT는 구조가 없으니
  줄만 유지한다 — 오늘과 같다.
- 셀 단위 LLM 호출, 셀 단위 저변경의 **기계적 강제**(모델이 표제 칸을 바꿨을 때 되돌리기). 1차는
  지시와 측정까지다. 강제는 §3 결과가 「지시로 부족하다」일 때 별도 결정.
- HWPX 번호 매김 스타일 해석, 제목 수준, 중첩 목록 깊이, 셀 병합 좌표.
- PDF.

## 3. 측정 — 유료, 사용자 승인 뒤

지시가 먹히는지는 실제 모델로만 안다. 골든 레인(`GoldenCorpusLlmEvaluationTest`, 제품 조립
anthropic·claude-sonnet-5)으로 §0-5의 표·목록형 30건을 **구조 절 on/off** 각 1회 돌린다.
지표는 넷이고 전부 무료 계산이다:

1. **run 줄 수 보존율** — 셀·항목 run의 원본 줄 수와 정렬 결과의 쉬운 글 줄 수가 같은 run의 비율.
2. **표제 칸 원문 유지율** — 낱말 하나뿐인 셀이 결과에 그대로 남은 비율(S7의
   `compliant_source_units`와 교집합으로 뽑는다).
3. 스타일 위반 밀도(§1.2 B3 자)와 사실 보존 — 오늘 자로 **나빠지지 않아야** 한다.
4. `segment_map` `high` 비율 — 화면에서 「확인 못 함」이 줄었는가.

판정: ⑴·⑵가 오르고 ⑶이 유지되면 S8-4를 켠다. ⑴이 오르지 않으면 「지시로 부족」이고 §1.6의
기계적 강제를 별도로 결정한다. 비용은 30건×2회 = 60호출, 오늘 단가로 수 달러 수준이며 **실행 전에
사용자 승인을 받는다**(CLAUDE.md 유료 평가 규칙). **→ 승인됨(2026-09-06, 사용자).** 승인 범위는
이 절의 설계(표·목록형 30건 × 구조 절 on/off 각 1회, 제품 조립 anthropic·claude-sonnet-5)
하나다. 실행은 S8-2가 병합돼 on/off를 만들 수 있게 된 뒤이며, 범위를 넘는 재실행은 다시
승인받는다.

## 4. 리스크

- **추출과 반영의 차례 불일치.** 종류는 추출기가, 자리는 반영기가 각자 걷는다. 둘의 차례가
  같다는 것은 이미 테스트가 지키고(`PackagedOriginalReflectorTest` fixture마다), 종류는 자리를
  바꾸지 않으므로 어긋나도 배지가 틀릴 뿐 파일이 틀리지 않는다.
- **프롬프트 길이.** run 수만큼 늘어난다. 장문 공고(`022`, 697줄)는 run이 수십 개일 수 있다 —
  S8-2에서 run 수 상한(예: 40)을 두고 넘으면 「이 문서에는 표·목록이 많습니다. 줄 수와 순서를
  그대로 두세요」 한 줄로 접는다. 상한은 구성값이다.
- **휴리스틱 오탐.** 「1. 신청 방법」 같은 제목 줄이 `LIST_ITEM`이 된다 — 무해하다(항목 안 문장만
  바꾸라는 지시는 제목에도 옳다). 반대로 글머리 기호 없는 목록은 `BODY`로 남는다 — 오늘과 같다.
- **옛 문서.** `null` 컬럼은 전부 `BODY`라 이 조각의 효과가 없다. 백필은 원본 바이트 재파싱이라
  하지 않는다.
- **셀 안 다중 문단.** 셀 하나에 문단 둘이면 줄 둘·종류 `T`·`T`다. 「한 줄이 한 칸」이라는 프롬프트
  문구는 근사다 — 「한 줄이 칸 하나(또는 칸 안 문단 하나)」로 쓴다.
