# 운영자·관리자 화면 개선

> 2026-10-08 통합 상태: 아래는 최초 브랜치의 계획·검증 기록이다. 현재 main 통합에서는
> 관리자 마이그레이션을 V47로 옮겼으며, 최신 검증은 [통합 기록](../reviews/2026-10-08-admin-operations-integration.md)을 따른다.

## 목표와 경계

관리자가 처리할 일을 발견하고 고객 상태를 확인한 뒤 안전하게 조치하고 결과를 확인한다.
브랜치는 `feat/admin-operations-20261007`, 작업 위치는 별도 worktree
`/home/deploy/project/easy-doc-admin-operations`다. 기존 main의 결제·월별 관리 변경은
기준선 `6a6007d1`에 보존했다. 기준선 이후 변경만 이번 구현·리뷰 대상이다.
main과 서버 설정을 수정하지 않는다. 운영 재배포, 라이브 결제 개방, 실제 메일 발송은
제외한다. `is_admin` 권한을 유지하며 역할 분리와 탈퇴·거래 보존 정책은 제외한다.

## 구현 범위

1. 금융 상태와 복구: 작업공간 공통 갱신으로 구독·결제·잔액·목록을 동기화한다.
   진행 중에만 폴링하며 실패 시 마지막 확인 시각과 재조회 수단을 제공한다.
   서버의 조치 가능 여부와 불가 사유를 표시한다. UUID와 제출 내용을 관리자·작업공간·
   조치별 sessionStorage에 보관하고 로그아웃 시 정리한다. 결과 미확정 요청은 같은
   UUID로 조회·재전송하며 409를 무조건 초기화하지 않는다. 새로고침·월 변경·재진입에
   미확정 작업을 복구한다. 결산 실패 중에도 구독과 결제 운영 관리가 표시되어야 한다.
2. 세금계산서: 선택한 행 상세에서 상호·사업자번호·기간·담당자 이메일·대표자·주소·
   메모·처리 시각을 함께 표시한다. 버튼은 ‘발급 완료로 기록’, ‘거절로 기록’이다.
   응답 유실과 처리 완료 409에는 최신 결과를 조회한다.
3. 처리할 일: 첫 탭에 장기 미확정 결제, 환불 진행, 카드 삭제 대기, 메일 실패·확인 필요,
   미처리 세금계산서를 서버 집계한다. 종류·상태·환경 필터, 페이지, 심각도·발생 시각·ID
   안정 정렬, 작업 건수, 경과 시간, 다음 조치, 상세 링크를 제공한다.
4. 메일 복구: 환경·이벤트·시각·시도 이력·운영자 확인 기록을 제공한다. 결과 미확정은
   미전달 확인 후에만 재발송하며 전달 확인은 완료로 분류한다. 확정 실패도 대상과 사유
   확인이 필요하다. 환경 미상·worker 환경 불일치는 재발송하지 않는다. 수신처를 바꾸지
   않고 기존 알림 아래 새 시도를 기록한다. claim과 시도 생성은 원자적이며 중단된 발송을
   자동 재발송하지 않는다. 기존 환경·시도·전달 여부를 추정해 채우지 않는다.
5. 감사·탐색: 관리자·대상·사유·요청/완료 시각·안전한 변경 전후 값과 거래 연결을 표시한다.
   공급자 원문·비밀값은 제외한다. 오류는 변환 ID 복사·작업공간 링크·코드/기간 필터·페이지,
   의견은 서버의 사용 가능 여부·최대 평점·기간 필터, 공지는 실제 노출 미리보기·게시 확인·
   작성/수정 시각을 제공한다. 초안·예약은 제외한다. 목록 결제 요약은 한 응답에 포함하여
   행별 원장 조회를 없애고 환불만 있는 달도 환불일을 표시한다. 탭·필터·페이지·작업공간·월을
   URL에 반영하고 직접 진입과 뒤로 가기를 지원한다.

## API와 데이터

- `GET /admin/operations`: 필터·페이지와 종류별 작업 집계.
- 기존 billing 조회: 가능한 조치·불가 사유·안전한 감사 상세·주문 종류/시각.
- `GET /admin/workspaces/{workspace_id}/billing/requests/{operation_id}`: 요청별 복구 조회.
- `GET /admin/notifications`, `POST /admin/notifications/{id}/resolve`,
  `POST /admin/notifications/{id}/retry`: 알림 이력·확인·조건부 재발송 예약.
- 기존 의견 조회의 서버 필터, `GET /admin/errors/events`, 목록의 결제·환불 요약.

공개 계약·Kotlin DTO/계약 테스트·프런트 타입을 함께 수정한다. 기존 API는 호환성을
유지하며 확장한다. 새 변경 요청은 UUID·확인한 revision·필수 사유로 보호하고 동일
UUID/내용은 같은 결과, 다른 내용은 거절한다. V46 이후 마이그레이션만 추가한다.
새 관리자 경로는 인증·권한 카탈로그와 계약 검증에 등록한다.

호환성 적용: 기준선에 이미 존재하는 결제 관리 조치 엔드포인트의 `expected_revision`은
기존 호출자 호환을 위해 선택 필드로 추가한다. 새 관리자 화면은 revision을 조회하기
전에는 새 조치를 제출하지 않고 항상 확인한 값을 보낸다. 새 알림 변경 엔드포인트는
revision을 필수로 받는다. 이는 기존 API에 필드·선택 파라미터를 추가한다는 요청을
따른 구분이며, 구형 호출자가 revision 없이 호출하면 CAS 보호를 받지 못한다.

## 분담과 반복

총괄 Codex는 계약·공유 API·문서·통합 검증·최종 리뷰를 담당한다. 실행 Codex는
백엔드, 금융 프런트, 나머지 관리자 프런트의 겹치지 않는 파일을 맡는다. 재귀 위임과
새 검증 하네스는 만들지 않는다. 설계→구현→검증→리뷰→수정으로 최대 3회 수정한다.

## 검증·완료 기준

기존 테스트에 상태 동기화, 응답 유실/409/422/동시 조치, 월 변경/새로고침 복구,
결산 장애, 세금계산서 대상, 큐 집계/정렬/페이지, 메일 환경/중복/중단,
감사 비밀값 제외, 서버 의견 필터, 게시 확인, 환불일, URL/뒤로 가기/키보드를 추가한다.
최종 diff에 백엔드 `./gradlew build`, 프런트 `npm run check`, 전체 테스트, build,
`docker compose config`를 실행한다. 기존 Playwright 관리자 흐름과 격리 DB Toss 테스트
E2E를 실행한다. 메일은 fake만 사용한다. 검증 전 Gradle 프로세스와 메모리를 확인하고
무거운 검증은 호스트에서 하나만 실행한다. 가용 메모리 6GB 미만이면 시작하지 않는다.

## Claude 리뷰

설치 CLI의 Sonnet을 명시하고 자동 상위 모델 전환 없이 최대 3회, 합산 $10
(최초 $4, 이후 각각 $3)로 제한한다. 기준선 이후 diff·관련 소스·계약·계획·검증 결과를
비밀 없는 리뷰 디렉터리로 전달한다. 읽기 도구만 허용하며 명령 실행·수정·하위 에이전트·
외부 연결을 금지한다. 실제 모델·비용·판정과 지적별 수정은
`docs/reviews/2026-10-07-admin-operations-claude-review.md`에 기록한다.
원문 실행 로그·API 키·개인 설정은 커밋하지 않는다. 한도나 환경 장애로 차단 결함이
남으면 완료로 표시하지 않는다. 산출물은 구현 로컬 커밋·계획·검증·리뷰 기록이다.
