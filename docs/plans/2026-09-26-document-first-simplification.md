# 쉬운 문서 작성에 집중하는 화면 단순화

작성일: 2026-09-26 · 상태: 구현·로컬 검증·독립 리뷰 완료, PR CI 후 파일럿 반영

## 제품 판단

사용자는 어려운 안내문이나 설명문을 쉽게 바꾸려는 작성자다. 서비스의 중심은 문서 입력 → 쉬운 글 확인·수정 → 저장·내려받기다. 문서 이해를 돕는 그림은 이 결과에 필요한 경우 선택적으로 추가한다.

R2 행동 안내는 별도의 적합성 분석, 추출 교정, 항목별 근거 대조, 두 결과 모드 선택, 재검토와 적용을 요구한다. 누락·과금·동시 편집을 보호하는 구현 검사는 통과했으나, 이것이 작성자에게 유용하고 이해하기 쉬운 기능이라는 증거는 아니다. 이전 계획은 사용자가 해야 할 일을 늘리는 문제를 해결하지 못했다. 행동 안내의 제품 노출과 추가 확장을 중단한다.

## 이번 변경

- 결과 화면에서 행동 안내 탭과 기존/신규 행동 안내 패널을 제거한다. 서버가 지원 capability를 보내도 마운트하거나 관련 API를 호출하지 않는다. 다른 이름의 고급 메뉴로 옮겨 동일한 복잡성을 남기지 않는다.
- 쉬운 글 결과를 항상 주 작업으로 보여 준다. 본문/행동 안내/검수 기록 중 작업을 고르는 상위 탭을 없앤다.
- 수정 기록은 필요할 때 여는 보조 영역으로 둔다. 기록을 보려고 본문 작업에서 이탈할 필요가 없게 한다.
- 만족도·소요 시간·의견을 받는 폼은 `의견 보내기 (선택)`을 열 때 보여 준다. 의견 제출을 문서 완성의 필수 단계처럼 보이게 하지 않는다. 제출 API·항목과 제출 성공 안내는 유지한다.
- 그림 관련 영역은 `그림으로 설명하기 (선택)`을 열 때 보여 준다. 내부 기능과 선택/배치 동작은 유지한다. 닫아도 기존 컴포넌트를 마운트 상태로 유지해 배치 수/상태 콜백과 그림의 파일 미포함 고지, 오래된 배치의 미리보기·생성 보호, 진행 작업 및 입력 상태를 잃지 않는다. 문서 다운로드에 새로운 그림 관련 차단을 추가하지 않는다.
- 본문 수정·저장·내려받기, 미저장 이탈 보호, 충돌 방지, 실제 필요한 부분의 검토 신호와 선택적 그림 설명은 유지한다.
- 저장된 본문·분석·이전 본문·기록을 삭제하지 않는다. backend 계약·자료 보존과 기존 회귀 검사는 유지한다. 미사용 서버 기능의 물리적 제거는 이번 변경 범위가 아니다.
- 운영의 행동 안내 신규 요청을 비활성화한다. 배포 전 진행 중 작업을 확인하고, 기존 작업 정산과 저장 자료를 손상시키지 않는다.

## 다른 복잡성을 판단하는 기준

1. 처음에는 결과물과 다음 행동을 이해할 수 있는 정보만 보여 준다.
2. 보조 기능은 결과를 고치거나 설명하는 맥락에서 요청할 때 연다.
3. 문제 없는 문단에 일괄 검토나 대응표 작성을 요구하지 않는다. 실제 확인 신호와 필요한 안전 안내는 숨기지 않는다.
4. 분석 버전·내부 분류·생성 모드 같은 구현 개념을 사용자 작업으로 바꾸지 않는다.
5. 기능 수나 구현 완료를 제품 가치의 근거로 삼지 않는다. 작성자의 선택과 작업 단계가 줄었는지 확인한다.

이번에는 결과 화면의 명확한 복잡성을 먼저 줄인다. 문서 입력·읽기 수준·오류/비용 고지·그림 기능을 일괄 삭제하거나 새 설정 체계를 추가하지 않는다. 추가 진단은 파일·사용자 영향과 함께 남기고 독립된 요구로 판단한다.

## 실행과 완료 기준

허용 범위는 `frontend/`와 관련 문서·운영 설정이다. API 계약·Kotlin 제품 로직·DB 스키마 변경은 없다. 프런트 구현 담당과 읽기 전용 독립 리뷰를 분리하고 재귀 위임·유료 모델 호출·새 검증 하네스를 만들지 않는다. 수정·검증은 최대 6회다.

필수 검증은 frontend check·전체 test·build, 기존 E2E runner의 결과 편집/저장/출력·기록·모바일 접근성 및 행동 안내 미노출/무요청 회귀다. 폐기하는 행동 안내 UI E2E는 활성 제품 흐름의 회귀 검사로 대체하며 백엔드 데이터·과금·정산 검사나 민감 정보/소유권 검사 기준을 완화하지 않는다.

검증과 독립 PR 리뷰 후 기존 사용자 승인 절차대로 최종 approve·CI 통과 → main 병합 → 파일럿 운영 반영·`docker_startup.sh restart` → API/worker/DB/프런트 확인을 진행한다. 호스트의 무거운 빌드·컨테이너 테스트는 한 번에 하나만 실행하고 가용 메모리 6GB 미만이면 시작하지 않는다.

## 추가 진단과 보류 범위

독립 리뷰에서 결과 화면의 동등한 작업 탭, 여러 보조 패널, 입력 단계의 읽기 수준/과금 계산 설명, 결과 하단의 상시 설문 폼을 복잡성 지점으로 확인했다. 이번에는 작업 탭과 상시 설문을 정리하고 상시 노출된 그림 영역을 한 선택적 펼치기로 낮춘다. 그림 도구를 자동 삽입하거나 일괄 삭제하지 않는다. 입력 화면의 읽기 수준·비용 고지는 후속 UX 설계에서 실제 예상 비용과 선택 시 설명 중심으로 검토하며 이번에 고지를 제거하지 않는다.


구현 결과와 검증 근거는 [단순화 구현 기록](../reports/2026-09-26-document-first-simplification.md)을 따른다.
