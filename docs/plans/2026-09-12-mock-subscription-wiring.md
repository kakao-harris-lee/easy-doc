# 월 구독 mock 연결 — 2026-09-12

사용자 요청: 기존 구독 문서·구현의 배선을 확인하고 `/usage`에서 플랜과 사용량을 간단히 확인한다. 카드 결제 제공자는 토스페이먼츠 예정이며 지금은 mock만 사용한다.

## 현재 연결

- React 런타임은 `frontend/src`다. `frontend/easy-read-ai`의 billing/admin-subscriptions는 디자인 시안이며 서비스·결제 데이터의 정본이 아니다.
- `/usage` → 작업 공간 구독 조회 → 플랜 선택 → 테스트 결제 → DB 결제 기록·구독 저장 → 기존 `CreditAccountService.setAllowance` → 사용량 새로 조회.
- 관리자 → 작업 공간 목록 → 상세 → 월 구독 플랜·테스트 결제 내역. 기존 크레딧 수동 조정은 추가/차감이며 구독 갱신이 아니다. UI의 잘못된 ‘월 구독 갱신’ 명칭을 ‘월 제공량 수동 보정’으로 수정했다.
- V21의 주기 이용량/초기화는 이미 구현되어 있다. V23은 `workspace_subscriptions`, `subscription_payments`를 추가한다(접속기록이 V22). 기존 계정의 기간·이용량을 자동 변경하지 않는다.
- 계약 2.33.0: GET/DELETE `/workspaces/{workspace_id}/subscription`, POST `.../subscription/checkout`, GET `/admin/workspaces/{workspace_id}/subscription`.

## 테스트 범위와 정책

이 문서의 최초 mock 플랜(Starter 1,000원·Pro 3,000원)은 2026-09-13 후속 결정으로 폐기됐다. 현재 서버 테스트 결제는 **Start 월 50크레딧·99,000원** 하나만 허용한다. `/usage`의 실제 가격표는 Start 99,000원·Basic 190,000원·Pro 599,000원이며, Basic·Pro는 선택만 가능하고 결제는 준비 중이다. 별도 `테스트 구성 · 동작 확인용` 영역은 제거했다.

`PaymentGateway`의 `StubPaymentGateway`만 구현되어 있다. 네트워크 호출, 카드번호 입력, SDK, 빌링키가 없다. `provider=toss`는 미구현 설정으로 기동을 거부한다. 향후 실제 결제 어댑터는 외부 결제 성공과 DB 커밋 사이의 복구·조회/대사를 별도로 구현해야 한다. 현재 DB 트랜잭션 안의 동기 stub를 그대로 실결제에 교체하면 안 된다.

- 테스트 성공: 플랜의 월 제공량으로 **설정**한다. 기존 잔액을 더하지 않으며 진행 중인 변환의 예약량을 보존한다.
- 테스트 실패: 실패 기록만 남기고 구독·이용량을 변경하지 않는다. 화면 체크박스로 실패를 재현한다.
- 같은 작업 공간·주문 UUID의 재시도: 한 번만 결제/설정. 다른 플랜·실패 설정으로 같은 UUID를 재사용하면 409. 이미 활성인 구독을 새 주문으로 중복 구매해도 409.
- 갱신: worker가 60초마다 종료된 구독을 조회한다. mock 결제가 성공한 뒤 한 주기 이용량을 설정한다. 중단된 여러 달을 소급 청구하지 않고 처리 시점부터 한 달을 연다. 실패하면 past_due로 중단하고 만료 이용량을 제거한다.
- mock 비활성화 후에도 이미 열린 주기는 종료 시 이용량을 제거하며 추가 결제하지 않는다.
- 취소: 현재 기간은 유지하고 갱신을 중단한다. 기간 종료 시 expired 및 이용량 0. 즉시 환불을 뜻하지 않는다.
- 기존 크레딧 초기화 배치는 구독 테이블에 등록된 계정을 제외한다. 결제 확인 없이 같은 계정이 자동 충전되는 두 번째 경로를 막는다.
- 결제 내역은 최근 20건. **가상 기록이며 세무 증빙이 아니다.** 실제 서비스의 결제 증빙은 카드 영수증이다. 사용자 세금계산서 요청 UI는 추가하지 않는다.

## 실행 설정

`.env.example`은 `EASYDOC_PAYMENT_PROVIDER=stub`, `EASYDOC_PAYMENT_MOCK_ENABLED=false`가 기본이다. 사용자가 요청한 로컬 `.env`만 mock을 켠다. API·worker 모두 같은 설정을 읽는다. mock 활성화는 local/test 프로필에서만 허용하고 prod/production과 함께 켜면 기동을 거부한다.

`EASYDOC_CREDITS_ENFORCED`는 별도 설정이며 이번 변경으로 켜지 않는다. mock 구독을 선택해도 기존 무료 파일럿 전체에 이용 제한을 소급 적용하지 않는다.

## 남은 범위

토스 라이브 결제 개시, Basic·Pro 결제, 실제 정기결제 계약, 플랜 변경/일할 계산, 연간 계약은 아직 구현하지 않았다. 기존 결제 계획의 해당 항목을 완료로 간주하지 않는다. mock 단계에서는 Start 월 구독 구매·갱신·실패·기간 종료 취소와 조회만 연결한다.
