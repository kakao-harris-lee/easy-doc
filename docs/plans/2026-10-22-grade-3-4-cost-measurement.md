## 1. 질문

`grade_3_4`(더 쉽게 · 초등 3~4학년 수준)는 고객 크레딧을 기본보다 1.2배 받는다. 0.1크레딧 단위 수에 1.2를 곱해 올림한다(D11, `Credits.requiredFor`). 프롬프트가 달라지고 설명이 길어지므로 provider 원가는 이와 다르게 움직일 수 있다. 이 계획은 그 원가를 재서, 1.2배가 원가 증가를 덮는지 판정한다.

**주 지표 R**은 청구 크레딧당 원가의 비다. 1 이하이면 1.2배가 원가 증가를 덮는다.

```text
R = (grade_3_4 원가 ÷ grade_3_4 청구 크레딧) ÷ (grade_5_6 원가 ÷ grade_5_6 청구 크레딧)
```

**보조 지표**는 원가가 왜 그렇게 나왔는지 설명하는 데 쓴다.

- **M:** 같은 원문 기준 원가 배율이다. 1.2와 직접 비교한다.
- **출력 팽창:** 원문 글자당 출력 토큰 수다. D12 상한의 근거로도 넘긴다.
- **입력 토큰:** 수준별 프롬프트 증가분을 본다.
- **운영 신호:** 보정 발생률, 변환 지연, 시간 초과·절단 수를 본다.

**범위 밖:**

- `grade_3_4`의 품질 판정은 ER-26의 일이다.
- D12의 입력·출력·저장 상한 결정은 이 측정의 팽창 수치를 근거로 넘기기만 하고, 여기서 정하지 않는다.
- `middle_school`은 1.0배 과금이라 질문 밖이다. 1단계 조회에는 함께 나오므로 참고로만 기록한다.

## 2. 판정 기준

판정에는 가격 정본에 이미 있는 규칙을 쓴다. 규칙은 "LLM 비용이 VAT 제외 매출의 25%를 넘으면 제공량·모델·재변환 정책을 조정한다"이다.

이용량을 전부 `grade_3_4`로 쓰는 최악의 경우를 가정한다. 플랜 p가 견디는 R의 한계는 아래와 같다.

```text
R_max,p = 0.25 × VAT 제외 매출_p ÷ (제공 크레딧_p × grade_5_6 크레딧당 원가 × 1,500원)
```

현재 `grade_5_6` 크레딧당 원가는 US$0.05750이다(3건 표본). 이 값으로 계산한 한계는 Start 약 5.2, Basic 약 2.5, Pro 약 1.58이다. 따라서 Pro가 판정을 정한다. 측정 뒤에는 `grade_5_6` 원가도 새 값으로 바꿔 다시 계산한다.

| 결과 | 판정 |
|---|---|
| R ≤ 1.0 | 1.2배를 유지한다. 가격 정본에 측정값만 기록한다 |
| 1.0 < R ≤ R_max,Pro | 1.2배를 유지한다. 가격 정본 표에 `grade_3_4` 원가를 더하고, 30일 운영 원장으로 다시 확인한다 |
| R > R_max,Pro | 사용자가 정한다. 선택지는 배율 조정, `grade_3_4`의 모델·effort 조정, Pro 제공량 조정이다 |

R의 범위가 두 구역에 걸칠 만큼 넓으면 판정하지 않고 다음 단계로 넘어간다.

## 3. 단계

### 1단계: 파일럿 원장 조회 (무료)

- **근거:** `llm_calls`에는 호출마다 수준 스냅샷 `reading_level`(V35·V46)이 남는다. 함께 남는 값은 용도(`convert`·`repair`·`reconvert`), 토큰, 지연, 예상 비용, 문서 글자 수 스냅샷(`document_char_count`)이다.
- **대상 기간:** 파일럿은 2026-09-25부터 `grade_3_4`를 켰다(`docs/pilot-runbook.md`의 「읽기 수준 선택 설정」).
- **실행:** 공개 서버의 운영자나 에이전트가 [handoff](2026-10-22-grade-3-4-cost-measurement-handoff.md) 절차대로 실행한다.
  - 이 작업 기기에는 파일럿 컨테이너가 없다.
  - 서버는 배포 작업 트리를 바꾸지 않고, `git show origin/main:`으로 SQL 파일만 꺼내 읽기 전용으로 돌린다.
  - 결과는 집계만 나온다. 원장에는 본문이 없다.
- **질의:** [`2026-10-22-grade-3-4-cost-measurement.sql`](2026-10-22-grade-3-4-cost-measurement.sql)에 있다. `BEGIN READ ONLY … ROLLBACK`, 질의당 60초 제한이다.
  - **① 표본 크기와 단가 기록:** 수준·용도·모델별 호출 수와 `estimated_cost_usd`가 비어 있는 호출 수를 센다. 비어 있는 행은 ②에서 빠진다.
  - **② 완료된 최초 변환(변환 + 보정):** 1건 기준으로 모델·수준·길이 구간별로 낸다. 항목은 청구 크레딧당 원가, 1천 자당 원가, 원문 글자당 출력 토큰, 입력 토큰, 보정률, 지연이다.
  - **③ 문단 재변환:** 재변환 1회는 원장에 1~2행(재변환과 그 보정 모두 `reconvert`)으로 남지만 크레딧은 1회만 받는다(`ReconversionInputPreparer.kt:63`, `unit.length` 기준). 그래서 같은 변환·같은 단위 길이로 3분 안에 이어진 행을 1회로 묶어 근사한다. 같은 문단을 3분 안에 다시 재변환하면 한 번으로 합쳐지는 한계가 있다.
- **사전 시험:** 2026-10-22에 로컬 일회용 PostgreSQL에서 확인했다. 원장과 같은 열 구성의 표에 표본 행을 넣고 돌린 결과가 손으로 계산한 기댓값과 같았다. 실패한 변환 제외, 재변환 묶음, 0.1크레딧 올림, `ROLLBACK` 종료를 확인했다.

**이 조회의 한계:**

- 두 수준이 서로 다른 문서를 변환했으므로 짝지은 비교가 아니다.
- 「더 쉽게」를 고르는 사용자의 문서가 따로 몰려 있을 수 있다.
- 운영자의 시험 사용이 섞여 있을 수 있다. 시험 워크스페이스를 알면 `workspace_id`로 뺀다.

길이 구간으로 나눠 보는 이유는 고정 프롬프트 비용 때문에 짧은 문서의 크레딧당 원가가 높아서다.

**2단계 이후 생략 조건:** 아래 두 가지를 모두 만족하면 1단계 결과만으로 판정하고 2·3단계를 생략한다.

- 길이 구간마다 수준별 완료 변환이 30건 이상이다.
- 구간별 R이 모두 2절 판정표의 같은 칸에 든다.

하나라도 아니면 2단계로 간다.

### 2단계: 유료 레인에 수준 노브 추가 (코드 변경, 무료)

**현재 상태:** 유료 골든 레인 `GoldenCorpusLlmEvaluationTest`는 `ConvertDocumentUseCase.convert`를 읽기 수준 없이 불러서 항상 `grade_5_6`으로 변환한다. 그런데 `convert`는 이미 `readingLevel` 인자를 받는다(`ConvertDocumentUseCase.kt:116`). judge 프롬프트도 수준 인자를 받는다(`LlmPrompt.kt:113`).

**바꿀 것(평가 레인 코드만):**

- 환경변수 `EASYDOC_LANE_READING_LEVEL`을 더한다. 기본값은 `grade_5_6`이다.
- 이 값을 변환과 `GoldenJudge`에 넘긴다.
- `GoldenJudge`는 `core/.../quality/JudgeLane.kt`에 있고 지금은 judge 프롬프트에 수준을 넘기지 않는다. 그래서 기본값 `grade_5_6`의 수준 인자를 더한다. 이 클래스는 품질 평가에서만 쓰인다.
- 조건 줄(`conditions.txt`와 리포트)에 수준을 찍는다.
- 문서별 줄에 아래 항목이 없으면 더한다. 이미 있는 항목은 그대로 쓴다.
  - 원문 글자 수
  - 출력 글자 수
  - 보정 여부
  - 변환+보정 비용과 judge 비용(서로 분리)

**바꾸지 않을 것:** 제품 변환·과금 경로와 계약은 그대로 둔다.

**진행 방식:**

- Sonnet 실행 에이전트가 구현한다.
- 실패하는 테스트를 먼저 쓴다. fake provider로 노브의 수준이 변환과 judge까지 전달되는지 고정한다.
- 기존 `./gradlew build`로 검증한다.
- PR을 열고, 저자와 다른 Claude 측 리뷰 판정(sonnet)을 PR 코멘트로 남긴다.

### 4단계: 기록

- **가격 정본:** `grade_3_4` 크레딧당 원가와 R, 판정, 표본 크기를 적는다. 판정표의 둘째 칸 이상이면 수익성 표에 `grade_3_4` 행을 더한다.

- **과금 변경:** 필요하면 별도 결정으로 다룬다. 계약·서버·프런트를 한 단위로 바꿔야 하기 때문이다.
