# 프롬프트·사전 주입 재검증과 개선

## 목표와 범위

사용자가 재확인한 이해 기준은 보편적인 초등학교 5~6학년 수준의 어휘와 문장으로 원문을 자연스럽게 풀어 쓰는 것이다. 독자 모집, 문서별 정답집, 사전 전수 구축은 선행 조건이 아니다. 기존 Kotlin 제품 경로와 유료 레인에서 변환·보정·사전 선별/주입·평가를 함께 점검한다. 공개 API와 프런트엔드는 바꾸지 않는다. 기존 작업 변경분을 유지한다.

## 확인한 구조와 가설

- 변환 system에는 역할, 스타일 원칙, 원문 보존, 길이, 분할 예시, 표 지시, 내장 어려운 말 목록, 조건부 목록, 개념 설명, 주입 방어, 자가 점검, 출력 형식이 조립된다. 의미 보존·길이·공식 이름·개념 설명 지시가 반복된다.
- user에는 사전에서 매칭한 자료가 문서 앞에 추가된다. 사전은 문자 트라이의 최장일치·경계 검사와 중요도/문자 예산 선별이다. 임베딩이나 외부 법령 검색이 아니다. substitute/gloss/keep 구역 자체가 다시 편집을 지시한다.
- 보정은 역할을 두 번 받고 규칙·뜻풀이 지시를 다시 받으며, 원문과 초안·기계 지적을 받는다. 첫 변환에 들어간 사전 자료는 보정에 전달되지 않는다.
- 50자·쉼표 제한은 의미 우선이라고 지시하면서도 해당 규칙 위반 하나만으로 보정을 호출한다. 문체 지적 개수로 채택을 결정해 길이 감소가 유리하다.
- judge는 낯선 용어의 설명 부족 하나도 문서 전체 실패로 처리한다. 사용자가 정한 전체 어휘·문장 수준과 국소 표현 개선의 구분에 맞지 않는다.

가설은 코드상의 구조 관측과 분리한다. 지시 중복/충돌이 실제 품질을 떨어뜨리는지, 사전이 기여하는지, 보정이 개선하는지는 같은 문서의 호출 결과로 판단한다. 단순히 짧게 만들었다는 이유로 새 지침을 채택하지 않는다.

## 예산과 비교 설계 — 유료 호출 전 고정

총 누적 승인 상한은 **US$50**이다. 이전 완료 호출의 응답 usage와 종료 기록으로 확인한 이월 예상액은 **$8.552242**다. 새 실행의 예약 합계 상한은 **$40.00**, 합계 $48.552242로 $1.447758를 여유로 둔다. 이번 실행 중 예약은 반환하지 않고 실패·재시도도 사전 예약한다. 모든 비용에 평가 호출을 포함한다. 기존 임시 Node 실행 명령은 기존 Kotlin 레인을 실행하는 용도로만 조정하며 새 하네스나 Python을 만들지 않는다.

1. 현재 변환/사전을 유지한 Astra medium 기준 3건(`001-current`, `087`, `097`), 출력 8,192. 기존 레인 opt-in 기록에 실제 system/user를 추가한다. judge만 사용자 기준에 맞춰 먼저 정렬하고 이후 모든 조건에 동일하게 적용한다. 예약 상한 $6.5.
2. 작성 원칙을 한곳으로 모은 간결한 변환/보정 프롬프트와 기존 사전 주입을 같은 3건·모델·effort·한도로 비교한다. 사전 데이터·보정 호출 조건은 이 단계에서 유지해 변수를 구분한다. 예약 상한 $6.0.
3. 2와 같은 코드에서 사전 주입만 끈 조건을 비교한다. 예약 상한 $5.5. 결과에 따라 사전 자료의 표현·선별 또는 보정 기준을 추가 수정할 필요가 있으면 변경 이유와 다음 조건을 호출 전에 기록한다.
4. 선택한 구성을 기존의 다른 유형 문서와 긴 문서에서 확인하고, 개발 표본의 반복 결과도 확인한다. 표본·횟수·예약 상한은 선택 후 해당 호출 전에 기록한다. 불필요한 추가 반복은 하지 않는다.
5. 품질이 확인된 구성에서 저비용 모델을 비교할 수 있다. 의미 오류나 전반적인 어려움이 있으면 가격만으로 교체하지 않는다. 총 상한을 유지한다.

## 이번 판정 방법

Codex가 원문과 실제 출력의 전체 문단을 대조한다. 평가 질문과 자료는 기존 것을 진단 보조로 쓰며 모든 단어의 정의를 채워야 하는 정답집으로 사용하지 않는다.

- **의미:** 대상·제외·필수/선택·가능성·조건 결합·날짜·금액·공식 이름이 달라져 해석이나 행동이 바뀌면 중대한 오류다. 숫자 보존 검사만으로 의미 보존을 확정하지 않는다.
- **전체 쉬운 정도:** 공문 어휘와 압축 문장을 일상적인 말과 자연스러운 문장으로 풀었는지 본다. 낯선 용어 하나가 남았다는 이유로 자동 실패시키지 않되, 핵심 내용을 이해하기 어렵게 만드는 설명 부족이나 문서 전반의 어려운 표현 반복은 수정한다.
- **문맥:** 관련 문장이 문단으로 이어지고 주어·조건·순위가 분명해야 한다. 무조건적인 분할·반복·뜻풀이 삽입 비문을 개선한다.
- **판정 기록:** 문서별로 중대한 의미 오류, 전반적인 작성 수준, 국소 개선점을 구분한다. 개발·확인 표본에서 중대한 의미 오류가 없고 전체 작성 수준이 목표에 맞는 구성을 채택한다. 국소 개선점은 별도 기록한다. 모델 judge와 스타일 점수는 진단용이며 직접 대조를 대체하지 않는다.
- **보정/비용:** 초안·보정·실제 채택 결과를 구분하고 변환+보정 비용을 문서별로 합산한다. judge 비용은 별도로 표시한다. 이전 기준의 통과율을 소급 변경하지 않는다.

## 2차 개선과 확인 조건 — 2026-09-12 09:25 KST, 다음 호출 전

## 자동 보정의 역할 정렬 — 2026-09-12 10:01 KST, 변경·호출 전

현재 작성 기준은 문장 길이를 보조 기준으로 삼고 낯선 단어 한 곳을 전체 실패로 처리하지 않는다. 그런데 자동 보정은 LENGTH·COMMA·DIFFICULT_WORD 하나에도 글 전체를 다시 쓴다. `reference-rag`의 Astra 첫 초안 3건을 전부 대조한 결과, 이미 전반적으로 쉬운 글이고 조건을 보존하고 있었다. 087의 보정은 정확한 조건 문장을 어색한 가능성 문장으로 나눴다. Sol high도 보정·추론 비용을 늘렸으나 문장 나열과 조건 설명의 범위를 안정적으로 개선하지 못했다.

이 모순을 고친다. LENGTH·COMMA·DIFFICULT_WORD는 기존 `checkStyle` 진단으로 남기되 이것만으로 추가 유료 보정을 시작하지 않는다. 자동 보정은 검출한 사실 누락, 뜻풀이 충돌(GLOSS_COLLISION), 이중 피동(DOUBLE_PASSIVE)에 한정한다. 보정 채택의 문체 비교도 같은 범위를 쓴다. 어휘·문장 수준을 만드는 책임은 통합된 첫 변환 프롬프트와 사전이며, 새 LLM 평가·라우팅 호출을 제품에 추가하지 않는다. 의미 오류 전체를 기계 검사가 잡는다고 주장하지 않는다.

이 정책은 품질 저하를 허용하는 비용 모드가 아니다. 최종 전체 출력이 앞에서 정한 의미·작성 수준 기준에 미달하면 채택하지 않는다. 기존 제품 테스트에서 사실 복원·두 번의 호출 상한·실패 시 첫 초안 유지·새 사실 누락 거부를 계속 검증한다.

- `focused-rag`: 변경된 보정 정책 + 동일 프롬프트/사전, 개발 3건, Astra medium, 출력 8,192, 예약 상한 $3.8.
- `reference-short`: 아직 실행하지 않은 확인 3건(001-current 반복·003·090)을 같은 최종 코드로 실행한다. 예약 상한을 $3.8로 낮춘다.
- `reference-long`: 아직 실행하지 않은 105 전체 원문(6,718자)을 같은 최종 코드로 실행한다. 출력 16,384, 예약 상한 $4.5 유지.
- 코드 변경 후 전체 빌드를 다시 통과하고 유료 실행한다. 이전 출력의 호출을 소급해 없애거나 비용을 재작성하지 않는다. 각 단계의 실제 사용량과 소스 해시는 그대로 보존한다.
