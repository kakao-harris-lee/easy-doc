# 변환 비용 개선 실행 계획

## 현재 요구와 아래 실험 기록의 구분 (2026-09-12)

사용자는 이해 기준이 보편적인 초등학교 5~6학년 수준의 어휘와 문장임을 재확인했다. [master-plan §3.3](../master-plan.md#33-품질-신뢰-체계)을 현재 기준으로 적용한다. 초등학생 실험·사전 전수 구축·모든 문서의 정답 사전 작성은 선행 작업으로 배정하지 않는다. 다음 비교에서는 문서 전반의 쉬운 정도와 국소적인 표현 개선점을 구분하며, 낯선 표현 하나로 모델 전체를 탈락시키지 않는다. 의미·조건 보존과 비용 효율 요구는 유지한다.

아래 비교 설계·통과율·미달 판정은 이미 완료된 실험 당시의 기록이다. 결과나 사용량을 소급 변경하지 않는다. 후속 작업은 기존 Astra 결과를 출발점으로 작성·평가 지시를 원래 목표에 맞추는 것이며, 이번 문서 정정은 제품 코드 변경이나 새 유료 실측을 뜻하지 않는다.

## 승인과 정산

사용자는 기존 비용 재검토 계획의 실행을 요청했고, 모델·effort 실측을 포함한 총 US$20 승인이 유지된다. 이전 두 차례 측정의 완료 호출별 응답 토큰·비용 기록과 종료 기록을 기준으로 누적 예상 사용액 US$5.565252를 이월한다. 앞선 보수적 예약액 US$19.423988은 모두 종료된 실험의 최대치이며 실제 사용액이 아니다. 이번 실험 경계에서 완료분을 정산하고 새 순차 실행의 **예약 합계 상한을 US$14.00**로 둔다. 이월 비용과 합해 US$19.565252이며 US$0.434748를 여유로 남긴다. 이번 실행 중 예약은 반환하지 않으며 실패·재시도도 호출 전에 예약한다. 사용량이 확인되지 않은 호출은 실제액 0으로 처리하지 않는다.

## 고정 조건과 비교 순서

1. 제품 동작을 바꾸기 전에 기존 Kotlin 레인에 opt-in 첫 변환·보정·채택 결정 기록을 추가한다. 기존 최종 결과 파일과 호출 관측을 유지하고 새 하네스를 만들지 않는다. 유료 호출 없는 테스트로 보정 기각·절단·보정 없음·문서 간 기록 분리를 확인한다.
2. 개발 원문은 기존 `001-current`, `087`, `097`로 고정한다. 최종 phase3 프롬프트, 제품 사전, 출력 상한 8,192, 각 문서 1회다. Astra medium을 기준으로 보정의 실제 역할을 대조한다. 품질을 알 수 없는 초안을 무조건 채택하지 않는다.
3. 확인된 불필요한 보정 사유를 제품 규칙과 회귀 테스트로 고친다. 기록된 본문을 같은 제품 함수로 다시 검사할 수 있는 경우 재유료 호출보다 우선한다. 프롬프트 또는 규칙이 달라지면 새 조건으로 기록하며 이전 조건과 반복 성공률을 합산하지 않는다.
4. 같은 최종 조건에서 Sonnet 5 low, Sol low, 필요하면 Terra medium을 순차 비교한다. 후보별 예약 상한은 각각 $1.4, $2.4, $1.6이고 Astra 기준은 $6.2다. 남은 예약 한도는 선택 후보의 추가 검증에 쓴다. 중대한 의미 오류가 확인된 후보는 가격이 낮다는 이유로 채택하지 않는다. 후보마다 자기 judge 점수가 달라질 수 있으므로 본문 대조가 결정 기준이다.
5. 추가 검증은 개발 문서에 포함하지 않은 기존 `088`, `090`과 개발에서 취약했던 한 문서로 구성한다. 이 문서들은 이전 품질 실험에서 이미 사용했으므로 새 미지의 holdout이라고 부르지 않는다. 선택 후보의 비용이 예산을 넘으면 범위를 축소하기 전에 실행 설계 변경과 이유를 기록한다.

## 판정

- 중대한 의미 오류: 연도·날짜·금액의 적용 대상, 공식 기관/서류 이름, 자격·제외·가능성·의무·조건 결합의 변경 또는 누락. 한 건이라도 확인되면 자동 운영 후보 채택을 보류한다.
- 이해: [기존 독해 질문](../reports/2026-09-12-model-reading-quality-artifacts/reading-checks.md)에 결과만으로 답할 수 있어야 한다. 핵심 개념·서류 역할을 어려운 범주 이름으로만 반복하면 미달이다. 원문 자체에 없는 법적 자격이나 오타 뜻을 추측해 답하도록 요구하지 않는다. 원문 결함은 별도 한계로 남긴다.
- 보정: 기계 지적뿐 아니라 첫 결과와 최종 결과를 직접 대조한다. 실제로 개선하지 못한 호출과 중요한 오류를 고친 호출을 구분한다. 모든 보정 생략이나 문장 길이 임계값 일괄 완화를 절감 수단으로 채택하지 않는다.
- 비용: 문서별 변환·보정·실패·재시도 비용을 합한 뒤 같은 원문의 평균을 비교한다. judge는 개발 평가비로 분리한다. 최소 목표는 기준 Astra 대비 **40% 이상**의 평균 처리 비용 절감이며, 품질 조건을 통과하지 못하면 절감률만으로 성공을 선언하지 않는다. 이 상대 목표는 이번 실행의 작업 기준이고 판매 가격이나 장문 비용 상한은 아니다.
- 후보가 기준을 충족하면 가장 저렴한 검증 구성을 로컬에 적용하고 실제 구성·health를 확인한다. 충족하는 후보가 없으면 검증된 규칙 개선만 적용하고 모델 한계와 미달 근거를 보고한다. 전체 백엔드 빌드와 Compose 검사를 완료한다.

공식 모델 단가·effort는 [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) 문서에서 재확인한다. 사전·프롬프트·판정 기준·단가·코드 해시를 실행 산출물에 보존한다.

## 실행 중 추가 배정: 저비용 모델의 medium

Sonnet low와 Sol low의 완료된 부모상담 결과는 2촌 관계와 필요한 서류 역할을 설명하지 않았다. 낮은 effort의 한계를 모델 전체의 한계로 일반화하지 않기 위해, Terra medium 비교 뒤 필요하면 **Sonnet medium**을 동일 개발 3건·동일 최종 프롬프트·8,192 상한으로 추가한다. 예약 상한은 $1.4이며 새 예약 합계 $14.00을 넘지 않는다. 최저 비용의 품질 통과 후보에 남은 예산을 추가 배정한다. 합격 기준을 완화하거나 설명이 부족한 문서를 표본에서 빼지 않는다. 이 결정은 Sonnet medium 호출 전에 기록했다.

## 실행 중 추가 배정: high의 출력 한도

Sonnet medium의 완료된 001·087에서도 건강보험 유형과 2촌 설명이 빠졌고, 001의 제출서류 선택 조건도 바뀌었다. 앞선 품질 실험의 Sonnet high는 8,192 한도에 걸려 품질을 온전히 비교할 수 없었다. 따라서 마지막 개발 후보로 **Sonnet high / 16,384**를 같은 개발 3건에서 시험한다. 입력 프롬프트·사전·보정 정책은 유지하고 출력 한도 차이를 조건에 명시한다. 예약 상한은 $2.15와 남은 $14 예약 한도 중 작은 값이다. 출력 한도가 다른 결과를 effort만의 효과로 해석하지 않는다. 후보가 품질 기준을 통과해야만 추가 검증을 진행하며, 통과 후보가 없으면 이 후보 비교를 종료하고 미달 근거를 보고한다. 이 결정은 high 호출 전에 기록했다.

## high 실행 전 변경: 설명 지침의 충돌을 먼저 검증

Sonnet medium까지 완료한 뒤, 원문·사전으로 뜻을 확정하지 못하면 유지하라는 문구가 일반적 단어·단위 설명을 허용한 문구와 함께 있는 것을 확인했다. 이것이 저비용 후보들의 설명 생략 원인인지는 아직 추정이다. 모델 강도를 더 올리는 high 실험은 실행하지 않고, 먼저 해당 지침을 짧고 명확하게 고친 **Sonnet low / 8,192**를 같은 개발 3건에서 비교한다. 사업 정보와 일반 어휘 설명의 경계를 분리하고, 개발 문서와 겹치지 않는 작업실·열람실 면적 예문으로 설명과 조건 결합을 함께 보인다. 원문별 정답을 넣지 않는다. 새 조건은 `sonnet-clear`로 구분하며 예약 상한 $1.4, 새 예약 합계 $14를 유지한다. 품질·비용 판정 기준은 바꾸지 않는다. high 실행 기록은 없으며, 이 변경은 새 조건의 유료 호출 전에 기록했다.

## 실행 결과

여섯 조건·54호출의 비교를 완료했다. 저비용 후보가 고정 이해/의미 기준을 통과하지 못해 모델 교체와 선택 후보 추가 검증은 진행하지 않았다. 짧은 지침은 실험 기록으로 보존하고 phase3 지침을 유지한다. 날짜·공식 파일명 검사와 기존 레인 관측 개선을 반영한다. 이번 예상 비용 $2.986990, 이전 포함 $8.552242다. [상세 결과와 적용/검증](../reports/2026-09-12-cost-efficient-conversion.md)을 참조한다.
