## 1. 결제대행사 — 토스페이먼츠 확정

**2026-09-09 사용자 결정: 토스페이먼츠를 쓴다.** 목표 프로세스 §12 결정 1이 닫혔다.

### 1.1 우리가 쓰는 기능

| 기능 | 쓰는 곳 |
|---|---|
| 일반 결제(카드) | 플랜 첫 결제, 50크레딧 추가 구매 |
| **빌링키 자동결제** | 월 구독 갱신(프로세스 §6.2) |
| **결제 취소** | 환불(§6.4), **카드→계좌이체 전환**(§10.5) |
| 결제 내역 조회 | 마이페이지 결제 내역, 어드민 대사 |

**결제 취소가 특히 중요하다.** 개인카드로 결제한 뒤 기관 명의 세금계산서가 필요한 경우, 카드 결제를 되돌려야 발행할 수 있다. 부분 취소 지원 여부와 취소 가능 기간을 계약 단계에서 확인한다.

### 1.2 계약 절차

신청 → 서류 제출 → 토스페이먼츠 심사 → **카드사 심사** → 결제·정산 개시 순이다. 신청 접수 후 3영업일 안에 계약부서 안내가 온다. **카드사 심사가 별도 단계라 리드 타임이 있으므로 지금 시작한다.**

법인사업자 기준 서류는 사업자등록증, 법인등기부등본, 주주명부, 법인인감증명서다.

### 1.3 선행 조건

**통신판매업 신고가 필요하다**(§2.1). 전자결제 계약과 사이버몰 표시 의무가 모두 이 신고번호를 요구한다. 신고는 관할 시·군·구청에 한다.

### 1.4 기술 연동에서 미리 정할 것

- **결제 키는 서버에만 둔다.** 카드번호는 우리 저장소에 남기지 않는다(프로세스 §6.1).
- 웹훅으로 결제 성공·실패·취소를 받는다. **크레딧 부여는 웹훅 수신 시점이 아니라 결제 확정 확인 뒤**에 한 트랜잭션으로 처리한다. 재전송을 전제로 멱등하게 만든다(기존 재변환·정산 패턴과 같다).
- 테스트 키로 통합 테스트를 만들고, **실제 결제는 자동 테스트에서 호출하지 않는다**(프로젝트 규칙: 유료 외부 호출은 승인 대상).

## 2. 사이트에 반드시 실어야 하는 정보

### 2.1 전자상거래법 표시 의무

사이버몰 운영자는 아래를 **초기 화면에 소비자가 알아보기 쉽게** 표시해야 한다. 관행대로 **푸터**에 둔다.

| 항목 | 비고 |
|---|---|
| 상호, 대표자 성명 | |
| 영업소 소재지 주소 | 소비자 불만을 처리할 수 있는 실제 주소 |
| 전화번호, 전자우편주소 | |
| 사업자등록번호 | |
| 통신판매업 신고번호와 신고기관 | §1.3 |
| 이용약관 | 링크 |
| 사업자정보 공개페이지 링크 | 공정거래위원회 통신판매사업자 조회 |

모바일처럼 한 화면에 다 담기 어려우면 순차 노출이 허용되고, 대표자 성명·사업자등록번호·이용약관은 **확인할 수 있는 방법**을 화면에 두면 된다.

### 2.2 개인정보 보호법 표시 의무

- **개인정보처리방침을 공개**하고, **다른 약관과 구분되도록 표시**한다. 푸터에서 이용약관과 나란히 두되 **굵게** 처리하는 것이 일반적이다.
- **개인정보 보호책임자**의 성명 또는 부서명과 연락처를 방침에 싣고 푸터에서 닿게 한다.

## 3. 크레딧 소멸 — 약관·법규 검토

프로세스 §8이 정한 소멸 설계(묶음별 유효기간, 만료 임박 순 차감, 자동 소멸)를 법적으로 받쳐 줄 것들이다.

### 3.1 쟁점 A — 우리 크레딧이 「선불전자지급수단」인가

전자금융거래법의 선불전자지급수단에 해당하면 **전자금융업 등록**과 선불충전금 관리 의무까지 따라온다. 해당 여부는 대체로 ① 이전(양도) 가능성 ② 발행자 외 가맹점에서 쓰이는지 ③ 사용 가능한 업종 수로 갈린다.

**우리 크레딧은 자사 서비스에서만 쓰이고 양도되지 않으므로 해당하지 않을 가능성이 높다.** 다만 이것은 서비스 설계에 달린 판단이라 **자문으로 확정해야 한다**(§7-1). 확정 전까지는 약관에 **양도·환급 불가와 자사 전용**을 명시해 그 성격을 분명히 한다.

### 3.2 쟁점 B — 「신유형 상품권 표준약관」의 잣대

공정거래위원회 표준약관은 소비자 대상 상품권을 겨눈 것이라 B2B 이용권에 그대로 적용되지는 않지만, 분쟁 시 유사한 잣대가 쓰일 수 있다. 그 기준은 이렇다.

| 표준약관 기준 | 우리 설계와의 거리 |
|---|---|
| 금액형 유효기간 **최소 1년**(+연장 3개월) | 추가 구매 12개월은 경계선에 걸친다. **연장 조항이 없다** |
| 유효기간 경과 후 **소멸시효 5년 내 90% 환급** | 우리 설계에는 없다. **가장 큰 간극** |
| 60% 이상(1만 원 이하 80%) 사용 시 잔액 환불 | 없다 |
| 구매일로부터 7일 내 전액 환불 | 프로세스 §6.4가 같은 취지로 이미 있다 |

**대응 방향(권고).** 크레딧을 두 종류로 나눠 약관에서 다르게 다룬다.

- **유상 크레딧**(추가 구매): 표준약관 잣대에 가깝게 간다. 유효기간 12개월, 만료 전 연장 요청 수용, 만료 후 일정 기간 환급 청구 가능.
- **구독 제공 크레딧**(플랜): 「구매한 상품권」이 아니라 **그 달의 이용권**이다. 주기 종료와 함께 소멸하는 것이 구독의 본질임을 약관과 요금 화면에 명시한다. 헬스장 월 회원권이 다음 달로 이월되지 않는 것과 같은 구조다.
- **무료 크레딧**: 대가가 없으므로 환급 대상이 아니다. 유효기간만 고지한다.

이 구분이 서지 않으면 **월 구독 크레딧의 매월 소멸이 통째로 위험해진다.** 소멸을 도입하는 이유가 부채를 닫는 것이므로, 이 구분을 약관에서 명확히 하는 것이 이 작업의 핵심이다.

### 3.3 쟁점 C — 소멸 전 고지

표준약관은 유효기간 도래 전 통지를 요구한다. 프로세스 §8.5는 7일 전 1회를 정했다. **30일 전과 7일 전 2회로 강화할 것을 권고한다** — 예산 담당자가 소진 계획을 세우려면 7일은 짧다.

### 3.4 약관에 반드시 들어갈 문장

1. 크레딧의 정의와 환산 기준(공백 포함 1,000자 = 1크레딧).
2. 종류별 유효기간과 **소멸 시점**.
3. **차감 순서**(만료 임박 순).
4. 소멸 예고 방법과 시점.
5. 환불·환급의 범위와 절차.
6. 양도 불가, 현금 교환 불가, 자사 서비스 전용.
7. 유효기간·요금 변경 시 사전 고지 방법과 기간.

## 4. 개인정보 취급·파기 이행

### 4.1 파기

개인정보처리자는 보유기간 경과·처리 목적 달성 등으로 개인정보가 불필요해지면 **지체 없이** 파기해야 하고, 정당한 사유가 없으면 **그날부터 5일 이내**다. 다른 법령에 보존 의무가 있으면 예외다.

우리가 이미 가진 것과 없는 것은 이렇다.

| 대상 | 현재 | 필요한 것 |
|---|---|---|
| 문서 원문·변환 결과 | 30일 보존 후 파기 배치가 **있다**(매일 03:00) | 방침에 보존기간과 파기 시점을 명시 |
| 회원 계정·이메일 | 탈퇴 기능·파기 절차 **없음** | 탈퇴, 탈퇴 시 파기, 법령 보존분 분리 |
| 결제 정보 | 없음(토스 도입 후 생김) | 법령 보존기간 뒤 파기 |
| 세금계산서 요청의 사업자 정보 | 저장 **있음** | 보존기간 결정과 파기 |
| 로그·접속기록 | 있음 | 보존기간 명시 |

**법령상 보존해야 하는 것**은 파기 대상에서 빼되 **분리 보관**하고 방침에 근거와 기간을 적는다. 전자상거래법의 계약·청약철회 기록, 대금결제·재화공급 기록, 소비자 불만·분쟁처리 기록, 통신비밀보호법의 접속기록이 여기에 해당한다. **각 기간은 자문으로 확정한다**(§7-2).

파기 방법은 전자 파일은 복구할 수 없는 방법으로, 출력물은 분쇄하거나 소각한다.

### 4.2 처리위탁과 국외이전

방침에 **수탁자와 위탁 업무를 공개**해야 한다. 지금 구조에서 공개 대상은 이렇다.

| 수탁자 | 업무 | 국외 |
|---|---|---|
| LLM 사업자(Anthropic·OpenAI 등) | 문서 변환 처리 | **국외이전 해당** |
| 메일 발송 | 인증·알림 메일 | 사업자에 따라 다름 |
| 토스페이먼츠 | 결제 처리 | 국내 |
| 클라우드·호스팅 | 인프라 | 리전에 따라 다름 |

**국외이전은 별도 고지·동의 요건이 있다.** master-plan §3.2가 이미 「마스킹 후 전송 + 개인정보처리방침·위탁 문서에 국외 이전 고지」를 정했고, 2026-09-07에 마스킹을 걷어내면서 **고지와 no-training 조항의 비중이 커졌다**고 같은 절에 적혀 있다. 그 판단을 방침 문구로 옮긴다.

### 4.3 개인정보처리방침에 담을 항목

처리 목적·항목·보유기간 / 제3자 제공 / **처리위탁** / **국외이전** / 파기 절차와 방법 / 정보주체의 권리와 행사 방법 / 개인정보 보호책임자 / 안전성 확보 조치 / 방침 변경 고지.

**안전성 확보 조치는 이미 상당 부분 갖췄다** — 본문 AEAD 암호화와 키 회전, 소유 술어 기반 접근 통제, 로그에 본문·개인정보·토큰을 남기지 않는 규칙이 코드와 테스트로 고정돼 있다. 방침에 그 사실을 적을 수 있다.

- ★ 표시는 **다른 링크와 구분되게**(굵게) 그린다 — 개인정보 보호법 요구.

- 로그인 여부와 무관하게 **모든 화면**에 나온다. 초기 화면 표시 의무가 있으므로 랜딩에도 반드시 있어야 한다.
- 모바일에서는 열을 접어 아코디언으로 쌓되, 회사 정보는 §2.1의 순차 노출 규정 안에서 처리한다.
- 접근성: 푸터는 `contentinfo` 랜드마크로 두고, 열 제목은 실제 heading으로 쓴다. 기존 화면 규칙(DESIGN.md §11)을 따른다.

### 5.3 카피라이트 표기

`© 2026 <회사명>. All rights reserved.` 한 줄이면 충분하다. 연도는 **최초 발행 연도를 고정**하고 매년 바꾸지 않는다 — 자동 갱신은 오래된 내용을 새것처럼 보이게 한다. 회사명은 사업자등록증의 상호와 같아야 한다.

## 6. 고객지원(C/S) 가이드

### 6.1 채널

| 채널 | 용도 | 응답 목표 |
|---|---|---|
| 이메일 | 기본 창구. 결제·세금계산서·품질·장애 전부 | 영업일 1일 이내 |
| 전화 | 긴급, 결제·계약 상담 | 운영시간 내 즉시 |
| 화면 내 문의 | 로그인 사용자의 맥락 있는 문의 | 이메일과 같음 |

**운영시간은 평일 10:00–18:00(점심 12:00–13:00 제외), 공휴일 휴무**를 제안한다. 푸터와 문의 화면에 같은 문구로 적는다.

### 6.2 문의 유형별 처리

| 유형 | 1차 처리 | 참고 |
|---|---|---|
| 결제 실패·환불 | 어드민에서 결제 내역 확인 | 프로세스 §6.3·6.4 |
| 세금계산서 | 어드민 세금계산서 탭 | §10. **카드 결제분이면 전환 절차 안내** |
| 크레딧 소멸 문의 | 거래 내역에서 소멸 건 확인 | 소멸 예고 메일 발송 여부를 함께 본다 |
| 변환 품질 | 문서 id로 재현. **본문은 열람하지 않는다** | 어드민은 본문을 보여 주지 않는다 |
| 장애 | 공지 배너로 먼저 알린다 | 공지 기능 구현됨 |

**변환 품질 문의에서 운영자가 문서 본문을 볼 수 없다는 점**을 응대 지침에 명시한다. 어드민 화면이 의도적으로 본문을 빼고 있으므로, 재현이 필요하면 사용자에게 원문 제공 동의를 받아야 한다.

### 6.3 응대 원칙

- 개인정보·문서 본문을 메일 본문에 옮기지 않는다. 문서 id로 지칭한다.
- 크레딧 조정으로 해결한 건은 **사유를 거래 메모에 남긴다**. 어드민 조정은 처리자가 기록된다.
- 같은 문의가 세 번 이상 오면 도움말 문서에 항목을 추가한다.

## 7. 확인이 필요한 항목

법률·세무 자문에 넘길 목록이다. **1·2번이 착수를 막는 항목이다.**

1. **크레딧의 법적 성격.** 선불전자지급수단에 해당하는가(§3.1). 해당하면 전자금융업 등록 문제로 번진다. 해당하지 않게 하려면 약관에 무엇을 명시해야 하는가.
2. **크레딧 소멸의 적법성**(§3.2). 특히 **월 구독 크레딧의 매월 소멸**이 「구독 이용권」 논리로 방어되는가. 유상 구매 크레딧의 유효기간·연장·환급 조항을 어떻게 써야 하는가.
3. **개인정보 보존기간표 확정**(§4.1). 항목별 법정 보존기간과 파기 시점.
4. **국외이전 고지·동의 문구**(§4.2). 마스킹을 걷어낸 현재 구조에서 필요한 범위.
5. **카드 결제분 세금계산서 미발행과 전환 절차**(프로세스 §10.5)의 세무 확인.
6. **통신판매업 신고**(§1.3)와 사업자 정보 확정 — 상호·주소·대표자·연락처.
7. **개인정보 보호책임자 지정.**
