## 미션 BB — 자동 제목 정리

- `_resolve_title`: 첫 줄에서 유도 시 **30자 내외로 절단**(단어/어절 경계 우선, 말줄임 "…" 부착, 정확 상한 40자 하드컷). 사용자가 title을 명시하면 손대지 않음(255자 상한만 유지).
- 파일 업로드 경로(파일명 유도 없음 — 본문 첫 줄)도 동일 적용. 기존 문서는 소급하지 않음.
- 테스트: 짧은 첫 줄 무변경·긴 첫 줄 어절 경계 절단·명시 title 비절단.

## 미션 CC — 워크스페이스

**Lean 결정(팀 공유는 P1-1로 보류 — 개인 소유 워크스페이스만):**
- 모델 `Workspace(id, user_id FK, name ≤50자, created_at)` + `Document.workspace_id FK(nullable→기본 워크스페이스 백필 후 NOT NULL)`. 마이그레이션: 기존 사용자마다 "기본 작업 공간" 생성·기존 문서 귀속.
- API: `GET/POST /workspaces`, `PATCH /workspaces/{id}`(이름), `DELETE /workspaces/{id}`(내부 문서 있으면 409 — 실수 방지, 비우고 삭제 유도), 문서 생성 시 `workspace_id` 선택(미지정 시 기본), `GET /documents?workspace_id=` 필터.
- 소유자 격리: 워크스페이스도 user_id 조인 검증(타인 404).
- UI: 헤더에 워크스페이스 선택 드롭다운(+생성·이름 변경), 업로드는 현재 워크스페이스로, 변환 기록은 현재 워크스페이스 필터. 선택 상태는 localStorage.
- 용어: UI 표기 "작업 공간".

## 미션 DD — hwpx 내보내기

- `ExportFormat.HWPX` 추가. `render_export`에 OWPML 패키지 생성: mimetype·version.xml·META-INF(container 등)·Contents/header.xml·Contents/section0.xml(문단 단위 `<hp:p>/<hp:t>`) — **우리 ingest 파서(`iter_hwpx_sections`)로 재열림을 왕복 테스트**(생성→추출→본문 일치). 한컴 실제 열람 확인은 사람 몫으로 한계 명시.
- media type `application/hwp+zip`(확인 후 확정), 파일명 `.hwpx`.
- 내보내기 API `format=hwpx` 허용, 프론트 다운로드 버튼 추가(docx·txt·hwpx 3종).
- 제어문자·플레이스홀더 복원·캐시 헤더 등 기존 export 규율 동일 적용.
