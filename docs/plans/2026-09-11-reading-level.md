# 초등학교 고학년 독해 수준의 쉬운 글 변환

## 사용자 요구 재확인 (2026-09-12)

현재 이해 기준은 [master-plan §3.3](../master-plan.md#33-품질-신뢰-체계)을 따른다. 보편적인 초등학교 5~6학년 어휘와 문장으로 자연스럽게 풀어 쓰는 것이 목표다. 실제 초등학생의 개인별 이해도 측정, 모든 단어·문장의 사전 정의, 문서별 정답집이나 대규모 사전 구축을 선행 조건으로 삼지 않는다. 기존 산출물로 문서 전체의 쉬운 정도와 의미 보존을 비교하며 구현을 이어 간다. 국소적인 어휘 설명 부족과 문서 전반의 난도·의미 오류를 구분한다.

아래 구현·실측 결과는 당시 조건의 기록으로 유지한다. 다음 구현은 이 요구에 맞춰 변환·보정·judge의 지시를 정렬하는 범위이며, 별도 독자 연구나 새 검증 하네스를 만들지 않는다.

## 목표와 확인한 문제

독해 수준은 초등학교 고학년으로 고정한다. 문서에 나온 지원 대상의 나이로 독자를 추정하지 않는다. 원문에 있는 사실·조건·행위 주체를 유지하면서, 낯선 개념과 문장 사이 관계를 이해할 수 있게 쓴다.

현재 Chrome 초안에서 `거주 → 사는 것을 하는`, 웹 `링크 → 경기장`, `기준 중위소득 → 나라가 정한 기준 소득`을 확인했다. 현재 코드는 문장 길이·쉼표·어려운 표현·수치 누락을 중심으로 보정하며, 사전 후보를 강한 치환 지침으로 제공한다. 기존의 개념 설명 지시만으로는 이 문제를 막지 못했다.

## 구현 순서

1. 기존 Kotlin 테스트에 회귀 사례를 먼저 추가한다. 실제 배포 사전의 잘못된 링크 후보, 거주의 문장형 풀이, 보정 요청의 원문 전달, 평가 프롬프트의 독해 기준을 확인한다.
2. 변환 프롬프트를 개정한다. 독해 수준, 의미 보존의 우선순위, 문맥에 맞는 뜻풀이, 관련 문장으로 이루어진 문단을 명시한다. 연결어·괄호마다 무조건 문장을 나누는 지시와 숫자 주변 표현의 축자 복사를 제거한다. 예시의 `취소될 수 있음 → 취소됨` 오류도 바로잡는다.
3. 사전의 두 rink 후보는 문맥 구분 근거가 부족하므로 배포 후보에서 제외하고 정본에는 폐기 사유를 남긴다. 거주의 어색한 명사형 대체어와 합성 예문을 수정한다. 원천 행정용어 CSV는 보존한다. 정본 SQLite·내보내기·백엔드 사본을 일치시킨다.
4. 사전 컨텍스트를 문맥 검토용 뜻풀이로 바꾼다. 정의·주의사항을 함께 제공하고 검수되지 않은 합성 예문은 주입하지 않는다. 기존 용어·문자 예산은 유지하며, 예산 때문에 후보 수가 달라질 수 있음을 기록한다.
5. 기존 1회 보정에 원문을 난수 구분자로 전달하고 동일한 독해·의미 보존 기준을 적용한다. 원문과 대조해 관련 문맥을 고칠 수 있게 한다. 호출 상한은 유지한다. 기계 검사만으로 모든 의미 오류를 판정할 수 있다고 주장하지 않는다.
6. 기존 유료 평가 레인의 judge 기준에 의미 보존, 고학년 수준의 단어·개념 설명, 조건·절차 이해, 자연스러운 문맥을 포함한다. 새 평가 호출이나 하네스는 만들지 않는다. 과거의 사실 보존 전용 judge 점수와 새 종합 판정을 같은 지표로 비교하지 않는다.

## 검증과 완료 범위

- TDD: 관련 회귀 테스트 실패 확인 후 구현한다. 기존 프롬프트·사전 고정 문서 픽스처는 변경 이유를 기록하고 Kotlin 산출물 기준으로 갱신한다. Python 구현이나 parity 작업은 하지 않는다.
- `cd backend-kotlin && ./gradlew build`를 실행한다. 공개 HTTP 계약과 프런트엔드는 이번 변경 대상이 아니다.
- 초기 구현 단계에서는 실제 유료 LLM 호출, 기존 변환 결과 덮어쓰기, 운영 설정 변경을 하지 않는다. 후속 사용자 승인에 따른 실측은 아래 별도 결과로 기록한다. 구현 검증과 실제 독해 품질 개선의 실측을 구분한다.
- 후속 실측에서는 동일 원문별 결과를 보존하고 반복 비교한다. 고학년 수준의 독자가 결과만 읽고 `누가 대상인가`, `어떤 조건인가`, `무엇을 어떻게 해야 하는가`에 정확히 답할 수 있는지 확인한다. 사업 조건을 새로 만들거나 가능성을 확정으로 바꾸면 실패다. 단순 분할·어려운 단어 반복·뜻풀이 축자 삽입도 실패다. 유료 실행에는 별도 승인과 예산이 필요하다.

## 진행 결과

- 구현 완료: 고학년 독해 기준, 의미 우선의 분할 지침, 가능성을 보존하는 예시, 원문을 포함한 보정 요청, 종합 judge 기준을 반영했다.
- 사전: rink 후보 2건을 폐기 상태로 보존하고 배포에서 제외했다. 거주 뜻풀이·주의와 비문 예문을 수정했다. 수정 예문은 사람 검수 완료로 표시하지 않으며 주입 대상에서도 제외했다. 배포 엔트리는 2,177건이다.
- 정본 SQLite 무결성, 정본/JSON 수정 항목 일치, 표면형의 참조 무결성, 배포 색인과 백엔드 리소스 일치를 확인했다.
- 기존 고정 문서 52건의 컨텍스트 픽스처를 Kotlin 산출물로 갱신했다. Python 비교 실행이나 새 하네스는 추가하지 않았다.
- TDD: 추가한 독해 기준·사전 후보·보정 원문 전달 테스트의 기존 구현 실패를 확인했다. 수정 후 core 623건은 통과했다. 원문 구분자 회귀 테스트의 ModelDraft 생성 지점 1건을 기존 provenance 검사 목록에 반영했다.
- 전체 백엔드 빌드: `cd backend-kotlin && ./gradlew build` 통과. core 623건, application 480건, infrastructure 929건, api 714건, worker 13건으로 총 2,759건이 실패·오류·건너뜀 없이 통과했다. 정적 검사와 사전 사본 일치 검사도 통과했다. `git diff --check` 통과.

### 남아 있는 검증 한계

기계 검사의 50자·쉼표 임계값과 보정 채택 규칙은 유지했다. 이 검사는 독해력 판정기가 아니며, 규칙에 걸리지 않는 의미 오류를 제품 경로에서 모두 잡지는 못한다. 새 judge 기준은 기존 opt-in 평가 레인에 반영했으며 실시간 변환에 추가 호출하지 않는다. 이전 사실 보존 전용 judge 점수와 직접 비교하지 않는다.

원문 전달로 보정 요청의 입력 토큰이 늘 수 있다. 호출 상한과 데이터 마스킹 경로는 유지했다. 실제 독해 품질과 비용 변화는 승인된 유료 비교 실행에서 확인해야 한다. 기존 Chrome 초안은 덮어쓰지 않았으며, 실행 중인 서비스 재배포·재변환은 하지 않았다.

### 후속 승인 실측 완료 (2026-09-11~12)

사용자가 유료 호출과 최종 US$10 상한을 승인했다. 기존 Kotlin 평가 레인에 호출 전 비용 예약 제한을 추가했고, 추가 후 전체 빌드에서 2,761개 테스트가 통과했다. 공개 문서 3건을 변경 전후 각 2회, 변경 후 사전 컨텍스트 제외 조건에서 각 1회 실행했다. 총 45회 호출의 예상 비용은 US$1.464392이다. 부분적 표현 개선은 확인했지만, 날짜·기관명 보존과 개념 설명에 실패가 남아 품질 목표를 달성했다고 판정하지 않는다. 평가기의 오탐·미탐도 재현했다. [상세 실측과 후속 수정 우선순위](../reports/2026-09-11-reading-level-measurement.md)를 참고한다. 서비스 재배포와 기존 Chrome 결과 변경은 하지 않았다.
