# 문서 범위

문서 작업은 현재 코드와 검증 결과를 설명한다. 문서 요청을 제품 코드 구현으로 확장하지 않는다.

계획 문서를 위해 Opus를 사용할 때, 같은 세션에서 구현으로 넘어가도 된다 — 다만 코드 수정과 테스트 실행은 Sonnet 실행 에이전트에 위임하고 Opus는 분할·종합만 한다(루트 `AGENTS.md` 「모델과 비용 상한」).

- `master-plan.md`: 제품 범위, 정책, 단계, 현재 진행률의 단일 기준.
- `kotlin-redevelopment-backlog.md`: 아직 구현되지 않은 기능/결정 목록.
- `plans/`: 현재 실행 계획만 유지.
- `plans/archive/`: 과거 런타임의 역사 기록. 현재 완료 근거로 사용 금지.

Python 관련 내용은 제거 결정의 역사나 fixture 출처를 설명할 때만 남긴다. 활성 명령과 작업 경로는 Kotlin/Gradle 또는 React/npm 기준이어야 한다.
