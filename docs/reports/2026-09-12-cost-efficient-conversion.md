# 비용 효율 개선 실행 결과

**후속 해석 정정(사용자 재확인, 2026-09-12):** 프로젝트의 이해 기준은 보편적인 초등학교 5~6학년 수준의 어휘와 문장이다. 이 보고서의 개별 용어 설명 부족과 judge 미통과를 실제 독자 시험·대규모 사전 구축이 끝날 때까지 개발을 보류해야 한다는 근거로 사용하지 않는다. Astra의 전반적인 개선과 국소적인 표현 보완을 구분하며, 아래 수치와 판정은 당시 실험 기록으로 유지한다. 자격·서류 선택 조건 변경은 계속 의미 오류로 다룬다. 현재 기준은 [master-plan §3.3](../master-plan.md#33-품질-신뢰-체계)에 반영했다.

판정: **저비용 모델 교체는 보류한다.** 같은 개발 원문 3건에서 처리비는 67~80% 낮아졌지만, 고정한 독해 기준을 충족한 저비용 후보가 없었다. 날짜·공식 파일명 검사 오탐과 유료 레인의 보정 관측을 개선했다. 비용 절감 목표 달성이나 초등학교 고학년 독해 수준 도달을 선언하지 않는다. Astra도 시술·전세형 등의 설명이 부족해 완성된 품질 기준이 아니다.

## 같은 원문에서의 비용과 품질

원문은 `001-current`, `087`, `097`, 후보당 각 1회다. 제품 사전을 사용하고 출력 상한은 모두 8,192다. 처리비는 첫 변환과 보정의 합이며 judge는 제외한다. 모든 후보에서 3건 모두 보정을 호출·채택했다. 가격은 응답 usage와 설정 단가로 계산한 예상액이며 청구서 확정액이 아니다.

각 후보의 모델이 자기 결과의 judge도 수행한다. 따라서 judge 통과율을 모델 간 공통 품질 점수로 비교하지 않는다. 특히 Sonnet의 3/3 통과는 고정 독해 질문에 답할 수 있다는 증거가 아니었다. [직접 대조 기록](2026-09-12-cost-efficient-conversion-artifacts/reading-review.md)에 누락·조건 변경의 근거를 남겼다. 실제 초등학생 참여 독해 실험은 아니다.

이 표는 기존 모델 구성과 개선 후 구성의 제품 비교다. Astra만 기존 검사이고 나머지는 검사 개선 후이므로 **모델 차이만을 분리한 인과 실험은 아니다.** 같은 프롬프트의 저비용 후보들 사이 비교와 짧은 지침 실험은 구분했다. 3문서·1회씩이므로 장문 비용이나 반복 성공률을 추정하지 않는다. 이전 실험과 조건이 달라 비용 평균을 합치지 않았다.

## 무엇을 바꿨는가

1. **날짜 범위의 생략된 연·월 인식.** `2024년 3월 5일부터 3월 14일까지`처럼 같은 구간의 자연스러운 날짜 표기를 누락으로 오인하지 않는다. 숫자식 범위의 끝 날짜도 날짜로 비교한다. 문장 밖으로 연도를 전파하거나 다음 해를 임의로 추측하지 않는다. 실제 연도·날짜 변경은 계속 검출한다.
2. **공식 첨부파일 이름과 설명을 구분하는 보정 검사.** 원문과 같은 파일 이름의 `변경`이나 긴 이름 자체를 다시 쓰라는 보정 사유에서 제외한다. 이름 바깥의 어려운 표현과 긴 설명은 계속 검사하고, 이름 변경·누락은 사실 보존 검사로 확인한다. 전각 숫자가 든 같은 파일 이름의 비교도 수정했다. 모든 공식 용어·법령·뜻풀이를 포괄 면제하지 않는다.
3. **기존 유료 레인의 opt-in 관측 확장.** 첫 변환·보정 본문, 토큰·비용, 보정 채택 여부, 사실/문체 지적을 기존 결과 디렉터리에 남긴다. judge를 제품 변환 비용에서 분리한다. 제품 로그에는 본문 기록을 추가하지 않는다. 새 하네스나 Python 구현은 만들지 않았다.

Astra 기준의 보정은 처리비 중 51.3%였다. 001에서 날짜 오탐이 보정 채택 판단에 영향을 주었지만, 087과 097은 보정으로 실제 설명도 좋아졌다. 따라서 전체 보정을 생략하는 방식은 채택하지 않았다. 이번 저비용 표본에서도 모두 보정이 필요했으므로 **검사 개선으로 전체 처리비가 실제 얼마나 줄었는지는 아직 입증하지 못했다.** 회귀 테스트는 다른 보정 사유가 없는 동일 파일명 사례가 1회 호출로 끝나는 것을 확인한다.

짧은 지침은 일반 어휘 설명과 새로운 사업 정보 생성을 구분하도록 줄인 실험이었다. Sonnet low의 이해 부족을 해소하지 못했고 평균 비용도 기존 지침보다 높았다. 실험 소스를 보존하고 제품은 이전 phase3 프롬프트로 복원했다. high/16,384와 추가 검증 문서 088·090은 호출하지 않았다. 최종 선택 후보가 없으므로 선택 후보 검증의 선행 조건이 충족되지 않았다.

## 적용 및 검증

2026-09-12 08:20 KST에 새 백엔드 이미지로 로컬 API·워커를 재기동했다. 두 컨테이너가 빌드한 이미지와 일치하고, API health 및 8080 프런트 프록시 경유 health가 모두 정상이다. 워커 시작 로그도 확인했다. 재기동 전 미완료 큐 작업은 0건이었다. [실제 구성 기록](2026-09-12-cost-efficient-conversion-artifacts/runtime.json)을 보존했다.

모델은 `openai / gpt-6-astra / medium`, 입력/출력 단가는 $10/$50로 유지한다. 실측 출력 상한은 8,192지만 로컬의 기존 64,000 상한은 유지했다. 같은 출력의 토큰 비용은 상한을 낮추는 것만으로 줄지 않으며 장문 절단 위험은 이번 표본에서 검증하지 않았다. 이번 코드 개선은 새 변환부터 적용된다. 기존 Chrome 페이지의 저장된 결과를 재변환하지 않았다.

`cd backend-kotlin && ./gradlew build`가 통과했다. 일반 테스트 **2,782건, 실패·오류·건너뜀 0건**이며 `docker compose config --quiet`, 이미지 빌드, `git diff --check`도 통과했다. [모듈별 검증 집계](2026-09-12-cost-efficient-conversion-artifacts/verification.json)를 참고한다. 개발 중 발생한 파일 함수 수 제한 위반은 숫자 필터를 관련 숫자 처리 파일로 옮겨 해결했다. 별도로 시도한 `:infrastructure:detektTest`에는 기존 테스트 소스의 타입 분석 지적 9개가 남아 있어, 해당 선택 검사가 통과했다고 주장하지 않는다. 필수 전체 build의 detekt·ktlint·테스트는 통과했다.

공개 HTTP 계약과 프런트엔드는 이번 비용 개선 작업에서 변경하지 않았다. 기존 작업 변경분을 유지했고 커밋은 만들지 않았다.

운영의 다음 비용 절감 후보는 무조건 저가 모델을 통과시키는 자동 전환이 아니다. 사전에 없는 필수 개념과 서류 역할을 찾아 검증된 설명을 제공하는 검색 자료, 대상과 조건의 결합을 확인하는 평가가 먼저 필요하다. 현재 단어 치환 사전과 숫자·이름 검사는 이 두 문제를 충분히 다루지 못한다. 해당 자료 구축과 자동 분기 구현은 이번 결과로 완료된 것처럼 보고하지 않는다.
