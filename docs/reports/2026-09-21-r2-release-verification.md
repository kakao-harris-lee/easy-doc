## 출시 판정

오탐 수정과 자동 검증만으로 실무자 파일럿·운영 배포를 완료로 판정하지 않는다. 실행 커밋/이미지, V31 schema, API·worker 토글, 실제 요청과 크레딧 예약·정산, 사람 평가 기록을 각각 확인해야 한다. 24시간 관측은 실제 배포 시각과 담당자를 정한 뒤 기록한다.

현재 일반 출시는 보류한다. 088의 사용 범위 누락을 보완·재검증해야 하며, 참여자·일정과 운영 미커밋 변경 유지 여부도 미확정이다. 이번 변경은 프롬프트나 응답을 고쳐 의미 누락까지 해결한 것이 아니다. 기존 후보를 이용한 탐색 검수 자료는 준비했지만 이를 출시 승인으로 쓰지 않는다.

## 배포 사전 점검

`https://easydoc.kr`과 `/api/health`가 HTTP 200이며 인증서 검증이 성공했다. 운영 Compose의 API·PostgreSQL·백업은 healthy, worker·frontend는 실행 중이다. 운영 작업 폴더의 HEAD는 `2f4695b5`이고 2026-09-18 생성된 로컬 태그 이미지를 사용한다. 이미지에 소스 커밋 라벨이 없으므로 HEAD만으로 실행 코드의 정확한 커밋을 단정하지 않는다.

운영 API·worker 환경에는 행동 안내 두 토글이 명시되지 않았다. 현재 소스 기본값은 false다. 공개 health 성공을 R2 생성·정산 경로 검증으로 보지 않는다. 운영 Compose 모델 검증은 성공했고, 로컬 모델도 성공했다. 로컬 파일럿 오버레이는 실제 SENS 설정이 없으므로 CI와 같은 더미 값으로 모델만 검사했다.

운영 폴더의 업로드 제한 관련 미커밋 변경은 덮어쓰지 않는다. 배포 전 main 포함 여부와 진행 중 작업·백업을 확인하고, V31 전환 때 구버전 API·worker를 함께 중단한다. `docker_startup.sh restart`를 그대로 실행하는 대신 이미지 준비·접수 중단·진행 작업 정리·백업·조율된 전환을 구분한다.

## 오프라인 회귀

`ActionGuideR2OfflineRegressionTest`는 일반 infrastructure 테스트로 실행되며 provider 객체를 만들거나 네트워크 모델을 호출하지 않는다. 실제 runner와 동일하게 원문을 `splitUnits`로 나눈 뒤 보존 응답을 production parser/validator에 전달한다. 첫 재현에서 기존 9개 거절을 확인했고 수정 후 20개 전부 통과했다. CI 컨테이너에도 보존 응답 폴더만 읽기 전용으로 연결했다.

이 결과는 동일한 20개 응답에 대한 **검증기 회귀 결과**다. 새로운 독립 생성 실험, 사용자 정답률, 인간 의미 승인 또는 새로운 지연 측정이 아니다. 최초 호출의 비용·지연·11/9 결과는 [원본 보고서](2026-09-21-r2-model-evaluation.md)에 그대로 유지한다.
