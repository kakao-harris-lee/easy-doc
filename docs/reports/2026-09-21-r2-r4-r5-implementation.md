# R2 잔여 오류 보완과 R4/R5 구현·리뷰

사용자 요청: R2에서 확인한 보완 가능성을 실제 처리하고 R4·R5까지 구현한 뒤 리뷰한다.
기준 커밋은 `1b118949476f8002ac971472fc58756a3cbc9696`이다.

## R2: 인접 근거의 무손실 결합

3회 평가 원본과 판정 기록은 수정하지 않는다. 남은 023 run2는 근거 수 11개로 제한 10개를 넘었다.
일부 근거가 원문의 바로 이어지는 구간을 나누어 인용한 경우이므로, 먼저 원래 후보의 인용·좌표·사실·기타 구조를 검증한 다음 인접 근거만 정확한 원문 구간으로 합친다.

- 이미 근거 10개 이하인 항목은 변경하지 않는다.
- 비연속 좌표나 1,000 코드 포인트를 넘는 결합 인용은 합치지 않는다.
- 근거를 삭제하거나 사실·주의문을 수정하지 않는다. 최종 후보는 기존 검증 상한을 모두 통과해야 한다.
- 실제 모델을 다시 호출하지 않는다. 이전 누적 보수 예약액 US$29.085720/50은 그대로다.
- 저장된 응답 재검증은 새 모델 생성의 품질이나 사람 파일럿 결과를 대신하지 않는다.

현재 코드로 3회차 원본 12개를 모두 재생해 **12/12 통과**했다. 원본 파일의 manifest 해시, 본문·주의문 문자열과 원문 좌표의 집합이 보존됨을 함께 확인했다. 023 run2는 인접한 두 쌍을 합쳐 11개 근거를 9개로 표현한다. 원래 유료 평가의 11/12 판정을 덮어쓰지 않고, 이번 결과는 후속 처리 보완 뒤의 오프라인 재검증으로 구분한다.

검증: `ActionGuideCandidateTest` 13개, `ActionGuideR2OfflineRegressionTest` 4개 통과. 비인접 근거, 결합 시 인용 상한 초과, 원래 인용 변조는 계속 거부하며 유효한 기존 항목은 그대로다.

## R4: 원문 표 관계

DOCX/HWPX 단순 표의 원문 단위 좌표를 보존한다. 값과 제목은 기존 원문으로 표시하며 표 관계 payload는 별도 암호화한다. 미지원 구조를 임의로 재구성하지 않고 사유를 반환한다. 과거 문서를 일괄 재추출하지 않는다.

API는 계약 2.42.0 `DocumentSourceResponse.tables`에 정의했다. `EASYDOC_TABLE_RELATIONS_ENABLED` 기본값은 false다.

HWPX 셀 구조는 한컴의 [공개 모델 `tc`](https://github.com/hancom-io/hwpx-owpml-model/blob/main/OWPML/Class/Para/tc.cpp)와 [`cellSpan`](https://github.com/hancom-io/hwpx-owpml-model/blob/main/OWPML/Class/Para/cellSpan.cpp)을 확인했다. 제목은 셀의 `header` 속성이고, 위치·병합 범위는 자식 `cellAddr`·`cellSpan`에 있으므로 표면적인 행/셀 개수만으로 지원 여부를 판단하지 않는다.

## R5: 버전별 검수 이력

검수 행위와 본문 변경을 같은 트랜잭션에서 기록한다. 담당자와 시각은 서버에서 정하고 과거 확인을 최신 본문으로 승계하지 않는다. 스냅샷에는 그 시점의 본문과 산출물을 암호화해 보관하며, 없는 본문은 명시적으로 표시한다.

API는 계약 2.42.0 `review-history` 조회와 TXT 출력이다. 소유권·보존 만료를 모든 요청에 적용하고, 출력 상한 초과는 잘라서 성공하지 않고 거절한다. `EASYDOC_REVIEW_HISTORY_ENABLED` 기본값은 false다.

스냅샷 보관은 문서당 최근 20개로 구체화했다. 본문 버전만 20개로 제한하면 같은 본문에서 확인·취소를 반복할 때 스냅샷이 무한히 쌓일 수 있기 때문이다. 오래된 스냅샷 연결은 제거하고 이벤트 자체에는 ‘본문 스냅샷 없음’을 표시한다. 스냅샷 한 개는 암호화 전 64KiB 이하이며 잘라서 저장하지 않는다.

## 검증·리뷰

작성자와 다른 에이전트의 R5 백엔드 리뷰에서 다음을 발견해 수정하고 재검토했다.

- 과거 본문 기반의 확인된 안내문을 새 후보로 교체할 때 새 본문을 옛 안내문 스냅샷에 연결하던 문제: 본문 변경에서 이미 무효화한 기록을 중복 생성하지 않는다.
- 극단적인 시각·비정규 나노초를 넣은 커서가 JDBC에서 500을 일으키던 문제: 커서 디코딩 단계에서 422로 거절한다.
- 저장된 스냅샷의 형식 손상을 사용자 입력 오류 422로 분류하던 문제: 저장 오류로 실패하며 일부 기록만 성공으로 출력하지 않는다.
- 이력 목록의 본문 버전 조회와 이벤트 조회 사이에 동시 저장이 끼어들 수 있던 문제: 같은 변환 행을 잠근 트랜잭션에서 읽는다.

R4 통합 리뷰에서는 HWPX 자식 셀 메타데이터·표 밖 꼬리 문장, DOCX 비활성 헤더·외부 각주, 새 문서의 빈 표 목록을 보완했다. 표가 1,000개를 넘으면 본문은 유지하고 관계 메타데이터만 `limit_exceeded`로 처리한다. 프런트에서는 더 보기 중 새로 고침과 문서 이동 중 TXT 응답의 비동기 경합, 로딩 중 미지원 표시, capability 제거 뒤 빈 탭을 수정했다.
