# 선택 단어 사전 조회의 무관한 후보 차단

완료 — 구현·전체 build·로컬 서비스 반영과 Chrome 화면 확인을 마쳤다.

사용자가 ‘소득’을 선택했을 때 ‘소송’이 표시됐다. 실제 Kotlin 조회로 ‘소득 → 소 → 소송’, ‘주소 → 소 → 소송’, ‘자녀 → 자 → 사람’, ‘고지대 → 고지 → 공식으로 알림’을 재현했다. 조회 실패 시 문자열을 한 글자까지 잘라 재검색하는 방식이 단어 경계를 우회했다. 생성용 RAG가 아니라 선택 문자열 조회의 별도 경로였다.

## 적용한 정책

- 임의 접두·접미 조각 검색을 제거했다. 정확한 표면형과 뒤따르는 조사로 선택 전체를 설명할 수 있어야 일반 후보로 반환한다. 활용형, 조사 연쇄, 사전에 등재된 여러 단어 표제어도 같은 범위 검사를 적용한다.
- ‘구비서류 제출’, ‘필요한 구비서류’의 일부 단어만 찾고 전체 일치·치환 가능으로 반환하던 오류를 고쳤다. 해당 선택에는 후보를 반환하지 않는다.
- 복합어는 기존 손작성 양성에서 의미 관계를 확인한 3개만 유지한다: 저소득가구→저소득, 고령운전자→고령, 무직저소득→저소득. 복합어 자체에 조사가 붙은 경우까지 허용한다. 새로운 복합어 관계는 검토와 사례 추가 없이 자동 확장하지 않는다. 이 후보는 설명용이며 치환 불가다. 고위험·검토 필요 항목으로 바뀌면 부분 설명도 노출하지 않는다.
- 원래 사전의 표면형·뜻풀이·우선순위와 생성용 RAG 경계 규칙은 유지한다. HTTP 필드·상태·DTO·프런트 계약 변경 없이, 기존 exact 정의인 ‘남는 것은 조사뿐’을 실제 조회에도 적용했다.

‘소득’ 자체는 현재 사전에 없으므로 무관한 뜻을 제시하는 대신 후보 없음으로 처리한다. 뜻을 새로 생성하는 LLM 호출이나 대규모 사전 추가는 하지 않았다. 이 변경은 동음이의어의 문맥별 뜻을 새로 판단하는 기능은 아니다.

## 검증

기존 조회 픽스처는 66개 중 양성 63개만 정확도를 계산했고, 음성에 치환 불가 설명이 나와도 실패하지 않았다. 이제 모든 음성 사례에서 후보 배열이 완전히 비어 있어야 한다.

기존 양성 63개를 그대로 유지하고, 제보 관련 오류 18개를 음성으로 추가했다. 총 84개(양성 63·음성 21)다. 기존 단위 테스트에 단어 경계·선택 전체·조사 연쇄·검토 필요 부분 설명 검증을 더했고, 실제 색인과 인증을 사용하는 HTTP 테스트에도 제보 사례를 추가했다. 수정 전 core 13개와 실제 색인/API가 실패했고, 수정 후 집중 검증이 통과했다. 이전 기대값을 현재 출력으로 덮어쓰는 비교 하네스는 추가하지 않았다.

추가 유료 호출: $0. 기존 변환 결과는 다시 생성하지 않는다.

전체 검증: backend-kotlin에서 ./gradlew build 통과(2분 36초). core 655, application 483, infrastructure 943, api 715, worker 13으로 총 2,809건이며 실패·오류·생략 0건이다. 조회 픽스처는 양성 63/63, 음성 21/21을 통과했다. Compose 설정과 git diff 공백 검사도 통과했다. [검증 원자료](2026-09-12-dictionary-lookup-fix-artifacts/build.log).
