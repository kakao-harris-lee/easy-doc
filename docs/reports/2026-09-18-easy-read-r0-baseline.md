## 1. 목적과 사용 규칙

이 문서는 쉬운 글 변환 개선에서 줄여야 할 의미 오류를 비교하기 위한 고정 기준선이다. 저장소에 이미 승인된 공개 문서 중 실수집 자료 10건을 골랐고, 조건 중심 4건·절차 중심 3건·표/금액 중심 3건으로 나눴다. 개발용 6건은 구현 중 반복 확인에 쓰고, 보류 평가용 4건은 후보 구현과 프롬프트를 고정한 뒤 한 번 평가한다.

질문과 정답은 `data/golden/documents/`의 `source_text`만 읽고 작성했다. `data/golden/conversions/`의 기존 결과는 질문을 고정하기 전에 열어 보거나 정답 근거로 쓰지 않았다. 따라서 아래 둘은 서로 다른 산출물이다.

- **수동 기준:** 이 문서의 질문, 정답, 원문 근거. 의미 보존 판정의 기준이다.
- **기존 결과 기준선:** 커밋된 `data/golden/conversions/{id}.txt` 파일. 파일 존재와 SHA-256만 기록했으며, 이번 작업에서 품질을 새로 측정하거나 재생성하지 않았다.

각 질문은 변환문만 읽고 답할 수 있어야 통과한다. 정답과 모순되거나, 답에 필요한 대상·조건·예외·금액·행동·기한이 빠지면 실패다. 표현이 달라도 의미가 같으면 통과한다. 원문에 없는 내용을 추측해서 맞힌 경우도 통과로 보지 않는다. 질문별 결과는 `통과 / 누락 / 의미 변경 / 원문 밖 추가 / 판정 불가` 중 하나로 기록한다.

보류 문서의 변환 결과는 후보 구현과 프롬프트를 고정하기 전에는 열람하거나 튜닝에 사용하지 않는다. 보류 결과를 보고 수정했다면 해당 문서는 개발용으로 이동하고 같은 유형의 새 공개 문서로 교체해야 한다.

## 6. 실행 기록 양식과 완료 판정

유료 모델 호출 승인 전에는 기존 변환 스냅샷 또는 사람이 만든 화면 예시에만 아래 양식을 적용한다. 이 경우 결과 머리말에 `기존 스냅샷 평가` 또는 `수동 UX 예시 평가`를 반드시 적고, 신규 모델 품질 결과로 합산하지 않는다.

| 실행 필드 | 기록 값 |
|---|---|
| 평가 일시·평가자 | 필수 |
| 표본 구분 | 개발 / 보류 |
| 입력 fixture SHA-256 | §3 값과 일치해야 함 |
| 결과 종류 | 기존 스냅샷 / 수동 예시 / 승인된 신규 실행 |
| 모델·effort·프롬프트·사전 버전 | 신규 실행일 때 필수 |
| 비용 승인·상한 | 신규 유료 실행일 때 필수 |
| 질문별 판정·근거 | 60개 질문 각각 기록 |
| 중대한 의미 오류 | 자격·예외·금액·행동·기한별 건수와 사례 |

R0 완료 조건은 충족했다: 공개 실수집 문서 10건, 4/3/3 유형 분할, 개발 6건·보류 4건 분리, 문서별 6개씩 총 60개 사전 질문과 원문 앵커, 출처·식별자·사용범위, 원문·기존 결과 해시가 고정되어 있다. 아직 수행하지 않은 것은 기존 결과의 질문별 채점, 신규 변환 실행, 사용자 독해 실험이다. 이 셋은 각각 평가 실행이며 R0 표본 정의와 구분한다.
