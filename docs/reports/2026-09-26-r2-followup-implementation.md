# R2 실제 행동 분석·문서 보완 후속 구현

작성일: 2026-09-26 · 상태: 최종 로컬 검증 통과 · PR 최종 CI/승인 후 main 병합·파일럿 반영

## 범위와 설계

사용자의 ‘후속 구현 진행’ 요청에 따라 [정정 계획 §10](../plans/2026-09-26-action-guide-correction.md#10-실제-분석보완-후속-구현-결정)을 구현한다. 시작 기준은 `3551a467`이며 [PR #162](https://github.com/kakao-harris-lee/easy-doc/pull/162)에 이어서 제출한다. 이전 fake 기반의 검증 결과는 [이전 기록](2026-09-26-r2-implementation.md)에 있으며 이번 변경의 통과 근거로 사용하지 않는다.

모델은 안내문 적합성과 행동·조건·근거를 분석한다. 분석 비용과 문서당 시도 한도는 기존 행동 안내 정책을 재사용한다. 담당자가 해당 분석 버전의 추출·원문 대응을 확인한 뒤 서버가 추가 안내 또는 전체 문서 보완을 구성하므로 후속 모델 호출과 추가 생성 과금은 없다. 전체 보완은 현재 저장 본문을 유지하면서 행동 안내를 덧붙이는 방식이다.

원문과 기존 본문 사이의 의미 보존은 위 보존 전략만으로 증명되지 않는다. 원문 전체를 서버가 고정한 검토 범위로 삼고 누락·불확실·충돌을 별도로 처리한다. 모델의 판단이나 대응률을 담당자 확인으로 승격하지 않는다. 전체 반영은 미해결 검토가 없는 해당 버전만 허용하고 이전 본문 보관과 미확인 본문 저장을 원자적으로 수행한다.

## 구현 내용

- 분석은 `action-guide-analysis-jobs`로 접수한다. 기존 작업 큐에 operation을 추가해 v1과 시도 한도·예약·반환·호출 원장을 공유한다. 같은 본문과 분석기 버전의 provider 분석은 검토 전에도 무료 재사용한다. 재사용 요청 키도 기존 작업으로 역조회해 v1 유료 요청으로 다시 사용할 수 없게 한다.
- 모델은 적합성·행동·근거·원문 전체 대응을 반환하며 담당자 확인을 부여하지 못한다. 원문 부분별 행동/조건 추출과 미기재·해당 없음 판단을 대조하고 잘못된 분석은 근거와 함께 교정한다. 교정은 분석/검토 버전을 올리고 이전 확인을 무효화한다.
- 추가 안내는 행동·조건 검토 후 별도 자료로 구성한다. 전체 보완에는 추가로 원문→현재 본문 대조를 요구한다. 배경 부분의 본문 대조가 남았다고 추가 안내까지 일괄 차단하지 않는다. 실제 수치·날짜 누락 신호는 확인 표시만으로 지우지 못한다.
- 구성은 확인한 행동 데이터의 결정적 렌더링이다. 명시된 선후관계와 조건·기한·미기재/해당 없음 구분을 보존한다. 전체 보완은 현재 본문 뒤에 행동 안내를 붙인다. 결과 한도는 기존 본문 저장 정책과 같은 20,000 코드포인트이며 초과를 자동 축약으로 숨기지 않는다.
- 전체 반영은 이전 본문 암호화 보존과 새 본문 CAS를 함께 실행한다. 새 반영은 revision을 올리고 `reviewed_at=null`로 저장하며 기존 파생 자료의 버전 무효화를 유지한다. 새로고침 후에도 이전 본문 목록·내용을 읽고 복사/TXT 보관할 수 있다. 자동 복구 mutation은 추가하지 않았으며 필요하면 기존 편집 화면에서 복원·확인 저장한다.
- 신규 요청과 자료 조회를 분리했다. API와 worker는 기존 enabled/worker-enabled와 새 analysis-enabled를 함께 사용하고, 읽기 capability는 별도로 제공한다. 운영 키·서버 `.env`는 커밋하지 않는다. V38은 작업 구분·분석 검토 버전·암호화 보완 자료, V39는 필수 이전본문 보관을 추가한다.
- OpenAPI 2.48.0과 Kotlin HTTP·React API 타입/호출을 함께 맞췄다. 화면은 자동 분석 호출 없이 비용 안내→분석→항목별 확인/교정→모드 선택→블록 대조→명시적 전체 반영으로 연결한다. dirty/stale/CAS와 문서 이동 뒤 늦은 응답을 보호한다.

## 구현 전 고정한 회귀 기대

실제 사용자 문서는 fixture로 커밋하지 않는다. 아래 실패 유형은 기존 Kotlin·React·Playwright 테스트에 합성 문서로 반영한다.

| 사례 | 기대 결과 |
|---|---|
| 사업 배경·대상 4개·과거 사업기간·희망 행사 1주 전 문의만 있는 문서 | 문의 행동 1개, 4개 대상과 기간·기한 유지. 없는 전화·방문·제출·접수완료 단계 추가 금지 |
| 안내문이 아닌 글, 안내문이지만 행동 없음, 판단 불확실 | 판단과 이유를 보여 주고 서버 허용 모드는 비워 둠 |
| 한 원문 부분에 행동과 조건 여러 개가 섞인 문서 | 일부 인용·단위 대응만으로 조건 보존 확인을 완료하지 않음 |
| 원문에 문의처·준비물이 있는데 미기재로 분류 | 원문 대조·교정 전 생성 검토 완료 불가 |
| 배경 문단 또는 유효한 편집 내용이 있는 현재 본문 | 전체 보완은 현재 본문과 쉬운 표현을 그대로 유지하고 행동 안내 추가 |
| 원문에 있으나 현재 본문에 없는 사실, 사용자 편집과 원문의 충돌 | 별도 신호와 근거 표시, 미해결 상태에서 전체 반영 차단 |
| 분석·본문·결과 수정 뒤 오래된 검토/적용 요청 | CAS 충돌 또는 검토 해제, 오래된 확인으로 반영 불가 |
| 전체 반영 중 이전 본문 스냅샷 저장 실패 | 전체 트랜잭션 롤백. R5 이력 OFF도 스냅샷 필수 |
| 신규 기능 OFF, 소유자/문서 만료/삭제 | 저장 자료 읽기는 신규 요청 토글과 분리하고 소유권·보존 경계 유지 |
| 네트워크 재전송·worker 복구·v1과 새 분석 혼용 | 기존 멱등·호출 원장·예약/반환·문서 합산 시도 한도 유지 |
| 출력 한도 초과 | 축약·절단으로 성공 처리하지 않고 제한을 설명 |

## 검증·리뷰·재시작

첫 컴파일 준비에서 API 모듈의 infrastructure 직접 참조를 발견해 설정 값 주입으로 고쳤다. 첫 전체 검사에서는 생성자 어노테이션 타깃, 함수 복잡도/길이, 새 SQL·민감 타입의 검사 목록 갱신이 필요했다. 검사 기준을 완화하지 않고 분리·명시 등록한 뒤 최종 변경으로 다시 검증했다. 데이터 저장·반영 통합 테스트에서 실패는 보고되지 않았다. 프런트는 마지막 호환 표시 수정을 포함해 check·64개 파일 867개 테스트·build를 통과했다.

구현 담당의 3회 검증에서 발견된 최종 통합 결함은 테스트용 bean 등록 위치, 전역 크레딧 헤더 스키마, 임의 Map 대신 명시적인 검토 신호 DTO와 정적 검사 항목이었다. 총괄자가 이 결함과 리뷰에서 발견한 특수문자 행동 ID의 확인 URL 오류를 통합 수정했다. 신호 ID는 서버의 행동 인덱스로 생성하고 원래 행동 ID를 별도 필드에 보존한다. 정적 검사 조건·소유권·암호문·민감 정보 검사 규칙을 완화하지 않았다. 추가 통합 검증은 1회로 한정하며 새로운 기능 실패가 남으면 배포하지 않고 상태를 보고한다.

Kotlin 최종 전체 build는 API 테스트 2건으로 실패했다. 연결 fake E2E와 검토용 재시작은 실행하지 않았다. OpenAPI YAML 파싱·91개 operation ID 중복 검사·내부 참조 검증과 Compose 파일럿/E2E 모델 검증은 통과했다. 초기 교차 리뷰에서는 작업 정산·본문 반영·분석 검토의 차단 결함을 발견하지 못했으나 최종 테스트에서 아래 P2 필수 검사 실패가 확인됐다. 최종 diff와 같은 변경의 테스트·리뷰 기준을 이 절에 기록한다. 무거운 빌드는 호스트에서 한 번에 하나만 실행한다.

자동 유료 평가의 달러 상한은 아직 미응답이다. 사용자의 유료 호출 허용과 별개로 자동 평가를 시작하지 않으며 실제 모델 품질 평가·독자/실무자 검증을 fake 통과로 대신하지 않는다.

### 최종 통합 검증 중단 기록

구현 담당 3회와 총괄의 추가 통합 검증 1회 한도에 도달했다. 마지막 실행 로그는 서버 로컬 `/tmp/easydoc-r2-integration-final.log`이다. 최종 실행에서 다음 항목이 확인되어 PR은 draft로 유지하고 새 코드를 운영에 반영하지 않는다.

1. `ActionGuideJobContractTest`의 응답 키 목록에 새 필수 `operation`이 없었다. 테스트에 키와 기존 v1의 `guide` 값 검증을 추가했다. 이 테스트 수정 후 재검증은 아직 하지 않았다.
2. `SensitiveToStringReachTest`가 `StoredGuideDraftApplication.previousBody`를 감지했다. 독립 리뷰 결과 자동 `toString()`이 `EncryptedContent.scheme`에 심은 검사 표식을 출력하는 것이 원인이며, 실제 이전 본문이 로그에 노출된 증거는 아니다. 실제 DB scheme은 고정되어 있다. 최소 수정은 저장 객체의 `toString()`을 snapshot ID만 표시하도록 재정의하는 것이다. 검사 예외나 탐지 규칙을 바꿀 필요는 없다. 한도에 따라 이 추가 제품 수정은 이번 실행에서 하지 않았다.

후속 순서는 위 최소 수정 → 두 기존 계약/민감 정보 테스트와 전체 backend build → fake 연결 E2E 4개 → 최종 PR 리뷰 → 검토용 restart다. 프런트는 check·64파일 867테스트·build 통과다. 실제 유료 호출과 운영 새 분석 활성화는 하지 않았다. 기존 운영 코드는 `3551a467` 상태를 유지한다.

최종 실행은 8분 18초였다. core 827·application 698·infrastructure 1,208·worker 68개는 모두 통과했고, API 799개 중 797개 통과·2개 실패였다(총 3,600개 중 3,598개 통과). 컴파일·정적 검사·모듈 경계 검사는 통과했다. 이 집계의 계약 테스트 기대값은 수정 전이므로 최종 커밋의 전체 통과 증거로 사용하지 않는다. 코드 커밋은 `3253394d`, [PR 리뷰 기록](https://github.com/kakao-harris-lee/easy-doc/pull/162#issuecomment-5842308752)에 남은 P2를 명시했다.


### 한도 상향 후 재검증 (2026-09-26)

사용자가 구현 3→6회, 통합 검증 1→2회 상향과 최종 approve 후 main 병합·파일럿 반영을 승인했다. 코드 `f06cb762`에서 `StoredGuideDraftApplication.toString()`이 snapshot ID만 출력하도록 수정했다. 기존 `operation` 계약 테스트의 수정과 함께 최종 전체 검증을 다시 진행한다. 프런트는 현재 코드로 check·64파일 867개 test·build를 다시 통과했다.

배포 범위는 제한 파일럿이다. 코드 기본 토글은 OFF를 유지하고 승인된 서버에서 새 분석을 켠다. 사용자 명시 요청·비용 안내·항목별 사람 검토·명시적 본문 반영을 유지하며 기존 문서를 자동 분석하거나 덮어쓰지 않는다. 실제 provider 품질 및 ER-32 실사용자 평가는 완료하지 않았으며 fake 검증이나 코드 리뷰로 대체하지 않는다.


최종 제품 코드 `f06cb762` 기준 승인 후 첫 수정·검증에서 backend `./gradlew build --max-workers=1`가 9분 51초에 통과했다. core 827·application 698·infrastructure 1,208·API 799·worker 68개, 총 3,600개 모두 실패·오류·건너뜀 0이다. 민감 정보 출력 5개, 소유권 14개, 암호화 쓰기 14개 검사도 모두 통과했으며 이전 P2와 계약 테스트 실패를 해소했다. 프런트 check·64파일 867개 test·build도 통과했다.

최신 API/worker jar와 격리 DB로 기존 runner의 fake E2E 4개를 실행해 51.4초에 모두 통과했다: 기존 ER-07 생성/확인/출력, dirty 선저장/stale 출력 차단, ER-30 분석→검토→추가 안내→전체 보완의 미확인 본문 반영→이전 본문 TXT, E17 320px/44px 접근성. 실행 후 임시 API·worker·DB·프런트 프로세스를 정리했고 기존 운영 서비스는 유지했다. Compose 파일럿/E2E 모델과 diff 검사도 통과했다. 최종 PR CI·리뷰·병합 및 배포 결과는 [PR #162](https://github.com/kakao-harris-lee/easy-doc/pull/162)의 최종 리뷰·운영 반영 기록을 따른다. 본 문서 앞의 실패/중단 내용은 이전 시점 이력이다.
