# 쉬운글 변환의 추가 강점 조사

조사일: 2026-09-18. 상태: 공개 자료와 저장소 문서를 바탕으로 한 제품 가설. 구현 계획 확정이나 성능 검증 결과가 아니다.

## 1. 추천 방향

**공공·복지 문서의 조건을 정확히 전달하고, 독자가 해야 할 일을 찾게 하며, 담당자의 검수 시간을 줄이는 변환**에 집중한다.

우선 조사·실험할 후보는 ① 조건·예외의 의미 보존 검수, ② 행동 순서 중심의 안내문 구성, ③ 공식 용어와 문맥 설명의 결합이다. 장기적으로는 실제 이해도와 검수 시간의 개선 증거가 강점이 된다. 경쟁 제품보다 우수하다는 비교 결과는 아직 없다.

현재 제품의 보편적인 초등학교 5~6학년 어휘·문장 목표는 유지한다. 당사자 독해 실험이나 대규모 사전 구축을 일상적인 표현 개선의 선행조건으로 삼지 않는다. 다만 특정 독자 집단에 대한 효과나 경쟁 우위를 주장하려면 그에 맞는 별도 검증이 필요하다.

## 2. 현재 기반과 확인 범위

이번에는 공통 기획·품질 보고서·공개 가이드만 확인했다. 제품 코드를 변경하거나 현재 배포 환경을 시험하지 않았다. 아래의 ‘현재 기반’은 해당 문서에 기록된 범위다.

| 현재 기반 | 추가 기회 |
|---|---|
| 원문·결과 비교, 직접 수정, 문단 재변환, 선택 단어 사전 조회 | 위험한 변경을 먼저 보여 주는 검수 지원 |
| 숫자·날짜·공식 이름 등의 보존 검사와 제한적 자동 보정 | 숫자가 누구에게, 어떤 행동과 조건에 적용되는지 확인 |
| 개념 설명과 문맥을 고려한 사전 참고 자료 | 공식 명칭·뜻·현재 문서에서의 역할을 일관되게 연결 |
| DOCX·HWPX 같은 형식 내려받기 | 배포 문서의 읽기 순서와 검수 흔적 개선 |

근거: [공개 이용 가이드](../../frontend/src/content/guide/user-guide.md), [모델·독해 품질 보고서](2026-09-12-model-reading-quality.md), [프롬프트·사전 재검증](2026-09-12-prompt-rag-revalidation.md), [현재 품질 정책](../master-plan.md#33-품질-신뢰-체계).

기존 보고서는 숫자 보존 검사로 모든 AND/OR 관계와 적용 대상을 보장할 수 없다고 명시한다. 실험 중에는 ‘60일 이내 제출’이 ‘60일 안에 작성’으로 바뀌거나, 여러 대상에 걸린 조건이 한 대상에만 붙는 사례가 있었다. 후속 프롬프트 수정과 표본 확인도 기록되어 있으므로, 이를 현재 제품의 미해결 오류라고 단정하지 않는다. **이런 오류 유형을 검수 가능한 형태로 다루는 것**이 확장 후보다.

## 3. 경쟁·연구에서 확인한 점

### 경쟁 서비스의 공개 안내

- 국내 **온글**은 말투 설정, 정보량·보기 방식 조절, 전문가 및 정보사용자 감수, 별도의 웹 접근성 서비스와 뷰어 설정을 소개한다. 따라서 ‘말투 조절’, ‘당사자 감수’, ‘글자 크기 변경’만으로 독자적인 강점을 주장하기 어렵다. 공식 안내를 확인한 것이며 실제 품질·제공 범위는 체험하지 않았다. [온글 기능 안내](https://easy-read.co.kr/plans/)
- **Read&Write의 Rewordify**는 어려운 표현을 쉽게 바꾸고 원래 표현과 바뀐 표현을 전환해 볼 수 있다. 단어 치환과 원문 확인 자체도 이미 알려진 기능이다. [공식 도움말](https://support.texthelp.com/help/readwrite-for-google-chrome-rewordify)

공개 페이지에 없는 기능이 경쟁 제품에 없다고 단정하지 않는다. 위 두 제품만으로 시장 전체를 조사했다고 보기도 어렵다.

### 연구와 지침

- **문맥 속 개념 설명:** EMNLP 2024의 전문 분야 개념 단순화 연구에서는 평가자가 어려운 표현의 치환보다 개념 설명을 선호했다. 한국어 복지 문서의 효과를 직접 증명한 연구는 아니지만, 사전의 역할을 확장할 근거가 된다. [원문](https://aclanthology.org/2024.emnlp-main.357/)
- **의미 보존:** TACL 2024는 변환문만 읽고 원문 기반 질문에 답할 수 있는지 평가했다. 해당 실험에서는 가장 우수한 지도학습 시스템도 최소 14%의 질문에 필요한 정보를 제공하지 못했다. 이 수치를 현재 모델이나 easy-doc의 오류율로 적용하지 않는다. [원문](https://aclanthology.org/2024.tacl-1.24/)
- **실제 이해도:** 2025년 arXiv 논문은 4,563명을 대상으로 한 무작위 실험에서 변환문 독자의 객관식 정답률이 전체 평균 3.9%p 높았다고 보고한다. 주제별 차이가 있었고, 한국어·발달장애인 대상의 제품 검증은 아니다. 이번 조사는 공개 초록의 결과를 확인한 범위다. [논문](https://arxiv.org/abs/2505.01980)
- **정보 구조:** W3C COGA는 단계별 지시, 암묵적인 내용 설명, 수치 이해 지원, 실제 사용자 참여를 권고한다. WCAG 적합성에 필수인 규범 요구사항과는 구분되는 보완 지침이다. [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **문서 구성:** 호주 정부 Style Manual은 Easy Read를 글·배치·이미지의 결합으로 설명한다. 독자 연구, 필요한 용어의 풀이, 성인에게 유아적인 표현을 쓰지 않는 점을 강조한다. 영어권의 학년·음절 기준을 한국어에 그대로 적용하지 않는다. [Style Manual](https://www.stylemanual.gov.au/content-types/easy-read)

## 4. 강점 후보와 작은 시작점

아래 우선순위와 비용은 제품 판단이다. 비용은 설계·개발·검수의 상대적 부담이며 견적이나 실측값이 아니다.

| 후보 | 독자·담당자가 얻는 가치 | 작은 시작점 | 상대 부담 | 우선순위 |
|---|---|---|---|---|
| 조건·예외 보존 검수 | 잘못된 신청 안내와 담당자 확인 부담 감소 | 대상·조건·예외·기한·행동을 원문과 대조하는 검수표 | 중~높음 | 1 |
| 행동 중심 안내 | 무엇을 준비하고 어디로 언제 제출하는지 찾기 쉬움 | 기존 변환문에 신청 절차 요약을 별도 제시 | 중간 | 1 |
| 공식 용어 + 문맥 설명 | 실제 서류·제도를 찾아가면서 의미도 이해 | 공식 명칭을 유지하고 역할 설명을 바로 옆에 제공 | 낮음~중간 | 1 |
| 표·수치 관계 설명 | 금액의 단위와 적용 대상을 잘못 읽는 문제 감소 | 소수의 표 유형에서 행·열 제목과 각주를 함께 설명 | 높음 | 2 |
| 근거가 연결된 검수 기록 | 변경 확인·인수인계·개정 작업 단축 | 중요 항목의 원문 위치, 수정 내용, 담당자 확인 기록 | 중간 | 2 |
| 읽는 목적에 맞춘 설명량 | 필요한 설명만 선택해 읽기 | 기본 본문과 추가 설명을 분리하는 한 가지 선택지 | 중간 | 3 |
| 의미를 전달하는 그림·배치 | 절차와 장소를 시각적으로 이해 | 검수한 소수의 그림과 일관된 문서 틀 | 높음 | 3 |

### 4.1 조건·예외 보존 검수

단어·숫자의 잔존 여부에서 더 나아가 **대상 — 조건 — 행동 — 기한 — 예외**의 연결을 보여 준다.

예시 원문(설명용 가상 문장): ‘A와 B를 모두 충족한 사람은 통지받은 날부터 60일 이내에 서류를 제출해야 한다. 다만 C에 해당하면 제외한다.’

검수 항목은 ‘A와 B를 모두 만족하는가’, ‘C가 제외 조건으로 남았는가’, ‘60일의 시작이 통지받은 날인가’, ‘60일이 작성이 아닌 제출 기한인가’다. 사람은 같은 숫자가 있다는 사실보다 이 관계를 확인해야 한다.

처음에는 담당자가 확인하는 검수표로 가능성을 시험한다. 자동 의미 판정은 별도 난도가 있으므로, 자동 검사에서 발견하지 못했다는 이유만으로 ‘의미 보존 완료’ 표시를 하지 않는다. 애매한 원문은 담당자가 확인할 항목으로 남긴다.

### 4.2 행동 중심 안내

문서 내용을 ‘신청 대상 → 받을 수 있는 지원 → 준비할 서류 → 제출 방법·기한 → 예외·문의’ 순서로 찾게 한다. 처음부터 원문의 모든 구조를 바꾸기보다, 기존 쉬운 본문과 구분되는 **신청 절차 요약**을 시험하는 편이 범위가 작다. W3C의 단계별 안내 원칙을 제품에 적용하는 제안이다. [W3C COGA](https://www.w3.org/TR/coga-usable/)

요약에도 신청에 영향을 주는 제외·예외 조건을 가까이 표시한다. 원문에 없는 서류 발급처·링크·신청 자격은 추정해서 채우지 않고 ‘원문에 안내 없음’으로 남긴다. 요약과 전체 변환문의 역할을 화면에서 명확히 구분한다.

### 4.3 공식 용어와 문맥 설명

공식 서류명을 없애면 실제 발급·제출 과정에서 찾기 어려워진다. 공식 명칭은 유지하고 ‘무엇인지’, ‘이 문서에서는 왜 필요한지’를 설명한다. 역할 설명은 원문 또는 검수한 근거에 한정한다.

일반 사전의 긴 뜻풀이를 매번 반복하는 대신, 해당 문서에서 이해에 필요한 설명을 첫 등장에 제공한다. 기존 사전과 개념 설명 정책을 강화하는 방향이며 새 기능 전체를 처음부터 만드는 제안은 아니다. 검수 완료 표현과 사업별 조건은 구분하여, 한 사업의 조건이 다른 사업으로 섞이지 않게 한다. [개념 설명 연구](https://aclanthology.org/2024.emnlp-main.357/)

### 4.4 표·숫자와 검수 기록

표에는 ‘월/연’, ‘가구/개인’, ‘최대/정액’, ‘이하/미만’, 각주에 따른 예외가 결합된다. 표를 문장으로 바꾸는 것보다 이 관계를 보존하는 것이 중요하다. 표 전체를 장황하게 풀기 전에 작은 표 유형으로 이해도·분량을 함께 비교한다. PDF 추출 단계에서 이미 행·열이 깨진 경우는 변환 품질과 따로 진단한다.

검수 기록에는 중요 항목의 원문 위치와 담당자 확인을 연결한다. 자동 검사·담당자 검수·당사자 감수의 상태를 구분한다. 기관별 검수 사례를 장기 자산으로 삼는다면 원문과 결과의 현재 30일 보관 정책을 지키고, 별도로 재사용 승인을 받은 표현·오류 유형만 축적하는 방식을 먼저 검토한다.

### 4.5 독자 선택과 시각 자료

‘발달장애인용’, ‘고령자용’이라는 분류만으로 독해 능력을 가정하지 않는다. 우선 ‘핵심만 먼저 보기’, ‘낯선 개념 설명 더 보기’처럼 목적·설명량을 선택하게 하는 가설을 시험한다. 기본 품질 기준은 유지한다.

그림은 후순위로 검토할 가치가 있다. 2025년 TSAR 연구도 문서 단순화와 삽화의 의미 정합성을 다룬다. 다만 생성 그림이 이해를 돕는지는 우리 문서와 독자에게 따로 확인해야 한다. 초기에는 검수한 그림·절차 도식으로 시작하는 편이 비용과 검수 범위를 제한하기 쉽다. [TSAR 논문](https://aclanthology.org/2025.tsar-1.2/)

## 5. 가장 작은 검증 제안

이번 조사에서 실험은 실행하지 않았다. 다음 순서로 진행하면 대규모 개발 이전에 방향을 확인할 수 있다.

1. **공개 문서 10건을 선정한다.** 자격 조건이 많은 문서 4건, 절차 안내 3건, 표·금액이 많은 문서 3건으로 시작한다. 기존 프롬프트 개선에 반복 사용한 문서와 새 평가 문서는 구분한다.
2. **출력을 보기 전에 확인 질문을 고정한다.** 각 문서의 대상·제외 조건·제출 서류·시점·금액 관계를 묻는다. 원문 자체로 답할 수 없는 질문도 표시한다.
3. **현재 결과와 후보 하나씩을 비교한다.** 기존 결과물과 사람이 편집한 예시로 우선 시험할 수 있다. 그 결과로 자동 생성 성능을 주장하지는 않는다. 여러 기능을 동시에 바꿔 무엇이 효과를 냈는지 모르게 만들지 않는다.
4. **담당자 검수 부담을 본다.** 3~5명의 실무자에게 확인 누락과 실제 배포 가능한 문서까지의 수정 시간을 관찰하는 탐색 실험을 제안한다. 순서를 바꾸고 가능한 범위에서 결과의 출처를 가린다.
5. **독자 효과는 별도로 측정한다.** 실제 목표 독자에게 이해 질문과 모의 신청 준비 과제를 적용한다. 같은 글을 반복해서 읽은 학습 효과를 줄이도록 문서·조건 순서를 배분한다. 독자 집단별 결과를 구분한다. 소규모 탐색은 통계적 우월성 입증이 아니다.

| 평가 축 | 볼 지표 | 해석 |
|---|---|---|
| 의미 보존 | 자격·예외·기한·대상 변경, 누락, 근거 없는 추가 | 읽기 쉬움과 별도로 확인 |
| 이해 | 질문 정답률, 필요한 정보 찾기 성공률 | AI judge 점수를 독자 이해율로 대체하지 않음 |
| 행동 | 모의 신청에서 서류·제출처·기한 선택 정확도 | 문장이 자연스럽다는 인상과 구분 |
| 업무 | 검수·수정 소요 시간, 배포 가능 판단 | 구매 가치에 대한 탐색 지표 |
| 운영 | 문서당 생성 비용·대기 시간, 경고 오탐 부담 | 품질 개선에 따르는 비용을 함께 측정 |

치명적인 의미 변경이 발견된 후보는 수정 후 다시 확인한다. ‘10건에서 오류를 찾지 못함’을 전체 정확도 100%로 표현하지 않는다. 가독성·의미 보존을 별도로 평가하는 연구 방향도 참고한다. [READI 2024](https://aclanthology.org/2024.readi-1.1/)

새 검증 하네스나 유료 호출을 이번 조사에 추가하지 않았다. 향후 유료 생성 실험을 할 때는 대상·반복 횟수·달러 상한을 먼저 확정하고 기존 Kotlin 평가 경로를 활용한다.

## 6. 권고

첫 실험은 **복지 신청 안내문에서 ‘조건 검수표 + 행동 순서 요약’이 담당자의 확인 시간과 독자의 정보 찾기를 개선하는가**로 잡는다. 두 후보의 효과를 먼저 따로 확인한 뒤 결합한다.

단어 치환·말투·뷰어·감수 서비스는 경쟁 제품에도 공개된 기능이다. easy-doc의 추가 강점은 한국어 공공·복지 문서에서 자주 나타나는 조건 관계를 정확히 전달하고 그 품질을 담당자가 빠르게 확인할 수 있도록 만드는 데서 찾아볼 만하다. 이는 조사에서 도출한 제품 가설이며, 경쟁 우위는 비교 검증으로 확인해야 한다.
