# 원문 위치 표식 보존

완료 — 구현·전체 build·유료 실측과 로컬 API·worker 반영을 마쳤다.

사용자는 원문의 `○`, `-`, `*`, `※`가 변환문에서 사라지거나 다른 기호가 되어 같은 항목을 찾기 어렵다고 보고했다. 후처리는 이 기호를 지우지 않았다. 시스템의 ‘기호는 말로 풀기’와 ‘제목은 일반 텍스트’ 지시에는 원문 위치 표식의 예외가 없었고, TEXT/TXT의 전체 변환에는 파일의 목록 구조 지시를 적용하지 않아 표식 보존 기준이 전달되지 않았다.

## 변경

- 기호를 일괄적으로 풀도록 한 문장을 제거하고, 제목·항목·주의사항의 표식을 같은 항목 앞에 유지하는 공통 기준을 변환·보정에 한 번씩 전달한다. 제목과 문장은 쉽게 고칠 수 있다.
- 문장 안의 `※` 안내를 나누면 `※`도 함께 옮겨 원래 항목 바로 아래에 둔다. 원문에 표식이 있으면 표의 값이나 새 설명을 나열하기 위한 추가 표식을 붙이지 않는다.
- Kotlin에서 원문·초안의 표식 종류·개수·순서를 비교한다. 줄 앞의 제목·목록·번호와 문장 안의 `※`를 검사한다. 날짜의 점, 음수, 전화번호의 붙임표, 본문 곱셈과 표의 빈 값 `-`는 검사 대상이 아니다.
- 표식이 바뀌면 기존 보정 1회 안에서 원문과 함께 복원을 요청한다. 원문 표식을 훼손한 보정문은 채택하지 않는다. 추가 재시도 루프나 별도 평가 모델은 제품 경로에 넣지 않았다.

기존 표의 값·조건 대응, 쉬운 어휘·문장 기준, 파일 구조 보호 정책은 유지한다. HTTP 계약과 프런트엔드는 변경하지 않았다. 기존 저장 결과는 자동으로 다시 생성하지 않으며 새 변환부터 적용한다.

## 검사 범위와 한계

표식 검사는 들여쓰기 공백과 줄 수를 고정하지 않는다. 동일한 표식끼리 의미상 위치가 바뀌었는지는 순서 비교만으로 판단할 수 없으므로 공통 지시와 실제 원문·출력 대조도 함께 사용한다. 한 번의 보정에 실패하면 기존 정책대로 첫 초안을 제공한다. 모든 생성 결과의 표식 보존을 무조건 보장하는 강제 렌더러는 아니다.

## 검증
