# 다중 AI 모델 변환 결과 비교 제공 검토

검토일: 2026-10-22.

질문: 같은 원문을 여러 AI 모델(GPT·Claude·Gemini·국산 모델)로 변환한 결과를 나란히 보여 주고 사용자가 고르게 하면, 경쟁사 대비 장점이 되는가?

같은 질문이 다시 나오면 이 문서부터 읽는다. 「다시 볼 조건」에 해당할 때만 재조사한다.

방법은 다음과 같다.

- **조사 범위:** 웹 5갈래(경쟁사, 비교 UX 선례, 구현·비용, 공공기관 규제, 수익화·활용)와 이 저장소 코드 1갈래를 조사했다.
- **검증:** 출처 12개를 정독해 주장 48개를 뽑았다. 그중 중요도 상위 20개를 반박자 3명이 각각 다른 관점으로 검증했다. 관점은 출처 정확성, 최신성, 일반화 범위다. 19개가 살아남았고 1개를 폐기했다.
- **측정하지 않은 것:** 실제 여러 모델 호출은 하지 않았다.

## 결론

상시 비교 기능은 도입하지 않는다. 기본은 결과 1개를 유지한다. 순서는 다음과 같다.

1. 오프라인 측정
2. 내부 자동 선택(사용자에게 노출하지 않음)
3. 상위 플랜 한정으로 대안 1개를 보여 주는 옵트인

각 단계는 실측으로 통과해야 다음으로 간다. 근거는 다음 세 가지다.

- 경쟁사의 신뢰 근거는 모델 수가 아니라 사람 검수와 기관 맞춤이다.
- 원가가 모델 수만큼 곱해진다.
- 사용자 선택 데이터는 쉬운 글에서 품질 대신 길이 선호를 학습할 위험이 있다.

## 근거

### 경쟁

- **온글(이큐포올+소소한소통):** 기관 고유 정책·매뉴얼 기반 RAG를 차별점으로 내세운다. 쉬운 정보 전문가·발달장애인 검증은 기관이 요청하면 붙는 옵션이다. 다중 모델 비교 언급은 없다([기사](https://www.tfmedia.co.kr/mobile/article.html?no=204369)).
- **SUMM AI:** 원문 재현과 사실 정확성을 사람이 확인하는 것을 전제로 한다([EIB Stories](https://www.eib.org/de/stories/language-simplifier-software-summai)).
- **범용 비교 도구와 번역 업계(미검증):** 범용 AI 도구(TypingMind 등)에서는 다중 모델 비교가 흔하다. 기계번역 B2B는 사용자 비교보다 자동 엔진 선택 쪽으로 간다(Phrase 등). 둘 다 검증하지 않은 검색 결과다.

### 이 저장소에서 바뀌어야 하는 것

- **공급자는 프로세스 전체에서 하나다.** `LlmProviderConfiguration`의 `when (properties.provider.lowercase())` 분기가 빈 하나를 만든다. Gemini·국산 모델 어댑터는 없다.
- **변환 1건에 결과는 1개다.**
  - `V1__initial_schema.sql`의 `easy_text_encrypted` 열이 하나이고, 공개 API도 `easy_text`·`edited_text`가 단일 필드다.
  - 후보 N개는 계약·contract test·프런트 타입을 함께 바꾸는 공개 API 변경이다.
- **재사용할 수 있는 부분:**
  - `LlmProvider`·`LlmCompletion`(토큰·지연·예상 비용)
  - 사실 보존·스타일 검사(결과와 원문만 받는다)
  - `llm_calls` 원장(`conversion_id` FK가 없어 같은 변환에 여러 행을 남길 수 있다, `V14__llm_calls.sql`)
- **최소 설계안:** 후보 표 `conversion_candidates`와 공급자 레지스트리를 더한다. 고른 후보 하나를 기존 `conversions` 경로로 확정하면 검수·내보내기·재변환은 그대로 둘 수 있다. 나란히 보기 화면은 새로 만들어야 한다. `ReviewEditor.tsx`는 1,972줄짜리 단일 결과 중심 컴포넌트다.

### 원가·과금

- **관측 원가:** 건당 평균 US$0.12841, 크레딧당 약 US$0.04815다. 표본은 3건뿐이다(`docs/plans/2026-09-13-service-pricing.md`). 모델 N개를 병행하면 원가가 대략 N배가 된다.
- **크레딧 정산:** 문서 등록 때 예약하고, 변환 1건당 한 번 consume 또는 release로 정산한다. 후보별 과금 개념은 없다.
- **모델 간 단가 차이:** Claude만 봐도 백만 토큰당 입력/출력 단가가 최대 5배 다르다. Fable 5.1은 $10/$50, Sonnet 5.5는 $2/$10이다([Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing), 2026-10-22 조회).
- **미확인 단가:** Gemini와 국산 모델 단가는 2차 출처끼리 엇갈려 확인하지 못했다.

### 지연·재시도

- **지연:** worker lease 1개가 변환 1건을 처리한다. LLM 읽기 타임아웃은 120초다. 모델을 순서대로 부르면 지연이 N배가 되고, 병렬로 부르려면 lease·예산 구조를 바꿔야 한다.
- **부분 실패:** 일부 모델만 실패했을 때 lease 전체를 다시 돌리면, 이미 성공한 모델도 다시 호출해 이중 과금된다. "재시도 책임은 한 계층" 규칙과 맞춰 설계해야 한다.

### 규제·보안

- **OpenAI 보존:** `store=false`로 호출해도 남용 감시 로그를 기본 최대 30일 보관한다. ZDR은 사전 승인이 필요하다([OpenAI Your data](https://developers.openai.com/api/docs/guides/your-data)). "무보존"이라고 고지하면 틀린다.
- **공급자별 보존 정책(미검증):** Gemini 유료 API는 55일 로깅([정책](https://ai.google.dev/gemini-api/docs/logs-policy)), Anthropic ZDR은 조직별 승인이다([정책](https://platform.claude.com/docs/en/build-with-claude/api-and-data-retention)).
- **법무 미결:** 해외 AI 처리·국외 이전 법무 항목이 아직 미결이다(`docs/plans/2026-09-10-legal-counsel-questions.md`). 공급자가 늘면 처리방침·국외 이전 고지·no-training 계약 대상도 함께 는다.
- **공공 보안 지침(미확보):** 국정원 AI 보안 가이드북, N2SF, CSAP, 행안부 지침 같은 국내 1차 자료는 원문을 확보하지 못했다.

### 사용자 선택 데이터

- **길이 편향:** 사람의 선택은 길이에 크게 끌린다. 회귀계수는 길이 0.249, 마크다운 목록 0.031이었다([LMSYS Style Control](https://lmsys.org/blog/2024-08-28-style-control)). 짧게 다듬는 쉬운 글에서 선택 비율을 품질 신호로 쓰면 거꾸로 학습할 수 있다.
- **아첨 편향:** 사람 선호는 아첨 편향도 키운다([Anthropic, ICLR 2024](https://arxiv.org/html/2310.13548v4)). OpenAI는 2025-04 GPT-4o 업데이트에서 엄지 피드백 보상이 아첨 억제를 약화시켰다고 분석했다([정리](https://simonwillison.net/2025/May/2/what-we-missed-with-sycophancy/)).
- **전문가 일치율:** 일반 사용자 투표와 전문가 평가의 일치율은 72~83%다([Chatbot Arena](https://arxiv.org/pdf/2403.04132)).
- **지표:** 선택 비율만 보지 말고 사실 보존 검사 통과율과 검수 중 수정량(`edited_text`)을 함께 본다.
- **검수 시간 근거 없음:** 비교가 검수 시간을 줄인다는 직접 근거는 찾지 못했다.

## 권장 단계

모든 단계에 실제 외부 LLM 호출이 들어간다. 단계마다 비용·범위를 제시하고 사용자 승인을 받는다.

| 단계 | 내용 | 다음 단계로 가는 조건(제안치) |
|---|---|---|
| 0. 오프라인 측정 | 기존 6문서 평가 세트로 후보 모델 2~3개의 사실 보존율·지연·호출당 원가를 측정 | 현 모델과 게이트 통과율이 같거나 높고, 원가가 허용 범위 안인 조합이 있다 |
| 1. 내부 자동 선택 | 노출 없이 게이트·품질 점수로 1개를 고르는 라우팅/캐스케이드 | 수정률과 게이트 통과율이 단일 모델보다 나빠지지 않는다 |
| 2. 옵트인 대안 1개 | 상위 플랜 한정 「대안 보기」, 후보 표와 선택 로그 추가, 고른 결과는 기존 편집기로 합류 | 검수 시간·수정량이 대조군보다 줄고 원가가 요금 안에 머문다 |
| 3. 확대 결정 | 길이를 통제한 선택 로그와 A/B 결과로 후보 수·대상 확대 여부 결정 | 사전에 정한 임계를 충족하고, 국외 이전 고지가 정리됐다 |

## 다시 볼 조건

1. 단계 0 측정을 승인하고 결과가 나왔을 때.
2. 국외 이전·처리위탁 법무 결론이 나왔을 때.
3. 국산 모델(Phase 2) 도입을 결정했을 때.
4. 경쟁사가 다중 모델 비교를 내세웠을 때.

## 문서 간 불일치

크레딧 계산식이 두 문서에서 다르다.

- 계약 `contracts/easy-doc-v1.yaml`(402 크레딧 예약 설명): `ceil(char_count / 100) / 10`, 0.1크레딧 단위
- `docs/plans/2026-09-13-service-pricing.md`: `ceil(char_count / 1000)`

계약이 정본이다. 가격 문서는 이번에 고치지 않았다.

## 폐기된 주장

Intento 보고서의 "요구사항 기반 맞춤화가 기본 대비 오류를 5~10배 줄인다"는 폐기했다. 기준과 측정 방법이 공개되지 않은 벤더 문구이고, 번역 맥락을 쉬운 글로 일반화한 것이기 때문이다.
