# R3 bounded review

검수일: 2026-09-21

대상: `055196d8` 기준 현재 R3 백엔드 변경. 이 문서는 독립적인 코드·호출 경로 검토이며, 유료 모델 평가나 사람 파일럿의 결과가 아니다.

## 발견 사항

재변환 경로가 모든 `RECONVERT` 호출에 `R3_UNIT` 설명 버전을 적용하면, 현재 문단 앞에 확실한 본문 prefix가 있더라도 새 공식 이름의 역할·정의를 덧붙이지 말라는 보수 지시가 우선한다. 반면 앞선 본문에 없는 이름은 현재 원문에 근거할 때 첫 설명을 허용하는 prior-context guard가 추가되어 두 지시가 충돌한다. 대상이 첫 단위이면 `targetEasyIndex == 0`에서 prefix를 `null`로 생략하므로 같은 보수 경로가 선택된다.

이는 안전성이나 호출 수의 결함이 아니라, R3의 “첫 등장에 필요한 짧은 설명” acceptance를 재변환에도 적용할 때 발생하는 **P2 acceptance gap**이다. 보수적인 `R3_UNIT` 정책을 명시적으로 유지할 경우 정책 선택으로 기록할 수 있지만, R3 acceptance를 재변환에 적용한다면 고쳐야 한다.

검토 중 P0/P1 수준의 사전 정보 유출, 내부 caution·예문 노출, marker 손상, edited body보다 easy body를 우선하는 mapping 오류, 누락된 DI/callsite, 추가 provider 호출은 발견하지 못했다. 재변환 context 계산은 현재 본문에서 `editedText`를 우선하고 명확한 `HIGH` 대응 prefix만 사용하며 provider를 추가 호출하지 않는다. repair도 기존의 최대 한 번 호출 경계를 유지한다.

## 수정 및 재검증 결과

수정은 context의 확실성을 세 상태로 분리했다.

- `null` 또는 mapping을 확인할 수 없는 context: 기존 보수 경로인 `R3_UNIT`
- 확인된 첫 단위의 빈 prefix: `R3`로 실행하여 첫 등장 설명을 허용
- 확인된 비어 있지 않은 prefix: `R3`와 prior-context guard를 함께 적용

첫 단위·유효 prefix·불확실 mapping의 회귀 테스트가 추가되었고 focused test가 통과했다. 이 P2 acceptance gap은 코드·테스트 기준으로 닫혔다. 다만 이 검토만으로 R3 release 또는 의미 품질 승인을 주장하지 않는다.

## 검증 상태

dictionary provenance/default-off, prompt wrapping, conversion/reconversion focused tests가 통과했다. 후속 정적 분석·형식 오류를 해결한 통합 `./gradlew build --no-daemon`도 통과했고, 3,158개 테스트의 실패·오류·건너뜀은 0개다. 프런트 check·729개 테스트·build와 R3 opt-in fake E2E 27개 통과/1개 건너뜀도 별도로 확인했다.

이번 review에서는 제품 코드, prompt, golden output을 수정하지 않았고 paid call도 실행하지 않았다.
