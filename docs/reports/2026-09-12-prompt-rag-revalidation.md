# 프롬프트·사전 재검증 결과

완료 — 통합 프롬프트·사전 참고·필요 시 보정·평문 구조 정책을 로컬 API와 worker에 반영했다. 채택 구성은 Astra medium이다. 대표 6종 문서를 비교·확인하고 실제 Chrome 입력까지 검증했다. 이전 측정부터의 유료 누적은 $17.234290으로 승인 상한 $50 이내다.

## 목표와 조사 범위

기준은 보편적인 초등학교 5~6학년 수준의 어휘와 자연스러운 문장이다. 실제 학생 시험이나 모든 용어의 정의를 요구하지 않는다. 원문의 의미·대상·조건은 유지한다. 공개 API와 프런트엔드는 이번 변경 대상이 아니다.

## 확인된 원인과 구조

1. 시스템에 역할·의미 보존·단어 설명·길이·자가 점검이 중복되고, 사전 구역이 다시 편집을 지시했다. 보정은 역할 지시부터 중복됐다. 현재 문서의 첫 system은 4,886자, 보정은 3,360자였다. 1차 통합안은 1,903자와 2,086자였고, 최종 변환 system은 2,021자다. 길이가 품질 저하의 직접 원인인지는 아래 실측으로 구분한다.
2. 사전 검색은 임베딩 RAG가 아니라 문자 트라이와 낱말 경계 검사다. 2,177개 항목, 40,128개 표면형을 갖지만 문맥에 따른 의미 선택 모델은 없다. 자동 매칭한 뜻이 현재 문맥과 다른지는 생성 모델이 판단한다. 예문은 검수 완료 표시가 있는 경우만 주입하는데 실제 색인의 검수 완료 예문은 0개다.
3. 조회와 생성 주입 스위치가 분리돼 있다. 주입 기본값은 true이고 조회 기본값은 false다. 조회가 비활성인 상태를 사전 주입도 꺼졌다는 뜻으로 해석하면 안 된다.
4. 현재 문서에 주입된 사전에는 다른 사업의 월 2만 원 부담금, 차상위계층의 50% 기준 등이 들어 있었다. 원문에 없는 조건을 참조 정보로 노출하고 있었다. 시술의 뜻풀이에는 ‘의학적인 처치’라는 어려운 표현이 있고, 환수의 후보는 ‘되거둠’이었다. 대규모 수량 확충보다 제공할 정보의 범위와 품질을 정리할 필요가 있다.
5. 50자 길이 제한은 프롬프트에서는 보조 기준이지만, 기계 지적 하나만으로 보정 호출이 발생한다. 공식 파일 이름은 면제하나 일반 서류명에 남은 ‘경감’ 등은 지적으로 남는다. 이는 의미 오류와 다른 종류의 한계다.

조회 기본값의 코드상 이유는 초기 기능 도입 시 API의 색인 적재를 명시적으로 켜도록 한 것이다(`DictionaryLookupProperties`). 사전 품질 실패를 보고 자동으로 끄는 분기는 없다. 과거 [2026-08-30 사전 A/B 기록](../../dictionary/docs/consumer-overlap-policy.md#51-ab-재실측-결과-2026-08-30--실행했고-이-설계로는-효과를-판별할-수-없다)은 on/off 모두 스타일 통과 47/56으로, 당시 설계로 효과를 판별할 수 없다고 결론 냈다. 이는 사전이 무의미하다고 입증한 결과가 아니다. 이번 소규모 비교도 모집단 전체의 통계적 우월성을 주장하지 않고, 실제 실패 사례와 문서별 원가를 바탕으로 개선 구성을 고른다.

## 적용한 변경

- 변환과 보정의 편집 기준을 한 함수로 모으고 반복된 역할·길이·고정 단어 목록을 제거했다. 원문 보존·문맥 연결·필요한 개념 설명·주입 방어는 유지했다.
- 사전 구역을 표현 후보·뜻풀이·공식 이름 참고로 바꿨다. 사업별 금액과 조건이 섞인 `caution`은 생성 자료에서 제외했다. 조회 응답에는 남긴다. 검색·우선순위·개수와 문자 예산은 유지했다.
- `시술`, `환수`, `중위소득` 세 항목을 정본 SQLite와 배포 JSON·런타임 색인에 함께 고쳤다. 사람이 검수한 예문으로 표시하지 않았다. 검수 SQL과 원천 데이터 이력은 보존한다.
- 금액의 천 단위 쉼표를 문장 나열로 세던 오탐을 고쳤다. 일반 나열 쉼표는 계속 검사한다.
- 평문 결과에 마크다운 표를 새로 만들지 않도록 했다. 파일 구조 지시가 있는 표는 기존 구조 기준을 유지한다.
- 사전 주입과 조회의 환경 변수를 분리해 예제 설정에 명시했다. 공개 HTTP 계약은 바뀌지 않는다.

## 평가 기준 정렬

기존 judge의 용어 설명 한 곳 부족도 전체 실패시키는 기준을 사용자 기준으로 고쳤다. 새 기준은 모든 실험 조건에 똑같이 적용했다. 각 실행의 judge도 해당 실행과 같은 모델·effort를 사용하므로 모델 사이의 yes 비율은 독립 평가자의 순위표가 아니다. 따라서 과거 보고서의 통과율과 이번 통과율은 직접 비교하지 않는다. 숫자 검사와 judge는 진단이며, 원문·초안·보정·최종 출력의 직접 대조를 함께 한다.

## 2차 프롬프트·사전 후보와 저비용 모델

`reference-rag`의 Astra medium은 개발 3건 모두 judge yes, 자동 사실 검사 76/76, 절단·재시도·인프라 오류 0건이었다. 변환 system은 1,954자, 보정은 2,137자다. 문서당 생성 비용은 001 $0.28634, 087 $0.22120, 097 $0.33821로 평균 $0.28192다. 변경 전 같은 Astra 구성보다 **약 27.0% 감소**했다. judge를 포함한 이 실행의 전체 비용은 $0.98501이다.

직접 대조에서도 개발 3건의 중요한 수치·조건 변경은 발견하지 못했다. 001은 시술과 기준 중위소득을 일상적인 말로 설명하고 표의 항목·값을 일반 텍스트로 옮겼다. 087은 9세 미만 예외, 6개월 이내 서류, 2년·12개월 조건, 60일 이내 제출을 유지했다. 097은 소득과 재산을 모두 충족해야 하는 조건, 순위별 제외 조건을 보존했다. 남은 국소 개선점은 087의 보정이 조건 문장을 ‘이용하지 않을 수 있습니다. 이 경우…’로 어색하게 나눈 부분, 097의 긴 소득 기준 표현 등이다. 모든 표현이 완벽해졌다는 뜻은 아니다.

같은 소스의 `reference-sol` medium은 평균 생성 비용 $0.11556으로 더 낮았으나 채택하지 않았다. 087에서 원문의 ‘2개월 이상 연속’ 조건이 불분명해지고, ‘60일 이내 제출’을 ‘60일 안에 작성’으로 옮겼다. judge도 연속 조건 누락으로 087을 no로 평가했다. 001은 시술·차상위계층 설명이 줄었고, ‘본인부담 경감 증명서’를 비용을 줄여 주는 서류처럼 설명했다. 한 낯선 단어가 남은 문제와 조건 보존·풀이 정확성 문제를 구분한 결정이다.

Sol high도 같은 개발 3건에서 확인했다. judge는 3/3 yes였지만, 087의 ‘발달장애가 의심된다는 내용’이라는 조건을 의뢰서 항목에만 붙여 의사소견서에도 적용되는지 불분명해졌다. 097은 임차료·자산기준·급여 등의 공문 어휘와 문장 나열이 전반적으로 남았다. 평균 생성 비용은 $0.21551로 Sol medium보다 약 86.5% 높아졌고, 문서당 생성 시간도 평균 120.4초였다. 첫 초안과 보정 모두를 읽은 결과 Astra보다 낫다고 볼 근거가 없어 선택하지 않았다. 모델 judge의 yes만으로 선택하지 않은 사례다.

## 3차: 작성 기준과 자동 보정의 일치

길이·낱말 지적 하나에 글 전체를 다시 쓰는 정책은 ‘의미 관계 우선, 국소적인 낯선 표현은 전체 실패와 구분’하는 작성 기준과 맞지 않았다. 2차 Astra의 첫 초안 3건을 전부 대조하니 이미 중요한 조건을 유지하고 있었고, 087은 오히려 보정 전 조건 문장이 자연스러웠다.

자동 보정 대상을 사실 누락·뜻풀이 충돌·이중 피동으로 좁혔다. `checkStyle`은 변경하지 않아 길이·쉼표·낱말 진단은 계속 보고한다. 새 의미 평가 호출이나 모델 자동 전환은 추가하지 않는다. 사실 복원 우선, 새 사실 누락 시 기각, 보정 실패 시 첫 초안 유지, 최대 2회 상한도 계속 검증한다. 재변환 원장의 예약·정산과 HTTP 응답의 호출 수 테스트는 새 자동 보정 대상인 이중 피동 사례로 유지했다.

첫 실행 `focused-rag`는 3문서의 생성 호출이 6회에서 3회로 줄었고, judge 포함 비용은 $0.50742였다. 그러나 087에서 60일 기한이 제출 대신 작성에 붙어 **이 상태로 채택하지 않았다**. judge는 087을 yes로 평가해 이 오류를 놓쳤다. 097은 긴 소득 기준을 풀지 않은 점과 법 조항으로만 표시된 대상을 이유로 no였다. 법 조항의 부재와 별개로 소득의 비교 관계는 더 쉽게 설명할 수 있다.

이에 기존 사실 보존 지시와 예시를 고쳐 기한을 해당 행동(작성·제출·도착)에 붙이도록 했다. 개념 설명 문장은 압축된 기준의 ‘누구의 무엇과 비교하는지’를 풀어 쓰도록 구체화했다. 문서별 정답 목록이나 별도 사전을 추가하지 않았다. 아래 최종 확인은 이 수정 후 소스로 다시 수행한다.
