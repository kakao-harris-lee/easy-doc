# 쉬운 글 독해 수준 개선 실측

전체 실측 완료: 공개 문서 3건, 최종 변환 결과 15개, 유료 호출 45회. **총 예상 비용 US$1.464392 / 승인 상한 US$10.** 보수적 예약액도 US$8.935236으로 상한 안에 머물렀다. 재시도·절단·통신 실패는 없었다. 부분적인 표현 개선은 확인했지만, 의미 보존과 독해 품질 목표를 달성한 결과는 아니다.

## 실행 조건

- 사용자 승인: 유료 호출 포함, 최종 총 US$10 상한. 실행 중 US$20에서 US$10으로 변경했다. 변경 전 조건의 예약액 전부를 뺀 잔여액만 변경 후 조건에 배정한다.
- 실행 시각: 2026-09-11 밤부터 2026-09-12 새벽까지(KST).
- 모델: `claude-sonnet-5`, effort `low`, 변환·보정 출력 상한 16,000토큰.
- 단가: 입력 US$2 / 출력 US$10, 각각 백만 토큰 기준. 2026-09-11 공식 모델 문서와 로컬 설정을 대조했다.
- 기존 Kotlin `GoldenCorpusLlmEvaluationTest` 레인을 사용한다. 새로운 검증 하네스나 Python 실행은 없다.
- 각 호출 시도 전 입력 UTF-8 바이트 수와 메시지 포장 여유, 출력 토큰 상한으로 보수적인 비용을 예약한다. 실패·재시도 예약도 반환하지 않는다. 실제 사용 토큰의 예상 비용은 별도로 기록한다.
- 원문 3건을 조건마다 2회씩 변환한다. 변경 전 조건을 먼저 실행하며, 각 레인 안의 호출도 순차 실행한다. 실행 순서에 따른 시간 효과를 배제한 무작위 실험은 아니다.
- 원문과 설정을 고정한다. 변경 전은 `27454421338f0331ef9b3e9293149a5a87515956`의 변환·사전 구현이다. 변경 후는 이번 작업의 소스 사본이다. 두 조건의 judge는 동일한 새 독해 평가 지침을 사용한다. 이전 사실 보존 전용 judge 점수와 비교하지 않는다.
- 서비스 재배포와 기존 Chrome 결과 변경 없이 별도 소스 사본에서 실행한다.

### 추가 사전 비교의 사전 기록

변경 전후 비교 진행 중, 사전 효과를 분리하기 위해 보조 조건을 추가하기로 했다(추가 호출 실행 전 기록). 변경 후 소스·모델·judge·출력 상한을 그대로 두고 `EASYDOC_LANE_DICT_PRODUCT`와 컨텍스트 디렉터리 환경변수를 모두 해제해 사전 참고 컨텍스트를 제공하지 않는다. 같은 공개 문서 3건을 각 1회 실행한다. 반복 횟수 차이가 있으므로 주 비교와 합쳐 개선율을 내지 않는다. 먼저 끝낸 두 조건의 예약액 전부를 차감한 잔액으로만 실행한다. 이 보조 조건은 실행 중 발견에 따른 탐색이며, 사전에 확정한 주 비교와 구분한다.

### 평가 도구 자체의 오류

- 현재 문서의 두 변경 전 결과에 대해 judge는 원문의 2024년 표기를 보존한 점을 실패 이유로 들었다. 이는 원문 보존 평가의 오판이다. 원문 자체의 날짜 모순과 모델의 임의 수정을 구분해야 한다.
- 기계 사실 보존 검사는 원문 표의 단위 없는 금액 `2,392,013`을 NUMBER로, 변환문의 `2,392,013원`을 AMOUNT로 추출한다. 값이 같아도 종류가 달라 누락으로 처리한다. `100% → 100퍼센트`도 현재 PERCENT 정규식에서는 같은 표현으로 인식하지 못한다. 따라서 기계 보존율을 실제 정보 손실률로 읽을 수 없다.
- 부모상담 변경 후 두 회차의 필수 사실 누락 1건은 `6개월 이내 → 6개월 안`을 별칭으로 인정하지 않은 결과다. 실제 기간 정보는 두 결과에 모두 남아 있다.
- 변경 후 현재 문서 1회차는 원문의 여러 날짜를 2025년으로 바꿨는데 judge가 yes로 판정했다. 2회차의 no 이유에는 실제 출력에 없는 하반기 날짜 혼동을 언급했다. 합격뿐 아니라 불합격 이유도 검증이 필요하다.
- 반대로 필수 사실 목록과 숫자가 남아 있어도, 연장 조건의 AND가 OR로 바뀌거나 특정 날짜의 연도가 바뀌는 관계 오류는 놓칠 수 있다.
- 실행 중 평가 지침이나 구현을 바꾸지 않았다. 두 조건의 원시 점수를 그대로 남기고 본문 대조 결과를 별도로 기록한다.

### 후속 수정의 우선순위

1. 원문 보존을 검사하는 judge가 원문 오류 수정을 요구하지 않도록 기준을 바로잡고, 허용되는 개념 설명과 새로운 신청 조건·혜택의 추가를 구분한다. 현재 judge 점수로 출시 합격을 결정하지 않는다.
2. 표의 단위·날짜·퍼센트 표기 차이를 동치로 인식하는 사실 검사를 회귀 사례로 보강한다. 같은 숫자가 다른 위치에 남아 있는 것과 원래 조건·날짜가 보존된 것을 구분해야 한다.
3. 원문에 있는 기관명·서류명·각 날짜의 연도와 자격 조건의 AND/OR 관계를 보존하도록 변환·보정 절차를 개선한다. 원문 모순은 모델이 임의로 고칠 대상이 아니다.
4. 사전은 중요한 개념을 설명하는 용도로 좁히고, `기준 중위소득`처럼 설명이 되지 않는 짧은 뜻풀이를 먼저 검수한다. 잘못된 단어 몇 개를 삭제한 것으로 사전 품질 문제가 끝나지 않는다.

이번 실측 중에는 비교할 소스와 judge를 고정했다. 위 후속 항목의 구현·재측정 완료를 주장하지 않는다.

### 일반 검증

예산 제한 지원 코드 추가 후 전체 백엔드 `./gradlew build` 통과. core 623, application 480, infrastructure 931, api 714, worker 13으로 총 2,761개 테스트가 실패·오류·건너뜀 없이 통과했다. 유료 품질 레인의 실패와 일반 코드 검증 결과는 구분한다.

## 증거 파일

[원문·출력·실행 조건·원시 결과 모음](2026-09-11-reading-level-artifacts/README.md)에 원문 3건과 최종 출력 15개, 조건별 레인 보고서·호출 사용량·실행 manifest를 보존했다. API 키는 포함하지 않는다. 출력은 실제 모델 결과 그대로이며 사람이 교정하지 않았다.

## 해석 한계

문서 3건·조건별 2회는 오류 재발과 개선 방향을 보는 소규모 탐색이다. 모집단의 개선율·통계적 유의성을 주장하지 않는다. 동일 모델 judge에는 자기 평가 편향이 있으며, 기존 필수 사실 목록은 모든 자격·예외 관계를 망라하지 않는다. 숫자 보존과 독자의 이해 가능성은 별도로 확인해야 한다.
