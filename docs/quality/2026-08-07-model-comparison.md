# 장문 충실성 — 모델 교체 실험 (2026-08-07)

진단(`2026-08-07-fidelity-diagnosis.md`)은 gpt-4o가 2,600자 이상 입력에서 출력을 0.44~0.77배로
압축한다는 것을 밝히고, 대책으로 **B(분할 변환)** 를 권장했다. 분할은 문서당 호출 수를 청크 수에
비례해 늘리므로, 그 전에 **모델 교체만으로 해결되는지**를 실측한 기록이다.

- 대상: 진단에서 압축이 심했던 장문 4건 `032` `042` `048` `097`
- 대조군: **진단의 gpt-4o-2024-08-06 수치 재사용**(재실행하지 않았다 — 예산 보존)
- 변환은 `ConversionService.convert()` 현행 파이프라인 그대로(마스킹·수리 패스 포함), 모델만 교체
- judge는 **gpt-4o-2024-08-06 고정**(채점자를 바꾸면 비교축이 오염된다)
- 사용한 LLM 호출: **37회 / 예산 40회** (내역은 §7)
- **코드·프롬프트·골든셋을 하나도 고치지 않았다.** provider 파라미터 차이는 스크래치패드 래퍼로만 처리했다.
- 이 문서에는 문서 본문·변환 결과·judge 코멘트를 싣지 않는다 (ID·수치만).

## 1. 결론

### 판정: **부분 해결**

기준(4건 전부 `압축비 ≥ 0.8` **&** `충실성 ≥ 4` **&** `팩트 전잔존`)을 세 조건 모두 만족한 모델은 없다.

| 모델 | 압축비 ≥0.8 | 충실성 ≥4 | 팩트 전잔존 | 판정 |
| --- | :--: | :--: | :--: | --- |
| gpt-4o-2024-08-06 (대조군) | 0/4 | 1/4 | 1/4 | **불충분** |
| gpt-4.1-2025-04-14 | **4/4** | **4/4** | 2/4 | **부분** |
| gpt-5.5-2026-04-23 (low) | **4/4** | 3/4 | 3/4 | **부분** |

핵심은 어느 조건이 깨졌는가다.

1. **진단이 지목한 주 증상(자발적 요약·압축)은 모델 교체만으로 완전히 사라진다.**
   두 후보 모두 4건 전부에서 출력이 입력보다 **길어졌다**(1.06~1.61배). 압축비 0.44~0.77의 무리는
   재현되지 않았다. 같은 프롬프트·같은 파이프라인·같은 문서인데 gpt-4o에서만 나타나는 현상이다.
2. **남는 것은 팩트 유실이다.** 후보 모델도 문서당 최대 1개를 놓친다(gpt-4o는 최대 5개였다).
   특히 `048`은 **세 모델 모두에서 1개를 잃었다** — 모델과 무관한 잔여 항목이다(§5.2).
3. 따라서 **분할 변환(B)은 "압축을 고치기 위해서는" 더 이상 필요하지 않다.**
   팩트 전잔존이라는 더 높은 목표를 위해서만 재검토 대상이다. 진단의 권장안은 이 실측으로 격하된다.

### 권고 (코드 수정은 하지 않았다 — 제안만)

- **기본 모델을 `gpt-4o` → `gpt-4.1`로 바꾸는 것을 제안한다.** 무설정 드롭인이고(파라미터 변경 0),
  압축이 해소되며 팩트·숫자 잔존이 크게 오른다. 지연은 사실상 동일하다. 비용은 약 +25%(§6).
- **gpt-5.5는 품질 지표가 가장 좋지만 지금 채택하지 않기를 권한다.** provider 파라미터 2개 변경이
  필요하고(§2.2) 지연이 2.4배다. 스타일 위반 0건·숫자 잔존 82~100%는 매력적이므로, 지연 요구가
  느슨한 경로(배치·워커)에서 별도 판단할 후보로 남긴다.

## 2. 후보 선정 (LLM 호출 없는 조회 + 호환성 프로브 8회)

### 2.1 사용 가능 모델 조회

`/v1/models`를 직접 조회했다(키는 `.env`, 로그 미노출). 이 키가 접근 가능한 모델은 **124종**이고,
텍스트 재작성 후보군은 gpt-4 계열(`gpt-4o` 스냅샷 3종, `gpt-4.1`/mini/nano), gpt-5 계열
(`gpt-5`~`gpt-5.5`, `gpt-5.6-luna/sol/terra`, 각 chat-latest·pro·codex 변종), o 계열(`o1`/`o3`/`o4-mini`)이다.
Anthropic 키는 없으므로 OpenAI 계열만 실험 대상이다.

### 2.2 호환성 프로브 — gpt-5·o 계열은 현행 provider와 그대로 맞지 않는다

우리 `OpenAIProvider`는 **항상 `temperature=0.2`를 보낸다**. 이 값으로 최소 요청을 던져 갈랐다.

| 모델 | temperature=0.2 | 결과 |
| --- | :--: | --- |
| `gpt-4.1-2025-04-14` | **OK** | 무수정 드롭인 |
| `gpt-5.2-chat-latest` | 400 | `temperature does not support 0.2 ... Only the default (1)` |
| `gpt-5.5-2026-04-23` | 400 | 〃 |
| `gpt-5.6-luna` / `-sol` / `-terra` | 400 | 〃 |

**gpt-5 계열은 chat-latest 변종까지 전부 거부한다.** 즉 "무마찰 후보"는 gpt-4 계열뿐이다.

o3/o4-mini는 **프로브하지 않았다**(예산 절약). 같은 추론 계열이라 동일 제약이 예상되지만
이는 추정이며 실측이 아니다. 어차피 §2.3의 reasoning 토큰 문제가 더 크게 걸리는 계열이라
후보에서 제외했다.

이어서 temperature를 빼고 다시 던지자 `gpt-5.5`·`gpt-5.6-terra` 모두 정상 응답했다(reasoning 512토큰).
**temperature는 1줄로 우회 가능한 장벽**이므로, gpt-5 계열을 여기서 버리면 사용자의 질문
("최신 모델로 바꾸면 되는가")에 답할 수 없다고 판단해 **조건부 후보로 승격**했다.

### 2.3 두 번째 장벽 — reasoning 토큰이 출력 예산을 통째로 먹는다

temperature만 빼고 `gpt-5.5`로 4건을 돌리자 **4건 전부 실패**했다. 원인을 1회 호출로 확인했다.

| 조건 | finish_reason | reasoning 토큰 | 본문 길이 |
| --- | --- | ---: | ---: |
| `gpt-5.5`, 기본 effort, `max_completion_tokens=4096` | `length` | **4,096** | **0자** |
| `gpt-5.5`, `reasoning_effort="low"`, 동일 4096 | `stop` | 86 | 3,341자 |

reasoning 토큰은 `max_completion_tokens`에 **함께 계상된다**. 개조식 장문에서는 기본 effort가
`DEFAULT_MAX_TOKENS=4096`을 사고에만 다 써 버리고 본문을 한 글자도 내지 못한다.
이 경우 provider는 "빈 응답"으로 실패 처리하므로, **호출 비용은 다 치르고 결과는 0이다.**

> **채택 시 필요한 변경 2개**: ① `temperature` 미전송 ② `reasoning_effort="low"` 전달.
> `DEFAULT_MAX_TOKENS`는 4096 그대로 충분했다(최대 출력 3,027토큰).

### 2.4 최종 후보

| # | 모델 | 근거 | provider 변경 |
| --- | --- | --- | --- |

(가격·포지셔닝 미확인), 제약은 gpt-5.5와 동일하다. 확인 후 재실험 대상으로 남긴다.

## 3. 실험 설계

- **변환**: `ConversionService.convert()` 그대로. 마스킹 → 1차 변환 → `check_style` 위반 시 표적 보정 1회.
  즉 문서당 변환 호출은 1~2회이고, 이 계약도 바꾸지 않았다.
- **judge**: `judge_conversion()` + `gpt-4o-2024-08-06`, `temperature` 기본(0.2). 진단과 동일.
- **지표 정의** (진단과 같은 축, 재현 가능하도록 정의를 명시한다)
  - `압축비` = 출력 문자수 / 입력 문자수
  - `팩트 잔존` = `GoldenDocument.missing_facts()` (리포 공유 코드 — 모델 간 완전 동일 기준)
  - `스타일 위반` = `check_style()` 위반 건수 (리포 공유 코드, 보정 패스 **이후** 최종 결과 기준)
  - `숫자 잔존` = 원문의 고유 숫자 토큰(`\d[\d,]*`, 쉼표·선행 0 정규화) 중 결과에 남은 비율
  - `어절 잔존` = 원문의 각 줄(불릿 제거 후 8자 이상)에서 **가장 긴 어절**을 대표로 뽑아 결과에 남은 비율
  - 문서별 분모: 숫자 토큰 032/042/048/097 = 25/31/29/17, 대상 줄 = 92/94/105/50
- **비교 가능성**: 압축비·팩트·스타일·충실성은 리포 공유 코드와 동일 judge 모델로 계산되어 대조군과 **정확히 비교된다**.
  숫자·어절 잔존은 진단 스크립트가 리포에 남지 않아 **위 정의로 재구현**했다 — 대조군 열의 두 값은
  진단 보고서 기재값이며 구현 미세 차이가 있을 수 있다(추세 판단용으로만 읽을 것).
- **한계**: 조건당 **n=1**이다. 진단 §3.4가 지적한 judge 재현성 문제(6건 중 5건이 1~2점 이동)는 여기서도 유효하다.

## 5. 읽는 법

### 5.1 압축은 gpt-4o 고유 현상이었다

진단의 핵심 관찰 — "700자 이하는 1.13배로 늘고, 2,600자 이상은 0.56배로 준다. **두 무리는 겹치지 않는다**" —
는 모델을 바꾸자 무너졌다. 같은 2,600~3,500자 구간에서 gpt-4.1은 1.06~1.21배, gpt-5.5는 1.37~1.61배다.
**입력 길이가 아니라 모델 세대가 지배 변수였다.**

병행 리서치의 정리(자발적 요약 편향은 LLM 일반의 SFT 부작용이지만 gpt-4o가 특히 심한 축이고,
추론 계열은 length-following이 우수하다)와 방향이 일치한다. 실제로 압축비 회복 폭도
gpt-4o < gpt-4.1 < gpt-5.5(추론 계열) 순이다.

진단 §7이 남긴 숙제도 여기서 정리된다. `MAX_CONVERTIBLE_CHARS = 4_000`의 근거를 "충실성 유지"로
바꿔 적자는 제안은 **gpt-4o 전제에서만 옳다**. 후보 모델에서는 3,500자에서도 품질이 붕괴하지 않는다.

### 5.2 남은 팩트 유실은 모델 문제가 아닐 수 있다

`048`은 gpt-4o 1/4 → gpt-4.1 3/4 → gpt-5.5 3/4로, **세 모델 모두 1개를 놓쳤다.**
그런데 gpt-5.5의 048은 압축비 1.57·숫자 잔존 82.8%·스타일 위반 0이다. 정보를 버리는 정황이 없는데
팩트 판정만 실패한다.

표적 4건의 `required_facts` 20개는 **전부 `accept` 변형이 0개**이고 길이가 2~7자인 짧은 리터럴이다.
`RequiredFact.retained_in()`은 문자열 포함만 보므로, 쉬운 글 변환이 표기를 바꾸면
(예: 자릿수 표기·단위 표기 변경) **실제로는 남아 있어도 유실로 집계된다.**
`goldenset.py`의 docstring이 `accept`를 둔 이유가 정확히 이 상황이다.

→ **후속 과제**: 048(및 042)의 미달 팩트가 진짜 누락인지 표기 변형인지 사람이 1회 확인할 것.
표기 변형이면 골든셋의 `accept` 보강 문제이지 모델 문제가 아니다. (이번 실행은 어느 팩트가
빠졌는지 개별 기록하지 않았다 — 건수만 집계했다. 진단과 같은 취급이다.)

### 5.3 gpt-4.1의 약점은 스타일이다

gpt-4.1은 스타일 위반이 오히려 늘었다(대조군 합계 10 → 22). 출력이 2배로 길어진 탓만은 아니다.
1,000자당 위반 건수로 정규화해도 097은 2.0 → 4.3으로 나빠졌다.

| 문서 | gpt-4o (건/1k자) | gpt-4.1 | gpt-5.5 |
| --- | ---: | ---: | ---: |
| 032 | 3.21 | **0.54** | **0** |
| 042 | 0.00 | 1.65 | **0** |
| 048 | 0.00 | 0.26 | **0** |
| 097 | 2.01 | 4.33 | **0** |

**gpt-5.5는 4건 전부 위반 0건이다** — 보정 패스 이후 기준이며, 048은 1차 변환만으로 통과해
호출 1회로 끝났다. 규칙 게이트 관점에서는 gpt-5.5가 압도적이다.

### 5.4 judge는 여전히 흔들린다 — 기계 지표를 우선할 것

`042`/gpt-5.5는 **팩트 6/6·숫자 90.3%·스타일 0건·압축비 1.61**인데 충실성 **3점**을 받았다.
반대로 `032`/gpt-4o는 진단에서 **팩트 1/4·어절 41.1%인데 5점**이었다.
진단 §3.4의 결론(judge는 더 엄격한 게 아니라 **더 흔들린다**)이 다른 모델에서도 재현됐다.

**이번 판정에서 "충실성 ≥4"를 깬 유일한 셀이 바로 이 042/gpt-5.5(3점)다.**
기계 지표만 보면 042는 이번 실험 전체에서 가장 잘 보존된 축에 든다.
진단 §6-E(압축비를 게이트 보조 지표로)의 근거가 한 건 더 쌓였다.

## 6. 비용·지연

### 6.1 실측 토큰 (문서당, 변환 호출 합계 — judge 제외)

| 문서 | gpt-4o 출력*(진단) | gpt-4.1 입력/출력 | gpt-5.5 입력/출력 |
| --- | ---: | ---: | ---: |
| 032 | 2,178 | 9,893 / 4,393 | 9,867 / 5,955 |
| 042 | 1,966 | 9,764 / 4,331 | 9,490 / 5,929 |
| 048 | 1,691 | 9,513 / 4,316 | 5,941 / 2,905 |
| 097 | 2,645 | 9,045 / 3,723 | 8,733 / 4,825 |
| **평균** | **2,120** | 9,554 / **4,191** | 8,508 / **4,904** |

*진단은 입력 토큰을 기록하지 않았다. 1차 호출 입력은 프롬프트가 같고 토크나이저 계열도 같아
후보 모델 측정값(5,558~6,137)과 사실상 동일하다.

**압축을 고치면 출력 토큰이 약 2배가 된다**(2,120 → 4,191 / 4,904). 비용 증가의 주된 원인은
단가가 아니라 "제대로 다 써낸 결과물의 길이"다.

### 6.2 문서당 원가

| 모델 | $/1M 입력 | $/1M 출력 | 문서당 원가(4건 평균) |
| --- | ---: | ---: | ---: |
| gpt-4o-2024-08-06 | $2.50 | $10.00 | **약 $0.042** (추정 — 아래 근거) |
| gpt-4.1-2025-04-14 | $2.00 | $8.00 | **$0.053** (실측) |
| gpt-5.5-2026-04-23 | **확인 필요** | **확인 필요** | 토큰만 실측(위 표) — 단가 확인 후 산정 |

gpt-4o 추정 근거: 출력 토큰은 진단 실측값(문서당 1,691~2,645)을 쓰고, 입력 토큰은
`1차 호출 = 후보 모델 측정값(5,558~6,137)` + `보정 호출 ≈ 2,500`으로 잡았다.
보정 호출 입력은 시스템 프롬프트 + 변환문인데 gpt-4o의 변환문이 후보 모델의 절반 이하라
후보 측정값(3,487~3,908)에서 그만큼 낮춰 잡은 값이다. **±20% 오차를 가정해도 결론(아래)은 바뀌지 않는다.**

- **gpt-4.1은 단가가 gpt-4o보다 20% 싸지만 총 원가는 약 +25%다.** 출력이 2배로 늘기 때문이다.
- 크레딧 환산(1,000자 = 1크레딧, master-plan 5장): 표적 4건 평균 3,100자 ≈ 3.1크레딧이므로
  gpt-4.1 기준 **크레딧당 약 $0.017**이다. 5장 원가 가정을 이 값으로 재확인할 것.
- **분할 변환(B)을 채택했을 때보다는 훨씬 싸다.** B는 3,300자 문서에서 호출을 최대 10회로 늘리는데,
  모델 교체는 호출 수 계약(문서당 최대 2회)을 그대로 둔다. gpt-5.5는 오히려 평균 1.75회로 줄었다.
- gpt-5.5 단가는 공개 근거를 확인하지 못했다. **채택 검토 시 반드시 먼저 확인할 것.**

### 6.3 지연

gpt-4.1 21~28초(평균 24.4초), gpt-5.5 43~70초(평균 58.1초)로 **2.4배** 차이다.
진단은 대조군 지연을 기록하지 않았으나, gpt-4.1은 호출당 10~15초로 gpt-4o와 같은 급이다.
비동기 워커(arq) 처리라 사용자 대기에 직접 노출되지는 않지만, 58초는 워커 점유·타임아웃
(`DEFAULT_TIMEOUT_SECONDS = 60.0`)과 **정면으로 부딪힌다** — gpt-5.5 채택 시 타임아웃 상향이 추가로 필요하다.

## 8. 후속 과제

1. **미달 팩트의 성격 확인**(§5.2) — 048·042의 놓친 팩트가 진짜 누락인지 표기 변형인지 사람이 1회 판정.
   표기 변형이면 `required_facts`의 `accept` 보강 문제다. 이 답에 따라 판정이 **부분 → 해결**로 바뀔 수 있다.
2. **골든셋 45건 전체 재평가** — 이번은 최악 4건만 봤다. 기본 모델을 바꾸기 전에 전체 통과율과
   진단 §6-D의 길이 구간별 집계(≤1,000 / 1,000~2,000 / 2,000자 초과)를 함께 낸다.
   합성 20건이 회귀하지 않는지 확인이 필요하다(합성은 gpt-4o에서 이미 정상이었다).
3. **`DEFAULT_MAX_TOKENS` 재검토** — 진단 §7의 예고대로 압축이 풀리자 출력이 늘었다.
   gpt-5.5 048이 2,905토큰(상한의 71%)까지 갔다. 4,000자 입력·팽창 1.6배면 상한에 닿는다.
   **모델 교체 시 옵션 A(4,096 → 8,192)를 다시 볼 것.** 진단 시점의 "기각"은 gpt-4o 전제였다.
4. **gpt-5.6 계열 재실험** — luna/sol/terra의 티어·단가 확인 후. 제약은 gpt-5.5와 동일하다.
5. **judge 재현성 정량화** — 진단 §8-3과 동일하게 미해결이다. 042/gpt-5.5 같은 사례가
   기준 판정을 좌우하므로 우선순위가 올라갔다.
6. **분할 변환(B) 재평가** — 압축 해소 목적의 근거는 사라졌다. master-plan 3.3의 분할 변환 항목과
   진단 권장안을 이 실측에 맞춰 갱신할 것을 제안한다.

## 부록 — 재현 방법

실험 스크립트는 임시 작업본이라 리포에 남기지 않았다(진단과 동일 방침). 조건만 적는다.

- 변환은 `ConversionService.convert()`를 그대로 쓴다(수리 패스 포함). 모델만 교체한다.
- judge는 `judge_conversion()` + `gpt-4o-2024-08-06` 고정.
- gpt-5 계열은 `app` 코드를 고치지 않고, `LLMProvider`를 구현한 스크래치패드 래퍼로
  `temperature`를 보내지 않고 `reasoning_effort="low"`를 전달한다. `max_completion_tokens`는 4096 유지.
- 토큰·절단·지연은 `LLMProvider`를 감싼 기록용 래퍼에서 `LLMResponse`를 통해 얻는다.
- 누락 휴리스틱 정의는 §3에 명시했다.
- 로그에는 문서 ID·수치·사유 코드만 남긴다. 본문·변환 결과·judge comment는 출력하지 않는다.
