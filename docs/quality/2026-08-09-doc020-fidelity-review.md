# 골든 문서 020 충실성 사람 대조 자료 (2026-08-09)

## 1. 배경 — 왜 사람이 봐야 하나

`docs/benchmarks/2026-08-08-2136-llm-benchmark.md`(Anthropic 재벤치마크)에서 문서 020이
**judge 충실성 2점**을 받았다. 같은 문서의 1차 벤치마크 점수는 anthropic 5·openai 5였다.

이 문서만 놓고 보면 자동 검사는 전부 깨끗하다.

| 지표 | 재벤치마크 값 |
| --- | --- |
| 규칙 위반(`check_style`) | 0 |
| 필수 팩트 잔존 | 4/4 |
| 자리표시자 유실 | 0 |
| 출력 문자 | 745자 (1차 openai 811자) |
| judge 충실성 | **2** (이해 용이성 4) |

즉 **judge만 떨어졌다**. 두 가지 중 하나다.

1. `effort=low`가 규칙·팩트 검사로는 잡히지 않는 종류의 내용 손실(날조·의미 왜곡·
   중요 정보 누락)을 만들었다 → effort 설정을 되돌릴 근거가 된다.
2. judge 단일 실행의 잡음이다 → 그대로 두어도 된다.

기계 검사로는 이 둘을 가를 수 없어 **사람이 원문과 대조해 판정한다.** 그 대조에 필요한
원문·변환본을 이 문서에 싣는다.

재벤치마크 하네스는 변환 산출물을 저장하지 않으므로(보안 규칙상 리포트에 본문 미기록)
**당시 결과물은 남아 있지 않다. 아래 변환본은 오늘 다시 만든 것이다.** 모델 출력은
비결정적이라 1건만 보면 그 1건이 이상치인지 알 수 없어 **3회 독립 변환**했다.

### 재생성 조건이 벤치마크 당시와 다른 점 (읽기 전 반드시 확인)

- **프롬프트가 다르다.** 커밋 `85ca2f5`(미션 EE, "시스템 프롬프트 어려운 단어 목록 동적
  필터링")가 재벤치마크 이후에 들어갔다. 지금 시스템 프롬프트는 치환 목록 전량이 아니라
  **입력에 실제 등장하는 어려운 낱말만** 싣는다. 아래 샘플의 입력 토큰이 약 6.1k로,
  재벤치마크 당시 020의 9,067보다 작은 것이 그 차이다.
  → 아래 변환본은 **재벤치마크 당시 산출물의 복제가 아니라 현행 프롬프트의 재현**이다.
    "당시 그 출력이 나빴는가"가 아니라 "이 문서·이 설정에서 충실성 문제가 재현되는가"를
    보는 자료로 읽어야 한다.
- 그 밖의 조건은 벤치마크와 동일하게 맞췄다.

| 항목 | 값 |
| --- | --- |
| provider / 모델 | anthropic / `claude-sonnet-5` (리포 기본값) |
| `output_config.effort` | `low` (재벤치마크와 동일) |
| `max_tokens` | 16,000 (리포 기본값) |
| 변환 경로 | `ConversionService.convert()` — 마스킹 선행 → 변환 → 조건부 보정 1회 |
| judge | **호출하지 않음** (사람 판정이 목적) |
| 실행 시점 리포 상태 | `e096760` (코드 변경은 `85ca2f5`가 마지막) |
| 실제 API 호출 | 6회 (샘플 3건 × (변환 1 + 보정 1)) |

원문의 이메일 주소는 마스킹 파이프라인이 먼저 처리하므로 변환본에는 `[[이메일1]]`
자리표시자로 남는다. 이는 정보 누락이 아니라 설계된 동작이다.

비결정성의 폭이다.

## 5. 사람 확인 가이드

샘플 A/B/C를 각각 원문과 나란히 놓고 아래 세 축으로 본다. **하나라도 걸리면 judge 2점은
잡음이 아니라 실제 품질 문제**이며, `effort=low` 되돌리기(또는 `medium` 재측정)의 근거가
된다. 셋 다 깨끗하면 judge 단일 실행 잡음으로 보고 설정을 유지한다.

### ① 원문에 없는 내용 날조

변환본에만 있고 원문에는 없는 사실(금액·날짜·기관·조건·절차)이 새로 생겼는가?

- [ ] 샘플 A — 날조 없음
- [ ] 샘플 B — 날조 없음
- [ ] 샘플 C — 날조 없음

특히 볼 자리: 원문에 없는 연도·시각을 모델이 보충한 곳(예: 샘플 A의 "2026년 3월 6일" —
원문은 "3월 6일"), 원문에 없는 신청 채널·문의 수단이 추가된 곳.

### ② 의미 왜곡 (조건·금액·기한·대상의 변형)

숫자는 남아 있는데 그 숫자가 걸리는 **대상·범위·조건**이 바뀌지 않았는가?

- [ ] 샘플 A — 왜곡 없음
- [ ] 샘플 B — 왜곡 없음
- [ ] 샘플 C — 왜곡 없음

특히 볼 자리:

- **200자 제한이 무엇에 걸리는가.** 원문은 "분야와 이유를 200자 이내로"다 — 분야+이유
  **전체**에 걸린다. 변환본이 이 제한을 '이유'에만 건 것처럼 읽히면 조건 변형이다.
- **자격 조건의 연결 관계.** 원문은 "만 19세 이상 성인 **중**" 세 부류다(AND). 변환본이
  나이와 소득 조건을 별개(OR)로 읽히게 바꾸지 않았는가.
- **35만 원의 단위.** "1인당 연간"이 "한 사람에게 한 해 동안" 등으로 바뀌어도 뜻이
  같은가, 아니면 1인당/연간 중 하나가 빠졌는가.
- **70만 원의 조건.** "우수 이용자로 선정되면 **다음 해에** 최대 70만 원"이라는 조건과
  시점이 유지되는가(올해 총액으로 읽히면 왜곡).
- **신청 기간의 시작/끝 방향.** 2월 10일 오전 9시=시작, 3월 6일 오후 6시=마감.
- **"모두 선정되지는 않는다"**는 유보 조건이 살아 있는가.
- **잔여 금액 소멸·현금 수령 불가**, **교재비는 수강료와 함께 결제할 때만**이라는
  제한이 그대로인가(제한이 완화되어 읽히면 실제 민원이 되는 자리다).
- **어려운 낱말 치환이 뜻을 망친 자리.** 사전 치환("선정"→"뽑음", "발급"→"내어 줌",
  "기한"→"정해진 날짜")이 기계적으로 들어가 비문이 된 곳이 있다(예: 샘플 C의 "바우처
  카드를 내어 줌 받아"). 이것이 **이해 용이성 문제인지, 뜻이 실제로 바뀐 충실성
  문제인지**를 구분해 판정할 것.

### ③ 중요한 정보 누락

위 2절 "원문이 담고 있는 정보" 19항목을 하나씩 대조한다. 특히 `required_facts` 4개
**바깥**의 15개가 기계 검사 사각지대다.

- [ ] 샘플 A — 누락 없음
- [ ] 샘플 B — 누락 없음
- [ ] 샘플 C — 누락 없음

특히 볼 자리: 70만 원(#4), 65퍼센트(#6), 지난해 수혜자 재신청 가능(#7), 3월 6일 마감(#9),
전원 선정 아님(#10), 200자 이내(#12), 평생학습관 도움(#13), 문자 안내(#14), 본인 확인
절차(#16), 현금 수령 불가(#17), 교재비 조건(#18).

### 판정 기준

- ①~③ 중 **한 샘플이라도** 실질적 날조·왜곡·누락이 확인되면 → 실제 품질 문제.
  `effort=medium` 재측정(재벤치마크 문서 "후속 확인" 3번)을 진행한다.
- 3건 모두 깨끗하고 문제가 문장의 어색함(이해 용이성)에 한정되면 → judge 충실성 2점은
  단일 실행 잡음으로 본다. 다만 사전 치환이 만드는 비문은 **별도 과제**로 남긴다
  (충실성이 아니라 이해 용이성 축).

## 부록 — 재현 방법

이 문서의 변환본은 스크래치 스크립트로 만들었고 리포에 커밋하지 않았다. 같은 결과를
다시 만들려면 `scripts/benchmark.py`의 단일 문서 경로를 따라 아래를 재현하면 된다.

1. `Settings()`로 `.env`의 `ANTHROPIC_API_KEY` 로드.
2. `AnthropicProvider(api_key=..., effort="low")` — 모델·`max_tokens`는 기본값.
3. `ConversionService(provider=...).convert(document.source_text)`를 3회 호출.
   (마스킹 선행 불변식 때문에 `LLMProvider`를 직접 부르지 않는다.)
4. 각 결과에 `check_style()`과 `GoldenDocument.missing_facts()`를 적용.

judge는 부르지 않았다. 총 API 호출 6회(변환 3 + 보정 3), 워밍업 호출 없음.
