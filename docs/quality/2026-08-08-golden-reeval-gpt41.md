# 골든셋 45건 재평가 — 기본 모델 gpt-4.1 (2026-08-08)

모델 비교 실험(`2026-08-07-model-comparison.md`)의 권고대로 기본 모델을 `gpt-4o` → `gpt-4.1`로
바꾸고, 표적 4건의 `required_facts`에 허용 변형(`accept`)을 보강한 뒤 골든셋 45건 전체를 재평가한 기록이다.
모델 비교는 최악 4건만 봤으므로, 여기서 처음으로 **합성 20건이 회귀하지 않았는지**를 함께 본다
(모델 비교 §8-2가 남긴 숙제).

- 대상: 골든셋 45건 (합성 20 + 실수집 25)
- provider: openai **`gpt-4.1-2025-04-14`** (응답 `model` 필드 실측), temperature 0.2, `max_completion_tokens` 4,096
- judge: **같은 provider 기본값이라 judge도 `gpt-4.1`이다.** 이전 측정은 judge가 `gpt-4o`였다 —
  채점자가 바뀌었으므로 **judge 점수의 이전 대비 절대 비교는 성립하지 않는다**(§6-2)
- 실행: `GOLDEN_PROVIDER=openai GOLDEN_JUDGE_PROVIDER=openai uv run pytest tests/golden -m llm -v`
  — **1회 실행**, 529초(8분 49초)
- 사용한 LLM 호출: **90~135회** (변환 45~90 + judge 45). 하네스가 호출 수를 기록하지 않아 범위로만 적는다(§6-3)
- 이 문서에는 문서 본문·변환 결과·judge 코멘트를 싣지 않는다 (ID·수치·사유 코드만)

## 5. 읽는 법

### 5.1 모델 교체가 고친 것은 "파국"이고, 남은 것은 "정밀도"다

gpt-4o의 실패는 문서를 절반으로 요약해 팩트를 무더기로 잃는 형태였다(진단 §3, 042는 6개 중 5개 유실).
gpt-4.1에서는 그 형태가 사라졌다. 45건 전체에서 유실 팩트가 17개뿐이고, 유실 문서 16건 중 15건이 1개씩이다.
충실성 바닥 게이트가 0건인 것도 같은 이야기다.

대신 **문장 길이 초과**가 실패의 새 주축이 됐다(스타일 위반 37건 중 26건). 모델 비교 §5.3이
1,000자당 위반 건수로 이미 관찰한 방향이며, 45건에서도 재현됐다. 출력을 제대로 다 써낼수록
긴 문장이 늘어난다.

### 5.2 규칙 게이트 통과율 0.51은 "모델 실패율"이 아니다

통과 조건이 세 개의 AND(스타일 0건 · 팩트 전잔존 · 플레이스홀더 전보존)이므로,
문서 하나에 위반이 1건만 있어도 실패로 집계된다. 실제로 실패 22건 중 **12건은 위반이 정확히 1개**다
(팩트 1개가 10건, 문장 1개가 2건). 팩트 잔존율 91.5%·스타일 위반 37건이라는 원자료를 함께 보아야 한다.

이 성질 때문에 통과율은 코퍼스 구성(문서 길이 분포)에 민감하다. §3.4의 길이 구간별 집계를
함께 보고해야 하는 이유다.

### 5.3 합성 20건의 팩트 유실 — 회귀인지 아직 단정할 수 없다

2026-08-06 벤치마크(gpt-4o, 합성 20건)에서 팩트를 놓친 문서는 **007·016 두 건**이었다(팩트 잔존율 98%).
이번에는 **001·006·007·008·012·016·018 일곱 건**(잔존율 91.4%)이다. 007·016은 그때도 놓쳤던 문서다.

다만 그 벤치마크 이후 파이프라인이 크게 바뀌었다 — 프롬프트 튜닝 2회, 쉬운 말 사전 25→246,
수리 패스 도입, 어려운 표현 채점 방식 변경, 골든셋 보정 3회. **모델만 다른 비교가 아니다.**

→ **분리 방법**: 지금 파이프라인 그대로 `LLM_MODEL=gpt-4o`로 **합성 20건만** 재측정하면
(호출 20~40 + judge 생략 시 0회) 모델 몫과 파이프라인 몫이 갈린다. 이번 커밋에서 추가한
`LLM_MODEL` 환경변수가 정확히 이 용도다.

### 5.4 어려운 표현 잔존 3건은 사전 쪽을 볼 신호일 수 있다

099가 `근로`를 2건, 042가 `명의`를 1건 남겼다. 두 낱말 모두 복합어·고유명사 안에서 나타나면
바꿀 수 없는 자리일 수 있다(사전 큐레이션 규칙 1이 이미 같은 이유로 `이행`·`검진` 등을 제외했다).
**문서 쪽이 아니라 사전 쪽을 확인할 후보**다 — 이번 미션에서는 손대지 않았다.

## 6. 한계

1. **모델과 골든셋을 동시에 바꿨다.** 표적 4건의 팩트 개선분을 모델 몫과 `accept` 표기 몫으로
   분리할 수 없다. 분리하려면 `accept` 보정 전 커밋에서 같은 4건을 다시 돌려야 한다(호출 8회).
2. **judge 모델이 바뀌었다.** provider 기본값을 공유하므로 judge도 gpt-4.1이다. 채점자를 고정해야
   비교축이 유지되는데(모델 비교 §3), 이번에는 예산 안에서 45건 전체를 한 번 돌리는 것을 우선해
   이를 수용했다. **judge 게이트가 PASS로 뒤집힌 것을 "품질이 좋아졌다"의 단독 근거로 쓸 수 없다.**
   judge 모델을 고정하려면 `GOLDEN_JUDGE_PROVIDER`가 모델까지 지정할 수 있어야 한다(§7-3).
3. **통과 시에는 집계가 출력되지 않는다.** `format_report`·`format_judge_report`는 assert 메시지라
   게이트가 통과하면 아무 수치도 남지 않는다. 그래서 이번에 judge 충실성·이해 용이성 **평균의
   정확값을 기록하지 못했다**(기준 4.0 이상이라는 사실만 안다). 호출 수도 하네스가 세지 않는다.
4. **n=1**이다. 진단 §3.4가 정량화한 judge 재현성 문제(6건 중 5건이 1~2점 이동)는 그대로 유효하다.

## 7. 후속 과제

1. **문장 길이 초과 대책** — 이제 규칙 게이트 실패의 최대 사유(26/37)다. 수리 패스가 이미
   문장 길이를 지적해 1회 보정하는데도 남는다. 프롬프트 쪽인지 보정 수용 조건(`_accepts_repair`)
   쪽인지 확인이 필요하다.
2. **합성 회귀 분리 측정**(§5.3) — `LLM_MODEL=gpt-4o`로 합성 20건 재측정.
3. **judge 모델 고정 수단** — 지금은 judge가 변환 provider의 기본 모델을 그대로 따라간다.
   평가 하네스가 judge 모델을 따로 지정할 수 있어야 측정 간 비교축이 유지된다.
4. **평가 리포트를 통과 시에도 남길 것**(§6-3) — 집계(통과율·팩트 잔존율·judge 평균·바닥 건수·호출 수)를
   assert 메시지가 아닌 별도 출력 경로로 내보내면, 이번처럼 "통과했는데 수치가 없다"가 생기지 않는다.
5. **절단과 API 오류의 사유 코드 분리** — 지금은 둘 다 `변환실패(LLMProviderError)`로만 남는다.
   `DEFAULT_MAX_TOKENS` 재검토(모델 비교 §8-3)를 하려면 절단이 따로 보여야 한다.
6. **048의 잔여 1건 확인** — 세 모델 공통이고 `accept` 대상도 아니다. 사람이 1회 판정할 것.

## 8. master-plan 갱신 제안 (이 미션에서는 수정하지 않았다)

1. **3.3 변환 호출 계약 문단** — "알려진 품질 한계(2026-08-07 진단): 입력 약 2,600자 이상에서
   모델이 내용을 자체 요약해 충실성이 떨어진다"는 **gpt-4o 전제였다**. 이번 45건에서 2,000자 초과
   9건의 팩트 잔존이 85.1%이고 충실성 바닥 0건이다. 문구를 "장문에서는 스타일 규칙(문장 길이)
   준수율이 떨어진다"로 갱신할 것을 제안한다.
2. **같은 문단의 "파일럿 안내는 2,000자 내외 문서를 권장"** — 근거였던 압축 현상이 해소됐다.
   다만 2,000자 초과 통과율이 0.11이므로 **권장 자체는 유지하되 사유를 바꿔 적는 것**이 정확하다.
3. **3.3 / 95행 `MAX_CONVERTIBLE_CHARS = 4,000`** — 진단 §7이 "근거를 충실성 유지로 바꿔 적자"고
   제안했으나, 모델 비교 §5.1대로 그것도 gpt-4o 전제다. 현재 근거는 "절단 방지"도 "충실성"도 아닌
   **스타일 준수율 하락**에 가깝다.
4. **3.1 벤더 확정 기록 표** — 기본 모델이 `gpt-4.1`로 갱신됐지만 Anthropic 키 미확보로
   **벤더 확정은 여전히 불가**하다. 표에 "현재 기본 모델 / 근거 리포트" 행을 추가해 미확정과
   기본값을 구분해 적을 것을 제안한다. no-training 약관 확인일도 여전히 미확인이다.
5. **7장 KPI** — 통과율 90% 목표 대비 현재 0.51임을 로드맵 진행 상황에 반영할 것.
   합성 20건만 보면 0.65, 실수집 25건은 0.40이다.
6. **3.3 분할 변환** — 압축 해소 목적의 근거는 모델 비교로 이미 소멸했고, 이번 45건도 이를 뒤집지 않는다.
   분할 변환 항목의 사유를 "충실성 회복"에서 "장문 스타일 준수" 또는 보류로 정리할 것을 제안한다.
