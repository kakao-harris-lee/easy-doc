# 실제 복지 안내문 수집 방안 (골든셋 ①-b)

> master-plan 7장 검증 절차 ①-b: 합성 골든셋 20건을 실제 수집본으로 교체·보강해야 벤더 확정 근거가 완성된다.
> 목표: **25건** (기존 합성 20건 주제와 겹치게 수집해 교체, 5건은 신규 주제).
> 갱신 2026-08-12: 마스킹 범주 5종 → 2종 축소(master-plan 3.2)를 반영했다. **자동 마스킹이 걷어 내는 것은 주민등록번호·카드번호뿐이다** — 전화번호·이메일·계좌번호는 수집 담당자가 직접 확인·제거한다(1장 원칙 2, 3장 3단계, 4.3, 6장).

## 1. 수집 원칙

1. **저작권**: 공공저작물 자유이용(저작권법 제24조의2) 대상 또는 **공공누리 제1유형**(출처 표시) 자료만 수집한다. 문서마다 출처 URL·기관명·공공누리 유형을 기록한다. 유형 표시가 없는 자료는 담당 기관에 이용 문의 후 편입한다.
2. **개인정보**: 처음부터 개인정보가 없는 **공개 배포용 안내문**을 우선한다. `mask_text` 파이프라인은 편입 전에 반드시 통과시키되, **이 파이프라인이 처리하는 범주는 주민등록번호·카드번호 2종뿐이다**(master-plan 3.2, 2026-08-12 결정). 담당자 연락처(기관 대표번호·부서 메일)와 계좌번호는 마스킹을 통과해도 **평문 그대로 남는다** — 이 3종은 수집 담당자가 초안에서 직접 찾아 지우거나 합성값으로 바꾼 뒤에만 편입한다(3장 3단계, 검출 명령은 4.3). 골든셋 JSON은 `tests/golden/documents/`에 커밋되므로 **걸러 내지 못한 연락처는 저장소를 통해 그대로 배포된다.** 파일럿 기관이 제공하는 내부 문서는 **기관 측이 개인정보 제거를 확인**했다는 서면(메일) 기록을 남긴다 — 다만 그 확인이 우리 쪽 육안 검수를 대신하지는 않는다.
3. **다양성**: 기관 유형(중앙부처/지자체/공단), 분야(현금성 급여/의료/주거/에너지/교육), 길이(500~4,000자), 문체(고시·공고체/안내문체/개조식)를 분산시킨다. 4,000자 초과 문서도 2~3건 수집해 두되(분할 변환 테스트용) 골든셋 편입은 보류한다.

## 3. 편입 절차 (문서당)

1. 원문 확보(웹 텍스트 복사 또는 hwpx/pdf 다운로드 → `extract_text`)
2. 출처 메타 기록: URL, 기관, 수집일, 공공누리 유형 → JSON `source` 필드(`GoldenSource`). `synthetic: false` 문서는 `source`가 없으면 스키마 검증에서 거부된다
3. **개인정보 제거 — 두 갈래로 나뉜다. 자동 단계만 밟고 넘어가면 연락처가 그대로 커밋된다**
   - **3-a. 자동(2종)**: `mask_text` 통과 → 플레이스홀더로 바뀐 주민등록번호·카드번호 항목을 사람이 확인. 스크립트가 대신하는 부분은 여기까지다
   - **3-b. 수동(3종) — 수집 담당자 전담**: 초안 `source_text`에서 **전화번호·이메일·계좌번호**를 직접 찾아 지우거나 합성값으로 바꾼다. `--title`을 주지 않아 본문 첫 줄에서 자동 생성된 `title`도 같이 본다. 4.3의 검출 명령으로 후보를 뽑되, 정규식이 못 잡는 표기(띄어쓴 번호, 괄호 국번, `내선 1234`, PDF 공백 소실로 붙어 버린 숫자열)가 있으므로 **본문을 눈으로 한 번 훑는 것까지가 이 단계다.** 번호를 남겨야 문서 뜻이 통하면 `044-000-0000`·`example@example.go.kr` 같은 **누가 봐도 합성인 값**으로 바꾼다 — "이미 공개된 대표번호니 괜찮다"고 두지 않는다(공개 여부와 저장소 재배포는 별개다). 골든셋 스키마는 `extra="forbid"`라 검수 표시용 필드를 늘릴 수 없으므로, **편입 커밋 메시지에 `연락처 검수: N건 확인 / M건 치환`을 남기는 것으로 기록을 대신한다** — 이 줄이 없는 편입 커밋은 3-b를 건너뛴 것으로 본다
4. `required_facts` 큐레이션 3~6개 (**연락처**·마스킹 대상 패턴 금지, 재작성 취약 표기는 accept 변형 부여)
5. `synthetic: false`로 `tests/golden/documents/`에 편입 → `uv run pytest tests/golden` 스키마 테스트 통과 확인
6. 교체된 합성 문서는 삭제하지 않고 `tests/golden/synthetic-archive/`로 이동(회귀 비교용)

## 4. 역할 분담

- **사람(운영자)**: 소스 접근·다운로드, 공공누리 유형 판단, 마스킹 결과 확인(2종), **전화번호·이메일·계좌번호 검출·제거(3-b)**, `required_facts` 큐레이션, 파일럿 기관 협의 — 법적 판단과 의미 판단이 필요한 단계는 자동화하지 않는다. 3-b는 판단이 필요해서가 아니라 **자동화가 아예 없어서** 사람 몫이다. 범주가 5종이던 때는 이 일을 파이프라인이 했으므로, 예전 절차를 기억하고 3-a까지만 밟으면 그대로 유출된다.
- **자동화**: `scripts/collect_golden.py` — URL/파일 입력 → 텍스트 추출 → 마스킹(2종) → 골든셋 JSON 초안 생성. 위 3장 절차의 1·2단계와 **3-a까지만** 대신한다. **3-b(연락처 제거)를 대신하는 자동화는 없다.** 4단계(`required_facts`)와 카테고리는 규칙 기반 **후보**까지만 채운다 — 무엇이 반드시 남아야 할 정보인지, 분류가 맞는지는 사람이 확정한다. 스크립트는 LLM을 호출하지 않는 오프라인 도구다.

### 4.1 `scripts/collect_golden.py` 사용법

```bash
# 웹 페이지에서 (html 본문 추출)
uv run python scripts/collect_golden.py "https://example.go.kr/board/view.do?id=1" \
    --org "보건복지부" --license "공공누리 제1유형"

# 내려받은 파일에서 (docx·pdf·hwpx·txt)
uv run python scripts/collect_golden.py ./기초연금안내.hwpx \
    --org "○○구청" --license "공공누리 제1유형" \
    --title "기초연금 신청 안내" --category "복지 안내문"

# 저장하지 않고 글자 수·마스킹 건수만 확인
uv run python scripts/collect_golden.py ./안내문.pdf --org "○○시" --license "공공누리 제1유형" --dry-run
```

| 옵션 | 설명 |
|---|---|
| `--org` (필수) | 발행 기관명 → `source.organization`. `--preview`일 때만 생략 가능 |
| `--license` (필수) | 이용 조건 → `source.license` (예: `"공공누리 제1유형"`, `"파일럿 기관 제공"`). `--preview`일 때만 생략 가능 |
| `--title` | 문서 제목. 생략하면 마스킹 후 본문 첫 줄 |
| `--category` | 주제 분류. **명시하면 자동 분류보다 우선한다.** 생략하면 규칙 기반 자동 분류, 그것도 실패하면 `미분류(사람 확인)` — 통제 어휘 밖이라 고치지 않으면 스키마 테스트가 막는다 |
| `--output` | 초안 저장 디렉터리 (기본 `docs/golden-drafts/`) |
| `--preview` | 저장하지 않고 **구조 통계만** 출력 (PDF는 쪽별, hwpx는 구역별 글자 수 + 2종 마스킹된 첫 줄). 어느 범위를 뽑을지 고르는 도구 |
| `--pages A-B` | **PDF 전용.** 그 쪽 범위만 추출 (1부터, 양끝 포함. `--pages 5`는 한 장). 다른 형식에 쓰면 한 줄 오류 |
| `--slice START:END` | **모든 형식.** 추출한 본문에서 글자 범위만 잘라낸다 (`0:1500`, `1500:`). 음수·역전 범위는 거부 |
| `--dry-run` | 파일을 쓰지 않고 통계만 출력 |

동작:

- URL이면 httpx로 받아 온다(타임아웃 30초, 리다이렉트 허용, User-Agent 명시). **요청 헤더 값은 ASCII만 쓴다** — 한글이 섞이면 요청이 나가기도 전에 `UnicodeEncodeError`로 죽는다. `text/html`은 표준 라이브러리 파서로 본문만 걷고(script·style·nav·header·footer·head 제외, 블록 요소 단위 개행), pdf/docx/hwpx 첨부는 `app/ingest/extractors.py`의 `extract_text`로 넘긴다. URL에 확장자가 없으면 Content-Type으로 형식을 가른다.
- **네이버 블로그 어댑터**: `blog.naver.com/<blogId>/<logNo>`는 본문이 iframe(PostView) 안에 있어 그대로 받으면 외피 HTML만 남는다. 받아 오기 전에 `PostView.naver?blogId=…&logNo=…`로 주소를 바꾼다(패턴이 맞지 않으면 원 주소 그대로). 공공기관이 블로그로 안내문을 배포하는 현실 대응이며, `source.url`에는 사람이 준 원 주소를 남긴다.
- 본문은 **반드시 `mask_text`를 통과한 뒤** 초안에 담긴다. 다만 `mask_text`가 걷어 내는 범주는 **주민등록번호·카드번호 2종뿐이므로**(master-plan 3.2), `source_text`는 "2종이 마스킹된 텍스트"이지 개인정보가 없는 텍스트가 아니다. **전화번호·이메일·계좌번호는 초안에 평문으로 들어온다** — 3장 3-b에서 사람이 걷어내야 한다.
- **category 자동 분류**(규칙 기반, LLM 호출 없음): 마스킹된 본문에서 카테고리별 키워드를 세어 서로 다른 키워드가 가장 많이 걸린 통제 어휘를 고른다. 동점이거나 하나도 안 걸리면 고르지 않고 `미분류(사람 확인)`로 남긴다. 결과는 표준출력에 `자동 분류: X (규칙 기반 추정 — 사람 확인 필요)`로 표시된다 — **맞는지 확인하는 것은 사람 몫이다.**
- **`required_facts` 후보 자동 제안**: 날짜·금액·기한·대상(만 N세)·기관명을 정규식으로 뽑아 최대 6개까지 초안에 채운다(갈래를 돌아가며 담아 한쪽으로 쏠리지 않게 한다). 마스킹 대상 패턴·마스킹 플레이스홀더·쉬운 말 치환 대상 낱말은 후보에서 뺀다. 후보가 없으면 예전처럼 빈 배열이다. **정확성·중요도 판단은 사람 몫이므로 반드시 검증·수정한다.**
  - **범주 축소의 부작용**: 후보 제외 필터는 `mask_text(후보).items`가 비었는지로 판정한다. 범주가 2종이 된 뒤로는 **전화번호·이메일·계좌번호가 이 필터에 걸리지 않아** `required_facts` 후보로 올라올 수 있다. 같은 이유로 `tests/golden/test_schema.py`의 `test_required_facts에_마스킹_대상_패턴이_없다`와 `test_실수집_문서는_마스킹_결과가_0건이다`도 이 3종을 더는 잡지 못한다 — **연락처가 섞였는지는 테스트가 아니라 3-b의 사람 검수만이 판정한다.**
- `id`는 `tests/golden/documents/`와 초안 디렉터리를 통틀어 최대 번호 + 1로 자동 채번한다.
- 초안은 `docs/golden-drafts/NNN-슬러그.json`에 쓴다. **`tests/golden/documents/`에 직접 넣지 않는다** — 사람 검토를 거치지 않은 문서가 평가셋에 섞이면 통과율이 사람 손을 타지 않은 채로 움직인다.
- 표준출력에는 저장 경로·글자 수·마스킹 건수·자동 분류·후보 개수·다음 단계만 나온다. 문서 본문과 마스킹 원문은 출력하지 않는다(CLAUDE.md 보안·데이터 규칙). 미리보기의 첫 줄도 **마스킹을 통과한 뒤** 40자까지만 보여 준다 — 단 그 마스킹도 2종뿐이라 **첫 줄에 기관 대표번호나 부서 메일이 그대로 찍힐 수 있다.** 이 출력을 이슈·채팅·로그에 그대로 붙여 넣지 않는다.

#### 대형 자료(책자·사업안내) 발췌 워크플로

수백 쪽짜리 사업안내 책자는 통째로는 골든셋 문서가 될 수 없다(실수집 문서 본문 500~4,000자 기준. 4,000자는 변환 상한 `MAX_CONVERTIBLE_CHARS`와 같은 값이라 넘기면 평가에서 하드 실패한다). `--preview`로 구조를 파악하고 안내문 단위로 발췌한다.

```bash
# 1) 구조 파악 — 쪽별 글자 수와 (2종만 마스킹된) 첫 줄이 나온다. 출처 메타는 아직 필요 없다
uv run python scripts/collect_golden.py ./2026년_장애인복지시설_사업안내.pdf --preview
#   미리보기: 페이지 671개 | 합계 474,486자
#     페이지   11 |   1,189자 | 누적     6,089자 | Ⅰ. 2026년 주요 변경 사항
#     페이지   12 |     952자 | 누적     7,041자 | 2026년 장애인복지시설 사업안내

# 2) 안내문 단위로 발췌 — 쪽 범위로 자르고, 길면 글자 범위로 한 번 더 줄인다
uv run python scripts/collect_golden.py ./2026년_장애인복지시설_사업안내.pdf \
    --pages 11-12 --slice 0:1500 \
    --org "보건복지부" --license "공공누리 제1유형"

# 3) 초안을 열어 연락처 제거(3-b)·자동 분류·팩트 후보를 사람이 확정한 뒤 tests/golden/documents/로 옮긴다
```

- `--preview`는 쪽(hwpx는 구역) 하나씩만 메모리에 들고 통계를 낸다. 12MB·671쪽 PDF 기준 약 21초 걸린다(전체 텍스트를 한 문자열로 잇지 않는다).
- hwpx에는 쪽 개념이 없다(쪽 나눔은 조판 결과다). 구역별 누적 글자 수를 보고 `--slice`로 자른다.
- 누적 글자 수는 단위를 이어 붙이는 과정에서 몇 글자씩 어긋나는 **근사치**다. 최종 길이는 `--dry-run`으로 확인한다.

초안이 나온 뒤 사람이 할 일(3장 3-b~6단계): **4.3으로 전화·이메일·계좌 검출 → 제거 또는 합성값 치환 → 본문 육안 훑기** → `required_facts` 3~6개 큐레이션(연락처 금지) → `category`를 통제 어휘로 수정 → 마스킹(2종) 결과 육안 검수 → `tests/golden/documents/`로 이동 → `uv run pytest tests/golden` → 커밋 메시지에 `연락처 검수: N건 확인 / M건 치환` 기록.

### 4.2 `scripts/collect_bokjiro.py` 사용법 (복지서비스 Open API)

한국사회보장정보원이 data.go.kr로 공개하는 복지서비스 데이터셋 두 개에서 **여러 건을 한 번에** 받아 온다. 사람이 페이지를 하나씩 찾아 들어가는 대신 목록 조회로 서비스ID를 얻고 상세를 받아, 서술 필드를 제목 달린 섹션으로 이어 붙여 안내문 모양으로 만든다. 그 뒤 단계(마스킹 → 자동 분류 → 팩트 후보 → 초안 저장)는 4.1과 **완전히 같은 파이프라인**이다. 따라서 **연락처가 걸러지지 않는 것도 똑같고, 이 경로는 그 문제가 가장 심하다** — 아래 '섹션 조립'의 `문의처` 필드가 기관 대표번호·부서 메일을 그대로 실어 온다. 실측(2026-08-12): 편입된 지자체복지서비스 레코드 **8건 중 8건**이 연락처를 포함했다(중앙부처는 15건 중 3건). 이 경로로 받은 초안은 4.3 검출을 **건너뛰지 않는다.**

```bash
# 지자체 복지서비스 10건 (기본 5건, 최대 15건)
uv run python scripts/collect_bokjiro.py --api local --limit 10

# 중앙부처 복지서비스 — 일일 상한 100건이라 아껴 쓴다
uv run python scripts/collect_bokjiro.py --api central --limit 5

# 서비스ID를 직접 지정 (목록 조회를 건너뛴다)
uv run python scripts/collect_bokjiro.py --api central --serv-id WLF00001138
```

| 옵션 | 설명 |
|---|---|
| `--api` (필수) | `local` 지자체복지서비스 / `central` 중앙부처복지서비스 |
| `--limit N` | 목록에서 받아 올 서비스 수 (기본 5, **최대 15**). 상한을 넘기면 조용히 자르지 않고 거부한다 |
| `--page N` | 목록 페이지 번호. 같은 페이지를 다시 부르면 같은 서비스가 나오므로 이어서 모을 때 쓴다 |
| `--serv-id ID` | 서비스ID 직접 지정 (여러 번 사용 가능). 주면 목록 조회를 건너뛴다 — 대신 상세 링크가 없어 `source.url`이 빈다 |
| `--min-chars N` | 이보다 짧은 본문은 건너뛴다 (기본 500 = 실수집 문서 길이 하한) |
| `--output` | 초안 저장 디렉터리 (기본 `docs/golden-drafts/`) |
| `--dry-run` | 저장하지 않고 통계만 출력 (API 호출은 그대로 일어난다) |

**인증키**: `.env`의 `DATA_GO_KR_API_KEY` 환경변수에서 읽는다. 앱 Settings(`app/config.py`)를 넓히지 않는 이유는 수집 도구가 서비스 런타임이 아니기 때문이다 — 서버 기동에 필요한 설정과 운영자가 가끔 돌리는 스크립트의 자격증명을 한 곳에 섞으면, 키가 없다는 이유로 서비스가 못 뜨거나 반대로 서버 설정에 수집용 키가 딸려 들어간다. 키가 없으면 한 줄 오류로 끝난다.

**호출 예산**: 한 번 실행에 목록 1회 + `--limit`만큼의 상세 조회를 쓴다. 개발계정 일일 상한은 **중앙부처 100건 / 지자체 1,000건**이다. `--limit` 상한(15)은 실수로 하루치를 태우지 않게 하는 안전장치다.

동작·주의점:

- **인증키 이중 인코딩** (data.go.kr의 고전적 함정): 포털이 주는 인증키는 Encoding 형태라 `%2B`·`%2F`가 들어 있다. 이 값을 그대로 httpx `params=`로 넘기면 `%`가 다시 인코딩되어 `%252B`로 나가고, 서버는 다른 키로 읽어 코드 30(등록되지 않은 인증키)을 돌려준다. `WelfareApiClient`가 생성 시 `urllib.parse.unquote`로 한 번 풀어 두고 인코딩은 httpx에 맡긴다(Decoding 형태 키에는 `%`가 없어 두 형태 모두 그대로 받는다). 전송된 쿼리의 `serviceKey`가 원본 디코드 값과 같은지 테스트가 기계적으로 지킨다.
- **인증키는 어디에도 남기지 않는다.** 예외 메시지에는 서버가 돌려준 문구가 아니라 코드에 대응하는 우리 설명만 담는다 — 인증키 오류 응답(`OpenAPI_ServiceResponse`)에는 요청 URL, 즉 키가 통째로 들어 있어서다. 로그·표준출력에도 키를 쓰지 않는다.
- **두 API의 필드 이름이 다르다**(중앙 `tgtrDtlCn` ↔ 지자체 `sprtTrgtCn` 등). 파싱 코드를 두 벌 두지 않고 차이를 `app/easyread/bokjiro.py`의 `WelfareApi` 표에 데이터로 적어 둔다 — API가 필드를 바꾸면 표만 고친다.
- **섹션 조립**: `서비스 요약 → 지원 대상 → 선정 기준 → 서비스 내용 → 신청 방법 → 문의처 → 근거 법령 → 구비 서류` 순으로 제목을 달아 잇는다. 빈 필드는 빠지고, **같은 본문이 두 필드에 들어 있으면 한 번만 담는다** — 지자체 레코드에는 `sprtTrgtCn`과 `slctCritCn`이 글자까지 같은 것이 실제로 있다. **`문의처` 섹션은 사실상 항상 전화번호(때로 부서 메일)를 담는다** — 2종 축소 뒤로는 마스킹을 통과해도 평문으로 남으므로, 이 섹션은 3-b에서 지우거나 합성값으로 바꾼다. 안내문 성격상 문의처를 통째로 지워도 골든셋 평가에는 지장이 없다(`required_facts`에 연락처를 넣지 않으므로).
- **데이터 품질**: 지자체 레코드 중 상당수가 서술 필드가 얕아 500자에 못 미친다. 2026-08-07 실측으로 **1페이지 14건 중 5건, 2페이지 15건 중 13건**이 미달 — 뒤쪽 페이지일수록 급격히 얕아진다(합계 29건 중 11건만 통과, 38%). 사유와 함께 건너뛰고 넘어가므로, 목표 건수를 채우려면 `--limit`을 여유 있게 잡고 앞쪽 페이지부터 훑는다.
- **같은 페이지를 다시 부르면 같은 서비스가 나온다.** 스크립트에 중복 제거가 없어 이미 만든 초안과 겹치는 서비스가 새 id로 한 번 더 저장된다(본문이 같은 문서 둘은 골든셋 스키마 테스트가 막는다). 이어서 모을 때는 `--page`를 올리거나, 이미 받은 `servId`를 피해 `--serv-id`로 지정한다.
- **출처 메타**: `url`은 목록 응답의 `servDtlLink`(복지로 상세 페이지), `organization`은 소관 부서명(지자체 `bizChrDeptNm`은 이미 시도·시군구를 품고 있어 앞에 덧붙이지 않는다), `license`는 `이용허락범위 제한 없음(data.go.kr)`. 여기에 `GoldenSource.dataset`·`record_id`(=`servId`)를 남겨 **어느 데이터셋의 몇 번 레코드인지**로 재현할 수 있게 한다(URL만으로는 부족하다).
- XML은 DTD 선언을 파서 수준에서 거부하고 읽는다(`app/ingest/extractors.py`와 같은 방어).

### 4.3 연락처 검출 (3장 3-b 보조 도구)

마스킹 범주가 2종이 된 뒤 **전화번호·이메일·계좌번호를 찾아 주는 코드 경로는 남아 있지 않다.** 스크립트를 새로 만들지 않고 아래 한 줄로 초안을 훑는다 — 검출 결과는 담당자 화면에만 남기고 이슈·채팅에 붙여 넣지 않는다.

```bash
# 초안 전체(또는 파일 하나)에서 연락처 후보와 앞뒤 맥락을 뽑는다
uv run python -c "
import json,re,sys,pathlib
P={'전화':r'(?<!\d)(?:01[016789]|02|0[3-6]\d|070|080|050\d)[-.\s]?\d{3,4}[-.\s]?\d{4}(?!\d)',
   '이메일':r'[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}',
   '계좌':r'(?<!\d)\d{3,6}-\d{2,6}-\d{4,8}(?!\d)'}
for f in sys.argv[1:]:
    t=json.loads(pathlib.Path(f).read_text(encoding='utf-8')).get('source_text','')
    for k,p in P.items():
        for m in re.finditer(p,t):
            print(pathlib.Path(f).name,k,m.group(),'|',t[max(0,m.start()-25):m.end()+15].replace('\n',' '))
" docs/golden-drafts/*.json
```

- 정규식은 축소 **전** `app/privacy/masking.py`가 쓰던 것과 같다. 코드에서 사라진 판정 기준을 절차 문서에 옮겨 둔 것이므로, 축소 커밋 이후에도 여기 값이 기준이다.
- **오탐과 중복 보고가 난다.** 계좌 패턴(`\d{3,6}-\d{2,6}-\d{4,8}`)이 넓어 전화번호·카드번호 앞자리를 겹쳐 집는다 — 실측(합성 문서 `011`)에서 같은 `070-4567-8901`이 '전화'와 '계좌'로 두 번, 카드번호 앞 12자리가 '계좌'로 한 번 더 보고됐다. 표 숫자열·사업 코드도 같은 이유로 걸린다. 후보는 사람이 하나씩 보고 판단한다.
- **미탐이 더 위험하다.** 띄어쓴 번호(`044 202 3000`), 괄호 국번(`(044)202-3000`), `내선 1234`, PDF 공백 소실로 붙어 버린 숫자열은 걸리지 않는다. 이 명령은 3-b를 대신하지 못하고 **본문 육안 훑기를 줄여 줄 뿐이다.**
- 편입 직전 `tests/golden/documents/`를 대상으로 한 번 더 돌려 확인한다(합성 문서 20건은 마스킹 회귀 테스트용으로 일부러 개인정보를 품고 있어 항상 걸린다 — `synthetic: true`인 문서의 검출은 정상이다).

변환 상한(4,000자)을 넘어 평가 시 변환 단계에서 거부된다. 본문을 잘라 붙이면 문맥이 끊기므로 `--pages`·`--slice`로 **안내문 한 편 단위로 다시 발췌**하는 것이 맞다. 넷 다 원본 PDF가 `docs/golden/`에 남아 있다.

**② 문서 유형 적합성 — 제외 권고**

- **노인실태조사 보고서군** (`052`·`060`·`062`): 통계 조사 **보고서**다. 우리 제품이 다루는 대상은 시민이 받아 읽는 대민 안내문인데, 이 문서군은 조사 방법·표본·집계표를 서술한다. 쉬운 글로 바꿀 대상이 아니라 요약 대상이라 변환 품질을 재는 기준으로 쓰면 평가가 제품 목표와 어긋난다. `052`·`062`는 스키마를 통과해 지금 평가셋에 들어 있으므로, 빼려면 사람이 결정해야 한다.
- **감사 처분요구서군** (`063`·`064`·`065`): 기관 내부 문서(처분요구·개선요구)이고 독자가 시민이 아니다. 더 큰 문제는 **PDF 공백 소실 아티팩트**가 확인된 점이다 — 낱말 사이 공백이 통째로 사라져 `신청단계신의료기술평가유예신청서제출` 같은 덩어리가 본문에 남아 있다. 이 상태로는 문장 분리·어려운 표현 검출·LLM 판정이 모두 원문 품질이 아니라 추출 결함을 측정하게 된다. **제외 권고**(재수집하더라도 같은 추출 경로면 같은 결함이 재현된다).

**③ `035` 12세 이하 어린이 국가예방접종사업 — 변별력 부족**

어려운 표현이 1개뿐이고(기준 2개) 필수 팩트도 1개다. 이미 상당히 쉬운 글이라 변환 전후 차이가 거의 없다 — 통과율만 올리고 실력은 재지 못한다. **제외 권고.**

**④ 잡파일 `tests/golden/041-2026년_국민기초생활보장_사업안내.jso`**

확장자가 `.jso`(오타)이고 `documents/` 밖에 있어 로더가 읽지 않는다. 내용은 정상적인 골든셋 초안 형식이며(`id: 041`, `synthetic: false`, 국민기초생활보장 사업안내 본문), 같은 번호의 다른 초안이 `docs/golden-drafts/041-2025년-발달장애인지원-사업안내.json`에 이미 있어 **id 충돌**이 난다. 이동·삭제하지 않고 보고만 한다 — 살릴지(id 재발급 후 초안 디렉터리로) 버릴지는 사람이 정한다.

**⑤ `032` 제주향토음식 요리교실 — 카테고리 재확인 (경미)**

원본이 `(공고문 제2026-2658) … 사업자 공모.hwpx`인데 카테고리는 `행정 안내문`이다. 분류기는 `행정 안내문`과 `공고문`이 동점이라 판단을 포기했다. 통제 어휘 안의 값이라 테스트는 통과하므로 급하지 않지만, 주제 분포 집계를 쓰려면 확정해 두는 편이 낫다.

**⑥ 남는 유효 문서 수**

②·③ 권고를 모두 받아들이면 실수집은 `032`·`039`·`042`·`048`·`051` **5건**만 남는다(합성 20건 포함 25건). 목표 25건(2장)에는 닿지만 **전량 교체**라는 원래 취지에는 못 미치므로, ①의 4건을 발췌 재수집해 되살리는 것이 우선순위가 가장 높다.

되살릴 수 있는 것부터 세면: ① 발췌 재수집 4건 + 팩트만 채우면 되는 4건(`031`·`034`·`036`·`065`, 단 `065`는 ②의 제외 권고 대상) + 카테고리만 정하면 되는 것들. 여기까지 손대면 실수집 12건 내외까지 회복된다.

## 6. 기존 골든셋 재검토 판단 (2026-08-12, 마스킹 2종 축소 대응)

**판단: 이미 편입된 문서와 초안은 재검수하지 않는다. 앞으로 만드는 것만 3-b 대상이다.**

근거 — 축소 **전** 마스킹 정규식 5종으로 `tests/golden/documents/` 56건(합성 20 + 실수집 36)과 `docs/golden-drafts/` 48건의 전 필드를 훑은 실측 결과다. 5장은 2026-08-06 시점 스냅숏이라 건수가 다르며, 아래 수치가 2026-08-12 현재 값이다.

| 대상 | 평문 연락처 | 마스킹 플레이스홀더가 남은 문서 |
|---|---|---|
| `tests/golden/documents/` 실수집 36건 | **0건** | 13건 — `[[전화번호N]]` 17회/12건, `[[계좌번호N]]` 15회/1건, `[[주민등록번호N]]`·`[[카드번호N]]` 각 1건(`064`) |
| `docs/golden-drafts/` 48건(전부 실수집) | **0건** | 18건 — `[[전화번호N]]` 44회/17건, `[[계좌번호N]]` 17회/2건, `[[이메일N]]` 2회/2건 |
| `tests/golden/documents/` 합성 20건 | 설계상 포함 | 마스킹 회귀 테스트용으로 일부러 개인정보를 품는다 — 대상 아님 |

읽어야 할 것은 "0건"이 아니라 **플레이스홀더 13건·18건** 쪽이다. 실수집 36건 중 **13건(36%)의 원문에 연락처가 실제로 들어 있었고**, 지금 안전한 이유는 우리가 조심해서가 아니라 **그때 파이프라인이 5종이었기 때문이다.** 같은 절차를 축소 이후에 그대로 밟으면 이 13건은 기관 대표번호·부서 메일이 박힌 채 커밋된다. 재검수가 필요 없다는 결론과 절차를 고쳐야 한다는 결론은 같은 실측에서 나온다.

**따라서 3-b를 반드시 밟아야 하는 경우:**

- 축소 커밋 이후 `scripts/collect_golden.py`·`scripts/collect_bokjiro.py`로 새로 만든 모든 초안
- **원본에서 다시 뽑는 모든 재수집** — 특히 5.3 ①의 4,000자 초과 문서(`047`·`050`·`060` — `docs/golden/`의 원본 PDF에서 `--pages`·`--slice`로 재발췌). 재발췌하면 지금 박혀 있는 플레이스홀더가 **평문 연락처로 되돌아온다**
- 5.2에서 `docs/golden-drafts/`로 되돌린 11건을 다시 편입할 때 — 되돌린 파일 그대로 쓰면 이미 마스킹된 상태라 안전하지만, 원본에서 다시 받으면 그렇지 않다

**하지 않는 것**: 이미 편입된 36건의 플레이스홀더를 원문으로 되돌리거나 다른 표기로 바꾸는 작업. 플레이스홀더가 박힌 본문은 그 자체로 안전하고, 손대면 `required_facts` 보존 검사와 통과율 추이가 함께 흔들린다.
